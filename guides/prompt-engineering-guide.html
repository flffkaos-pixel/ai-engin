프롬프트 엔지니어링 실전: 6개 패턴과 실패 사례

운영자 직접 작성 · 2026년 9월 업데이트 · 약 9분 분량

프롬프트는 길게 쓴다고 좋아지지 않습니다. 저는 30줄짜리 프롬프트보다 8줄 구조화 프롬프트가 더 잘 동작하는 경우를 수없이 봤습니다. 아래 6개 패턴만 익히세요.

1. 역할 + 작업 + 제약

당신은 시니어 코드 리뷰어입니다.
아래 파이썬 함수를 리뷰하세요.
제약: 문제점 3개까지만, 각각 수정 코드 포함.

2. Few-shot 2개가 10개보다 낫다

예시는 2~3개면 충분합니다. 중요한 것은 정답 예시와 오답+이유 예시를 섞는 것입니다. 같은 유형만 10개 넣으면 모델이 패턴을 외워버립니다.

3. 구조화 출력 강제

JSON 스키마를 먼저 주고 "스키마 외 텍스트 금지"를 명시하세요. 파싱 실패가 90% 줄어듭니다. Phase 5-20 Structured Outputs 레슨과 함께 보세요.

4. 단계 분리: 추론과 답변 분리

"먼저 근거를箇条書き로 정리한 뒤 답하라"는 식으로 추론과 최종 답변을 분리하세요. 복잡한 질문에서 정답률이 체감상 올라갑니다.

5. 자기검증 한 줄

마지막에 "위 답을 검증하고 틀린 부분을 고쳐라"를 붙이세요. 수학·코드 문제에서 특히 효과적입니다. 단, 2회 이상 반복하면 수렴하지 않는 경우가 있어 1회가 적당합니다.

6. 실패했을 때 고치는 순서

  1. 질문이 모호한가? → 입력에 예시와 반례 추가
  2. 출력이 불안정한가? → temperature를 0~0.2로 낮춤
  3. 길이가 부족한가? → "500자 이상" 같은 숫자 제약 추가
