# DualPipe 병렬 처리

> DeepSeek-V3는 MoE 전문가가 노드 전체에 분산된 2,048개의 H800 GPU에서 학습되었습니다. 노드 간 전문가 all-to-all 통신 비용은 1 GPU-시간의 연산마다 1 GPU-시간의 통신이 필요했습니다. GPU는 절반의 시간 동안 유휴 상태였습니다. DualPipe (DeepSeek, 2024년 12월)는 순전파와 역전파 연산을 이들이 촉발하는 all-to-all 통신과 중첩시키는 양방향 파이프라인입니다. 버블이 줄어들고, 처리량이 증가하며, 두 개의 모델 파라미터 복사본을 유지하는 비용("dual"이라는 이름의 유래)은 Expert Parallelism이 이미 전문가를 랭크 전체에 분산시키고 있기 때문에 저렴합니다. 이 과는 DualPipe가 실제로 무엇을 하는지, 그리고 Sea AI Lab의 DualPipeV 개선이 약간 더 타이트한 버블을 대가로 2배 파라미터 비용을 어떻게 없애는지에 대한 학습형 워크스루입니다.

**유형:** 학습
**언어:** Python (stdlib, 스케줄 시뮬레이터)
**사전 필요과목:** 10단계 05과 (분산 학습, FSDP, DeepSpeed), 10단계 14과 (오픈 모델 아키텍처 및 MoE)
**시간:** ~60분

## 학습 목표

- DualPipe 순전파-역전파 청크의 네 가지 구성 요소와 각각이 고유한 중첩 윈도우를 가지는 이유를 말할 수 있다
- 대규모에서의 파이프라인 버블 문제와 "버블 없음"이 실제로와 마케팅에서 각각 무엇을 의미하는지 설명할 수 있다
- 8개의 PP 랭크와 16개의 마이크로-배치에 대해 DualPipe 스케줄을 손으로 추적하고 순방향과 역방향 스트림이 서로의 유휴 슬롯을 채우는지 확인할 수 있다
- Sea AI Lab(2025)의 DualPipeV가 어떤 트레이드오프를 하는지 설명할 수 있다: Expert Parallelism이 비활성화되었을 때 약간 더 큰 버블을 대가로 2배 파라미터 복제를 없앰

## 문제

671B MoE 모델을 2k H800 GPU에서 학습하는 것은 세 가지 복합 병목에 직면합니다:

1. **메모리 압박.** 각 GPU는 모델의 일부를 보유합니다. 128개 헤드에서 61개 층을 가로지르는 시퀀스 8k의 활성화 메모리는 엄청납니다.
2. **파이프라인 버블.** 전통적인 파이프라인 병렬 처리(GPipe, 1F1B)는 GPU가 자신의 스테이지 입력이나 그래디언트를 기다리는 동안 유휴 상태로 둡니다. 8개 스테이지에서 1F1B 스케줄링으로도 약 12%의 GPU 시간이 버블이 될 수 있습니다.
3. **노드 간 all-to-all.** Expert Parallelism을 사용한 MoE는 전문가를 노드 전체에 분산시킵니다. 모든 순전파는 토큰을 전문가에게 보내기 위한 all-to-all과 결과를 결합하기 위한 또 다른 all-to-all을 촉발합니다. 2k GPU에서 이는 쉽게 1:1의 연산-대-통신 비율이 됩니다.

이 각각에는 별도의 해결책이 있습니다: 메모리를 위한 그래디언트 체크포인팅, 파이프라인 버블을 위한 Zero Bubble (Sea AI Lab, 2023), all-to-all을 위한 expert-parallel 통신 커널. DualPipe가 하는 것은 이들이 함께 작동하도록 만드는 것입니다. 스케줄은 단일 순전파-역전파 청크 내에서 연산과 통신을 중첩시키고, 파이프라인의 양 끝에서 동시에 마이크로-배치를 주입하며, 결과 스케줄을 사용하여 all-to-all을 연산 윈도우 내에 숨깁니다.

보고된 결과: 파이프라인 버블의 거의 완전한 제거, DeepSeek-V3의 14.8T-토큰 학습 실행에서 95% 이상의 GPU 활용률.

## 개념

### 파이프라인 병렬 처리 복습

N-층 모델을 P개 장치에 분할합니다. 장치 `i`는 층 `i * N/P .. (i+1) * N/P - 1`을 보유합니다. 마이크로-배치는 장치 0에서 P-1로 순전파된 다음, P-1에서 0으로 역전파됩니다. 각 장치는 이전 장치가 출력을 보낼 때만 자신의 순전파 스테이지를 시작할 수 있고, 하류 장치가 상류 그래디언트를 보낼 때만 역전파를 시작할 수 있습니다.

GPipe (Huang et al., 2019)는 한 번에 하나의 마이크로-배치를 스케줄링하여 대부분의 GPU 시간을 낭비합니다. 1F1B (Narayanan et al., 2021)는 여러 마이크로-배치에 대해 순전파와 역전파를 인터리브합니다. Zero Bubble (Qi et al., 2023)은 역전파를 두 부분(입력 그래디언트용 B와 가중치 그래디언트용 W)으로 분할하고 이를 스케줄링하여 버블을 채웁니다. Zero Bubble 이후 파이프라인은 거의 타이트해집니다.

DualPipe는 다음 단계입니다. 그 위에 두 가지 아이디어를 추가합니다:

### 아이디어 1: 청크 분해

각 순전파 청크는 네 가지 구성 요소로 분할됩니다:

- **어텐션.** Q/K/V 투영, 어텐션, 출력 투영.
- **All-to-all 디스패치.** 토큰을 해당 전문가에게 보내는 노드 간 통신.
- **MLP.** MoE 전문가 연산.
- **All-to-all 결합.** 전문가 출력을 다시 가져오는 노드 간 통신.

역전파 청크는 이 각각의 그래디언트 버전을 추가합니다. DualPipe는 all-to-all 디스패치가 다음 청크의 어텐션 연산과 병렬로 일어나고, all-to-all 결합이 다음 청크의 MLP 연산과 병렬로 일어나도록 스케줄링합니다.

### 아이디어 2: 양방향 스케줄링

대부분의 파이프라인 스케줄은 스테이지 0에서 마이크로-배치를 주입하고 스테이지 P-1 쪽으로 흐르게 합니다. DualPipe는 양쪽 끝에서 마이크로-배치를 주입합니다. 스테이지 0는 거기서 시작하는 순전파 마이크로-배치를 보고, 스테이지 P-1도 거기서 시작하는 순전파 마이크로-배치를 봅니다. 두 스트림은 중간에서 만납니다.

이를 위해 장치 `i`는 초기-파이프라인 층 `i`와 후기-파이프라인 층 `P - 1 - i`를 모두 보유해야 합니다. 이것이 DualPipe의 "dual" 부분입니다: 각 장치는 서비스해야 하는 모델 층의 두 복사본(각 방향당 하나)을 유지합니다. DeepSeek-V3의 규모에서 이는 2배의 파라미터 복제 비용입니다. Expert Parallelism이 이미 MoE 전문가를 매우 얇게 분산시켜 비전문가 층을 두 번 복제하는 것이 작은 비용이기 때문에 감당할 수 있습니다.

중요하게도, 한 방향의 순전파 스트림과 다른 방향의 역전파 스트림은 단일 방향 스케줄에서 버블이 있었을 정확히 그 위치에서 중첩됩니다. 버블이 사라집니다.

### 손으로 추적한 스케줄

P = 4개 랭크, 8개 마이크로-배치, 4개 순방향 / 4개 역방향으로 분할. 시간은 왼쪽에서 오른쪽으로 흐릅니다; 행은 장치 랭크입니다.

```
            Time →
rank 0:  F1 F2 F3 F4  F5R F6R F7R F8R  B1 B2 B3 B4  ...
rank 1:     F1 F2 F3  F4/F5R F6R F7R   B1 B2 ...
rank 2:        F1 F2  F3/F5R F4/F6R    B1 ...
rank 3:           F1  F2/F5R F3/F6R    ...
```

"F4/F5R" 표기법을 읽으면: rank 1은 동일한 시간 슬롯에서 마이크로-배치 4의 순전파(파이프라인에서 왼쪽에서 오른쪽으로)와 마이크로-배치 5의 순전파(오른쪽에서 왼쪽으로)를 실행하고 있습니다. 이것이 "양방향"이 운영상 의미하는 바입니다.

rank 2에서 교차 스트림이 더 일찍 중첩되고, rank 0과 P-1에서 가장 늦게 중첩됩니다. 스케줄의 안정적 중간 단계에서 모든 랭크는 순방향-X-방향과 역방향-Y-방향이 중첩된 상태로 실행됩니다. 연산은 바쁩니다. 순전파를 위한 all-to-all 디스패치는 역전파 연산 내에 숨습니다. All-to-all 결합은 순전파 연산 내에 숨습니다. 버블은 압착됩니다.

### 버블 계산

표준 1F1B 파이프라인 버블 (랭크당 낭비되는 시간):

```
bubble_1F1B = (P - 1) * forward_chunk_time
```

Zero Bubble 개선은 이를 줄이지만 0으로 만들지는 않습니다. DualPipe는 안정적 단계에서 마이크로-배치 수가 파이프라인 깊이의 2배로 나누어떨어지면 버블이 0입니다. 안정적 단계 외부(워밍업 및 쿨다운)에는 약간의 버블이 있지만 마이크로-배치 수에 따라 증가하지 않습니다 — 논문이 강조하는 핵심 속성입니다.

마케팅 용어로: "버블 없음". 기술적 용어로: 버블이 마이크로-배치 수에 따라 증가하지 않습니다. Sea AI Lab의 후속 분석(DualPipeV / Cut-in-half)은 Expert Parallelism이 병목이 아닐 때만 완전한 제로 버블이 가능하며, EP 기반 all-to-all에서는 항상 일부 스케줄링 타협이 존재함을 보여줍니다.

### DualPipeV — 개선

Sea AI Lab (2025)은 EP 통신 중첩이 중요하지 않을 때 2배 파라미터 복제가 낭비라고 관찰했습니다. 그들의 DualPipeV 스케줄은 양방향 주입을 단일 파라미터 복사본에서 실행되는 "V-모양" 스케줄로 접습니다. 버블은 DualPipe보다 약간 크지만 메모리 절감은 상당합니다. DeepSeek은 EP-끄기 모드로 오픈소스 DualPipe 구현에서 DualPipeV를 채택했습니다.

트레이드오프:

| 기능 | DualPipe | DualPipeV | 1F1B | Zero Bubble |
|---------|---------|-----------|------|------------|
| 장치당 파라미터 복사본 | 2 | 1 | 1 | 1 |
| 마이크로-배치 대비 버블 | 일정 | 작은 증가 | 증가 | 증가 |
| 연산-통신 중첩 | 전체 | 부분 | 최소 | 부분 |
| 사용 시기 | EP-무거운 MoE | 밀집 또는 EP-경량 | 기준선 | 모든 파이프라인 |

### 14.8T-토큰 실행에 미치는 의미

DeepSeek-V3의 사전학습은 2,048개의 H800 GPU에서 약 280만 GPU-시간으로 14.8T 토큰을 소비했습니다. 순진한 1F1B를 사용했다면 12-15%를 파이프라인 버블로 잃었을 것입니다 — 340-420K GPU-시간, 전체 70B 모델을 학습하기에 충분한 양입니다. DualPipe는 대부분을 회수했습니다. 내부 로그 없이 기여도를 직접 정량화하기는 어렵지만, 논문의 주장은 학습 전체에 걸쳐 평균 95% 이상의 GPU 활용률입니다.

더 작은 실행(1k GPU 미만)의 경우 DualPipe는 과잉입니다 — 파이프라인 버블이 총 비용에 비해 더 작고, 밀집 모델 학습은 거의 all-to-all 병목에 부딪히지 않습니다. 수천 GPU 규모의 프런티어 MoE 학습에서는 사실상 필수입니다.

### 스택에서의 위치

- **FSDP** (10단계 05과)와 상호 보완적. FSDP는 모델 파라미터를 랭크 전체에 샤딩하고, DualPipe는 랭크 전체에 연산을 스케줄링합니다. 결합됩니다.
- **ZeRO-3** 그래디언트 샤딩과 호환. 두-복사본 복제를 위한 부기는 ZeRO의 샤딩된 그래디언트와 협력해야 합니다.
- 특정 클러스터 토폴로지에 맞춰진 **맞춤 all-to-all 커널**이 필요합니다. DeepSeek의 오픈소스 커널이 참조 구현입니다.

## 활용하기

`code/main.py`는 파이프라인 스케줄 시뮬레이터입니다. `(P, n_micro_batches, schedule)`을 입력받고 1F1B, Zero Bubble, DualPipe, DualPipeV 각각에 대한 안정적 단계 활용률을 출력합니다. 이는 교육 도구입니다 — 숫자는 논문의 정성적 주장과 일치하지만, 프로덕션 측정 속도 향상에 대한 주장은 아닙니다.

시뮬레이터의 가치: 다른 P와 마이크로-배치 수로 실행하고 1F1B에서는 버블 비율이 증가하지만 DualPipe에서는 증가하지 않는 것을 관찰합니다.

실제 학습 실행을 위한 통합 고려사항:

- 마이크로-배치 수에 깔끔하게 나누어떨어지는 파이프라인-병렬 깊이를 선택하십시오.
- Expert-parallel 메시가 양방향 all-to-all을 지원하는지 확인하십시오. DeepSeek의 커널이 참조입니다.
- 처음에 스케줄 자체를 디버깅하는 데 일주일을 소비할 것으로 예상하십시오. 부기가 까다롭습니다.
- GPU 활용률을 집계뿐 아니라 랭크별로 모니터링하십시오. DualPipe의 이점은 지연자를 조이는 데서 옵니다.

## 연습 문제

1. `code/main.py`를 `(P=8, micro_batches=16, schedule=dualpipe)`와 `(P=8, micro_batches=16, schedule=1f1b)`로 실행하십시오. GPU 활용률 차이를 계산하고 백만 토큰 학습당 회수된 GPU-시간으로 표현하십시오.

2. `(P=4, micro_batches=8, schedule=dualpipe)`에 대한 스케줄 표를 손으로 스케치하십시오. 각 시간 슬롯에 마이크로-배치 ID와 방향을 표시하십시오. 버블이 없는 첫 번째 시간 슬롯을 식별하십시오.

3. DeepSeek-V3 기술 보고서(arXiv:2412.19437)의 그림 5를 읽으십시오. DualPipe 순전파 청크 내에서 all-to-all 디스패치의 중첩 윈도우를 식별하십시오. 연산 스케줄이 어떻게 이를 숨기는지 설명하십시오.

4. P=8 파이프라인 스테이지를 가진 70B 밀집 모델과 P=16 파이프라인 스테이지를 가진 671B MoE 모델에 대한 DualPipe의 2배 파라미터 오버헤드를 계산하십시오. MoE 경우의 오버헤드가 비례적으로 더 작은 이유를 보이십시오(대부분의 파라미터는 전문가이며, 큰 EP 그룹 전체에 샤딩됨).

5. DualPipe를 Chimera(2021년의 경쟁 양방향 스케줄러)와 비교하십시오. 논문의 섹션 3.4를 참조로 DualPipe가 추가했고 Chimera에는 없었던 두 가지 특정 속성을 식별하십시오.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|-----------|
| 파이프라인 버블 | "랭크당 유휴 시간" | 파이프라인 스테이지가 입력이나 그래디언트를 기다리는 동안 낭비되는 GPU 사이클 |
| 1F1B | "기본 파이프라인 스케줄" | 하나의 순전파 / 하나의 역전파를 인터리브하는 스케줄링; DualPipe가 이기는 기준선 |
| Zero Bubble | "Sea AI Lab 2023" | 역전파를 B(입력 그래디언트)와 W(가중치 그래디언트)로 분할; 파이프라인을 거의 완전히 조임 |
| DualPipe | "DeepSeek-V3 스케줄" | 양방향 파이프라인 + 연산-통신 중첩; 버블이 마이크로-배치 수에 따라 증가하지 않음 |
| DualPipeV | "Cut-in-half" | 2배 파라미터 복제를 약간 더 큰 버블을 대가로 없애는 V-모양 개선 |
| 청크 | "파이프라인 작업 단위" | 하나의 파이프라인 스테이지를 통한 하나의 마이크로-배치의 순전파 또는 역전파 |
| All-to-all 디스패치 | "토큰을 전문가에게 전송" | 토큰을 할당된 MoE 전문가로 라우팅하는 노드 간 통신 |
| All-to-all 결합 | "전문가 출력 가져오기" | MLP 후에 전문가 출력을 수집하는 노드 간 통신 |
| Expert Parallelism (EP) | "GPU 간 전문가 분산" | MoE 전문가를 랭크 전체에 샤딩하여 다른 GPU가 다른 전문가를 보유 |
| Pipeline Parallelism (PP) | "GPU 간 층 분산" | 모델 층을 랭크 전체에 샤딩; DualPipe가 스케줄링하는 차원 |
| 버블 비율 | "낭비된 GPU 시간" | (bubble_time / total_time); DualPipe가 0으로 몰아가는 비율 |
