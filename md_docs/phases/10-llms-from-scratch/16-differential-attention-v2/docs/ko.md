# 차등 어텐션 (V2)

> 소프트맥스 어텐션은 일치하지 않는 모든 토큰에 소량의 확률을 분산합니다. 10만 개의 토큰에서 이 노이즈는 누적되어 신호를 압도합니다. Differential Transformer (Ye et al., ICLR 2025)는 어텐션을 두 개의 소프트맥스 차이로 계산하여 공유된 노이즈 바닥을 제거함으로써 이를 해결합니다. DIFF V2 (Microsoft, 2026년 1월)는 프로덕션 스택 재작성입니다: 기준 트랜스포머와 디코드 지연 시간 일치, 맞춤 커널 불필요, FlashAttention 호환 가능. 이 과는 V1에서 V2까지 종단간을 다루며, stdlib Python에서 실행할 수 있는 차분 연산의 작동하는 장난감 구현을 제공합니다.

**유형:** 구축
**언어:** Python (stdlib)
**사전 필요과목:** 7단계 02과 (자기-어텐션), 7단계 15과 (어텐션 변형), 10단계 14과 (아키텍처 워크스루)
**시간:** ~60분

## 학습 목표

- 소프트맥스 어텐션이 노이즈 바닥(noise floor)을 가지는 이유와 그것이 컨텍스트 길이에 따라 증가하는 이유를 정확히 설명할 수 있다
- 차등 어텐션 공식을 유도하고 뺄셈이 공유된 노이즈 성분을 제거하면서 신호를 보존하는 이유를 설명할 수 있다
- V1에서 V2로의 diff를 설명할 수 있다: 무엇이 빨라졌고, 무엇이 단순해졌고, 무엇이 더 안정적이 되었으며, 각 변경이 프로덕션 사전학습에 왜 필요했는지
- 순수 Python으로 차등 어텐션을 처음부터 구현하고 합성 신호-더하기-노이즈 질의에서 노이즈 제거 특성을 경험적으로 검증할 수 있다

## 문제

표준 소프트맥스 어텐션에는 대규모에서 운영상의 골칫거리로 변하는 수학적 특성이 있습니다. 질의 `q`에 대해 어텐션 가중치는 `softmax(qK^T / sqrt(d))`입니다. 소프트맥스는 절대 정확한 0을 생성할 수 없습니다 -- 일치하지 않는 모든 토큰이 약간의 양의 질량을 얻습니다. 이 잔차 질량은 노이즈이며, 컨텍스트 길이에 비례합니다. 128k 토큰에서 각 불일치 토큰이 0.001%의 확률만 받더라도, 127,999개가 합쳐져 전체의 약 12%를 기여합니다. 모델은 컨텍스트에 따라 증가하는 노이즈 바닥을 피해 가는 법을 학습해야 합니다.

경험적으로 이는 어텐션 헤드 간섭으로 나타납니다: 긴 컨텍스트 RAG에서 환각 인용, 10만 토큰 검색 작업에서 lost-in-the-middle 실패, 32k를 넘는 needle-in-haystack 벤치마크에서 미묘한 정확도 저하. Differential Transformer 논문(arXiv:2410.05258, ICLR 2025)은 그 격차를 측정했습니다: DIFF 트랜스포머는 동일한 크기의 기준선보다 더 낮은 퍼플렉서티, 더 높은 긴 컨텍스트 정확도, 더 적은 환각을 달성했습니다.

DIFF V1에는 프런티어 사전학습 파이프라인에서 배제된 세 가지 문제가 있었습니다. 값 캐시를 디코드 단계당 두 번 로드해야 했고, FlashAttention 호환성을 깨는 맞춤 CUDA 커널이 필요했으며, 헤드별 RMSNorm이 70B 이상 규모에서 장기 학습을 불안정하게 만들었습니다. DIFF V2 (Microsoft unilm 블로그, 2026년 1월 20일)는 세 가지를 모두 수정했습니다. 이 과는 두 버전을 모두 다루고, 차분 연산자를 구축하며, 장난감 질의에서 노이즈 제거를 벤치마킹합니다.

## 개념

### 소프트맥스의 노이즈 바닥

질의 `q`와 키 `K = [k_1, ..., k_N]`에 대해 어텐션 가중치는:

```
w_i = exp(q . k_i / sqrt(d)) / sum_j exp(q . k_j / sqrt(d))
```

어떤 `w_i`도 절대 0이 아닙니다. `k_i`가 `q`와 완전히 무관하더라도 점수 `q . k_i`는 0이 아닙니다 -- 분산 `||q||^2 / d`로 0 주변에서 변동합니다. 소프트맥스 정규화 후에도 각 무관 토큰은 여전히 가중 합에 `O(1/N)`을 기여합니다. 무관 토큰의 총 기여도는 `O((N-1)/N) = O(1)`입니다 -- 작은 양이 아닙니다.

모델이 원하는 것은 하드 top-k와 비슷한 것입니다: 일치하는 토큰에는 높은 가중치, 나머지는 거의 0에 가깝게. 소프트맥스는 이를 직접 수행하기에는 너무 부드럽습니다.

### 차등 아이디어

각 헤드의 Q와 K 투영을 두 개로 분할합니다: Q = (Q_1, Q_2), K = (K_1, K_2). 두 개의 어텐션 맵을 계산합니다:

```
A_1 = softmax(Q_1 K_1^T / sqrt(d))
A_2 = softmax(Q_2 K_2^T / sqrt(d))
```

출력:

```
DiffAttn = (A_1 - lambda * A_2) V
```

뺄셈은 두 맵이 공유하는 노이즈 분포를 상쇄합니다. 두 맵이 127,000개의 무관 토큰에 대해 대략 균일한 가중치를 가진다면(무작위 초기화에서 그럴 것입니다), 이들은 상쇄됩니다. 신호 -- 실제로 관련된 소수 토큰에 집중된 가중치 -- 는 두 맵에서 동일한 크기로 나타나야만 상쇄되는데, 모델이 학습되면 그렇지 않을 것입니다.

`lambda`는 헤드당 학습 가능한 스칼라로, `lambda = exp(lambda_q1 dot lambda_k1) - exp(lambda_q2 dot lambda_k2) + lambda_init`으로 파라미터화됩니다. 음수일 수 있습니다. `lambda_init`은 기본적으로 0.8과 같은 작은 양수입니다.

### 이것이 헤드폰 노이즈 캔슬링과 같은 이유

동일한 목소리를 녹음하는 두 개의 노이즈 마이크를 생각해 보십시오. 둘 다 화자와 상관된 배경 소음을 포착합니다. 하나에서 다른 하나를 빼면 공유된 노이즈가 사라집니다. 목소리는 두 신호가 위상이나 진폭에서 충분히 달라 완전한 상쇄를 방지하기 때문에 살아남습니다. 헤드당 `lambda`는 정확히 이 균형을 학습합니다.

### V1 vs V2: diff

V1은 기준 트랜스포머와 파라미터 수를 동일하게 유지했습니다. 헤드당 두 개의 질의를 얻기 위해 헤드 차원을 절반으로 줄였습니다. 이는 헤드 표현력을 희생했고, 더 고통스럽게는 헤드당 값 캐시를 절반으로 줄였습니다. 디코드는 단계당 값 캐시를 두 번 로드해야 했습니다(소프트맥스 분기당 한 번). 결과: 파라미터 수가 일치함에도 디코드가 기준선보다 느렸습니다.

V2는 질의 헤드 수를 두 배로 늘리고 KV 헤드는 동일하게 유지합니다(up-projection에서 파라미터를 빌려옴). 헤드 차원은 기준선과 동일하게 유지됩니다. 뺄셈 후, 추가 차원은 기준 트랜스포머의 O_W 투영과 일치하도록 다시 투영됩니다. 세 가지가 동시에 발생합니다:

1. 디코드 속도가 기준선과 일치합니다 (KV 캐시가 한 번 로드됨).
2. FlashAttention이 변경 없이 실행됩니다 (맞춤 커널 불필요).
3. 디코드에서 산술 강도가 증가합니다 (HBM에서 로드된 바이트당 더 많은 연산).

V2는 또한 V1이 뺄셈을 안정화하기 위해 사용했던 헤드별 RMSNorm을 제거합니다. 70B급 사전학습 규모에서 이 RMSNorm은 후기 학습을 불안정하게 만들었습니다. V2는 추가 모듈 없이 학습을 안정적으로 유지하는 더 간단한 초기화 방식으로 대체합니다.

## 직접 구현하기

`code/main.py`는 순수 Python으로 차등 어텐션을 구현합니다. 알려진 신호-더하기-노이즈 구조를 가진 장난감 질의를 통해 노이즈 제거 비율을 직접 측정할 수 있습니다.

### 1단계: 표준 소프트맥스 어텐션

Stdlib 행렬 연산: 리스트의 리스트, 수동 행렬곱, 최댓값을 뺀 수치 안정성 소프트맥스.

```python
def softmax(row):
    m = max(row)
    exps = [math.exp(x - m) for x in row]
    s = sum(exps)
    return [e / s for e in exps]
```

### 2단계: Q, K를 두 개의 반으로 분할

V1 스타일: 헤드 차원을 절반으로. V2 스타일: 헤드 차원을 유지하고 헤드 수를 두 배로. 장난감 구현은 교육적 명확성을 위해 V1을 사용합니다 -- 수학은 동일하고 부기만 다릅니다.

### 3단계: 두 개의 소프트맥스 분기 + 뺄셈

```python
A1 = [softmax([dot(q1, k) / scale for k in K1]) for q1 in Q1]
A2 = [softmax([dot(q2, k) / scale for k in K2]) for q2 in Q2]
diff_weights = [[a1 - lam * a2 for a1, a2 in zip(r1, r2)] for r1, r2 in zip(A1, A2)]
out = [[sum(w * v[j] for w, v in zip(row, V)) for j in range(d_v)] for row in diff_weights]
```

참고: 출력 가중치는 음수가 될 수 있습니다. 문제없습니다 -- 값 캐시는 여전히 부호 있는 기여를 처리합니다. 후속 V 투영이 부호를 흡수합니다.

### 4단계: 노이즈 제거 측정

길이 1024의 합성 시퀀스를 구축합니다. 알려진 위치에 신호 토큰을 배치하고 나머지를 노이즈로 채웁니다. (a) 신호 위치에 대한 표준 소프트맥스 어텐션 가중치와 (b) 차등 어텐션 가중치를 계산합니다. 각각의 신호 대 잡음비를 측정합니다. DIFF 어텐션은 두 분기가 얼마나 다르게 학습되었는지에 따라 3배에서 10배까지 더 높은 신호 대 잡음비를 생성합니다.

### 5단계: V1 vs V2 파라미터 계산

설정이 주어지면(hidden=4096, heads=32, d_head=128):

- 기준 트랜스포머: Q, K, V 각각 크기 `hidden * hidden`, MLP 4 * hidden.
- DIFF V1: Q, K 각각 크기 `hidden * hidden`, V 크기 `hidden * hidden` (변경 없음), 헤드 차원이 내부적으로 절반으로 줄어듦. 헤드당 `lambda` 파라미터 추가 (O(heads * d_head)).
- DIFF V2: Q 크기 `2 * hidden * hidden`, K 크기 `hidden * hidden`, V 크기 `hidden * hidden`. O_W 전에 추가 차원이 다시 투영됨. 동일한 `lambda` 파라미터 추가.

장난감은 V2의 추가 파라미터 비용(어텐션 블록당 대략 `hidden * hidden` 추가)을 측정하고 출력합니다.

## 활용하기

DIFF V2는 2026년 4월 기준으로 모든 프로덕션 추론 서버에서 제공되지는 않지만, vLLM과 SGLang에서 통합이 진행 중입니다. 한편 패턴은 다음에서 나타납니다:

- Microsoft 내부 긴 컨텍스트 프로덕션 모델.
- 256k 이상 컨텍스트를 목표로 하는 여러 오픈 모델 학습 실행의 연구 재현.
- DIFF 어텐션과 슬라이딩 윈도우 어텐션을 교차 층에 결합한 하이브리드 아키텍처.

2026년에 이를 사용해야 할 때:

- 64k 이상의 효과적 컨텍스트를 목표로 새 모델을 처음부터 학습할 때. 처음부터 차등 어텐션을 추가하십시오; 나중에 재학습하는 것은 비용이 많이 듭니다.
- Lost-in-the-middle 실패가 평가를 지배하는 긴 컨텍스트 모델을 미세 조정할 때. Q 투영에 대한 LoRA가 DIFF 구조를 근사할 수 있습니다.

사용하지 말아야 할 때:

- 안정적인 긴 컨텍스트 성능을 가진 사전 학습된 밀집 모델을 서빙하고 있을 때. 재학습 비용이 기존 가중치에서 거의 회수되지 않습니다.
- 컨텍스트가 항상 16k 미만일 때. 노이즈 바닥이 무시할 만합니다.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|-----------|
| 차등 어텐션 | "두 소프트맥스의 뺄셈" | Q, K를 두 개의 반으로 분할, 두 개의 소프트맥스 맵 계산, 두 번째(람다로 스케일링됨)를 첫 번째에서 뺀 후 V에 곱함 |
| 노이즈 바닥 | "소프트맥스의 0이 아닌 꼬리" | 소프트맥스가 모든 무관 토큰에 배치하는 O(1/N) 가중치로, 긴 컨텍스트에서 O(1)로 합산됨 |
| lambda | "뺄셈 스케일" | 헤드당 학습 가능한 스칼라로 `exp(lq1.lk1) - exp(lq2.lk2) + lambda_init`으로 파라미터화됨; 음수 가능 |
| DIFF V1 | "ICLR 2025 버전" | 원래 Differential Transformer; 파라미터 수 유지를 위해 헤드 차원 반으로 줄임, 맞춤 커널 필요, 디코드 느림 |
| DIFF V2 | "2026년 1월 수정" | KV 헤드는 유지하고 Q 헤드 두 배로; 기준선 디코드 속도와 일치, FlashAttention과 호환 |
| 헤드별 RMSNorm | "V1 안정화 장치" | V1이 차분 후 적용한 추가 정규화; V2는 후기 학습 불안정을 방지하기 위해 제거 |
| 신호 대 잡음비 | "어텐션이 얼마나 낭비되는지" | 실제 신호 위치의 가중치와 무관 위치의 평균 가중치의 비율 |
| Lost in the middle | "긴 컨텍스트 실패 모드" | 긴 컨텍스트 중간의 문서에 대한 검색 정확도가 떨어지는 경험적 현상 -- DIFF 어텐션이 이를 줄임 |
| 산술 강도 | "로드된 바이트당 FLOPs" | V2가 KV 로드당 질의를 두 배로 하여 디코드에서 증가시킨 비율; 메모리 바운드 디코드에 중요 |
