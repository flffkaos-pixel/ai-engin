# DeepSeek-V3 아키텍처 워크스루

> 10단계 14과는 모든 오픈 모델이 돌리는 여섯 가지 아키텍처 노브를 명명했습니다. DeepSeek-V3 (2024년 12월, 총 671B 파라미터, 활성 37B)는 여섯 가지를 모두 돌리고 네 가지를 더 추가합니다: Multi-Head Latent Attention, 보조-손실-없는 부하 균형, Multi-Token Prediction, DualPipe 학습. 이 과는 DeepSeek-V3의 아키텍처를 위에서 아래로 읽고 공개된 설정에서 모든 파라미터 수를 유도합니다. 완료되면 671B/37B 비율이 왜 올바른 선택인지, 그리고 MLA + MoE가 함께 프런티어에서 어느 하나만 사용할 때보다 왜 더 나은지 설명할 수 있습니다.

**유형:** 학습
**언어:** Python (stdlib, 파라미터 계산기)
**사전 필요과목:** 10단계 14과 (오픈 모델 워크스루), 10단계 17과 (NSA), 10단계 18과 (MTP), 10단계 19과 (DualPipe)
**시간:** ~75분

## 학습 목표

- DeepSeek-V3 설정을 위에서 아래로 읽고 각 필드를 여섯 가지 GPT-2 노브와 네 가지 DeepSeek 특화 추가의 관점에서 설명할 수 있다
- 총 파라미터 수(671B), 활성 파라미터 수(37B), 그리고 각각에 기여하는 구성 요소를 유도할 수 있다
- 128k 컨텍스트에서 MLA의 KV 캐시 풋프린트를 계산하고 동일한 활성 파라미터를 가진 GQA 밀집 모델이 부담할 비용과 비교할 수 있다
- 네 가지 DeepSeek 특화 혁신(MLA, MTP, 보조-손실-없는 라우팅, DualPipe)을 설명하고 각각이 아키텍처/학습 스택의 어느 부분을 대상으로 하는지 명명할 수 있다

## 문제

DeepSeek-V3는 아키텍처가 Llama 패밀리와 의미 있게 다른 첫 번째 프런티어 오픈 모델입니다. Llama 3 405B는 "여섯 개의 노브가 돌아간 GPT-2"입니다. DeepSeek-V3는 여섯 개의 노브 모두에 네 개가 더 추가된 GPT-2입니다. Llama 3 설정을 읽는 것은 DeepSeek 설정을 읽기 위한 워밍업이지만, 깊은 구조(어텐션 블록의 형태, 라우팅 로직, 학습 시점 목적)는 별도의 워크스루가 필요할 정도로 충분히 다릅니다.

이를 배우는 이점: DeepSeek-V3의 오픈-가중치 출시는 오픈 모델에서 "프런티어 성능"의 의미를 바꾸었습니다. 이 아키텍처는 많은 2026년 학습 실행이 복사하고 있는 청사진입니다. 이를 이해하는 것은 프런티어 LLM 학습이나 추론을 다루는 모든 역할의 기본 요건입니다.

## 개념

### 불변 코어, 다시

DeepSeek-V3는 여전히 자기회귀적입니다. 여전히 디코더 블록을 쌓습니다. 각 블록은 여전히 어텐션 + MLP + 두 개의 RMSNorm을 가집니다. MLP에서 여전히 SwiGLU를 사용합니다. 여전히 RoPE를 사용합니다. Pre-norm. Weight-tied 임베딩. 모든 Llama 또는 Mistral과 동일한 기준선입니다.

### 차이점: GQA 대신 MLA

10단계 14과에서 GQA가 Q 헤드 그룹 전체에서 K와 V를 공유하여 KV 캐시를 줄이는 것을 알고 있습니다. Multi-Head Latent Attention (MLA)은 더 나아갑니다: K와 V는 공유된 저랭크 잠재 표현(`kv_lora_rank`)으로 압축된 후, 즉석에서 헤드별로 역압축됩니다. KV 캐시는 잠재 변수만 저장합니다 — 층당 토큰당 일반적으로 512개의 float이며, 8 x 128 = 1024개의 float가 아닙니다.

128k 컨텍스트에서 MLA(층당 토큰당 하나의 공유 잠재 `c^{KV}`; K와 V는 모두 이 잠재에서 up-projection을 통해 파생되며, 이는 후속 행렬곱에 흡수될 수 있음)를 가진 DeepSeek-V3:

```
kv_cache = num_layers * kv_lora_rank * max_seq_len * bytes_per_element
         = 61 * 512 * 131072 * 2
         = 7.6 GB
```

가상의 GQA 기준선(Llama 3 70B 형태, 8 KV 헤드, 헤드 차원 128)이 부담할 비용:

```
kv_cache = 2 * 61 * 8 * 128 * 131072 * 2
         = 30.5 GB
```

MLA는 128k 컨텍스트에서 Llama-3-70B-스타일 GQA 캐시보다 4배 더 작습니다.

트레이드오프: MLA는 어텐션 연산당(헤드당) 역압축 단계를 추가합니다. 추가 연산은 절약된 대역폭에 비해 작습니다. 긴 컨텍스트 추론에서 순이익입니다.

### 라우팅: 보조-손실-없는 부하 균형

MoE 라우터는 각 토큰을 처리할 상위 k개 전문가를 결정합니다. 순진한 라우터는 작업을 소수 전문가에 집중시켜 다른 전문가를 유휴 상태로 둡니다. 표준 해결책: 부하 불균형을 패널티로 주는 보조 손실 항목을 추가합니다. 이는 작동하지만 주 작업 성능을 약간 저하시킵니다.

DeepSeek-V3는 보조-손실-없는 방식을 도입합니다. 전문가별 편향 항목이 라우터 로짓에 추가되며, 간단한 규칙으로 학습 중에 조정됩니다: 전문가 `e`에 과부하가 걸리면 `bias_e`를 감소시키고, 부하가 적으면 증가시킵니다. 추가 손실 항목이 없습니다. 학습이 깨끗하게 유지됩니다. 전문가 부하가 균형을 유지합니다.

주 손실에 미치는 영향: 측정 가능한 수준 없음. MoE 아키텍처에 미치는 영향: 더 깔끔하고, 조정할 보조-손실 하이퍼파라미터가 없음.

### MTP: 더 조밀한 학습 + 무료 초안

10단계 18과에서 DeepSeek-V3가 두 위치 앞의 토큰을 예측하는 D=1 MTP 모듈을 추가한다는 것을 알고 있습니다. 추론 시 학습된 모듈은 80% 이상의 수락률을 가진 추측적 디코딩 초안으로 재사용됩니다. 학습 시 각 은닉 상태는 D+1 = 2개의 목표로 지도되어 더 조밀한 신호를 제공합니다.

파라미터: 671B 주 모델 위에 14B. 오버헤드: 2.1%.

### 학습: DualPipe

10단계 19과에서 DualPipe가 순전파 및 역전파 청크를 노드 간 all-to-all 통신과 중첩시키는 양방향 파이프라인임을 알고 있습니다. DeepSeek-V3의 2,048-H800 규모에서 1F1B가 파이프라인 버블로 잃었을 약 245k GPU-시간을 회수합니다.

### 설정, 필드별

다음은 DeepSeek-V3 설정(단순화됨):

```
hidden_size: 7168
intermediate_size: 18432   (밀집 MLP 은닉 크기, 처음 몇 층에서 사용)
moe_intermediate_size: 2048 (전문가 MLP 은닉 크기)
num_hidden_layers: 61
first_k_dense_layers: 3    (처음 3개 층은 밀집 MLP 사용)
num_attention_heads: 128
num_key_value_heads: 128   (형식적으로 MLA 아래에서 num_heads와 같지만,
                            실제 압축은 kv_lora_rank에 있음)
kv_lora_rank: 512          (MLA 잠재 차원)
num_experts: 256            (블록당 MoE 전문가 수)
num_experts_per_tok: 8      (top-8 라우팅)
shared_experts: 1           (블록당 항상 켜져 있는 공유 전문가)
max_position_embeddings: 163840
rope_theta: 10000.0
vocab_size: 129280
mtp_module: 1               (깊이 1에 1개의 MTP 모듈)
```

분석:

- `hidden_size=7168`: 임베딩 차원.
- `num_hidden_layers=61`: 총 블록 깊이.
- `first_k_dense_layers=3`: 처음 3개 블록은 크기 18432의 밀집 MLP 사용. 나머지 58개는 MoE 사용.
- `num_attention_heads=128`: 128개 질의 헤드.
- `kv_lora_rank=512`: K와 V가 이 잠재 차원으로 압축되고 헤드별로 역압축됨.
- `num_experts=256, num_experts_per_tok=8`: 각 MoE 블록은 256개 전문가, top-8 라우팅.
- `shared_experts=1`: 256개 라우팅 전문가 외에, 1개의 항상 켜진 전문가가 모든 토큰에 기여. 모든 토큰이 신뢰할 수 있는 것을 얻도록 보장하는 "밀집 바닥"으로 생각하십시오.
- `moe_intermediate_size=2048`: 각 전문가의 MLP 은닉 크기. 256개가 있으므로 밀집 MLP보다 작습니다.

### 파라미터 계산

전체 계산은 `code/main.py`에 있습니다. 주요 내용:

- 임베딩: `vocab * hidden = 129280 * 7168 = ~0.93B`.
- 처음 3개 밀집 블록: MLA를 사용한 어텐션(블록당 ~144M) + 밀집 MLP(블록당 ~260M) + 정규화. 총 약 1.2B.
- 58개 MoE 블록: MLA를 사용한 어텐션(~144M) + 256개 전문가 각각(각 30M) + 1개 공유 전문가(30M) + 정규화. 모든 전문가 포함 블록당 총 ~7.95B. 58개 MoE 블록에 대해 461B 총.
- MTP 모듈: 14B.

총계: 핵심 아키텍처 ~476B + 14B MTP + 명확히 발표된 671B 숫자는 추가 구조적 파라미터(편향 텐서, 전문가 특화 구성 요소, 공유 전문가 스케일링 등)를 포함합니다. 계산기에서 재현하는 숫자는 발표된 것의 3-5% 이내입니다 — 차이는 DeepSeek 보고서의 섹션 2 부록에 문서화된 세분화된 계산에서 비롯됩니다.

순전파당 활성 파라미터:

- 어텐션: 층당 144M * 61 = 8.8B (모든 층 실행).
- MLP 활성: 처음 3개 층 밀집(3 * 260M = 780M), 58개 MoE 층 각각 8개 라우팅 + 1개 공유 + 라우팅 오버헤드로 활성. 층당 활성 MLP: ~260M. 총: 3 * 260M + 58 * 260M = ~15.9B.
- 임베딩 + 정규화: 1.2B.
- 총 활성: 핵심 약 26B + 14B MTP (학습되었지만 추론에서 항상 실행되지는 않음) ≈ 37B.

### 671B / 37B 비율

18배 희소성 비율(활성 파라미터가 전체의 5.5%). DeepSeek-V3는 오픈 가중치를 출시한 가장 희소한 프런티어 MoE 모델입니다. Mixtral 8x7B는 비율 13/47(28%)로 훨씬 더 조밀합니다. Llama 4 Maverick은 비율 17B/400B(4.25%)로 비슷합니다. DeepSeek의 선택: 프런티어 규모에서 더 많은 전문가와 더 낮은 활성화 비율이 활성-FLOP당 더 나은 품질을 생성합니다.

### DeepSeek-V3의 위치

| 모델 | 총계 | 활성 | 비율 | 어텐션 | 새로운 아이디어 |
|-------|------|-------|-------|-----------|-------------|
| Llama 3 70B | 70B | 70B | 100% | GQA 64/8 | — |
| Llama 4 Maverick | 400B | 17B | 4.25% | GQA | — |
| Mixtral 8x22B | 141B | 39B | 27% | GQA | — |
| DeepSeek V3 | 671B | 37B | 5.5% | MLA 512 | MLA + MTP + aux-free + DualPipe |
| Qwen 2.5 72B | 72B | 72B | 100% | GQA 64/8 | YaRN 확장 |

### 후속: R1, V4

DeepSeek-R1 (2025)은 V3 백본에서 추론-학습 실행입니다. R1은 동일한 아키텍처를 사용합니다. 변경된 것은 사후-학습 레시피(검증 가능한 작업에 대한 대규모 RL)이며, 사전학습 아키텍처가 아닙니다.

DeepSeek-V4 (출시된다면)는 MLA + MoE + MTP를 유지하고 DSA(DeepSeek Sparse Attention)를 추가할 것으로 예상됩니다 — 10단계 17과의 NSA 후속입니다. 계보는 안정적입니다: 아키텍처 수준의 혁신이 축적되고, 각 버전이 추가 노브를 돌립니다.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|-----------|
| MLA | "Multi-Head Latent Attention" | K와 V를 공유된 저랭크 잠재(kv_lora_rank, 일반적으로 512)로 압축하고 즉석에서 헤드별로 역압축; KV 캐시는 잠재만 저장 |
| kv_lora_rank | "MLA 압축 차원" | K와 V를 위한 공유 잠재의 크기; DeepSeek-V3는 512 사용 |
| first k dense layers | "초기 층은 밀집 유지" | MoE 모델의 처음 몇 층은 MoE 라우터를 건너뛰고 안정성을 위해 밀집 MLP 실행 |
| num_experts_per_tok | "Top-k 라우팅" | 토큰당 실행되는 라우팅 전문가 수; DeepSeek-V3는 8 사용 |
| Shared experts | "항상 켜진 전문가" | 라우팅과 관계없이 모든 토큰을 처리하는 전문가; DeepSeek-V3는 1 사용 |
| 보조-손실-없는 라우팅 | "편향 조정 부하 균형" | 손실 항목을 추가하지 않고 전문가 부하를 균형 있게 유지하도록 학습 중에 조정되는 전문가별 편향 항목 |
| MTP 모듈 | "추가 예측 헤드" | h^(1)과 E(t+1)에서 t+2를 예측하는 트랜스포머 블록; 더 조밀한 학습, 무료 추측적 디코딩 초안 |
| DualPipe | "양방향 파이프라인" | 순전파/역전파 연산을 노드 간 all-to-all과 중첩시키는 학습 스케줄 |
| 활성 파라미터 비율 | "희소성" | active_params / total_params; DeepSeek-V3는 5.5% 달성 |
| FP8 학습 | "8비트 학습" | FP8에서의 학습 저장 및 많은 연산; 작은 품질 비용으로 BF16 대비 메모리 절반 |
