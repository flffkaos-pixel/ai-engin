# Jamba — 하이브리드 SSM-트랜스포머

> 상태 공간 모델(SSM)과 트랜스포머는 서로 다른 것을 원합니다. 트랜스포머는 이차 비용의 어텐션을 통해 품질을 얻습니다. SSM은 순환을 통해 선형 시간 추론과 일정 메모리를 얻지만 품질에서 뒤집니다. AI21의 Jamba (2024년 3월)와 Jamba 1.5 (2024년 8월)는 이들을 동일한 모델에 넣었습니다: Mamba 7개 층마다 1개의 트랜스포머 층, 다른 모든 블록에 MoE, 단일 80GB GPU에 맞는 256k 컨텍스트 윈도우. Mamba-3 (ICLR 2026)는 복소수 값 상태 공간과 MIMO 투영으로 SSM 측을 강화합니다. 이 과는 두 아키텍처를 종단간 읽고, 순수-SSM과 순수-트랜스포머 긴 컨텍스트 시도가 실패했을 때 하이브리드 레시피가 왜 3년의 스케일링을 견뎌냈는지 설명합니다.

**유형:** 학습
**언어:** Python (stdlib, 층-혼합 계산기)
**사전 필요과목:** 10단계 14과 (오픈 모델 아키텍처), 10단계 17과 (네이티브 희소 어텐션)
**시간:** ~60분

## 학습 목표

- Jamba 블록의 세 가지 프리미티브(트랜스포머 층, Mamba 층, MoE)와 1:7:짝수 인터리빙 레시피를 설명할 수 있다
- SSM의 순환이 높은 수준에서 어떻게 생겼는지와 왜 일정-메모리 추론을 가능하게 하는지 설명할 수 있다
- Jamba 모델의 256k 컨텍스트에서 KV 캐시 풋프린트를 계산하고 순수-트랜스포머 모델이 필요로 하는 것과 비교할 수 있다
- 세 가지 Mamba-3 혁신(지수-사다리꼴 이산화, 복소수 값 상태 업데이트, MIMO)과 각각이 목표로 하는 문제를 명명할 수 있다

## 문제

어텐션은 시퀀스 길이에 대해 이차입니다. 상태 공간 모델은 선형입니다. 그 차이는 누적됩니다: 256k 토큰에서 트랜스포머 어텐션 맵은 헤드당 65B 항목입니다; SSM의 순환 상태는 시퀀스 길이와 관계없이 고정 크기입니다.

순수-SSM 모델(Mamba, Mamba-2)은 작은 규모에서 트랜스포머 퍼플렉서티와 일치하지만 상태 추적 작업에서 뒤지고 일부 맥락 내 검색 범주에서 실패합니다. 직관: SSM은 히스토리를 고정 상태로 압축하며, 히스토리가 길면 정보가 누출됩니다. 어텐션은 모든 것을 정확히 기억하지만 이차 비용을 지불합니다.

명백한 해결책: 둘 다 사용하십시오. 정확한 회상이 필요한 곳에 트랜스포머 층을 배치하고, 다른 곳에는 SSM 층을 사용하십시오. 비율을 조정하십시오. Jamba는 이 하이브리드 레시피를 대규모로 출시한 첫 번째 프로덕션-급 모델입니다(52B 총, 12B 활성, 256k 컨텍스트, 단일 80GB GPU). Jamba 1.5는 패밀리를 398B 총 / 94B 활성으로 확장합니다. Mamba-3 (ICLR 2026)는 하이브리드가 재구축될 수 있는 현재 최고의 순수-SSM 기준선입니다.

이 과는 세 논문을 모두 읽고 "올바른 비율 선택"을 위한 정신 모델을 생성합니다.

## 개념

### SSM을 한 페이지로

상태 공간 모델은 시퀀스 `x_1, ..., x_N`을 고정 크기 상태 `h`를 통해 처리합니다:

```
h_t = A h_{t-1} + B x_t
y_t = C h_t
```

각 단계에서 상태는 선형 동역학 `A`를 통해 진화하고, 입력 `B x_t`를 받으며, 출력 `C h_t`를 방출합니다. `A, B, C`는 학습될 수 있습니다. 중요한 속성: `y_t`를 계산하는 데는 `h_{t-1}`과 `x_t`만 필요하며, 이전의 어떤 `x`도 필요하지 않습니다. 메모리는 일정합니다. 추론은 토큰당 O(1)입니다.

모델링 품질을 위한 비결은 `A`의 구조입니다. S4 (Gu 2021)는 학습 중에 긴 컨볼루션으로 효율적으로 평가될 수 있는 고도로 구조화된 행렬을 사용했습니다. Mamba (Gu, Dao 2023)는 고정된 `A, B, C`를 데이터-의존적인 것으로 대체했습니다("선택적" 부분). Mamba-2 (2024)는 구조를 더욱 단순화했습니다. Mamba-3 (2026)는 특정 위치에 복잡성을 다시 추가합니다.

핵심 속성: 디코더 LLM의 경우 SSM 층은 어텐션 층의 드롭인 대체품이며, 증가하는 KV 캐시 대신 고정 크기의 층별 상태를 가집니다.

### Jamba 블록

Jamba 블록은 두 숫자에 따라 층을 인터리브합니다:

- `l`: 어텐션-대-Mamba 비율. Jamba는 `l = 8`을 사용하며, 이는 Mamba 7개 층마다 1개의 트랜스포머 층을 의미합니다(7 Mamba + 1 Attention = 그룹당 8개 층).
- `e`: MoE 빈도. Jamba는 `e = 2`를 사용하며, 이는 다른 모든 층이 MoE를 적용함을 의미합니다.

블록 내 층 시퀀스:

```
M  M  M  M  M  M  M  A    (7 Mamba + 1 Attention)
|  M  |  M  |  M  |  M    (|는 MoE가 적용된 위치)
```

각 Jamba 블록은 8개 층입니다. 4개 블록 깊이(총 32개 층)에서 28개의 Mamba와 4개의 Attention 층을 얻습니다. 이 중 16개가 MoE를 사용합니다.

### 왜 1:7 비율인가

AI21은 절제 연구를 실행했습니다: 어텐션-대-Mamba의 어떤 비율이 파라미터당 최상의 퍼플렉서티와 긴 컨텍스트 평가에서의 맥락 내 회상을 제공하는가?

- 너무 많은 어텐션 (1:1): 품질은 올라가지만 메모리와 속도가 저하됩니다.
- 너무 적은 어텐션 (1:15): 메모리는 좋지만 맥락 내 검색이 실패합니다.
- 최적점: 1:7 또는 1:8.

직관: 트랜스포머 층은 정확한 회상과 상태 추적을 처리합니다. Mamba 층은 저렴한 대량 처리를 처리합니다.

### 위치 인코딩

Mamba 층은 자체적으로 위치-인식입니다(순환을 통해). 원래 Mamba 기반 하이브리드의 어텐션 층은 RoPE를 사용하지 않았습니다 — SSM 층이 위치 정보를 제공했습니다. Jamba 1.5는 더 긴 컨텍스트 일반화를 위해 어텐션 층에 RoPE를 추가하는데, 이는 경험적 긴 컨텍스트 평가에 기반한 사후 개선입니다.

### 메모리 예산

Jamba-1 형태(32개 층: 28 Mamba + 4 Attention, hidden 4096, 32개 어텐션 헤드)의 경우:

- KV 캐시(어텐션 층만): `2 * 4 * 32 * 128 * 256k * 2 = 8.4 GB` (256k BF16에서). 4개의 어텐션 층만 기여합니다.
- SSM 상태: `28 * hidden * state_size` (토큰 프리픽스당), 하지만 이는 층당 고정 크기이며 시퀀스 길이에 따라 증가하지 않습니다. 일반적인 Mamba 상태는 피처당 16, hidden 4096: `28 * 4096 * 16 * 2 = 3.7 MB` 총.

동일한 은닉, 32개 헤드의 전체 MHA를 가진 32개 층의 순수 트랜스포머와 비교: `2 * 32 * 32 * 128 * 256k * 2 = 128 GB` (256k BF16에서). KV 캐시에서 8배 감소. 대부분의 2024년 모델이 사용하는 GQA(8) 기준선(`2 * 32 * 8 * 128 * 256k * 2 = 32 GB`)에 대해서도 Jamba의 1:7 하이브리드는 16 GB에서 여전히 2배 더 작습니다.

이것이 AI21이 "단일 80GB GPU에서 256k 컨텍스트"라고 말할 때 의미하는 바입니다. 전체-MHA 순수 트랜스포머의 KV 캐시는 맞지 않을 것입니다; GQA 기준선조차 가중치와 활성화를 위한 공간을 남기지 않습니다; Jamba는 가능합니다.

### Mamba-3: 2026년 순수-SSM 기준선

Mamba-3 (ICLR 2026, arXiv:2603.15569)는 순수-SSM 측에서 세 가지 혁신을 도입합니다:

1. **지수-사다리꼴 이산화.** Mamba-2의 오일러 방법 이산화를 더 표현력 있는 순환으로 대체합니다. 핵심 순환 내에서 상태-입력에 컨볼루션-유사 연산을 적용하며, `x_t`에 대한 외부 컨볼루션이 아닙니다.

2. **복소수 값 상태 업데이트.** 이전 Mamba는 상태 행렬을 복소수(S4)에서 실수 대각(Mamba)으로, 스케일링된 항등(Mamba-2)으로 축소했습니다. Mamba-3는 복소수 값을 다시 추가합니다 — 이는 상태에 대한 데이터-의존적 회전 임베딩과 동등합니다. 이전 실수 값 단순화가 비용으로 했던 상태 추적 능력을 복원합니다.

3. **다중 입력 다중 출력 (MIMO) 투영.** 피처별 스칼라 투영 대신 행렬 값 투영을 사용합니다. 모델링 능력과 추론 시 하드웨어 활용도를 디코드 지연 시간 증가 없이 개선합니다.

1.5B 파라미터에서 Mamba-3는 평균 하류 정확도를 Gated DeltaNet보다 0.6 포인트 개선합니다; MIMO 변형은 1.2를 더 추가하여 총 1.8 포인트 향상됩니다. 동일한 상태 크기에서 Mamba-3는 절반의 상태로 Mamba-2와 일치합니다.

Mamba-3는 아직 대규모 프로덕션 하이브리드로 출시되지 않았지만 — 차세대 Jamba-급 모델의 SSM 측에 대한 명백한 후보입니다.

### 하이브리드를 사용해야 할 때

하이브리드가 이기는 경우:

- 순수 트랜스포머 KV 캐시가 고통스러울 정도로 긴 컨텍스트(64k+).
- 작업이 단거리 구조(SSM에 좋음)와 장거리 회상(트랜스포머 필요)을 혼합하는 경우.
- 트랜스포머 KV 캐시만으로도 맞지 않는 단일-GPU 메모리 예산에 배포하려는 경우.

하이브리드가 지는 경우:

- 컨텍스트가 짧은 경우(16k 미만). SSM 오버헤드가 낭비됨; 순수 트랜스포머로 충분.
- 작업이 모든-곳에서-모든-곳으로의 어텐션이 필요한 경우(깊은 추론, 다중 문서 교차 참조). 하이브리드의 어텐션 층 희소성이 해를 끼침.
- 조 단위 파라미터 프런티어 모델로 스케일링하는 경우. 순수-트랜스포머 + MLA + MoE (DeepSeek-V3 스타일)가 현재 성능 경쟁에서 이기고 있음.

### 경쟁 구도

| 모델 | 패밀리 | 규모 | 고유 주장 |
|-------|--------|------|-------------|
| Mamba-2 | 순수 SSM | 3B | 선형 시간, 일정 메모리 |
| Jamba | 하이브리드 | 52B/12B | 80GB에서 256k |
| Jamba 1.5 Large | 하이브리드 | 398B/94B | 엔터프라이즈-급 긴 컨텍스트 |
| Mamba-3 | 순수 SSM | 1.5B (논문) | 상태 추적 복원 |
| DeepSeek-V3 | 순수 트랜스포머 + MoE | 671B/37B | 프런티어 성능 |

2026년 구도: 순수-트랜스포머 MoE가 프런티어를 지배하지만, 하이브리드는 256k-플러스 컨텍스트 틈새를 소유합니다. Mamba-3의 상태 추적 개선은 차세대에서 하이브리드 비율을 더 낮출 수 있습니다(더 많은 SSM, 더 적은 어텐션).

## 활용하기

`code/main.py`는 하이브리드 아키텍처를 위한 메모리 계산기입니다. SSM-트랜스포머 비율과 은닉-크기/층-수 설정이 주어지면 다음을 계산합니다:

- 목표 컨텍스트에서의 KV 캐시.
- SSM 상태 메모리.
- 다양한 모델 형태에 대한 컨텍스트 N에서의 총 메모리.

계산기는 다음을 지원합니다:

- 순수-트랜스포머 기준선 (KV 캐시가 N에 따라 증가).
- Jamba-스타일 1:7 하이브리드.
- 순수-SSM (KV 캐시 전혀 없음).

숫자는 발표된 형태에 대해 Jamba-1 및 Jamba-1.5 논문에서 직접 가져오고 가상 변형에 대해 외삽됩니다.

실제 배포를 위한 통합 고려사항:

- 대부분의 프로덕션 추론 서버(vLLM, SGLang)는 Jamba와 Mamba를 지원합니다. 특정 버전을 확인하십시오.
- 256k 컨텍스트에서 Jamba의 메모리 이점은 동시 요청 처리량에서 나타납니다. 동일한 VRAM에서 트랜스포머 시퀀스보다 더 많은 Jamba 시퀀스를 맞출 수 있습니다.
- Mamba-3는 독립형 모델로 아직 프로덕션에 출시되지 않음 — 1.5B에서 연구 미리보기.

## 연습 문제

1. `code/main.py`를 실행하여 32개 층 순수 트랜스포머(hidden 4096, 32 헤드)와 동일한 형태의 Jamba-1 하이브리드에 대한 256k 컨텍스트에서의 KV 캐시를 계산하십시오. AI21 논문이 주장하는 약 8배 메모리 감소를 확인하십시오.

2. 계산기를 1:3 하이브리드(4 Mamba : 1 Attention)와 1:15 하이브리드(14 Mamba : 1 Attention)로 모델링하도록 수정하십시오. KV 캐시 대 비율을 플로팅하십시오. KV 캐시가 SSM 상태 메모리와 같아지는 비율은 무엇인가?

3. Jamba 논문(arXiv:2403.19887)의 섹션 3을 읽으십시오. Mamba-2가 더 빠름에도 AI21이 Mamba-2 대신 Mamba-1을 사용하는 이유를 설명하십시오. 힌트: 하이브리드 절제 섹션이 이를 문서화합니다.

4. Jamba 1.5 Large(398B 총, 94B 활성)에서 모든-다른-층 MoE의 파라미터 오버헤드를 계산하십시오. 활성 비율을 DeepSeek-V3(37B/671B)와 비교하고 Jamba의 아키텍처가 활성 비율을 더 높게 만드는 이유를 설명하십시오.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|-----------|
| 상태 공간 모델 (SSM) | "고정 상태를 가진 순환" | 학습된 순환 `h_t = A h_{t-1} + B x_t`를 가진 층; 토큰당 일정 메모리 |
| 선택적 SSM | "Mamba의 비결" | 데이터-의존적 A, B, C 파라미터로 선형 시간에 게이트-유사 선택성을 제공 |
| 어텐션-대-Mamba 비율 | "어텐션 층 수" | Jamba에서 `l = 8`은 Mamba 7개 층당 1개의 어텐션 층을 의미 |
| Jamba 블록 | "8-층 그룹" | 하나의 어텐션 + 일곱 Mamba + 교차 위치의 MoE |
| SSM 상태 | "은닉 버퍼" | Mamba 층의 KV 캐시를 대체하는 층당 고정 크기 상태 |
| 256k 컨텍스트 | "Jamba의 주요 숫자" | Jamba-1이 단일 80GB GPU에 맞는 시퀀스 길이; 순수 트랜스포머는 그 크기에서 불가능 |
| Mamba-3 | "2026 순수 SSM" | 복소수 상태 + MIMO를 가진 현재 최고의 순수-SSM 아키텍처; 하이브리드가 재구축하는 기준선 |
| MIMO | "다중 입력 다중 출력" | 피처별 스칼라 대신 행렬 값 투영을 사용하는 Mamba-3 혁신 |
| 지수-사다리꼴 이산화 | "Mamba-3의 순환" | Mamba-2의 오일러 방법 이산화를 포괄하는 더 표현력 있는 순환 |
| 하이브리드 아키텍처 | "어텐션과 SSM 혼합" | 트랜스포머와 SSM 층을 인터리브하는 모든 모델; Jamba가 프로덕션 원형 |
