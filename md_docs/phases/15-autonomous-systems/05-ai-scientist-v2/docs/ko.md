# AI Scientist v2 — 워크숍 수준의 자율 연구

> Sakana의 AI Scientist v2(Yamada et al., arXiv:2504.08066)는 전체 연구 루프를 실행한다: 가설, 코드, 실험, 그림, 논문 작성, 제출. 생성된 논문이 ICLR 2025 워크숍에서 동료 검토를 통과한 최초의 시스템이다. 독립 평가(Beel et al.)는 실험의 42%가 코딩 오류로 실패했고, 문헌 검토가 확립된 개념을 새로운 것으로 잘못 레이블링하는 경우가 빈번했다고 밝혔다. Sakana의 자체 문서는 코드베이스가 LLM 작성 코드를 실행한다고 경고하고 Docker 격리를 권장한다. 그 그림의 양면이 요점이다.

**Type:** 학습
**Languages:** Python (stdlib, research-loop state-machine toy)
**Prerequisites:** Phase 15 · 03 (AlphaEvolve), Phase 15 · 04 (DGM)
**Time:** ~60분

## 문제

연구는 개방형 작업이다. AlphaEvolve의 알고리즘 탐색이나 DGM의 벤치마크 경계 자기 수정과 달리, 연구 결과에는 기계 검증 가능한 정확성 기준이 없다. 논문은 단위 테스트가 아닌 검토자에 의해 판단된다. 이는 루프를 닫기 더 어렵게 만든다 — 그리고 닫혀 있다면 더 가치있게 만든다, 연구가 복합적 진전이 있는 곳이기 때문이다.

AI Scientist v1(Sakana, 2024)은 인간이 작성한 템플릿에서 시작하여 루프를 닫았다. LLM은 고정된 스캐폴딩 내에서 실험을 채웠다. AI Scientist v2(Yamada et al., 2025)는 에이전틱 트리 탐색과 비전-언어 모델 평가 루프를 사용하여 템플릿 요구 사항을 제거한다. 시스템은 아이디어를 생성하고, 실험을 구현하며, 그림을 생성하고, 논문을 작성하며, 검토자 피드백에 대해 반복한다.

동료 검토 결과: v2에서 생성된 논문 하나가 ICLR 2025 워크숍에서 수락되었다(공개 포함). 독립 평가 결과: 시스템은 신뢰성과 거리가 멀다. 둘 다 사실이다.

## 개념

### 아키텍처

1. **아이디어 생성.** LLM이 주제와 사전 문헌에 조건화된 연구 아이디어를 제안한다. v1은 템플릿을 사용했다; v2는 가설 공간에 대한 에이전틱 탐색을 사용한다.
2. **참신성 확인.** 문헌 검색 단계에서 아이디어가 발표되었는지 확인한다. Beel et al.의 평가가 잘못된 레이블링을 발견한 단계다 — 확립된 방법이 자주 새로운 것으로 분류되었다.
3. **실험 계획.** 에이전트가 실험 프로토콜을 작성하고 코드를 작성한다.
4. **실행.** 코드가 샌드박스에서 실행된다. 실패는 재시도 루프로 피드백된다. Beel et al.의 측정에서, 실험의 42%가 이 단계에서 코딩 오류로 실패했다.
5. **그림 생성.** 비전-언어 모델이 생성된 그림을 읽고 명확성을 위해 다시 작성한다. 이것이 v2의 주요 기술적 추가 사항이었다.
6. **논문 작성.** LLM이 논문을 작성하고 내부 검토자와 반복한다.
7. **선택 사항: 제출.** 논문이 학술 행사에 제출된다.

### 워크숍 수락 결과의 의미

하나의 v2 생성 논문이 ICLR 2025 워크숍에서 동료 검토를 통과했다. 저자는 논문의 기원을 프로그램 위원회에 공개했다. 수락은 하나의 데이터 포인트다; 시스템이 "연구를 한다"고 주장할 수 있는 허가는 아니다.

중요한 맥락: 워크숍 논문은 본 학회 논문보다 기준이 낮다. 동료 검토는 노이즈가 많다; 소수의 제출만이 특정 날짜에 수락된다. 하나의 성공은 개념 증명이지 신뢰성 주장이 아니다. Nature 2026 논문은 종단간 루프를 문서화했고 자체적으로 인간 연구자들이 공동 저술했다; "시스템이 Nature 논문을 썼다"는 말은 아니다.

### 독립 평가가 발견한 것

Beel et al. (arXiv:2502.14297)은 외부 평가를 실행했다. 주요 발견:

- **실험 실패.** 실험의 42%가 코딩 오류(잘못된 임포트, 형태 불일치, 정의되지 않은 변수)로 실패했다. 재시도 루프가 일부를 잡았지만 전부는 아니다.
- **참신성 오레이블링.** 문헌 검색 단계가 확립된 개념을 자주 새로운 것으로 플래그했다. 이는 연구 버전의 환각이다.
- **발표 품질 격차.** 비전-언어 그림 평가가 출판 등급의 시각 자료를 생성하여 근본적인 실험적 약점을 가렸다.

마지막 발견이 이 단계에서 중요하다. 설득력 있는 연구 없이 설득력 있는 출력을 생성하는 시스템은 명백히 실패하는 시스템보다 더 위험하고, 더 안전하지 않다. 평가는 그림에서 멈추지 않고 근본적인 주장에 도달해야 한다.

### 샌드박스 탈출 우려

Sakana의 자체 저장소 README는 다음과 같이 경고한다:

> 이 소프트웨어의 특성상(LLM 생성 코드를 실행함) 안전을 보장할 수 없습니다. 위험한 패키지, 제어되지 않은 웹 접근, 의도하지 않은 프로세스 생성의 위험이 있습니다. 자신의 책임하에 사용하고 Docker 격리를 고려하십시오.

이는 검증되지 않은 도메인에서 자율성의 운영적 형태다. LLM이 코드를 작성하고, 코드가 실행되며, 코드는 프로세스가 허용된 모든 것을 할 수 있다. 파일시스템, 네트워크 및 프로세스 동작을 하드 제한하는 샌드박스 없이, 자기 주도 연구 에이전트는 데이터를 유출하고, 컴퓨팅을 소진하거나, 스스로를 다시 작성할 수 있다.

AlphaEvolve의 샌드박스 이야기는 평가기가 엄격하기 때문에 더 쉽다. AI Scientist v2의 루프는 개방형 목표로 개방형 코드를 실행한다. 이것이 더 강력한 격리(최소 Docker, 선호되는 seccomp/gVisor)와 시스템을 떠나기 전에 모든 제출물에 대한 수동 검토가 필요한 이유다.

### 프론티어 스택에서 v2의 위치

| 시스템 | 대상 | 출력 종류 | 평가기 | 알려진 실패 |
|---|---|---|---|---|
| AlphaEvolve | 알고리즘 | 코드 | 단위 + 벤치마크 | 평가기 엄격함에 제한됨 |
| DGM | 에이전트 스캐폴딩 | 코드 | SWE-bench | 보상 해킹 |
| AI Scientist v2 | 연구 논문 | 텍스트 + 코드 + 그림 | 동료 검토 (약함) | 실험 실패, 오레이블링, 다듬기가 약점을 가림 |

v2는 세 가지 중 가장 약한 자동 평가기, 가장 넓은 출력 표면, 그리고 공개 아티팩트로 가는 가장 짧은 경로를 가지고 있다. 운영적 통제(샌드박스, 검토, 공개)가 안전 작업의 대부분을 수행하고 있다.

## 사용하기

`code/main.py`는 v2 루프를 상태 머신으로 시뮬레이션한다: 아이디어 → 참신성 확인 → 실험 → 그림 → 논문 작성 → 검토 → 수락 또는 반복. 각 상태는 Beel et al.의 발견에서 가져온 구성 가능한 실패 확률을 가지고 있다. N 루프에 대해 시뮬레이터를 실행하고 다음을 계산하라:

- 얼마나 많은 아이디어가 제출에 도달하는지.
- 얼마나 많은 제출이 다듬어진 논문이 숨기는 중요한 실험적 결함을 가지고 있는지.
- 재시도 예산이 품질과 수율을 어떻게 절충하는지.

## 연습문제

1. `code/main.py`를 기본 매개변수로 실행하라. 루프 실행의 몇 퍼센트가 "깨끗한" 논문을 생산하는가? 몇 퍼센트가 그림 평가가 다듬은 실험 실패 결함이 있는 논문을 생산하는가?

2. 기본값은 이미 Beel et al.의 42% / 25%를 사용한다. `--experiment-failure 0.20 --novelty-mislabel 0.10`으로 다시 실행한 다음 `--experiment-failure 0.60 --novelty-mislabel 0.40`으로 실행하라. 다듬어졌지만 결함이 있는 비율이 두 실행 사이에 어떻게 변화하는가?

3. Sakana의 AI Scientist v2 저장소 README에서 샌드박스 요구 사항을 읽어라. 다일 자율 실행을 위해 Docker 외에 적용할 두 가지 추가 제한 사항을 말하라.

4. Beel et al. 섹션 4(발표 품질 격차)를 읽어라. 다듬어졌지만 실험적으로 결함이 있는 논문을 잡아낼 하나의 추가 평가기를 설계하라.

5. "PhD가 모든 논문을 읽는 것"보다 더 잘 확장되는 연구 에이전트 출력에 대한 인간 검토 프로토콜을 제안하라. 병목을 식별하고 그 주변을 설계하라.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| AI Scientist v1 | "Sakana의 템플릿 기반 연구 에이전트" | 고정된 스캐폴드에 실험 채움 |
| AI Scientist v2 | "템플릿 없는 연구 에이전트" | VLM 그림 평가가 있는 에이전틱 트리 탐색 |
| 에이전틱 트리 탐색 (Agentic tree search) | "분기 연구 에이전트" | 여러 실험 계획을 병렬로 확장; 내부 비평가로 가지치기 |
| 비전-언어 평가 (Vision-language critique) | "그림에 대한 VLM 다듬기" | 다중 모드 모델이 그림을 읽고 명확성을 위해 다시 작성 |
| 문헌 검색 (Literature retrieval) | "참신성 확인" | 아이디어 참신성을 확인하기 위해 선행 연구 검색 — 오레이블링이 문서화됨 |
| 다듬기 마스킹 (Polish masking) | "예쁜 논문, 깨진 연구" | 발표 품질이 실험적 품질을 초과; 약점 숨김 |
| 샌드박스 탈출 (Sandbox escape) | "LLM 코드가 벗어남" | 에이전트가 실행한 코드가 루프 설계자가 의도하지 않은 일을 함 |
