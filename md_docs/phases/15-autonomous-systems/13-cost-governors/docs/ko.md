# 작업 예산, 반복 상한 및 비용 거버너

> 중간 규모 전자상거래 에이전트의 월간 LLM 비용이 팀이 "주문 추적" 스킬을 활성화한 후 $1,200에서 $4,800로 급등했다. 이는 가격 버그가 아니다. 새로운 루프를 찾고 그 안에서 계속 지출하는 에이전트다. Microsoft의 Agent Governance Toolkit(2026년 4월 2일)은 이 클래스에 대한 방어를 체계화한다: 요청당 `max_tokens`, 작업당 토큰 및 달러 예산, 일/월 상한, 반복 상한, 계층형 모델 라우팅, 프롬프트 캐싱, 컨텍스트 윈도잉, 비싼 작업에 대한 HITL 체크포인트, 예산 위반 시 킬 스위치. 재정적 속도 제한(예: 10분 내 $50 초과 시 접근 차단)은 월별 상한보다 빠르게 루프를 잡는다.

**Type:** 학습
**Languages:** Python (stdlib, layered cost-governor simulator)
**Prerequisites:** Phase 15 · 10 (권한 모드), Phase 15 · 12 (지속적 실행)
**Time:** ~60분

## 문제

자율 에이전트는 모든 턴에서 실제 돈을 쓴다. 챗봇의 나쁜 출력은 나쁜 응답이다; 에이전트의 나쁜 루프는 청구서다. 이 실패 모드에 대한 업계 문서화된 용어는 "Denial of Wallet"이다 — 에이전트가 계속 추론하고, 계속 도구를 호출하며, 계속 청구하고, 아무것도 막지 못한다. 왜냐하면 아무것도 설계되지 않았기 때문이다.

수정은 하나의 숫자가 아니다. 다른 시간 규모와 세분성에서의 한계 스택이다: 요청당, 작업당, 시간당, 일당, 월당. 잘 설계된 스택은 폭주 루프를 몇 분 내에, 느린 누출을 몇 시간 내에, 나쁜 릴리스를 하루 내에 잡는다. 동일한 스택이 에이전트가 장기 실행이고 자율적일 때 모든 예산을 유지한다.

이는 엔지니어링 레슨이다: 수학은 간단하고, 규율이 팀이 실패하는 곳이다. 아래의 한계 목록은 모두 Microsoft Agent Governance Toolkit 또는 Anthropic Claude Code Agent SDK 문서에 명명되어 있다.

## 개념

### 비용 거버너 스택

1. **요청당 `max_tokens`.** 간단하다. 단일 호출이 무제한 완료를 출력하는 것을 방지한다.
2. **작업당 토큰 예산.** 전체 실행에서 N 토큰을 초과하지 않는다. 상한에서 하드 스톱.
3. **작업당 달러 예산.** 토큰과 같지만 통화 단위. Claude Code의 `max_budget_usd`.
4. **도구 호출당 상한.** N번 이상의 `WebFetch` 호출, N번 이상의 `shell_exec` 호출 등 없음.
5. **반복 상한 (`max_turns`).** 총 에이전트 루프 반복; 무한 추론 루프 방지.
6. **분/시간/일/월 상한.** 롤링 윈도우. 다른 시간 규모에서 누출을 잡는다.
7. **재정적 속도 제한.** 예: "10분 내 지출이 $50 초과 시 접근 차단." 월별 상한보다 먼저 루프 기반 소진을 잡는다.
8. **계층형 모델 라우팅.** 기본적으로 더 작은 모델 사용; 분류기가 작업이 정당하다고 판단할 때만 더 큰 모델로 상향.
9. **프롬프트 캐싱.** 시스템 프롬프트와 안정적인 컨텍스트가 제공자 캐시에 저장; 재전송의 토큰 비용이 거의 0.
10. **컨텍스트 윈도잉.** 압축/요약으로 활성 컨텍스트를 임계값 아래로 유지; 직접적인 토큰 비용 감소.
11. **비싼 작업에 대한 HITL 체크포인트.** 비싼 것으로 알려진 작업(긴 도구 호출, 큰 다운로드, 비싼 모델 업그레이드) 전에 인간 탭 필요.
12. **예산 위반 시 킬 스위치.** 상한이 발사되면 세션 중단. 상한이 기록됨; 별도의 재활성화 경로 필요.

### 하나의 상한이 아닌 스택인 이유

단일 월별 상한은 지갑이 사라진 후에야 폭주 에이전트를 잡는다. 단일 요청당 상한은 세션 수준에서 아무것도 잡지 못한다. 다른 실패 모드는 다른 시간 규모가 필요하다:

- **폭주 루프**(5초 재시도에 갇힌 에이전트): 속도 제한이 잡음.
- **느린 누출**(작업당 예상 작업량의 ~2배를 하는 에이전트): 일일 상한이 잡음.
- **나쁜 릴리스**(새 버전이 5배 토큰 사용): 주간/월간 상한이 잡음.
- **합법적 급증**(버그가 아닌 실제 수요): 명확한 로그가 있는 시간/일 상한이 잡음.

### Claude Code의 예산 표면

Claude Code Agent SDK는(공개 문서):

- `max_turns` — 반복 상한.
- `max_budget_usd` — 달러 상한; 위반 시 세션 중단.
- `allowed_tools` / `disallowed_tools` — 도구 허용 목록 및 거부 목록.
- 사용자 정의 비용 회계를 위한 도구 사용 전 후크 포인트.

권한 모드 사다리(레슨 10)와 결합하라. `max_budget_usd` 없는 `autoMode` 세션은 통제되지 않은 자율성이다. Anthropic은 Auto Mode에 예산 제어가 필요하다고 명시적으로 프레이밍한다; 분류기는 비용과 직교한다.

### EU AI Act, OWASP Agentic Top 10

Microsoft의 Agent Governance Toolkit은 OWASP Agentic Top 10 및 EU AI Act 제14조(인간 감독) 요구 사항을 다룬다. EU에서 프로덕션의 경우 로깅 및 상한 집행은 선택 사항이 아니다.

### 관찰된 $1,200 → $4,800 사례

Microsoft 문서의 실제 사례: 새 도구가 추가된 후 월간 비용이 3배가 된 전자상거래 에이전트. 도구는 에이전트가 모든 세션 동안 주문 상태를 폴링할 수 있게 했다. 루프 탐지 없음. 도구당 상한 없음. 주간 성장에 대한 경고 없음. 수정은 도구당 상한과 일일 성장 경고였다. 이는 템플릿이다: 모든 새로운 도구 표면은 새로운 잠재적 루프다; 모든 새로운 도구에는 자체 상한과 자체 경고가 필요하다.

## 사용하기

`code/main.py`는 계층형 비용 거버너 스택이 있거나 없는 에이전트 실행을 시뮬레이션한다. 시뮬레이션된 에이전트는 몇 턴 후에 폴링 루프로 표류한다; 계층형 스택은 단일 월별 상한이 며칠 후까지 발사되지 않을 동안 속도 윈도우 내에서 잡는다.

## 출시하기

`outputs/skill-agent-budget-audit.md`는 제안된 에이전트 배포의 비용 거버너 스택을 감사하고 누락된 계층을 플래그한다.

## 연습문제

1. `code/main.py`를 실행하라. 폴링 루프 궤적에서 속도 제한이 반복 상한보다 먼저 발사되는지 확인하라. 이제 속도 제한을 비활성화하고 반복 상한이 잡기 전에 에이전트가 얼마나 "지출"하는지 측정하라.

2. 브라우저 에이전트(레슨 11)를 위한 도구당 상한 세트를 설계하라. 어떤 도구가 가장 엄격한 상한이 필요한가? 어떤 도구가 위험 없이 무제한으로 실행될 수 있는가?

3. Microsoft Agent Governance Toolkit 문서를 읽어라. 도구가 명명하는 모든 상한 유형을 나열하라. 각각을 실패 모드(폭주 루프, 느린 누출, 나쁜 릴리스, 급증) 중 하나에 매핑하라.

4. 현실적인 작업(예: "저장소에서 50개 이슈 분류")에 대한 야간 무인 실행 가격을 책정하라. `max_budget_usd`를 포인트 추정치의 2배로 설정하라. 2배를 정당화하라.

5. Claude Code의 `max_budget_usd`는 세션 집계 비용에서 발사된다. 외부에서 적용할 보완적 속도 제한을 설계하라. 차단을 트리거하는 것은 무엇이며, 재활성화는 어떻게 보이는가?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| Denial of Wallet | "폭주 청구서" | 에이전트 루프가 멈출 상한 없이 지출 생성 |
| max_tokens | "요청당 상한" | 단일 완료 크기의 상한 |
| max_turns | "반복 상한" | 세션에서 에이전트 루프 반복의 상한 |
| max_budget_usd | "달러 킬 스위치" | 세션 비용 상한; 위반 시 중단 |
| 속도 제한 (Velocity limit) | "비율 상한" | 짧은 윈도우당 지출 제한 (예: $50 / 10분) |
| 계층형 라우팅 (Tiered routing) | "작은 모델 우선" | 저렴한 모델 기본; 분류기가 정당할 때만 상향 |
| 프롬프트 캐싱 (Prompt caching) | "캐시된 시스템 프롬프트" | 제공자 측 캐시가 재전송 토큰 비용을 거의 0으로 감소 |
| HITL 체크포인트 (HITL checkpoint) | "인간 승인 게이트" | 비싼 작업 전에 인간 탭 필요 |
