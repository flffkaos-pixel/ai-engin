# 킬 스위치, 회로 차단기 및 카나리 토큰

> 킬 스위치는 에이전트의 편집 표면 외부에 유지되는 부울(Redis 키, 기능 플래그, 서명된 설정)로, 에이전트를 완전히 비활성화한다. 회로 차단기는 더 세분화되어 있다: 특정 패턴(연속 다섯 번의 동일한 도구 호출)에서 트립되고, 문제가 있는 경로를 일시 중지하며, 인간에게 상향한다. 카나리 토큰은 고전적 속임수에서 유래한다: 에이전트가 닿을 정당한 이유가 없는 가짜 자격 증명 또는 허니팟 레코드로, 접근이 경보를 트리거한다. eBPF 기반 데이터패스(예: Cilium)는 격리된 파드의 이그레스를 커널 계층에서 포렌식 허니팟으로 다시 쓸 수 있다; 발표된 Cilium 벤치마크는 부하 하에서 서브 밀리초 P99 데이터패스 지연 시간을 보고한다(전파 예산은 정책 업데이트가 노드에 도달하는 방식에 따라 달라지며, 데이터패스 자체가 아니다). 이동 기준선에 적응하는 통계적 탐지기(EWMA, CUSUM)는 조용히 표류를 수용할 것이다 — 구부러지지 않는 하드 헌법적 한계와 계층화하라.

**Type:** 학습
**Languages:** Python (stdlib, three-detector simulator: kill switch, circuit breaker, canary)
**Prerequisites:** Phase 15 · 13 (비용 거버너), Phase 15 · 10 (권한 모드)
**Time:** ~60분

## 문제

비용 거버너(레슨 13)는 에이전트가 지출할 수 있는 것을 제한한다. 예산 내에서 에이전트가 할 수 있는 것을 제한하지는 않는다. $50 속도 제한이 있는 에이전트도 비밀을 유출하거나, 잘못된 게시물을 올리거나, 리소스를 삭제할 수 있다 — 비싼 작업은 종종 토큰에서 저렴하다.

이 레슨은 비용 계층 옆에 위치한 세 가지 탐지기를 다룬다:

1. **킬 스위치**: 에이전트의 접근 밖에 유지되는 부울 오프 버튼.
2. **회로 차단기**: 특정 경로를 일시 중지하는 작업 패턴 탐지기.
3. **카나리 토큰**: 닿을 정당한 이유가 없는 에이전트가 닿음으로써 자신을 드러내는 미끼.

세 가지 모두 LLM 이전의 엔지니어링이다. 고전적 속임수, 비율 제한 차단기 및 기능 플래그 킬은 자율 에이전트보다 먼저 존재했다. 새로운 점은 공격 표면이다: 에이전트는 신뢰할 수 없는 콘텐츠를 읽고(레슨 11), 자신의 메모리를 편집하며, 많은 안전해 보이는 작업을 안전하지 않은 것으로 구성할 수 있다. 여기에 명명된 탐지기는 에이전트의 자체 보고를 신뢰하지 않기 때문에 작동한다.

## 개념

### 킬 스위치

킬 스위치는 에이전트가 읽지만 쓸 수 없는 부울이다. 구현 선택:

- **관리형 서비스의 기능 플래그.** LaunchDarkly, Statsig, Unleash. 업데이트가 몇 초 내에 전파된다.
- **에이전트가 폴링하는 Redis 키.** 간단함; 에이전트 프로세스가 모든 턴에서 확인해야 함.
- **객체 저장소의 서명된 설정.** 에이전트가 부팅 시 서명을 확인; 서명되지 않은 상태 거부.
- **OS 수준 신호 또는 컨테이너 수명 주기 킬.** Docker `kill`, Kubernetes `kubectl delete pod`, systemd stop.

올바른 킬 스위치의 속성:

- 에이전트가 이를 `off`로 설정할 수 없다. (에이전트의 자격 증명이 쓰지 않는 시스템에 있음.)
- 시작 시뿐만 아니라 모든 결과적 작업에서 확인된다.
- 꺼져 있을 때, 에이전트는 에이전트가 닿을 수 있는 시스템에 로깅하는 것을 포함하여 외부에서 관찰 가능한 일을 전혀 하지 않는다.
- 재활성화는 자동 시간 초과가 아닌 명시적인 인간 행동이다.

### 회로 차단기

회로 차단기는 전체 에이전트가 아닌 특정 패턴을 일시 중지한다. 고전적 형태(2007년 Nygard 책에서, 여전히 현재):

- **닫힘**: 작업이 허용됨.
- **열림**: 작업이 차단됨.
- **반열림**: 쿨다운 후 1-3회 프로브 시도 허용(기본값 1); 성공 시 차단기 닫힘, 남은 실패 시 다시 열림.

에이전트 관련 트리거:

- 연속 다섯 번의 동일한 도구 호출(반복 루프).
- 다른 입력으로 동일한 도구에서 연속 다섯 번 실패(시스템적 실패).
- 임계값 이상의 도구 호출 비율(레슨 13 속도).
- 신뢰 외부 콘텐츠 읽기 후 특정 도구 호출(예: `file.delete`)(레슨 11).

### 카나리 토큰

카나리 토큰(허니토큰이라고도 함)은 에이전트가 절대 닿지 말아야 할 입력이다. 접근이 경보다.

에이전트용 예시:

- 실제 권한이 없는 환경의 가짜 `AWS_SECRET_ACCESS_KEY`. 유출 시도가 즉시 귀속 가능.
- 알려진 센티넬 값으로 플래그된 가짜 데이터베이스 레코드. 이 레코드의 읽기 또는 업데이트가 경보를 발사.
- 워크스페이스의 가짜 파일. 이 파일의 읽기 또는 편집이 의심스러움.
- 세션 시작 시 주입된 가짜 메모리 항목. 이후 출력에 나타나면 메모리가 유출된 것.

카나리 설계는 워크플로우에 특화된다. 에이전트가 닿을 정당한 이유가 있는 카나리는 노이즈다.

### 통계적 한계와 하드 한계를 계층화하는 이유

통계적 탐지기(EWMA, CUSUM, 도구 호출 비율의 z-점수)는 이동 기준선에 적응한다. 이는 합법적 표류에는 기능이고, 적대적 표류에는 버그다. 인내심 있는 공격자는 어떤 경보도 발사되지 않을 만큼 충분히 느리게 기준선을 이동시킬 수 있다.

하드 헌법적 한계(레슨 17)는 구부러지지 않는다. "절대 `secrets@`에 이메일 보내지 않음"을 헌법 규칙으로 하는 것은 더 간단하고, 감사 가능하며, 느린 표류로 게임할 수 없다. 계층화 패턴: 통계적 탐지기가 대부분의 노이즈를 잡고, 하드 한계가 탐지기를 지나친 공격을 잡는다.

### eBPF 데이터패스 리디렉트를 통한 격리

Cilium의 eBPF 기반 네트워크 정책은 격리된 파드의 이그레스를 커널 계층에서 포렌식 허니팟으로 다시 쓸 수 있다. Cilium의 공개 벤치마크는 TCP_RR에서 서브 밀리초 P99 데이터패스 지연 시간을 보고한다; 클러스터에서 격리를 *트리거*하는 벽시계 예산은 제어 평면에서 노드로 정책 업데이트가 전파되는 방식에 의해 지배된다(운영자가 사전 로드된 Kubernetes에서 수백 밀리초가 현실적; 꼬리 지연 시간은 클러스터 크기와 조정 주기에 따라 다름). 이는 두 가지를 제공한다: 에이전트는 실제로 아무것도 유출하지 않으며, 허니팟 내부의 에이전트 행동이 완전히 관찰된다. 카나리 토큰과 동일한 패턴, 다른 계층: 에이전트는 포함된 동안 시도하는 것으로 의도를 드러낸다.

### 어떤 탐지기도 잡지 못하는 것

- **허용된 기본 요소로 구성된 의미적 공격.** 모든 개별 작업이 모든 탐지기를 통과; 구성이 문제다. 이는 레슨 10의 Auto Mode 복합 실패다.
- **페이로드의 일부로 탐지기를 포함하는 공격.** 에이전트가 "행동하기 전에 카나리를 비활성화하라"고 말하는 페이지를 읽고 에이전트가 그 능력을 가지고 있다면, 탐지기는 손상된다. 카나리 토큰은 에이전트가 수정할 수 없는 시스템에 있어야 한다.

## 사용하기

`code/main.py`는 세 가지 탐지기를 통한 짧은 에이전트 궤적을 시뮬레이션한다. 외부 딕트에 유지된 킬 스위치; 다섯 번의 동일한 도구 호출에서 트립되는 회로 차단기; 읽기가 경보를 트리거하는 카나리 파일. 합성 궤적(합법적 작업, 반복 루프, 카나리 프로브, 에이전트의 행동이 중단되는 킬 스위치 트리거 시나리오)을 공급한다.

## 출시하기

`outputs/skill-tripwire-design.md`는 에이전트 배포를 위한 제안된 탐지기 스택을 검토하고 격차(누락된 킬 스위치, 누락된 카나리, 너무 느슨한 회로 차단기 임계값)를 플래그한다.

## 연습문제

1. `code/main.py`를 실행하라. 회로 차단기가 5턴(다섯 번째 동일 호출)에서 발사되고 카나리가 9턴(가짜 키 읽기)에서 발사되는지 확인하라.

2. 통계적 탐지기를 추가하라: 도구 호출 비율에 대한 EWMA z-점수. 천천히 표류하는 궤적을 공급하고 탐지기가 절대 발사되지 않음을 보여라. 이제 하드 한계(10분 내 50회 이상 도구 호출 없음)를 추가하고 동일한 궤적에서 하드 한계가 발사되는 것을 보여라.

3. 브라우저 에이전트(레슨 11)를 위한 카나리 토큰 세트를 설계하라. 적어도 세 가지 카나리와 각각이 탐지할 것을 나열하라.

4. Cilium 네트워크 정책 문서를 읽어라. 이그레스-리디렉트 격리 흐름을 구체적으로 설명하라: 어떤 정책 선택기, 어떤 파드, 어떤 이그레스 재작성, 어떤 경보. "격리 결정"에서 "첫 번째 리디렉트된 패킷"까지의 벽시계 지연 시간을 결정하는 것은 무엇인가?

5. 킬 스위치된 에이전트를 위한 재활성화 절차를 정의하라. 누가 재활성화할 수 있는가? 무엇이 문서화되어야 하는가? 재활성화 전에 에이전트에 대해 무엇이 바뀌어야 하는가?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| 킬 스위치 (Kill switch) | "오프 버튼" | 에이전트의 편집 표면 외부 부울; 모든 결과적 작업에서 확인 |
| 회로 차단기 (Circuit breaker) | "패턴 일시 중지" | 반복, 실패율 또는 비율 제한에 대한 작업별 트립 |
| 카나리 토큰 (Canary token) | "허니토큰" | 에이전트가 닿을 정당한 이유가 없는 미끼; 접근이 경보 발사 |
| 허니팟 (Honeypot) | "포렌식 샌드박스" | 격리된 에이전트가 관찰되는 리디렉트된 트래픽/워크스페이스 |
| EWMA | "이동 평균" | 지수 가중치; 표류에 적응 (기능 + 버그) |
| CUSUM | "누적 합" | 기준선에서 지속적 변화 탐지 |
| 하드 한계 (Hard limit) | "헌법적 규칙" | 적응하지 않음; 이력과 관계없이 일정 |
| 헌법적 한계 (Constitutional limit) | "항상 참인 규칙" | 레슨 17의 헌법에 연결; 에이전트가 편집할 수 없음 |
