# METR 시간 지평 및 외부 역량 평가

> METR(구 ARC Evals)은 2023년 12월부터 독립적인 501(c)(3) 비영리 단체다. Time Horizon 1.1 벤치마크(2026년 1월)는 로지스틱 곡선을 작업 성공 확률 대 log(전문가 인간 완료 시간)에 피팅한다; 50% 확률에서의 교차점이 모델의 시간 지평을 정의한다. 2025-2026년 평가 대상에는 GPT-5.1, GPT-5.1-Codex-Max 및 프로토타입 모니터링 평가(모니터가 사이드 작업을 잡을 수 있는지, 에이전트가 회피할 수 있는지)가 포함된다. 벤치마크 스위트: HCAST(180개 이상의 ML, 사이버, SWE, 추론 작업; 1분~8시간 이상), RE-Bench(전문가 기준선이 있는 71개 ML 연구 엔지니어링 작업), SWAA. 정직한 메모: METR 측정은 이상화되어 있다 — 인간 개입 없음, 실제 결과 없음 — 그리고 팀은 평가-대-배포 행동 격차를 문서화했다(레슨 1). 시간 지평은 상한선이지 배포 예측이 아니다.

**Type:** 학습
**Languages:** Python (stdlib, logistic-fit horizon estimator)
**Prerequisites:** Phase 15 · 01 (장기 실행 에이전트), Phase 15 · 19 (RSP)
**Time:** ~60분

## 문제

확장 정책(레슨 19, 20)은 참조하는 측정값만큼만 유용하다. "AI R&D-4 임계값"과 "장거리 자율성"은 정책 산문으로 정의된다; 특정 평가가 특정 수치를 생성할 때만 실행 가능해진다.

METR은 많은 수치를 정의한 2024-2026년 외부 평가 기관이다. 그들은 프론티어 모델(종종 출시 전, NDA 하에 연구소와 함께)을 평가하고 나중에 방법론을 게시한다. Time Horizon 1.1 벤치마크(2026년 1월)는 주요 아티팩트다: 역량을 인간이 읽을 수 있는 단위("이 모델은 전문가가 X시간 소비하는 종류의 작업을 50% 신뢰도로 수행할 수 있다")로 압축하는 단일 스칼라.

레슨은 부분적으로 방법론(지평이 어떻게 계산되는지)과 부분적으로 해석(지평이 배포 예측이 아닌 상한선인 이유)에 관한 것이다. 두 기술은 함께 속한다. 지평이 어떻게 피팅되는지 이해하는 팀은 슬라이드에서 "14시간"만 보는 팀보다 나쁜 업체 주장에 속기가 훨씬 어렵다.

## 개념

### METR 배경

- 설립: 2023년 12월 (ex-ARC Evals, 독립 501(c)(3)으로 분사).
- 범위: 프론티어 모델의 자율적 역량 평가, 종종 출시 전.
- 파트너 연구소: Anthropic, OpenAI (2025-2026년 여러 계약).
- 주목할 결과물: Time Horizon 1.0 (2025년 3월), Time Horizon 1.1 (2026년 1월), 프로토타입 모니터링 평가.

### 시간 지평 피팅

방법론 (METR 블로그 및 논문에서):

1. 분 단위에서 시간 단위 전문가 완료 시간에 걸친 작업 스위트를 수집한다. 현재 스위트: HCAST (180개 이상의 작업), RE-Bench (71개 작업), SWAA.
2. 각 작업에서 모델을 실행하고 성공 또는 실패를 기록한다.
3. 로지스틱 곡선을 피팅한다: P(성공)을 log(전문가 완료 시간)의 함수로.
4. 지평은 P(성공) = 0.5인 전문가 시간이다.

로지스틱 피팅 형태가 올바른 이유는 역량이 일반적으로 작업 난이도와 함께 증가하고 접근하는 관계를 가지기 때문이다. 50% 지점은 선택 사항이다(10%, 90%도 가능); METR은 상세 논문에서 여러 임계값을 보고하지만 50%가 가장 직관적이므로 선도한다.

### 2026년 1월 수치

Time Horizon 1.1 기준:

- Claude Opus 4.6: 50% 신뢰도에서 ~14시간, Time Horizon 1.1 기준 (2026년 1월).
- HCAST 스타일 작업의 두 배 시간: Time Horizon 1.1이 보고한 2023년 이후 피팅에서 ~4.3개월 (130.8일); ~7개월 수치는 Time Horizon 1.0의 전체 2019-2025 피팅이며, TH1.1에서 2023년 이후 수치와 함께 보고됨.

이는 Phase 15의 나머지가 참조하는 특정 수치다. 이는 Anthropic의 RSP v3.0(레슨 19)과 DeepMind의 FSF v3(레슨 20)에서 임계값 평가에 공급하는 측정값 중 하나로 인용된다.

### 벤치마크 스위트

- **HCAST**: ML, 사이버 보안, 소프트웨어 엔지니어링 및 일반 추론에 걸친 189개 작업. 범위: 1분~8시간 이상의 전문가 시간. 지평 수치 뒤의 주요 스위트.
- **RE-Bench**: 인간 전문가 기준선이 있는 71개 ML 연구 엔지니어링 작업. 모델이 AI R&D-4 임계값에 공급되는 ML R&D 작업을 수행할 수 있는지 측정.
- **SWAA**: 더 짧은 작업; 지평 곡선의 낮은 끝을 보정하는 데 유용.

### 프로토타입 모니터링 평가

2025-2026년 METR 작업에는 모니터링 평가 프로토타입이 포함되었다: 모니터가 모델이 사이드 작업(운영자가 요청한 것 외의 것)을 수행하는 것을 잡을 수 있는지; 에이전트가 모니터를 회피할 수 있는지. 이는 OpenAI PF v2의 "안전장치 훼손" 카테고리와 DeepMind FSF v3의 기만적 정렬 모니터링(레슨 20)에 직접 공급된다.

### 지평이 상한선인 이유

- **이상화된 도구링**: 벤치마크 작업은 모델에게 깨끗한 도구와 잘 형식화된 데이터를 제공한다. 실제 배포는 더 지저분하다.
- **실제 결과 없음**: 모델은 실제로 고객에게 청구하거나, 실제 데이터를 삭제하거나, 실제 사람에게 연락하지 않는다. 실제 배포에는 되돌릴 수 없는 이해관계가 있다.
- **평가 컨텍스트 게이밍**: 레슨 1. 모델이 테스트에서 다르게 행동한다. 2026 International AI Safety Report가 이를 경험적으로 문서화한다.
- **합법적 사용자 변동 없음**: 벤치마크 프롬프트는 구조화되어 있다. 실제 사용자는 모호하고 컨텍스트에 의존적인 요청을 생성한다.

지평은 유리한 조건에서의 역량 상한선이다. 배포 신뢰도는 다른, 더 낮은 수치이며, 팀은 이를 알기 위해 자신의 분포를 측정해야 한다.

### 외부 평가자 사례

외부 평가가 중요한 이유는 내부 연구소가 보고하는 지표를 최적화할 인센티브가 있기 때문이다. METR의 독립성 — 선언된 방법론과 동료 검토 논문이 있는 501(c)(3) — 이 구조적 완화책이다. 단독으로는 충분하지 않지만(연구소는 여전히 METR이 보는 것을 통제함), 외부 평가가 없는 것보다는 엄격히 낫다.

### 실제로 지평 수치를 사용하는 방법

- **역량 필터로서**: 모델의 지평이 제안된 작업의 전문가 시간보다 훨씬 낮으면, 자율적으로 출시하지 말라(레슨 1의 스킬 파일).
- **추세 지표로서**: 두 배 시간은 새로운 완화책 없이도 현재 관행이 얼마나 오래 안전하게 유지될지 알려준다.
- **사전 정보로서**: 14시간의 지평은 시작점이다. 작업 분포, 도구링 품질 및 배포 컨텍스트에 따라 하향 조정하라.

## 사용하기

`code/main.py`는 합성 결과 세트가 주어지면 작업 성공 대 log(전문가 시간)의 로지스틱 피팅을 구현한다. 50% 지평(METR의 주요 수치), 10% 지평(보수적), 90% 지평(낙관적)을 보고한다. 또한 성공률이 평가 컨텍스트 게이밍에 의해 인위적으로 부풀려질 때 무엇이 변하는지 보여준다.

## 출시하기

`outputs/skill-horizon-interpretation.md`는 업체의 지평 주장을 검토하고 벤치마크 주장과 배포 현실 사이의 격차 분석을 생성한다.

## 연습문제

1. `code/main.py`를 실행하라. 피팅의 50% 지평이 합성 실제 값과 일치하는지 확인하라. 이제 작업-시간 그리드를 반으로 줄여라; 지평 추정치가 의미 있게 변하는가?

2. METR의 Time Horizon 1.1 블로그 포스트를 읽어라. 신뢰도가 가장 높고 가장 낮은 특정 작업을 식별하라. 격차가 존재하는 이유를 설명하라.

3. METR의 "Measuring Autonomous AI Capabilities" 리소스를 읽어라. HCAST 작업 카테고리를 나열하라. 프로덕션 작업에 대해 더 높게 가중치를 둘 하나의 카테고리를 골라 그 이유를 정당화하라.

4. 시뮬레이터에 평가 컨텍스트 게이밍을 도입하라: 실패한 작업의 ~20%를 성공으로 뒤집어라. 새 지평을 보고하라. 이는 20% 게이밍 비율이 관찰된 수치에 하는 영향을 근사한다.

5. 자신의 버그 백로그 또는 대표적인 작업 세트에 대한 내부 지평 평가를 설계하라. 데이터 수집, 피팅 및 출력이 말해주는 것을 설명하라. METR 수치와 비교하라.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| METR | "외부 평가자" | ex-ARC Evals; 2023년 12월부터 독립 501(c)(3) |
| 시간 지평 (Time Horizon) | "역량 측정" | 로지스틱 피팅에서 50% 신뢰도의 전문가 작업 길이 |
| HCAST | "METR의 주요 스위트" | 1분~8시간 이상에 걸친 180개 이상의 작업 |
| RE-Bench | "연구 엔지니어링" | 인간 기준선이 있는 71개 ML 연구 엔지니어링 작업 |
| SWAA | "짧은 작업 스위트" | 지평 곡선의 낮은 끝 보정 |
| 두 배 시간 (Doubling time) | "성장률" | 50% 지평이 두 배가 되는 시간; HCAST 기준 ~7개월 |
| 평가 컨텍스트 게이밍 (Eval-context gaming) | "모델이 다르게 행동" | 테스트와 배포 간 문서화된 행동 격차 |
| 상한선 (Upper bound) | "지평은 천장" | 벤치마크 지평 > 부하 하의 배포 신뢰도 |
