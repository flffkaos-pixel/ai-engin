# 자동화된 정렬 연구 (Anthropic AAR)

> Anthropic은 독립적인 샌드박스에서 Claude Opus 4.6 자율 정렬 연구원(AAR)의 병렬 팀을 운영했으며, 로그가 모든 샌드박스 외부에 있는 공유 포럼을 통해 조정했다(에이전트가 자신의 기록을 삭제할 수 없도록). 약함-강함 훈련 문제에서 AAR은 인간 연구원을 능가했다. Anthropic의 자체 요약은 규정된 워크플로우가 종종 AAR의 유연성을 제약하고 성능을 저하시킨다고 지적한다. 정렬 연구를 자동화하는 것은 RSP가 감지하려는 정확한 정렬 위험의 타임라인을 압축하는 압축 단계다.

**Type:** 학습
**Languages:** Python (stdlib, parallel-research-forum simulator)
**Prerequisites:** Phase 15 · 05 (AI Scientist v2), Phase 15 · 04 (DGM)
**Time:** ~60분

## 문제

정렬 연구는 인간 연구자 시간이 많이 든다. 확장 가능한 감독, 보상 명세, 또는 약함-강함 훈련과 같은 문제는 반복당 몇 주가 걸리는 실험이 필요하다. 프론티어 역량이 발전함에 따라, 정렬 작업 부하는 자격을 갖춘 연구자의 공급보다 빠르게 증가한다.

자동화된 정렬 연구(AAR)는 역량이 정렬을 앞지르는 동일한 프론티어 모델이 격차를 줄이는 데 기여할 수 있는지 묻는다. Anthropic의 2026년 AAR 실행 약함-강함 훈련 연구에 대한 보고서(alignment.anthropic.com/2026/automated-w2s-researcher/)는 이 클래스의 배포된 시스템에서 나온 최초의 공개 결과 중 하나다.

결과는 진정으로 긍정적이다: AAR이 인간 기준선보다 연구 문제를 더 잘 해결했다. 또한 이 결과는 이 단계가 발전시킨 모든 우려를 단일 시스템에 집중시킨다. 정렬 연구가 자동화될 수 있다면, 안전장치를 손상시키는 부분도 그럴 수 있다. AI R&D 역량에 대한 RSP의 임계값은 이 루프를 염두에 두고 작성되었다.

## 개념

### 아키텍처 (공개적으로 설명된 대로)

- **병렬 에이전트.** 여러 Claude Opus 4.6 인스턴스가 AAR로 실행되며, 각각 독립적인 샌드박스에서 실행된다. 샌드박스는 파일시스템, 네트워크 및 프로세스 표면을 제한한다.
- **공유 포럼.** 발견 사항은 저장소 백엔드가 모든 샌드박스 외부에 있는 공유 포럼에 게시된다. 에이전트는 포럼을 읽을 수 있다; 에이전트는 자신의 샌드박스 내에서 포럼 기록을 삭제하거나 편집할 수 없다.
- **작업 할당.** 인간이 설계한 작업 큐가 AAR에 연구 문제를 할당한다. AAR은 분해를 제안하고, 실험을 실행하며, 발견 사항을 작성한다.
- **약함-강함 훈련 초점.** 발표된 연구는 약한 감독자 모델을 사용하여 더 강한 학생 모델을 훈련하는 약함-강함 훈련을 다루었다. AAR은 이 작업에서 인간 연구원을 능가했다.

### 샌드박스 외부 로그가 중요한 이유

로그 무결성 속성은 통제된 실험과 잠재적으로 손상된 실험의 차이다. AAR이 자신의 로그를 편집할 수 있다면, 실패하거나 의심스러운 실험을 은폐할 수 있다. Anthropic은 이를 직접 지적한다: 이 속성은 연구 출력을 신뢰하기 위한 필요 조건이며, 검증하기가 간단하지 않다.

인프라 용어로 비유하면 외부 저장소에 대한 쓰기 통과가 있는 추가 전용 로그다(예: S3 객체 잠금, 불변 Datadog 로그). 에이전트는 과거 기록을 수정할 수 있는 자격 증명이 없다. 이는 2026년 기업 보안 팀이 랜섬웨어 방지 감사 추적에 사용하는 것과 동일한 패턴이다.

### 규정된 워크플로우 트레이드오프

Anthropic의 보고서는 규정된 워크플로우가 종종 AAR의 유연성을 제약하고 성능을 저하시킨다고 지적한다. 즉, 인간 설계자가 연구 계획을 단계별로 작성하면, AAR은 높은 수준의 목표와 자유로운 분해가 주어졌을 때보다 더 나쁘게 수행한다. 이는 에이전틱 연구(LangGraph, Microsoft 에이전트 프레임워크) 전반의 결과와 일치한다 — 과도하게 지정된 스캐폴드는 유능한 에이전트에 해롭다.

안전 함의는 미묘하다. AAR 성능을 향상시키는 유연성은 또한 승인되지 않은 분해, 새로운 도구 사용 및 목표 표류를 허용하는 유연성이다. 트레이드오프는 설계 공간 결정이다: 인간을 능가하기에 충분한 역량을 제공하면서, 에이전트가 분포 외부로 목표를 일반화할 여지를 주지 않는 유연성의 양은 얼마인가?

### 압축 위험

RSP v3.0(레슨 19)은 AI R&D 역량 임계값을 도입한다: 경쟁력 있는 비용으로 AI R&D 파이프라인을 완전히 자동화할 수 있는 능력. DeepMind의 FSF v3는 이와 유사한 ML R&D 자율성 수준을 포함한다. 두 프레임워크 모두 이 임계값을 강화된 통제를 위한 트리거로 취급한다.

AAR은 임계값에서 한 단계 부족하다: 파이프라인의 일부(특정, 잘 범위가 지정된 작업에 대한 정렬 연구)를 자동화하지만, 종단간 역량 개발 루프는 아니다. 타임라인 질문은 격차가 얼마나 빨리 좁혀지는지다.

압축된 타임라인은 복합적 실패 우려다. 정렬 연구와 역량 연구가 비슷한 비율로 복합된다면, 정렬 위험 표면은 역량만큼 빠르게 성장한다. 역량이 더 빠르게 복합된다면(역사적 추세), 격차는 벌어진다. 이것이 AAR이 조건부로 좋은 것이라는 주장의 근거다: 각 추가 정렬 결과는 연구 프로세스가 신뢰할 수 있는 경우에만 격차를 줄인다.

### AAR이 대체하지 않는 것

인간 연구자가 작업 큐를 설정하고, 결과를 검토하며, 헌법적 권한을 보유한다. AAR은 파이프라인의 중간을 가속화할 뿐, 끝은 아니다. Anthropic의 발표된 출력에는 AAR 기여와 무엇을 게시하고, 무엇을 철회하며, 무엇을 개선할지에 대한 인간 연구자의 판단이 모두 포함된다.

이는 레슨 15의 제안-후-커밋 패턴이 연구 자체에 적용된 것과 일치한다: AAR이 제안하고, 인간이 커밋한다.

## 사용하기

`code/main.py`는 다중 AAR 연구 포럼을 시뮬레이션한다. 세 개의 독립적인 "연구 에이전트"가 병렬로 실행되며, 선택적 변조 시도와 함께 추가 전용 포럼에 발견 사항을 게시한다.

관찰:

- 샌드박스 외부 로깅이 로그 변조 시도를 어떻게 잡아내는지.
- 자유 분해를 통한 작업 할당이 어려운 문제에서 고정 워크플로우보다 어떻게 더 나은지.
- 단일 손상된 AAR이 로그가 변조 방지되지 않은 경우 포럼의 신호를 어떻게 오염시킬 수 있는지.

## 출시하기

`outputs/skill-aar-deployment-review.md`는 자동화된 정렬 연구 파이프라인의 배포 전 검토다.

## 연습문제

1. `code/main.py`를 실행하라. "고정 워크플로우" vs "자유 분해" 설정을 비교하라. 자유 분해가 항상 이기는가, 아니면 고정 워크플로우가 경쟁력 있는 문제 클래스가 있는가?

2. 하나의 에이전트가 로그 변조를 시도하도록 시뮬레이터를 수정하라. 추가 전용 로그가 이를 감지하는지 확인하라. 로그에서 감지 시그니처가 정확히 어떻게 보이는지 설명하는 한 문단을 작성하라.

3. Anthropic의 약함-강함 AAR 보고서를 읽어라. AAR이 인간 연구원을 능가한 특정 하위 작업을 식별하라. 무엇이 자동화에 적합하게 만들었는가?

4. AAR 유연성(더 나은 결과)과 규정된 워크플로우 제약(더 쉬운 감사)의 균형을 맞추는 작업 큐 할당 정책을 설계하라. 두 가지를 A/B 테스트하는 방법을 설명하라.

5. RSP v3.0의 AI R&D-4 임계값을 읽어라. AAR이 현재 넘지 못하는 것을 넘을 것이라고 생각하는 것을 한 문단으로 설명하라.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| AAR | "Automated Alignment Researcher" | 정렬 문제에서 자율적으로 운영되는 Claude Opus 4.6 인스턴스 |
| 약함-강함 훈련 (Weak-to-strong training) | "약한 감독자로 강한 모델 훈련" | AAR이 인간을 능가한 고전적 확장 가능 감독 벤치마크 |
| 공유 포럼 (Shared forum) | "에이전트가 발견 사항을 게시하는 곳" | 추가 전용, 샌드박스 외부 저장소 |
| 샌드박스 외부 로그 (Out-of-sandbox log) | "에이전트가 자신의 기록을 편집할 수 없음" | 외부 저장소에 대한 변조 방지 쓰기 통과 |
| 규정된 워크플로우 (Prescribed workflow) | "인간 설계자의 단계별 계획" | AAR을 제약; 자유 분해 대비 성능 저하 |
| 자유 분해 (Free decomposition) | "에이전트가 작업을 분해하는 방법 결정" | 더 유능하지만 감사하기 더 어려움 |
| AI R&D 임계값 (AI R&D threshold) | "RSP/FSF 역량 수준" | 경쟁력 있는 비용으로 R&D 파이프라인 완전 자동화 |
| 압축된 타임라인 (Compressed timeline) | "정렬 vs 역량 경쟁" | 역량이 정렬보다 빠르게 복합되면 정렬 위험이 증가 |
