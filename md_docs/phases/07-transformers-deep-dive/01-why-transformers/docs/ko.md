# 왜 트랜스포머인가 — RNN의 문제점

> RNN은 토큰을 하나씩 처리한다. 트랜스포머는 모든 토큰을 한 번에 처리한다. 이 단일 아키텍처적 선택은 2017년 이후 딥러닝의 모든 스케일링 곡선을 바꿨다.

**Type:** 학습
**Languages:** Python
**Prerequisites:** Phase 3 (딥러닝 코어), Phase 5 · 09 (시퀀스-투-시퀀스), Phase 5 · 10 (어텐션 메커니즘)
**Time:** ~45분

## 문제

2017년 이전, 지구상의 모든 최첨단 시퀀스 모델 — 언어, 번역, 음성 — 은 순환 신경망이었다. LSTM과 GRU는 5년 동안 ImageNet에 상응하는 번역 벤치마크를 석권했다. 그것이 모두가 가진 유일한 도구였다.

그것들은 세 가지 치명적인 약점을 가졌다. 순차 계산은 시간 축을 따라 병렬화가 불가능했다: 토큰 `t+1`은 토큰 `t`의 은닉 상태가 필요하다. 1,024개 토큰 시퀀스는 사이클당 1,000,000번의 부동소수점 연산을 수행할 수 있는 GPU에서 1,024번의 직렬 단계를 의미했다. 훈련 벽시계 시간은 병렬 처리를 위해 설계된 하드웨어에서 시퀀스 길이에 따라 선형으로 증가했다.

기울기 소실은 50토큰 뒤의 정보가 이미 50번의 비선형성을 통과하며 압축되었음을 의미했다. 게이트 순환 유닛(LSTM, GRU)은 압축을 완화했지만 제거하지는 못했다. 장거리 의존성 — "지난여름 교토행 비행기에서 읽은 책은..." — 은 routinely 실패했다.

고정 너비 은닉 상태는 인코더가 디코더가 무언가를 보기 전에 전체 소스 시퀀스를 단일 벡터로 압축했음을 의미했다. 소스가 5토큰이든 500토큰이든 병목은 동일한 형태였다.

2017년 논문 "Attention Is All You Need"는 급진적인 것을 제안했다: 순환을 완전히 없애라. 모든 위치가 모든 다른 위치에 병렬로 주목하게 하라. 1,024개의 순차적 연산 대신 하나의 큰 행렬 곱셈으로 훈련하라.

그 결과는 2026년까지 모든 모달리티를 지배한다. 언어(GPT-5, Claude 4, Llama 4), 비전(ViT, DINOv2, SAM 3), 오디오(Whisper), 생물학(AlphaFold 3), 로보틱스(RT-2). 동일한 블록, 다른 입력.

## 개념

![RNN 순차 계산 vs 트랜스포머 병렬 어텐션](../assets/rnn-vs-transformer.svg)

**순환의 병목.** RNN은 `h_t = f(h_{t-1}, x_t)`를 계산한다. 각 단계는 이전 단계에 의존한다. `h_4` 이전에 `h_5`를 계산할 수 없다. 10,000개 이상의 병렬 코어를 가진 현대 GPU에서 이는 긴 시퀀스에서 실리콘의 99%를 낭비한다.

**어텐션을 통한 브로드캐스트.** 셀프-어텐션은 모든 쌍 `(i, j)`에 대해 동시에 `output_i = sum_j(a_ij * v_j)`를 계산한다. 전체 N×N 어텐션 행렬은 한 번의 배치된 matmul로 채워진다. 어떤 단계도 다른 단계에 의존하지 않는다. GPU가 좋아한다.

**속도 향상은 상수가 아니다.** 이는 `O(N)` 직렬 깊이와 `O(1)` 직렬 깊이의 차이이다. 실제로 트랜스포머는 N=512에서 일치하는 하드웨어에서 에폭당 5–10배 빠르게 훈련되며, 어텐션의 `O(N²)` 메모리 벽(이후 Flash Attention이 수정 — Lesson 12 참조)에 도달할 때까지 시퀀스 길이에 따라 격차가 벌어진다.

**트랜스포머의 비용.** 어텐션 메모리는 `O(N²)`으로 확장된다. 2K 컨텍스트에서는 괜찮다. 128K 컨텍스트에서는 슬라이딩 윈도우, RoPE 외삽, Flash Attention 타일링, 또는 선형 어텐션 변형이 필요하다. 순환은 시간과 메모리 모두에서 `O(N)`이었다; 트랜스포머는 시간을 메모리와 교환한 다음 병렬 처리를 통해 시간을 되찾는다.

**귀납적 편향의 전환.** RNN은 지역성(locality)과 최신성(recency)을 가정한다. 트랜스포머는 아무것도 가정하지 않는다 — 모든 쌍이 어텐션의 후보다. 이것이 트랜스포머가 잘 훈련되기 위해 더 많은 데이터가 필요하지만, 일단 데이터를 가지면 더 멀리 확장되는 이유이다. Chinchilla(2022)는 이를 공식화했다: 충분한 토큰이 주어지면 트랜스포머는 항상 동일한 파라미터 수의 RNN을 이긴다.

## 직접 구현하기

여기서는 신경망이 없다 — 노트북에서 격차를 느낄 수 있도록 핵심 병목을 수치적으로 시뮬레이션한다.

### 단계 1: 직렬 깊이 측정

`code/main.py` 참조. 두 개의 함수를 만든다. 하나는 덧셈의 체인으로 시퀀스를 인코딩한다(직렬, RNN처럼). 하나는 병렬 리덕션으로 인코딩한다(브로드캐스트, 어텐션처럼). 동일한 수학, 다른 의존성 그래프.

```python
def rnn_style(xs):
    h = 0.0
    for x in xs:
        h = 0.9 * h + x   # 병렬화 불가: h는 이전 h에 의존
    return h

def attention_style(xs):
    return sum(xs) / len(xs)  # 모든 x는 독립적
```

두 함수를 최대 100,000개 요소의 시퀀스에서 시간을 측정한다. RNN 버전은 O(N)이며 단일 CPU 파이프라인이다. 순수 Python에서도 attention-style 리덕션은 길이 ≥ 1,000에서 이를 이기는데, Python의 `sum()`이 C로 구현되어 단계당 인터프리터 오버헤드 없이 반복되기 때문이다.

### 단계 2: 이론적 연산 수 계산

두 알고리즘 모두 N개의 덧셈을 수행한다. 차이는 *의존성 깊이(dependency depth)*이다: 다음 연산이 시작되기 전에 얼마나 많은 연산이 순차적으로 발생해야 하는가. RNN 깊이 = N. 어텐션 깊이 = 트리 리덕션의 경우 log(N), 병렬 스캔의 경우 1. 연산 수가 아니라 깊이가 GPU 시간을 결정한다.

### 단계 3: 긴 시퀀스에서 경험적 스케일링

O(N) 격차를 시각적으로 보여주는 타이밍 테이블을 출력한다. 2026년 맥 노트북에서 1,000개 요소 미만의 시퀀스는 측정하기에 너무 빠르다. 100,000개 시퀀스는 깔끔한 선형 스캔을 보여준다. 이를 12-레이어 LSTM과 동등한 16,384-토큰 트랜스포머로 확장하면 2016년에 훈련 벽시계 시간이 왜 장애물이었는지 알 수 있다.

## 활용하기

2026년에 여전히 RNN을 선택해야 하는 경우:

| 상황 | 선택 |
|-----------|------|
| 스트리밍 추론, 한 번에 하나의 토큰, 상수 메모리 | RNN 또는 상태-공간 모델(Mamba, RWKV) |
| 어텐션 메모리가 폭발하는 매우 긴 시퀀스(>1M 토큰) | 선형 어텐션, Mamba 2, Hyena |
| matmul 가속기가 없는 엣지 디바이스 | Depthwise-separable RNN이 여전히 FLOPs/watt에서 승리 |
| 그 외 모든 것 (훈련, 배치 추론, 최대 128K 컨텍스트) | 트랜스포머 |

Mamba와 같은 상태-공간 모델(SSM)은 본질적으로 구조화된 파라미터화를 가진 RNN으로, 양쪽의 장점을 제공한다: `O(N)` 스캔 메모리, 선택적 스캔을 통한 병렬 훈련. 더 나은 장거리 컨텍스트 스케일링으로 트랜스포머 품질의 90%를 회복한다. 2026년에는 대부분의 프론티어 연구소에서 하이브리드 SSM+트랜스포머 모델(예: Jamba, Samba)을 훈련한다 — 순환은 죽지 않았으며, 하나의 구성 요소가 되었다.

## 연습문제

1. **쉬움.** `code/main.py`에서 `rnn_style`을 가져와 스칼라 은닉 상태를 길이-64 벡터 은닉 상태로 교체하라. 다시 측정하라. 은닉 상태 차원에 따라 직렬 오버헤드가 얼마나 증가하는가?
2. **중간.** 순수 Python으로 병렬 프리픽스-합(prefix-sum, Hillis-Steele 스캔)을 구현하라. 길이 1024에서 직렬 스캔과 동일한 수치 출력을 생성하는지 확인하라. 깊이를 계산하라.
3. **어려움.** attention-style 리덕션을 PyTorch GPU로 포팅하라. 시퀀스 길이를 64에서 65,536으로 변화시키며 두 방식을 시간 측정하라. 곡선 형태를 플롯하고 설명하라.

## 주요 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|-----------------------|
| 순환(Recurrence) | "RNN은 순차적이다" | 단계 `t`가 단계 `t-1`에 의존하여 시간 축을 따라 직렬 실행을 강제하는 계산. |
| 직렬 깊이(Serial depth) | "그래프가 얼마나 깊은지" | 의존적 연산의 가장 긴 체인; 무한 하드웨어에서도 벽시계 시간을 제한. |
| 어텐션(Attention) | "토큰들이 서로를 보게 하라" | 위치 i와 j 사이의 유사도 점수에서 나오는 `sum_j a_ij v_j`의 가중합. |
| 컨텍스트 윈도우(Context window) | "모델이 보는 양" | 어텐션 레이어가 입력으로 받을 수 있는 위치 수; 이차 메모리 비용이 여기서 확장. |
| 귀납적 편향(Inductive bias) | "아키텍처에 내장된 가정" | 데이터가 어떻게 생겼는지에 대한 사전 지식; CNN은 변환 불변성, RNN은 최신성을 가정. |
| 상태-공간 모델(State-space model) | "뒤에 대수가 있는 RNN" | 구조화된 상태-공간 행렬을 통해 병렬 훈련을 위해 파라미터화된 순환. |
| 이차 병목(Quadratic bottleneck) | "컨텍스트 비용이 많이 드는 이유" | 어텐션 메모리 = 시퀀스 길이에서 `O(N²)`; Flash Attention은 상수를 숨기고 스케일링은 숨기지 않음. |
