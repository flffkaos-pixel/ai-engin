# 도구 인터페이스 — 에이전트가 구조화된 입출력을 필요로 하는 이유

> 언어 모델은 토큰을 생성합니다. 프로그램은 액션을 수행합니다. 이 둘 사이의 간극이 바로 도구 인터페이스입니다: 모델이 액션을 요청하고 호스트가 이를 실행하도록 하는 계약입니다. 2026년의 모든 스택 — OpenAI, Anthropic, Gemini의 함수 호출; MCP의 `tools/call`; A2A의 태스크 파트 — 은 동일한 4단계 루프를 각기 다르게 인코딩한 것입니다. 이 레슨은 그 루프를 명명하고 이를 실행하는 최소한의 기계 장치를 보여줍니다.

**Type:** 학습
**Languages:** Python (표준 라이브러리, LLM 없음)
**Prerequisites:** 11단계 (LLM 완성 API)
**Time:** 약 45분

## 학습 목표

- 텍스트만 생성할 수 있는 LLM이 그 자체만으로 실제 세계에 액션을 취할 수 없는 이유를 설명할 수 있다.
- 4단계 도구 호출 루프(기술 → 결정 → 실행 → 관찰)를 그리고 각 단계를 누가 소유하는지 명명할 수 있다.
- 도구 설명을 이름, JSON 스키마 입력, 결정론적 실행자 함수의 세 부분으로 작성할 수 있다.
- 순수 도구와 부수 효과 도구를 구분하고, 안전성을 위해 이 구분이 중요한 이유를 설명할 수 있다.

## 문제

LLM은 다음 토큰에 대한 확률 분포를 출력합니다. 그것이 전체 출력 표면입니다. 채팅 모델에게 "지금 벵갈루루 날씨가 어때?"라고 물으면 그럴듯한 문장을 쓸 수는 있지만, 날씨 API에 직접 접속할 수는 없습니다. 그 문장은 우연히 맞거나 3일 전의 정보일 수 있습니다.

이 간극을 메우는 것이 도구 인터페이스의 목적입니다. 호스트 프로그램(여러분의 에이전트 런타임, Claude Desktop, ChatGPT, Cursor 또는 커스텀 스크립트)은 호출 가능한 도구 목록을 모델에 광고합니다. 모델은 액션이 필요하다고 판단하면 도구 이름과 인자를 지정한 구조화된 페이로드를 출력합니다. 호스트는 그 페이로드를 파싱하고 실제로 도구를 실행한 후 결과를 다시 전달합니다. 모델이 더 이상 호출이 필요 없다고 판단할 때까지 이 루프가 계속됩니다.

이 계약의 첫 번째 버전은 2023년 6월 OpenAI의 "functions" 파라미터로 출시되었습니다. Anthropic은 Claude 2.1에서 `tool_use` 블록으로 뒤따랐습니다. Gemini는 몇 달 후 `functionDeclarations`를 추가했습니다. 모든 제공자는 이제 동일한 형태를 제공합니다: JSON-Schema로 타입이 지정된 도구 목록을 입력으로, JSON 페이로드 도구 호출을 출력으로 받습니다. Model Context Protocol(2024년 11월)은 이 계약을 일반화하여 하나의 도구 레지스트리가 모든 모델을 서비스할 수 있게 했습니다. A2A(2026년 4월, v1.0)는 에이전트 간 위임을 위해 동일한 프리미티브를 계층화했습니다.

4단계 루프는 이 모든 것 아래에 있는 불변의 구조입니다. 13단계의 나머지 모든 내용은 이에 대한 상세한 설명입니다.

## 개념

### 1단계: 기술

호스트는 각 도구를 세 가지 필드로 선언합니다.

- **이름.** 안정적이고 기계가 읽을 수 있는 식별자. `get_weather`이지, "날씨 가져오기"가 아닙니다.
- **설명.** 한 문단 분량의 자연어 요약. "사용자가 특정 도시의 현재 날씨를 물을 때 사용합니다. 과거 데이터에는 사용하지 마십시오."
- **입력 스키마.** 도구의 인자를 설명하는 JSON Schema 객체(draft 2020-12).

모델은 이 목록을 전달받습니다. 최신 제공자는 이러한 선언을 제공자별 템플릿을 사용하여 시스템 프롬프트에 직렬화하므로, 호출자는 구조화된 형식만 다루면 됩니다.

### 2단계: 결정

사용자의 메시지와 사용 가능한 도구가 주어지면, 모델은 세 가지 동작 중 하나를 선택합니다.

1. **텍스트로 직접 응답.** 도구 호출 없음.
2. **하나 이상의 도구 호출.** 구조화된 호출 객체 출력. `parallel_tool_calls: true`(OpenAI와 Gemini에서는 기본값, Anthropic에서는 옵트인)에서 모델은 한 턴에 여러 호출을 출력할 수 있습니다.
3. **거절.** 엄격 모드 구조화된 출력은 호출 대신 타입이 지정된 `refusal` 블록을 생성할 수 있습니다.

도구 호출 페이로드는 세 가지 안정적인 필드를 가집니다: 호출 `id`, 도구 `name`, JSON `arguments` 객체. id는 호스트가 나중에 결과를 특정 호출과 연관시킬 수 있도록 존재하며, 이는 병렬 호출이 순서 없이 반환될 때 중요합니다.

### 3단계: 실행

호스트는 호출을 수신하고, 선언된 스키마에 대해 인자를 검증한 후 실행자를 동작시킵니다. 유효하지 않은 인자는 모델이 필드를 환각했거나 잘못된 타입을 사용했음을 의미합니다 — 약한 모델에서 매우 흔한 실패 모드입니다. 프로덕션 호스트는 유효하지 않은 인자에 대해 세 가지 중 하나를 수행합니다: 빠르게 실패하고 오류를 모델에 표시, 제약 조건이 있는 파서로 JSON 수정, 또는 검증 오류를 프롬프트에 포함시켜 모델을 재시도.

실행자 자체는 평범한 코드입니다. Python, TypeScript, 셸 명령, 데이터베이스 쿼리. 결과를 생성하며, 보통 문자열이지만 JSON 값 또는 구조화된 콘텐츠 블록(MCP의 텍스트, 이미지, 리소스 참조)일 수도 있습니다. 결과는 직렬화 가능해야 합니다.

### 4단계: 관찰

호스트는 도구 결과를 대화에 추가하고(일치하는 `id`를 가진 `tool` 역할 메시지로) 모델을 다시 호출합니다. 모델은 이제 컨텍스트에 도구 출력을 가지고 최종 답변을 생성하거나 추가 호출을 요청할 수 있습니다. 모델이 호출 생성을 중단하거나 호스트가 반복 횟수에 대한 안전 제한에 도달할 때까지 계속됩니다.

### 신뢰 분할

도구는 안전성에 영향을 미치는 두 가지 유형이 있습니다.

- **순수.** 읽기 전용, 결정론적, 부수 효과 없음. `get_weather`, `search_docs`, `get_current_time`. 추측하여 호출해도 안전합니다.
- **결과적.** 상태를 변경하거나, 비용을 지출하거나, 사용자 데이터에 접근합니다. `send_email`, `delete_file`, `execute_trade`. 반드시 게이트가 필요합니다.

Meta의 2026년 에이전트 보안 "Rule of Two"는 단일 턴이 신뢰할 수 없는 입력, 민감한 데이터, 결과적 액션 중 최대 두 개까지만 결합할 수 있다고 말합니다. 도구 인터페이스는 호출을 거부하거나, 사용자 확인을 요구하거나, 범위를 확대하여 이 규칙을 시행하는 곳입니다. 전체 보안 챕터는 13단계 15과, 에이전트 수준 권한 정책은 14단계 09과를 참조하세요.

### 루프가 존재하는 곳

| 컨텍스트 | 누가 기술 | 누가 결정 | 누가 실행 |
|---------|----------|---------|---------|
| 단일 턴 함수 호출 (OpenAI/Anthropic/Gemini) | 앱 개발자 | LLM | 앱 개발자 |
| MCP | MCP 서버 | MCP 클라이언트를 통한 LLM | MCP 서버 |
| A2A | 에이전트 카드 발행자 | 호출하는 에이전트 | 호출된 에이전트 |
| 웹 브라우저 (함수 호출 에이전트) | 브라우저 확장 / WebMCP | LLM | 브라우저 런타임 |

모든 곳에서 동일한 4단계입니다. 열 이름은 바뀌지만 구조는 변하지 않습니다.

### 그냥 모델에게 JSON을 출력하라고 프롬프트하면 안 되나요?

"모델에게 JSON으로 응답하라고 요청"은 함수 호출 이전의 패턴이었습니다. 최첨단 모델에서도 약 5~15% 실패하며, 작은 모델에서는 훨씬 더 자주 실패합니다. 실패 모드에는 중괄호 누락, 후행 쉼표, 환각된 필드, 잘못된 타입이 포함됩니다. 그러면 JSON 수정 패스, 재시도, 또는 제약 조건 디코더가 필요합니다.

네이티브 함수 호출이 더 나은 이유는 세 가지입니다. 첫째, 제공자는 정확한 호출 형태에 대해 모델을 종단간 학습시키므로, 엄격 모드에서 유효 JSON 비율이 98~99%로 올라갑니다. 둘째, 호출 페이로드는 자유 텍스트가 아닌 자체 프로토콜 슬롯에 있으므로 도구 호출이 사용자에게 보이는 응답으로 누출되지 않습니다. 셋째, 제공자는 제약 조건 디코딩(OpenAI의 strict 모드, Anthropic의 `tool_use`, Gemini의 `responseSchema`)으로 스키마 준수를 강제합니다. 출력이 검증을 통과함이 보장됩니다.

13단계 02과는 세 가지 제공자 API를 나란히 살펴봅니다. 13단계 04과는 구조화된 출력을 깊이 다룹니다.

### 회로 차단기

루프는 모델이 호출 생성을 중단하거나 호스트가 최대 턴 수에 도달하면 종료됩니다. 프로덕션 호스트는 이를 5~20턴 사이로 설정합니다. 그 이상이면 모델이 빠져나올 수 없는 루프에 거의 확실히 빠진 것입니다. Claude Code는 기본 20턴, OpenAI Assistants는 10턴, Cursor의 에이전트 모드는 25턴입니다.

대안인 무제한 루프는 "에이전트가 밤새 API 호출에 400달러를 사용했습니다"라는 사후 분석으로 6개월마다 나타납니다. 제한 없이 배포하지 마십시오.

오류 복구와 자기 치유에 대한 심층 내용은 14단계 12과, 프로덕션 속도 제한은 17단계를 참조하세요.

### 13단계가 여기서 가는 방향

- 02과부터 05과까지는 제공자 수준의 도구 호출 표면을 다듬습니다.
- 06과부터 14과까지는 루프를 MCP로 일반화합니다.
- 15과부터 18과까지는 적대적 서버, 적대적 사용자, 인증되지 않은 원격 인증 표면으로부터 루프를 방어합니다.
- 19과부터 22과까지는 패턴을 에이전트 간 협업, 관찰 가능성, 라우팅, 패키징으로 확장합니다.
- 23과는 모든 프리미티브를 사용하여 완전한 에코시스템을 구축합니다.

나머지 모든 레슨은 이 4단계 루프의 상세한 설명입니다. 이것을 불변의 구조로 기억하십시오.

## 사용하기

`code/main.py`는 LLM 없이 4단계 루프를 실행합니다. 가짜 "결정자" 함수가 사용자 메시지에 대한 패턴 매칭으로 모델을 시뮬레이션합니다; 실행자, 스키마 검증기, 관찰 단계 하네스는 실제입니다. 실행하여 인쇄 가능한 중간 상태와 함께 전체 요청/응답 동작을 확인한 후, 이후 레슨에서 가짜 결정자를 실제 제공자로 교체하십시오.

살펴볼 내용:

- 도구 레지스트리는 도구당 세 가지 필드(이름, 설명, 스키마, 실행자 참조)를 보유합니다.
- 검증기는 표준 라이브러리만으로 작성된 최소 JSON Schema 하위 집합(타입, required, enum, min/max)입니다. 13단계 04과는 더 완전한 버전을 제공합니다.
- 루프는 반복 횟수를 5회로 제한합니다. 프로덕션 에이전트는 정확히 이런 종류의 회로 차단기가 필요합니다.

## 배포하기

이 레슨은 `outputs/skill-tool-interface-reviewer.md`를 생성합니다. 주어진 도구 정의 초안(이름 + 설명 + 스키마 + 실행자 개요)에 대해 스킬이 루프 적합성을 감사합니다: 이름이 기계에 안정적인지, 설명이 완전한 사용 요약인지, 스키마가 JSON Schema 2020-12를 올바르게 사용하는지, 순수 대 결과적 분류가 명시적인지.

## 실습

1. `code/main.py`에 `get_stock_price(ticker)`라는 네 번째 도구를 추가하세요. 설명을 "사용자가 티커로 현재 주가를 물을 때 사용합니다. 과거 가격이나 시장 요약에는 사용하지 마십시오."로 작성하세요. 하네스를 실행하고 가짜 결정자가 티커를 언급하는 쿼리를 새 도구로 라우팅하는지 확인하세요.

2. 스키마 검증기를 깨뜨리세요. `arguments` 객체에 필수 필드가 누락된 호출을 전달하고, 호스트가 실행 전에 이를 거부하는지 확인하세요. 그런 다음 알 수 없는 필드가 추가된 호출을 전달하세요. 결정하세요: 호스트가 거부해야 할까요, 무시해야 할까요? 안전성 논거로 선택을 정당화하세요.

3. 하네스의 각 도구를 순수 또는 결과적으로 분류하세요. 필요한 레지스트리 항목에 `consequential: true` 플래그를 추가하고, 결과적 도구가 선택될 때마다 "사용자에게 확인하겠습니다"라는 줄을 출력하도록 루프를 변경하세요. 이것은 모든 프로덕션 호스트에 필요한 확인 게이트의 형태입니다.

4. 선호하는 클라이언트(Claude Desktop, Cursor, ChatGPT, 또는 커스텀 스택)에 대해 위의 제공자 열 표를 채워 4단계 루프를 종이에 그리세요. 13단계 06과의 MCP 특화 변형과 교차 참조하세요.

5. OpenAI의 함수 호출 가이드를 처음부터 끝까지 읽으세요. 여기에 제시된 4단계 루프에는 없지만 요청에 있는 하나의 필드를 식별하세요. 그것이 무엇을 추가하는지, 그리고 왜 필수적이기보다는 편리한 것인지 설명하세요.

## 주요 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|----------|
| 도구(Tool) | "모델이 호출할 수 있는 것" | 이름 + JSON-Schema-타입 입력 + 실행자 함수의 삼중체 |
| 함수 호출(Function calling) | "네이티브 도구 사용" | 산문 대신 구조화된 도구 호출을 출력하기 위한 제공자 수준 API 지원 |
| 도구 호출(Tool call) | "모델의 액션 요청" | 모델이 출력한 `id`, `name`, `arguments`를 가진 JSON 페이로드 |
| 도구 결과(Tool result) | "도구가 반환한 것" | 일치하는 id로 `tool` 역할 메시지에 래핑된 실행자 출력 |
| 병렬 도구 호출(Parallel tool calls) | "한 번에 여러 호출" | 한 모델 턴의 여러 호출 객체, 독립적이며 id로 정렬 가능 |
| 엄격 모드(Strict mode) | "보장된 JSON" | 모델의 출력이 선언된 스키마에 대해 검증을 통과하도록 강제하는 제약 조건 디코딩 |
| 순수 도구(Pure tool) | "읽기 전용 도구" | 부수 효과 없음; 재실행해도 안전 |
| 결과적 도구(Consequential tool) | "액션 도구" | 외부 상태 변경; 게이트, 감사 또는 사용자 확인 필요 |
| 4단계 루프(Four-step loop) | "도구 호출 사이클" | 기술 → 결정 → 실행 → 관찰 |
| 호스트(Host) | "에이전트 런타임" | 도구 레지스트리를 보유하고, 모델을 호출하며, 실행자를 실행하는 프로그램 |
