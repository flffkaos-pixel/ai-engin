# LLM 라우팅 계층 — LiteLLM, OpenRouter, Portkey

> 제공자 종속은 비용이 많이 듭니다. 도구 호출 워크로드에 따라 다른 모델이 적합합니다. 라우팅 게이트웨이는 하나의 API 표면, 재시도, 장애 조치, 비용 추적 및 가드레일을 제공합니다. 2026년을 지배하는 세 가지 아키타입: LiteLLM(오픈 소스 자체 호스팅), OpenRouter(관리형 SaaS), Portkey(프로덕션 등급, 2026년 3월 오픈 소스화). 이 레슨은 결정 기준을 명명하고 stdlib 라우팅 게이트웨이를 살펴봅니다.

**Type:** 학습
**Languages:** Python (표준 라이브러리, 라우팅 + 장애 조치 + 비용 추적기)
**Prerequisites:** 13단계 02과 (함수 호출), 13단계 17과 (게이트웨이)
**Time:** 약 45분

## 학습 목표

- 자체 호스팅, 관리형 및 프로덕션 등급 라우팅 옵션을 구분할 수 있다.
- 정의된 우선순위 순서로 제공자 실패 시 재시도하는 폴백 체인을 구현할 수 있다.
- 제공자 간 요청별 비용 및 토큰 사용량을 추적할 수 있다.
- 주어진 프로덕션 제약 조건에 대해 LiteLLM, OpenRouter 및 Portkey 중에서 결정할 수 있다.

## 문제

제공자 라우팅이 중요한 시나리오:

1. **비용.** Claude Sonnet은 Haiku보다 3배 비쌈. 분류 작업에는 Haiku로 충분; 합성 작업에는 Sonnet이 가치 있음. 요청별 라우팅.

2. **장애 조치.** OpenAI에 나쁜 시간이 있음. 모든 요청 실패. 재배포 없이 Anthropic으로 자동 폴백 원함.

3. **지연 시간.** 라이브 채팅 UI는 빠른 최초 토큰 시간 필요. 배치 요약기는 그렇지 않음. 지연 시간 SLA별 라우팅.

4. **규정 준수.** EU 사용자는 EU 리전에 남아야 함. 리전별 라우팅.

5. **실험.** 동일 워크로드에서 두 모델 A/B 테스트. 테스트 버킷별 라우팅.

이 모든 것을 통합별로 수동 코딩하는 것은 반복적. 라우팅 게이트웨이는 하나의 OpenAI 호환 API를 제공하고 나머지를 처리.

## 개념

### OpenAI 호환 프록시 형태

모두 OpenAI 형태를 사용. 라우팅 게이트웨이는 `/v1/chat/completions`를 노출하고 OpenAI 스키마를 수락하며 내부적으로 Anthropic / Gemini / Cohere / Ollama / 무엇이든 프록시. 클라이언트는 상관하지 않음.

### 모델 별칭

`claude-3-5-sonnet-20251022` 대신 코드에서 `our_smart_model`이라고 말함. 게이트웨이가 별칭을 실제 모델에 매핑. Anthropic이 Claude 4를 출시하면 서버 측에서 별칭 변경; 코드는 건드릴 것 없음.

### 폴백 체인

```
primary: openai/gpt-4o
on 5xx: anthropic/claude-3-5-sonnet
on 5xx: google/gemini-1.5-pro
on 5xx: refuse
```

게이트웨이는 이를 구성에서 정의. 재시도는 예산에 대해 계산되어 폴백 계단식이 비용을 폭발시키지 않음.

### 의미론적 캐싱

동일 또는 거의 동일한 프롬프트가 제공자 대신 캐시에 적중. 반복 에이전트 루프에서 30~60% 절감. 키는 임베딩 기반; 거의 동일한 프롬프트가 캐시 슬롯 공유.

### 가드레일

게이트웨이 수준:

- **PII 삭제.** 프롬프트 전송 전 정규식 또는 ML 기반 패스.
- **정책 위반.** 금지된 콘텐츠가 있는 프롬프트 거부.
- **출력 필터.** 누출에 대한 완성 검열.

Portkey와 Kong은 모두 독단적인 가드레일을 제공. LiteLLM은 선택 사항으로 남김.

### 키별 속도 제한

하나의 API 키 = 하나의 팀. 키별 예산이 한 팀이 공유 할당량을 소비하는 것을 방지. 대부분의 게이트웨이가 이를 지원.

### 자체 호스팅 vs 관리형 트레이드오프

| 요소 | LiteLLM (자체 호스팅) | OpenRouter (관리형) | Portkey (프로덕션) |
|--------|----------------------|----------------------|----------------------|
| 코드 | 오픈 소스, Python | 관리형 SaaS | 오픈 소스 (2026년 3월) + 관리형 |
| 설정 | 프록시 배포 | 가입 | 둘 중 하나 |
| 제공자 | 100+ | 300+ | 100+ |
| 청구 | 자체 키 | OpenRouter 크레딧 | 자체 키 |
| 관찰 가능성 | OpenTelemetry | 대시보드 | 전체 OTel + PII 삭제 |
| 최적 대상 | 완전한 제어를 원하는 팀 | 빠른 프로토타이핑 | 규정 준수가 필요한 프로덕션 |

LiteLLM은 SRE 팀이 있고 데이터 주권을 원할 때 승리. OpenRouter는 단일 구독과 인프라 없음을 원할 때 승리. Portkey는 가드레일과 규정 준수가 기본으로 필요할 때 승리.

### 비용 추적

모든 요청은 `provider`, `model`, `input_tokens`, `output_tokens`를 전달. 모델별 토큰당 가격(게이트웨이가 유지하는 가격표에서 가져옴) 곱하기. 사용자별 / 팀별 / 프로젝트별 집계.

### MCP + 라우팅

게이트웨이는 LLM 호출과 MCP 샘플링 요청을 모두 라우팅 가능. 샘플링 요청의 modelPreferences가 특정 모델을 선호할 때 게이트웨이가 올바른 백엔드로 변환. 이것이 13단계 17과(MCP 게이트웨이)와 이 레슨의 라우팅 게이트웨이가 때로는 하나의 서비스로 병합되는 곳.

### 라우팅 전략

- **정적 우선순위.** 목록의 첫 번째; 오류 시 폴백.
- **부하 분산.** 라운드 로빈 또는 가중치.
- **비용 인식.** 지연 시간/품질을 충족하는 가장 저렴한 모델 선택.
- **지연 시간 인식.** 최근 N분 동안 가장 빠른 모델 선택.
- **작업 인식.** 프롬프트 분류기가 코딩을 한 모델로, 요약을 다른 모델로 라우팅.

## 사용하기

`code/main.py`는 약 150줄의 라우팅 게이트웨이 구현: OpenAI 형태 요청 수락, 제공자별 스텁으로 변환, 우선순위 폴백 체인 실행, 요청별 비용 추적, 입력에 PII 삭제 패스 적용. 세 가지 시나리오로 실행: 정상 요청, 폴백을 트리거하는 기본 제공자 중단, 삭제에 걸린 PII 누출.

살펴볼 내용:

- `ROUTES` 딕셔너리: 별칭 -> 우선순위 순서의 구체적 제공자 목록.
- 폴백 루프가 5xx에서 재시도.
- 비용 추적기가 토큰 사용량에 모델별 요율 곱하기.
- PII 삭제기가 전달 전에 SSN 형태 패턴을 제거.

## 배포하기

이 레슨은 `outputs/skill-routing-config-designer.md`를 생성합니다. 워크로드 프로파일(지연 시간, 비용, 규정 준수)이 주어지면 스킬이 LiteLLM / OpenRouter / Portkey를 선택하고 라우팅 구성을 생성합니다.

## 실습

1. `code/main.py`를 실행하세요. 중단 시나리오를 트리거하고 폴백이 두 번째 제공자에 도달하고 비용이 올바르게 귀속되는지 확인하세요.

2. 의미론적 캐싱 추가: 프롬프트의 SHA256이 조회 키; 캐시 적중은 즉시 반환. 반복 호출에서 비용 절감 측정.

3. "code ..." 프롬프트를 지능을 선호하는 별칭으로, "summarize ..." 프롬프트를 속도를 선호하는 별칭으로 라우팅하는 프롬프트 분류기 추가.

4. 팀별 예산 설계: 각 팀에 월별 지출 상한이 있음; 게이트웨이가 상한 도달 후 요청 거부. 적용 세분성 선택(요청별 또는 윈도우).

5. LiteLLM, OpenRouter 및 Portkey 문서를 나란히 읽으세요. 각각이 제공하고 다른 두 개는 제공하지 않는 기능 하나씩을 명명하세요.

## 주요 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|----------|
| 라우팅 게이트웨이(Routing gateway) | "LLM 프록시" | 많은 제공자 앞의 단일 API 표면 계층 |
| OpenAI 호환(OpenAI-compatible) | "OpenAI 스키마 사용" | `/v1/chat/completions` 형태 수락, 모든 백엔드로 변환 |
| 모델 별칭(Model alias) | "our_smart_model" | 게이트웨이가 구체적 모델에 매핑하는 코드의 이름 |
| 폴백 체인(Fallback chain) | "재시도 목록" | 실패 시 시도되는 제공자의 순서 목록 |
| 의미론적 캐싱(Semantic caching) | "프롬프트 임베딩 캐시" | 키는 프롬프트의 임베딩; 근접 중복이 캐시 적중 공유 |
| 가드레일(Guardrails) | "입력/출력 필터" | PII 삭제, 정책 위반 거부 |
| 키별 속도 제한(Per-key rate limit) | "팀 예산" | API 키로 범위 지정된 할당량 |
| 비용 추적(Cost tracking) | "요청별 지출" | 토큰 사용량 x 모델당 가격 집계 |
| LiteLLM | "오픈 프록시" | 자체 호스팅 가능한 OSS 라우팅 게이트웨이 |
| OpenRouter | "관리형 SaaS" | 크레딧 기반 청구가 있는 호스팅 게이트웨이 |
| Portkey | "프로덕션 옵션" | 내장 가드레일이 있는 오픈 소스 + 관리형 |
