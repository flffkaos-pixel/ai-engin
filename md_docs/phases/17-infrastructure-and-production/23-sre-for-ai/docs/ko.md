# AI를 위한 SRE — 멀티 에이전트 인시던트 대응, 런북, 예측 감지

> AI SRE는 RAG를 통해 인프라 데이터 (로그, 런북, 서비스 토폴로지)에 기반한 LLM을 사용하여 조사, 문서화 및 조정 단계를 자동화합니다. 2026년 아키텍처 패턴은 멀티 에이전트 오케스트레이션입니다 — 전문화된 에이전트 (로그, 메트릭, 런북)가 supervisor에 의해 조정됩니다; AI가 가설을 제안하고 쿼리하며, 인간이 판단 통화를 승인합니다. Datadog Bits AI와 Azure SRE Agent가 관리형 제품으로 출시했습니다. 런북이 진화하고 있습니다: NeuBird Hawkeye는 역진행 평가 (두 모델이 동일한 인시던트를 분석; 동의 = 확신,不同意 = 불확실성)를 사용합니다; 운영 메모리가 팀 변경 전반에 걸쳐 유지됩니다. 자동 재시작은 여전히 신중합니다: AI가 제안하고, 인간이 승인합니다. 완전 자율 행동은 좁습니다 (팟 재시작, 특정 배포 롤백) 엄격한 가드레일과 함께 — "설정 후 방치"를 판매하는 사람은 과대 광고입니다. emerging 프론티어: 사전 인시던트 예측. MIT 연구는 역사적 로그 + GPU 온도 + API 오류 패턴으로 훈련된 LLM이 테스트 세트에서 10-15분 일찍 89%의 중단을 예측했다고 보고합니다. 예측: 2026년 말까지 엔터프라이즈 LLM의 95%가 자동 장애 조치를 가지고 있을 것입니다.

**유형:** 학습
**언어:** Python (stdlib, toy 멀티 에이전트 인시던트 트라이지 시뮬레이터)
**선수 과목:** Phase 17 · 13 (관찰 가능성), Phase 17 · 24 (카오스 엔지니어링)
**소요 시간:** ~60분

## 학습 목표

- 멀티 에이전트 AI SRE 아키텍처를 다이어그램으로 그립니다: supervisor + 전문화된 에이전트 (로그, 메트릭, 런북) + 인간 승인 게이트.
- 자동 재시작이 좁은 (팟 재시작, 배포 reverted)而非 broad (서비스 재설계)理由를 설명합니다.
- 역진행 평가 패턴 (NeuBird Hawkeye)을 이름 짓습니다: 두 모델 동의 = 확신;不同意 = 에스컬레이션.
- MIT 89% 조기 감지 결과를 인용하고 운영 제약 조건을 설명합니다: 행동을 위한 actuation 없는 예측은 그냥 대시보드입니다.

## 문제

온콜 엔지니어가 새벽 3시에 페이지합니다. "체크아웃에서 높은 오류율." Datadog, Loki, 세 개의 런북, 배포 로그를 확인합니다. 30분 후根本 원인이 KV 캐시 스파이크에서 vLLM OOM임을 realized합니다. 팟을 재시작합니다; 오류가 지워집니다.

2026년 이 조사 처음 20분은 자동화 가능합니다. 로그를 서비스별로 그룹화하고, 최근 배포에 연관시키고, 런북과 매칭 — 모두 RAG + 도구 사용입니다. 감독된 에이전트는 인간이 Datadog을 열기 전에 가설을 제시할 수 있습니다.

완전 자율 재시작은 다른 문제입니다. 팟 재시작: 안전. GPU 풀 확장: 정책이 허용하면 안전. 서비스 재설계: 절대 아닙니다. 규율은 좁은 선을 그리는 것입니다.

## 개념

### 멀티 에이전트 아키텍처

```
           Incident
              │
              ▼
         Supervisor
         /    |    \
        ▼     ▼     ▼
  Log agent  Metric agent  Runbook agent
        │     │     │
        └─────┴─────┘
              │
              ▼
         Hypothesis + evidence
              │
              ▼
         Human approval
              │
              ▼
         Action (narrow set)
```

Supervisor가 인시던트를 하위 쿼리로 분해합니다. 전문화된 에이전트는 도구 액세스 (로그 검색, PromQL, 문서 검색)를 가집니다. Supervisor가 합성하고, 인간에게 가설 + 증거를 제시합니다. 인간이 승인하거나 리디렉션합니다.

### 자동 재시작 범위

**안전 (좁은)**: 팟 재시작, 특정 배포 reverted, 사전 승인된 범위 내에서 풀 확장, 사전 승인된 기능 플래그 활성화.

**안전하지 않음 (broad)**: 서비스 토폴로지 변경, 리소스限制修改, 새 코드 배포, IAM 변경, 데이터베이스 변경.

"설정 후 방치"를 판매하는 사람은 과대 광고입니다. 안전한 세트는 AI SRE가 성숙함에 따라 증가하지만, 경계는 실제입니다.

### 역진행 평가 (NeuBird Hawkeye)

두 모델이 독립적으로 동일한 인시던트를 분석합니다._root 원인에 동의하면 확신이 높습니다.同意하지 않으면 두 가설이 표시된 인간에게 에스컬레이션합니다. 간단한 패턴, 환각된_root 원인에 대한 효과적인 필터.

### 운영 메모리

전통적인 SRE의 조용한kill —部落 지식이가 떠납니다. AI SRE는 런북 + 사후 분석을 벡터 DB에 저장합니다; 에이전트가 모든 새 인시던트에서 검색합니다. 새 엔지니어가 합류할 때 AI는 전체 이력을 가집니다.

### 사전 인시던트 예측

MIT 2025 연구: historical 로그, GPU 온도, API 오류 패턴으로 훈련된 LLM이 테스트 세트에서 10-15분 전에 89%의 중단을 예측했습니다.

현실 점검: 행동을 위한 actuation 없는 예측은 대시보드입니다. 운영 질문은 "예측할 때 무엇을 합니까?"입니다. 선제적 drain? 페이저? 자동 확장? 답은 정책 특정입니다.

### 2026년 제품

- **Datadog Bits AI** — Datadog 내부의 관리형 SRE copilot.
- **Azure SRE Agent** — Azure 네이티브.
- **NeuBird Hawkeye** — 역진행 평가 + 운영 메모리.
- **PagerDuty AIOps** — 트라이지 + 중복 제거.
- **Incident.io Autopilot** — 인시던트 commander + 조정.

### 코드로 된 런북

런북이 Confluence 페이지에서 구조화된 섹션이 있는 버전이 지정된 마크다운으로进化합니다 (증상, 가설, 검증, 행동). 구조화된 런북은 더 나은 RAG 검색을 제공합니다. 모든 AI-SRE 롤아웃을 시작할 때 구조화되지 않은 런북을 구조화된 것으로 변환하여 시작하세요.

### 기억해야 할 숫자

- MIT 조기 감지: 89%의 중단, 10-15분 리드 타임.
- 멀티 에이전트 트라이지: supervisor + (로그, 메트릭, 런북) + 인간.
- 안전한 자동 재시작 세트: 팟 재시작, 배포 reverted, 범위 내 확장.
- 역진행 평가: 두 모델 독립적; 동의 = 확신.

## 활용

`code/main.py`는 멀티 에이전트 트라이지를 시뮬레이션합니다: 로그 에이전트가 오류를 찾고, 메트릭 에이전트가 CPU 스파이크를 찾고, 런북 에이전트가 알려진 문제와 매칭됩니다. Supervisor가 가설을 순위로 매깁니다.

## 연습문제

1. `code/main.py`를 실행하세요. 로그와 메트릭 에이전트가同意하지 않으면 어떻게 됩니까? Supervisor가 어떻게 해결합니까?
2. 서비스에 대해 세 가지 "안전한" 자동 재시작 작업을 정의하세요. 각각에 justification을 제공하세요.
3. 구조화된 런북 템플릿을 작성하세요: 섹션, 필수 필드, 검증 명령.
4. 예측 감지가 12분 리드로 발생합니다. 정책이 무엇입니까 — 페이저, 선제적 drain, 또는 둘 다?
5. 3인팀이 2026년에 AI SRE를 채택해야 하는지 아니면 기다려야 하는지 주장하세요. 성숙도, 볼륨, 위험을 고려하세요.
