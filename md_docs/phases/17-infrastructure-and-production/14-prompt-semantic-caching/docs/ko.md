# 프롬프트 캐싱 및 의미론적 캐싱 경제학

> **2026-04의 가격 스냅샷.** 아래의 숫자 주장은 이 레슨 게시 시점에 캡처된 공급업체 요금 카드입니다.下游에서引用하기 전에 연결된 문서에서 확인하세요.

> 캐싱은 두 가지 레이어에서 발생합니다. L2 (공급업체 수준) 프롬프트/접두사 캐싱은 반복되는 접두사에 대한 주의 KV를 재사용합니다 — Anthropic의 프롬프트 캐싱 문서는 긴 프롬프트에서 최대 90% 비용 감소와 85% 지연 시간 감소를 광고합니다; Claude 3.5 Sonnet의 경우 캐시 읽기는 $3.00/M 신선에 대해 $0.30/M이며 5분 TTL과 1시간 TTL 옵션에 대해 2배 쓰기 프리미엄이 있습니다 (docs.anthropic.com, 2026-04). OpenAI 프롬프트 캐싱은 ≥1024토큰 프롬프트에 자동으로 적용되며 캐시된 입력을 신선 대비 약 90% 할인 가격으로 책정합니다 (platform.openai.com, 2026-04); 정확한 모델당 캐시된 요율은 라이브 요금 카드에 따라 다릅니다. L1 (앱 수준) 의미론적 캐싱은 임베딩 유사성 적중에서 LLM을 완전히 건뜁니다. 공급업체 "95% 정확도"는 일치 정확도를 참조하며 적중율이 아닙니다 — 보고된 프로덕션 적중율은 10% (열린 채팅)에서 70% (구조화된 FAQ)까지 다양합니다; 공급업체 모두 공식 기준선을 게시하지 않으므로 이것들을 보장而非 커뮤니티 원격 측정의로 취급하세요. 프로덕션 함정: 병렬화가 캐싱을 죽입니다 (첫 번째 캐시 쓰기 전에 시작된 N개의 병렬 요청이 비용을 수 배로 부풀릴 수 있습니다), 그리고 접두사 내 동적 콘텐츠가 캐시 적중을完全に prevent합니다. ProjectDiscovery는 동적 텍스트를 캐시 가능한 접두사 밖으로 이동하여 7%에서 74% 적중률로 이동했다고 보고했습니다 (2025-11).

**유형:** 학습
**언어:** Python (stdlib, toy 2층 캐시 시뮬레이터)
**선수 과목:** Phase 17 · 04 (vLLM Serving Internals), Phase 17 · 06 (SGLang RadixAttention)
**소요 시간:** ~60분

## 학습 목표

- L2 프롬프트/접두사 캐싱 (공급업체의 KV 재사용)과 L1 의미론적 캐싱 (유사한 프롬프트에서 LLM 우회)을 구분합니다.
- Anthropic의 명시적 `cache_control` 표시와 두 가지 TTL 옵션 (5분 대 1시간)과 해당 가격 승수를 설명합니다.
- 적중률, 프롬프트/응답 혼합, 토큰 가격을 감안하여 예상 월간 절감액을 계산합니다.
- 병렬화 안티패턴 (5-10배 청구서를 부풀림)과 동적 콘텐츠 안티패턴 (적중률을崩溃시키는)을 이름 짓습니다.

## 문제

RAG 서비스에 프롬프트 캐싱을 추가합니다. 청구는 평평하게 유지됩니다. 적중률을 측정합니다; 7%입니다. 프롬프트가 정적으로 보이지만 그렇지 않습니다 — 시스템 프롬프트에는 현재 날짜 (분 단위로 형식화), 요청 ID, 다양성을 위한 무작위 예제 재배열이 포함되어 있습니다. 모든 요청이 새 캐시 항목을 쓰고, 0을 읽습니다.

개별적으로, 에이전트가 사용자 질문당 10개의 병렬 도구 호출을 실행합니다. 10개 모두 첫 번째 캐시 쓰기가 완료되기 전에 공급업체에 도착합니다. 10개 쓰기, 0 읽기. 청구서는 "캐싱 포함"이 비용을 절감해야 했던 것의 5-10배입니다.

캐싱은 플래그가 아닌 프로토콜입니다. 두 레이어, 두 가지 다른 실패 모드.

## 개념

### L2 — 공급업체 프롬프트/접두사 캐싱

공급업체는 캐시 가능한 접두사에 대한 주의 KV를 저장하고 접두사가 일치하는 다음 요청에서 재사용합니다. 한 번 쓰기 비용을 지불하고 읽기는 거의 무료입니다.

**Anthropic (Claude 3.5 / 3.7 / 4 시리즈)**: 요청의 명시적 `cache_control` 마커. 어떤 블록이 캐시 가능한지 태그합니다. TTL: 5분 (쓰기 비용 1.25x 기본) 또는 1시간 (쓰기 비용 2x 기본). 캐시 읽기: Claude 3.5 Sonnet에서 $0.30/M 대 $3.00/M 신선 — 10배 저렴합니다 (2026-04 현재 docs.anthropic.com). 모델마다 요율이 다릅니다 (Opus/Haiku 별도로 게시); 항상 라이브 가격 페이지를 교차 확인하세요.

**OpenAI**: ≥1024토큰 프롬프트에 자동 캐싱 (platform.openai.com, 2026-04). 명시적 플래그 없음. 캐시된 입력은 현재 gpt-4o/gpt-5 요금 카드에서 신선 대비 약 10배 저렴합니다. 문서도 발표 노트도 공식 적중률 기준선을 게시하지 않습니다; 커뮤니티 보고는 신중한 프롬프트 디자인으로 30-60% 주변에 클러스터링됩니다. 자신의 것을 측정하려면 `usage.cached_tokens`를 모니터하세요.

**Google (Gemini)**: 명시적 API를 통한 컨텍스트 캐싱; 1M 토큰 컨텍스트는 캐싱이 훨씬 더pay합니다.

**자체 호스팅 (vLLM, SGLang)**: Phase 17 · 06은 RadixAttention을 다룹니다 — 사용자 자신의 컴퓨트에서 동일한 패턴.

### L1 — 앱 수준 의미론적 캐싱

전적으로 LLM을 호출하기 전에, 프롬프트를 해시하고, 임베딩하고, 유사한 캐시된 요청을 찾습니다 (코사인 유사성 above threshold, 일반적으로 0.95+). 적중 시 캐시된 응답을 반환합니다. 미스 시 LLM을 호출하고 결과를 캐시합니다.

오픈소스: Redis Vector Similarity, GPTCache, Qdrant. 상업용: Portkey Cache, Helicone Cache.

공급업체 정확도 주장은 반환된 캐시된 응답이 의미론적으로 적절한頻度를 참조합니다 — 얼마나 자주 hit하는지가 아닙니다. 프로덕션 적중률:

- 열린 채팅: 10-15%.
- 구조화된 FAQ / 지원: 40-70%.
- 코드 질문: 20-30% (작은 변형이 적중을 죽입니다).
- 음성 에이전트 프롬프트 반복: 50-80% (음성 정규화가 고정 세트).

### 병렬화 안티패턴

에이전트가 10개의 도구 호출을 병렬로 실행합니다. 10개 모두 동일한 4K 토큰 시스템 프롬프트를 가집니다. Anthropic 캐시 쓰기는 요청당입니다; 첫 번째 캐시 쓰기는 공급업체가 프롬프트를 본 후 ~300 ms 후에 완료됩니다. 요청 2-10이 같은 밀리초 창에서 도착하고 각각 캐시 미스를 봅니다. 10개의 쓰기 프리미엄, 0개의 읽기 할인.

수정: 배치 + 순차 우선 — 요청 1만 만들고 1의 캐시가 채워진 후 2-10을 실행합니다. 첫 번째 도구 호출에 300 ms가 추가됩니다; 청구서의 5-10배를 절약합니다.

### 동적 콘텐츠 안티패턴

시스템 프롬프트가 다음과 같이 보입니다:

```
You are a helpful assistant. The current time is 14:32:17.
User ID: abc123. Today is Tuesday...
```

모든 요청이 고유합니다. 모든 요청이 씁니다. 0 적중.

수정: 진정으로 정적인 것을 모두 캐시 가능한 접두사로 이동합니다; 캐시 경계 후 동적 콘텐츠를 추가합니다:

```
[cacheable]
You are a helpful assistant. [rules, examples, instructions]
[/cacheable]
[dynamic, not cached]
Current time: 14:32:17. User: abc123.
```

ProjectDiscovery는 이러한 방식으로 7%에서 74% 캐시 적중률로 이동하고 해부학을 게시했습니다.

### 스택 배치 + 캐싱으로 야간 작업

배치 API (Phase 17 · 15)는 24시간 턴어라운드에서 50% 할인을 제공합니다. 그 위에 캐시된 입력을 얹으면 ~10배가 됩니다. 야간 분류, 레이블링, 보고서 생성 작업은 스택을叠加하여 동기-uncached 비용의 ~10%로 떨어질 수 있습니다.

### 기억해야 할 숫자

가격 지점은 2026-04의 연결된 공급업체 문서에서 캡처되며 몇 달마다drift합니다 — 它们에 의존하기 전에 다시 확인하세요.

- Anthropic 캐시 읽기: Claude 3.5 Sonnet에서 $0.30/M, 신선 입력보다 약 10배 저렴합니다 (docs.anthropic.com).
- Anthropic 캐시 쓰기 프리미엄: 1.25x (5분 TTL) 또는 2x (1시간 TTL).
- OpenAI 자동 캐시: ≥1024토큰 프롬프트에 적용됩니다; 현재 요금 카드에서 캐시된 입력이 신선 입력의 약 10%에 가격이 책정됩니다 (platform.openai.com).
- 의미론적 캐시 적중률 (커뮤니티 보고): 열린 채팅 ~10%; 구조화된 FAQ ~70%까지. 공급업체 문서화된 기준선이 아닙니다.
- ProjectDiscovery: 접두사에서 동적을 이동하여 7% → 74% 적중률 (project blog, 2025-11).
- 병렬화 안티패턴: N개의 병렬 요청이 첫 번째 캐시 쓰기를 놓칠 때 일반적인 5–10배 청구서 팽창 보고.

## 연습문제

1. `code/main.py`를 실행하세요. 병렬화 플래그를 전환하세요. 청구서가 얼마나 변합니까?
2. 시스템 프롬프트에 날짜가 있습니다. 그것을 외부로 이동하세요. 전후 적중률 수학을 보여주세요.
3. 1시간 TTL (2x 쓰기) 대 5분 TTL (1.25x 쓰기)의 균형을 요청 도착률 given으로 계산하세요.
4. 의미론적 캐시가 0.95 임계값에서 20% 적중합니다. 0.85에서 50% 적중하지만 잘못된 캐시된 응답이 보입니다. 올바른 임계값을 선택하고 정당화하세요.
5. 사용자 질문당 10개의 병렬 하위 쿼리를 배치합니다. 종단 간 지연 시간을 추가하지 않고 캐시 우호적으로 다시 작성하세요.
