# LLM의 섀도 트래픽, 카나리 롤아웃, 점진적 배포

> LLM 롤아웃은 소프트웨어 배포의 가장 어려운 부분을 결합합니다: 단위 테스트 없음, 분산된 실패 모드, 지연된 신호. 순서는 (1) 섀도 모드 — 프로덕션 요청을 후보 모델에 복제하고, 로깅하고, 사용자 영향 없이 비교합니다; 명백한 분포 문제를 catches하지만 품질 보장이 아닙니다; (2) 카나리 롤아웃 — 10% → 25% → 50% → 75% → 100%로 점진적 트래픽 전환, 각 단계에서 게이트; 지연 시간 백분위, 비용/요청, 오류/거절율, 출력 길이 분포, 사용자 피드백율을 추적합니다; (3) 안정성이 확인된 후 고유한 대안들에 대한 A/B 테스트. 비결정론은 irreducibles입니다 — GPU FP 비연관성 plus 배치 크기 분산으로 identical 입력에 대해 실행 간 최대 15% 정확도 변동. 비용은 상수가 아닌 변수입니다 — 20% 더 나은 모델은 호출당 3배 더 expensive할 수 있습니다. 롤백 속도가 결정적입니다: 롤백에 다시 배포가 필요하면 너무 느립니다. 정책은 config/flags에 있습니다; 모델은 고정 digests로 레지스트리에 있습니다; 롤백 = 정책 플립 + 임계값 되돌림 + 초 단위로 이전 모델 고정.

**유형:** 학습
**언어:** Python (stdlib, toy canary-progression 시뮬레이터)
**선수 과목:** Phase 17 · 13 (Observability), Phase 17 · 21 (A/B Testing)
**소요 시간:** ~60분

## 학습 목표

- 섀도 모드 (제로 임팩트 비교), 카나리 (라이브 트래픽 점진적), A/B (안정성 확인 후 비교)를区別합니다.
- 5가지 LLM 특정 카나리 메트릭 (지연 시간, 비용/요청, 오류/거절, 출력 길이 분포, 사용자 피드백)을 열거합니다.
- LLM 비결정론 (최대 15%)이 롤아웃에서 "안정"의 의미를 변경하는 이유를 설명합니다.
- 초 단위로 걸리는 (정책 플립)而非 시간 (재배포) 롤백 경로를 디자인합니다.

## 문제

새 모델을 shipping합니다. 오프라인 평가가 3% 정확도 이득을 보입니다. 프로덕션에서 켭니다. 24시간 이내에 비용이 40% 올라가고, 사용자 엄지 아래가 8% 올라가고, 세 고객 티켓이 "이상한 답변"을 보고합니다. 롤백합니다. 다시 배포하는 데 3시간이 걸립니다. 주말이 망쳐졌습니다.

그 모든 것이 회피 가능했습니다. 섀도 모드가 사용자가 saw기 전에 40% 비용 급증을 잡았을 것입니다. 카나리가 엄지 아래가 움직일 때 10%에서 멈췄을 것입니다. 정책 플래그 롤백이 30초가 걸렸을 것입니다. 규율은 "오프라인 평가가 좋아 보입니다"와 "실제 사용자가 행복합니다" 사이의 격차를 채웁니다.

## 개념

### 섀도 모드

후보가 프로덕션과 동일한 요청을 수신합니다; 출력은 로깅되지만 사용자에게 반환되지 않습니다. 제로 사용자 임팩트. 로그:

- 출력 콘텐츠 (프로덕션 대비 diff).
- 토큰 수 (비용 델타).
- 지연 시간.
- 거절 및 오류.

Catches: 비용 폭등, 길이 회귀, 명백한 거절 변경,硬的 오류. 포착하지 않음: 사용자가感知할 품질 델타. 섀도는 흡연 테스트이지 품질 테스트가 아닙니다.

### 카나리 롤아웃

게이트가 있는 점진적 트래픽 전환. 일반적인 진행: 1% → 10% → 25% → 50% → 75% → 100%. 각 단계에서 5가지 메트릭에 게이트:

1. **지연 시간 백분위** — P50, P95, P99. 위반: 카나리가 P99 > 1.5x 기준.
2. **요청당 비용** — 혼합 $. 위반: 기준보다 >20% 위.
3. **오류 / 거절율** — 5xx plus 명시적 거절. 위반: 기준의 2x.
4. **출력 길이 분포** — 평균 + P99. 위반: 분포 이동.
5. **사용자 피드백율** — 엄지 아래 / 티켓 제출. 위반: 기준의 1.5x.

### 비결정론은 새로운 분산입니다

동일한 입력이 비동일한 출력을 산출합니다. 이유:

- GPU FP 비연관성 (부동 소수점 감소 순서가 배치에 따라 다름).
- 배치 크기 분산 (128 배치 vs 16 배치에서 동일한 프롬프트).
- 샘플링 (temperature > 0).

측정: 동일한 eval 세트에서 실행 간 최대 15% 정확도 변동. "안정"은rollout에서 메트릭이 기준과 동일하다는 것이 아니라 예상 분산 내임을 의미합니다. 노이즈 플로어 위에 게이트를 설정합니다.

### 비용은 변수입니다

20% 더 나은 모델은 호출당 3배 더 expensive할 수 있습니다. 요청당 비용은 5가지 게이트 중 하나입니다. "더 나은" 모델이 단위 경제학을 깨면 롤백 사례입니다.

### 롤백이 무기입니다

- 정책 플래그 (기능 플래그 시스템): 구성에서百分比를 플립합니다; 초가 걸립니다.
- 모델 고정 (레지스트리 digest): 고정된 모델이 자동 업그레이드되지 않습니다.
- 롤백 = 플래그 되돌림 + 이전으로 고정 digest 설정. 초, 시간이 아닙니다.

스택이 롤백에 다시 배포를 요구하면 롤아웃하기 전에 그것을 수정하세요.

### 도구

**Argo Rollouts** / **Flagger** — Kubernetes 점진적 전달 컨트롤러. Istio/Linkerd 가중치 라우팅과 통합합니다.

**Istio 가중치 라우팅** — 서비스 메시 수준 트래픽 분할.

**KServe / Seldon Core** — 빌트인 카나리가 있는 모델 제공.

**기능 플래그** — LaunchDarkly, Flagsmith, Unleash. 정책 수준 플립, 재배포 없음.

### 메트릭 캐던스

카나리 게이트는 트래픽 볼륨에 따라 5-15분마다 확인합니다. 10 req/min에서 1% 트래픽은 창당 50-150개 데이터 포인트를 제공합니다 — 지연에는 충분하지만 사용자 피드백에는 시끄럽습니다. 10%는 ~10x 더 많습니다. 진행은 각 단계에서 충분한 샘플을 축적할 만큼 충분히 오래 일시 중지해야 합니다.

### A/B 단계는 선택 사항입니다

새 모델이 고유하게 다른 경우 (다른 동작, 다른 비용 곡선, 다른 어조), 카나리가 통과된 후 50%에서 A/B 테스트합니다. 그것이 단순히 개선된 버전이면 카나리 게이트가 통과하면 100%로 건너뛰세요.

### 기억해야 할 숫자

- 카나리 진행: 1% → 10% → 25% → 50% → 75% → 100%.
- 비결정론 천장: 동일한 입력에서 실행 간 최대 15% 분산.
- 5가지 카나리 메트릭: 지연 시간, 비용, 오류/거절, 출력 길이, 사용자 피드백.
- 비용 게이트: 기준보다 >20% 위가 위반입니다.
- 롤백: 초가 걸립니다, 시간이 아닙니다.

## 연습문제

1. `code/main.py`를 실행하세요. 25% 비용 회귀를 주입합니다. 카나리가 어느 단계에서 중지합니까?
2. 새 모델은 오프라인에서 3% 정확도 이득이 있지만 요청당 비용이 +18%입니다. 그것을 shipping합니까? 정책에 따라 다릅니다 — 양쪽 경로를 작성하세요.
3. 60초 이내에 걸리는 롤백을 디자인하세요. 필요한 인프라를 나열하세요.
4. 비결정론이 eval에서 ±7%를 보여줍니다. 가양 알람을하지 않도록 카나리 게이트를 설정하세요. 어떤乗数を 사용합니까?
5. 섀도 모드가 카나리 전에 40% 비용 급증을 포착합니다. 섀도에서 발화하는 경고 규칙을 작성하세요.
