# LLM 프로덕션을 위한 카오스 엔지니어링

> 2026년 LLM용 카오스 엔지니어링은 그 자체의 дис플리너입니다. 프로덕션에서 실험을 실행하기 위한 전제 조건: 정의된 SLI/SLO, 추적+메트릭+로그 관찰 가능성, 자동화된 롤백, 런북, 온콜. 아키텍처에는 4개 평면이 있습니다: 제어 (실험 스케줄러), 대상 (서비스, 인프라, 데이터 저장소), 안전 (가드 + 중단 + 트래픽 필터), 관찰 가능성 (메트릭 + 추적 + 로그), 피드백 (SLO 조정으로). 가드레일은 필수입니다: 버너트 알림이 일일 오류 예산burn이 예상치의 2배를 초과하면 실험을 일시 중지합니다; 억제 창 + 추적 ID 연관으로 경고 노이즈를 중복 제거합니다. 주기: 주간 소규모 카나리 + SLO 검토; 월간 게임 데이 + 사후 분석; 분기별 팀 간 회복력 감사 + 의존성 매핑. LLM 특정 실험: 메모리 과부하, 네트워크 오류, 공급업체 중단, 변형된 프롬프트, KV 캐시 축출 폭풍. 도구: Harness Chaos Engineering (LLM 파생 권장 사항, blast-radius 축소, MCP 도구 통합); LitmusChaos (CNCF); Chaos Mesh (CNCF Kubernetes 네이티브).

**유형:** 학습
**언어:** Python (stdlib, toy 카오스 실험 실행기)
**선수 과목:** Phase 17 · 23 (AI용 SRE), Phase 17 · 13 (관찰 가능성)
**소요 시간:** ~60분

## 학습 목표

- 다섯 가지 카오스 엔지니어링 전제 조건 (SLI/SLO, 관찰 가능성, 롤백, 런북, 온콜)을 이름 짓고任何一个를 건너뛰면 관행이 깨지는 이유를 설명합니다.
- 4개 평면 (제어, 대상, 안전, 관찰 가능성)과 SLO로의 피드백 루프를 다이어그램으로 그립니다.
- 5가지 LLM 특정 실험 (메모리 과부하, 네트워크 오류, 공급업체 중단, 변형된 프롬프트, KV 축출 폭풍)을 열거합니다.
- 스택 given으로 도구를 선택합니다 — Harness, LitmusChaos, Chaos Mesh.

## 문제

전통적인 스택에서 카오스 테스트는 확립되어 있습니다. LLM 스택은 새로운 실패 모드를 추가합니다. poison 문자가 있는 4K 토큰 프롬프트가 토큰화를 12초 동안 stall합니다. 상류 공급업체가 429s를 보냅니다; 게이트웨이가 재시도합니다; 서비스가 재시도-증폭 동시성에서 OOM합니다. 버스트 부하에서 KV 캐시 축출 폭풍이 계산을 포화시키는 re-prefill cascades를 유발합니다.

이 중 어느 것도 단위 테스트에 나타나지 않습니다. 카오스 엔지니어링은 사용자가 它们를 발견하기 전에 发现하는 방법입니다.

## 개념

### 전제 조건

다음 없이 프로덕션에서 카오스를 실행하지 마세요:

1. **SLI/SLO** — 정의된 서비스 수준 지시자와 목표.
2. **관찰 가능성** — 추적, 메트릭, 로그, 대시보드에 연결.
3. **자동화된 롤백** — Phase 17 · 20 정책 플래그 롤백.
4. **런북** — 구조화된, Phase 17 · 23.
5. **온콜** — 응답할 사람.

任何一个가 없으면 카오스가 실제 인시던트가 됩니다.

### 4개 평면 + 피드백

**제어 평면** — 실험 스케줄러 (Litmus 워크플로, Chaos Mesh 일정, Harness UI).

**대상 평면** — 서비스, 팟, 노드, 부하 분산 장치, 데이터 저장소.

**안전 평면** — 킬 스위치, 억제 창, blast-radius限制, 오류 예산 게이트.

**관찰 가능성 평면** — 일반 메트릭 + 추적 ID 연관으로 카오스 유발 vs 자연 실패를 구별합니다.

**피드백 루프** — 발견이 SLO 조정, 런북 업데이트, 코드 수정으로 피드백됩니다.

### 가드레일은 필수입니다

- **버너트 알림**: 일일 오류 예산 burn이 예상치의 2배를 초과하면 실험을 일시 중지합니다.
- **억제 창**: 실험 중 blast radius의 비실험 경고를 음소거합니다.
- **추적 ID 연관**: 모든 실험 유발 오류가 태그를携带하여 온콜이 중복 제거할 수 있습니다.

### 5가지 LLM 특정 실험

1. **메모리 과부하** — 높은 동시성으로 긴 컨텍스트 요청을 보내 KV 캐시 선점 폭풍을 강제합니다. 관찰: 서비스가 우아하게 분산되는가 아니면 충돌하는가?

2. **네트워크 오류** — 추론 게이트웨이와 공급업체 간의 연결을切断합니다. 관찰: 장애 조치가 SLA 내에서 작동하는가? (Phase 17 · 19)

3. **공급업체 중단 시뮬레이션** — OpenAI에서 100% 429. 관찰: 라우팅이 Anthropic으로 장애 조치하는가? (Phase 17 · 16, 19)

4. **변형된 프롬프트** — 토큰화를 stall하는 페이로드 주입 (예: 깊이 중첩된 유니코드, 거대한 UTF-8 코드 포인트). 관찰: 단일 요청이 워커를 잠그는가?

5. **KV 축출 폭풍** — vLLM 블록 예산을 포화시켜 축출을 강제합니다. 관찰: LMCache가 복구되는가 아니면 서비스가 degrading되는가?

### 주기

- **주간** — 스테이징에서 소규모 카나리 실험, 어쩌면 프로덕션의 5%.
- **월간** — 특정 시나리오에 대한 예약된 게임 데이; 팀 간 참석; 사후 분석.
- **분기별** — 팀 간 회복력 감사; 의존성 맵 업데이트.

### 도구

- **Harness Chaos Engineering** — 상업용; AI 파생 실험 권장 사항; blast-radius 축소; MCP 도구 통합.
- **LitmusChaos** — CNCF graduated; Kubernetes 워크플로 기반.
- **Chaos Mesh** — CNCF sandbox; Kubernetes 네이티브 CRD 스타일.
- **Gremlin** — 상업용; 광범위한 지원.
- **AWS FIS** / **Azure Chaos Studio** — 관리형 클라우드 제품.

### 작게 시작하기

첫 번째 실험: 정상 트래픽에서 하나의 디코드 레플리카를 팟 킬합니다. 라우팅 및 복구를 관찰합니다. 이것이 작동하고 안전해 보이면 네트워크 카오스로 graduation하세요.

첫 번째 LLM 특정 실험: 5분 동안 하나의 공급업체 429를 주입합니다. 장애 조치를 관찰합니다. 대부분의 팀이 장애 조치가 완전히 테스트되지 않았음을发现합니다.

### 기억해야 할 숫자

- 4개 평면: 제어, 대상, 안전, 관찰 가능성.
- 버너트 일시 중지: 예상 일일 예산 burn의 2배.
- 주기: 주간 카나리, 월간 게임 데이, 분기별 감사.
- 5가지 LLM 실험: 메모리, 네트워크, 공급업체, 변형된 프롬프트, KV 폭풍.
