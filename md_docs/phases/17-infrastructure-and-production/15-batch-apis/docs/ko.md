# 배치 API — 업계 표준인 50% 할인

> 모든 주요 공급업체는 50% 할인 및 ~24시간 턴어라운드로 비동기 배치 API를 shipping합니다. OpenAI, Anthropic, Google, 대부분의 추론 플랫폼 (Fireworks 배치 계층, Together 배치)이 동일한 패턴을 구현합니다. 배치와 프롬프트 캐싱을 스택하면 야간 파이프라인이 동기-uncached 비용의 ~10%로 떨어집니다. 규칙은 무자비하게 단순합니다: 대화형이 아니면 배치에 속합니다. 콘텐츠 생성 파이프라인, 문서 분류, 데이터 추출, 보고서 생성, 대량 레이블링, 카탈로그 태깅 — 24시간 지연 시간에宽容任何 것은 배치로 이동할 때까지桌上的 돈입니다. 2026년 프로덕션 패턴은 모든 새로운 LLM 작업을 세 차선으로 분류합니다: 대화형 (캐싱으로 동기식), 준대화형 (동기 폴백이 있는 비동기 큐), 배치 (야간, 스택된 캐시된 입력). 상호작용인 척하지만 수 분의 지연 시간을 容認하는 작업은大部分을浪费합니다.

**유형:** 학습
**언어:** Python (stdlib, toy batch-vs-sync 비용 시뮬레이터)
**선수 과목:** Phase 17 · 14 (Prompt & Semantic Caching)
**소요 시간:** ~45분

## 학습 목표

- 세 가지 공급업체 배치 API (OpenAI, Anthropic, Google)와 공통 50% 할인 + 24시간 턴어라운드 보증을 이름 짓습니다.
- 야간 분류 작업에서 배치 + 캐시된 입력의 스택 비용을 계산하고 동기-uncached 기준선과 비교합니다.
- 작업을 대화형 / 준대화형 / 배치로 분류하고 차선을 정당화합니다.
- 두 가지 함정: 부분 대화형 (사용자가 24h보다 빠리를期望) 및 출력 스키마 드리프트 (배치 파일 형식이 공급업체마다 다름).

## 문제

팀이 야간 보고서 생성 파이프라인을 shipping합니다. 50,000개 문서, 각각을 요약하고, 요약을 클러스터링하고, 경영진 브리프를起草합니다. 동기식으로 실행하면 4시간이 걸리고 밤에 $2,000입니다. 배치 API에 대해 들었습니다.

배치가 50% 할인을 제공합니다. 시스템 프롬프트 (모든 50k 호출에서 공유)에서 프롬프트 캐싱도 활성화합니다. 스택하면 청구서가 $180/밤으로 떨어집니다 — 기준선의 ~9%. 같은 파이프라인, 세 가지 구성 변경.

배치는 LLM 비용 도구 키트에서 아무도pull하지 않는 가장 저렴한 레버입니다. 이유는 주로 조직적입니다: 팀은 "실시간"으로 생각하지만 SLA는 실제로 "아침까지"입니다. 이 레슨은 청구서의 90%를桌子上에 두지 않는 것에 관한 것입니다.

## 개념

### 세 가지 배치 API

**OpenAI Batch API**: 요청 목록이 있는 JSONL 파일 업로드. 24시간 턴어라운드 보장 (일반적으로 실제로는 ~2-8시간). 입력 및 출력 토큰 50% 할인. `/v1/batches` 엔드포인트. 캐시 가능한 입력도 캐시된 입력 가격을 받습니다.

**Anthropic Message Batches**: JSONL 업로드. 24시간 턴어라운드. 50% 할인. `cache_control` 지원 — 캐시 쓰기가 명시적이며 읽기는 배치 내에서 자동으로 발생합니다.

**Google Vertex AI Batch Prediction**: BigQuery 또는 GCS 입력. Gemini에 대해 유사한 50% 할인. Vertex 파이프라인과 통합됩니다.

### 의미론: 비동기, 느리지 않음

배치는 "24시간 이내에 반환할 것을 약속합니다" — "24시간 걸릴 것입니다"가 아닙니다. 일반적인 P50은 2-6시간입니다. 공급업체는 GPU 재고가 활용되지 않을 때 오프피크 창 중에 배치 일정을 정합니다.

### 캐싱과 스택

동일한 4K 토큰 시스템 프롬프트가 있는 50k-문서 요약:

- 동기 비캐시: 50000 × ($input × 4000 + $output × 200) 전액.
- 동기 캐시: 시스템 프롬프트가 첫 번째 쓰기 후 캐시됩니다; 나머지 49999는 10배 저렴한 입력을 얻습니다.
- 배치 캐시: 위의 모두 plus 읽기 및 쓰기 모두 50% 할인.

스택: 배치 + 캐시 = 동기 비캐시 청구서의 ~10%. 야간에 실행되고 공유 시스템 프롬프트가 있는 모든 작업은 이것을 사용해야 합니다.

### 작업 삼파리

**대화형** — 사용자가 응답을 기다립니다. TTFT가 중요합니다. 프롬프트 캐싱으로 동기식 호출. 배치할 수 없습니다.

**준대화형** — 사용자가 작업을 제출하고 몇 분 후에 다시 확인합니다. 배치 없으면 동기식으로 폴백하는 비동기 큐. 중간 볼륨 RAG 인덱싱을 생각하세요.

**배치** — 사용자가 "아침까지" 또는 "다음 시간까지" 결과를期望합니다. 대규모 콘텐츠 파이프라인, 분류, 오프라인 분석. 항상 배치, 항상 캐싱 스택.

일반적인 실수:一切를 대화형으로 분류하는 것, 파이프라인이 프로덕션이기 때문입니다. 프로덕션은 지연 시간 사양이 아닙니다 — SLA입니다.

### 부분 대화형 함정

일부 기능은 대화형으로 보이지만 5-10분을 容認합니다. 예: "새로고침" 버튼이 있는 야간 고객 상태 보고서. 사용자가 새로고침을 클릭합니다; 10분 대기 Fine. 팀이 동기식으로 shipping합니다. 50개의 동시 새로고침이 배치 후 이메일로 제공되는 것보다 10배 많은 비용이 듭니다.

물어볼 질문: "이 사용자에게 24시간이 무엇을 의미합니까?" 대답이 "그들은 그것을 notices 않을 것"이면 배치하세요.

### 출력 스키마 함정

배치 파일 형식이 공급업체마다 다릅니다:

- OpenAI: JSONL, 요청당 한 줄.
- Anthropic: JSONL, 메시지당 한 줄; 응답 형식이 임베디드.
- Vertex: BigQuery 테이블 또는 TFRecord가 있는 GCS 접두사.

공급업체 전반에 "하나의 배치 클라이언트"를 작성한다는 것은 공급업체당 어댑터 코드를 의미합니다. 멀티 공급업체 배치 (Portkey, LiteLLM 일부 계층)를 광고하는 게이트웨이도 여전히 Raw 형식의 얇은 래핑입니다.

### 기억해야 할 숫자

- 공급업체 전반의 배치 할인: 입력 + 출력에 대해 50% 평면.
- 턴어라운드 SLA: 24시간 보장, 2-6시간 전형적.
- 스택된 배치 + 캐시된 입력: 동기 비캐시 비용의 ~10%.
- 작업 삼파리 규칙: 24h 지연 시간이容認되면 항상 배치.

## 연습문제

1. `code/main.py`를 실행하세요. 3K 토큰 시스템 프롬프트와 500 토큰 출력이 있는 100k-문서 파이프라인의 경우 전체 스택 (배치 + 캐시)이 동기 기준선과 비교하여 얼마나 절약되는지 계산하세요.
2. 실제 제품에서 세 가지 기능을 선택하세요. 각각을 대화형/준/배치로 분류하세요.
3. 사용자가 보고서가 3시간 걸렸다고 불평합니다. 배치 잘못 분류였습니까, 합리적인 대화형이었습니까? 결정 기준을 작성하세요.
4. 배치 API 반환 SLA는 24h이지만 P99는 20시간입니다. 이를 사용자에게 어떻게 전달합니까 — 경계 사례에서 하류 시스템 동작은 무엇입니까?
5. 균형을 계산하세요: 어느 공유 접두사 길이에서 배치 + 캐시가 자체 예약 GPU에서 야간으로 실행하는 것보다 저렴해집니까?
