# MDP, 상태, 행동 및 보상

> 마르코프 결정 과정은 다섯 가지입니다: 상태, 행동, 전이, 보상, 할인. RL의 모든 것 — Q-learning, PPO, DPO, GRPO —은 이 형태에 대해 최적화합니다. 한 번 배우면 나머지 강화 학습을 무료로 읽을 수 있습니다.

**유형:** 학습
**언어:** Python
**선수 과목:** Phase 1 · 06 (Probability & Distributions), Phase 2 · 01 (ML Taxonomy)
**소요 시간:** ~45분

## 문제

체스 봇을 작성하고 있습니다. 또는 재고 플래너. 또는 트레이딩 에이전트. 또는 추론 모델을 훈련하는 PPO 루프. 네 가지 다른 도메인, 하나의 놀라운 사실: 네 가지 모두 동일한 수학적 개체로 압축됩니다.

지도 학습은 `(x, y)` 쌍을 제공하고 함수에 피팅하도록 요청합니다. 강화 학습은 레이블을 제공하지 않습니다 — 상태의 스트림, 당신이 취한 행동, 스칼라 보상만 있습니다. 그 움직이가 게임에서 이겼나요? 재고 보충 결정이 비용을 절약했나요? 거래가 이익을냈나요? LLM이 방금 생성한 토큰이 심사자からの更高的 보상으로 이어졌나요?

이 스트림에서 학습하려면 형식화해야 합니다. "내가 본 것", "내가 한 것", "다음에 무슨 일이 일어났는지", "얼마나 좋았는지" — 각각 추론할 수 있는 개체가 되어야 합니다. 그 형식화가 마르코프 결정 과정입니다. 마지막의 RLHF 및 GRPO 루프를 포함한 이 단계의 모든 RL 알고리즘은 이 형태에 대해 최적화합니다.

## 개념

![마르코프 결정 과정: 상태, 행동, 전이, 보상, 할인](../assets/mdp.svg)

**다섯 가지 객체.**

- **상태** `S`. 결정에 필요한 모든 것. GridWorld에서 셀. 체스에서 보드. LLM에서 컨텍스트 창 plus any memory.
- **행동** `A`. 선택지. 상하좌우 이동. 수 두기. 토큰 생성.
- **전이** `P(s' | s, a)`. 상태 `s`와 행동 `a`가 주어지면, 다음 상태에 대한 분포. 체스에서는 결정론적, 재고에서는 확률적, LLM 디코딩에서는 거의 결정론적.
- **보상** `R(s, a, s')`. 스칼라 신호. 승리 = +1, 패배 = -1. 수익 minus 비용. GRPO의 로그 우도 비율 항.
- **할인** `γ ∈ [0, 1)`. 현재 대비 미래 보상의 중요도. `γ = 0.99`는 ~100단계의 시야를 확보; `γ = 0.9`는 ~10.

**마르코프 속성** `P(s_{t+1} | s_t, a_t) = P(s_{t+1} | s_0, a_0, …, s_t, a_t)`. 미래는 현재 상태에만 의존합니다. 그렇지 않으면 상태 표현이 불완전합니다 — 방법의 실패가 아니라 상태의 실패입니다.

**정책과 수익.** 정책 `π(a | s)`는 상태를 행동 분포에 매핑합니다. 수익 `G_t = r_t + γ r_{t+1} + γ² r_{t+2} + …`는 미래 보상의 할인 합계입니다. 가치 `V^π(s) = E[G_t | s_t = s]`는 정책 `π` 하에서 `s`에서 시작하는 예상 수익입니다. Q-값 `Q^π(s, a) = E[G_t | s_t = s, a_t = a]`는 특정 행동으로 시작하는 예상 수익입니다. 모든 RL 알고리즘은 이 두 가지를 추정하고, 그에 따라 `π`를 개선합니다.

**벨만 방정식.** 이 단계의 모든 것이 사용하는 고정점 방정식:

`V^π(s) = Σ_a π(a|s) Σ_{s', r} P(s', r | s, a) [r + γ V^π(s')]`
`Q^π(s, a) = Σ_{s', r} P(s', r | s, a) [r + γ Σ_{a'} π(a'|s') Q^π(s', a')]`

이들은 예상 수익을 "이 단계의 보상" plus "도착处的 할인된 가치"로 분해합니다. 재귀적. 단계 9의 모든 알고리즘은 이 방정식을 수렴할 때까지 반복하거나(동적 프로그래밍), 이것에서 샘플링하거나(몬테 카를로), 또는 한 단계 부트스트랩합니다(시간 차분).

## 실습

### Step 1: 작은 결정론적 MDP

4×4 GridWorld. 에이전트가左上에서 시작, 右下에서 종착, 단계당 -1 보상, 행동 `{up, down, left, right}`. `code/main.py`를 참조하세요.

```python
GRID = 4
TERMINAL = (3, 3)
ACTIONS = {"up": (-1, 0), "down": (1, 0), "left": (0, -1), "right": (0, 1)}

def step(state, action):
    if state == TERMINAL:
        return state, 0.0, True
    dr, dc = ACTIONS[action]
    r, c = state
    nr = min(max(r + dr, 0), GRID - 1)
    nc = min(max(c + dc, 0), GRID - 1)
    return (nr, nc), -1.0, (nr, nc) == TERMINAL
```

5줄. 그것이 전체 환경입니다. 결정론적 전이, 일정한 단계 페널티, 흡수 종착 상태.

### Step 2: 정책 rollout

정책은 상태에서 행동 분포로의 함수입니다. 가장 간단한 것: 균일 무작위.

```python
def uniform_policy(state):
    return {a: 0.25 for a in ACTIONS}

def rollout(policy, max_steps=200):
    s, total, steps = (0, 0), 0.0, 0
    for _ in range(max_steps):
        a = sample(policy(s))
        s, r, done = step(s, a)
        total += r
        steps += 1
        if done:
            break
    return total, steps
```

무작위 정책을 1,000번 실행합니다. 평균 수익은 이 4×4 보드에서 약 -60에서 -80입니다. 최적 수익은 -6입니다(대각선으로 우하향 경로). 이 격차를 좁히는 것이 단계 9의 모든 것입니다.

### Step 3: 벨만 방정식을 통해 `V^π` 정확하게 계산

작은 MDP에 대해 벨만 방정식은 선형 시스템입니다. 상태를 열거하고, 기대치를 적용하고, 값이 변경될 때까지 반복합니다.

```python
def policy_evaluation(policy, gamma=0.99, tol=1e-6):
    V = {s: 0.0 for s in all_states()}
    while True:
        delta = 0.0
        for s in all_states():
            if s == TERMINAL:
                continue
            v = 0.0
            for a, pi_a in policy(s).items():
                s_next, r, _ = step(s, a)
                v += pi_a * (r + gamma * V[s_next])
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < tol:
            return V
```

이것이 반복적 정책 평가입니다. Sutton & Barto의 첫 번째 알고리즘이며, 뒤따르는 모든 RL 방법의 이론적 기초입니다.

### Step 4: `γ`는 물리적 의미가 있는 하이퍼파라미터

유효 시야는 대략 `1 / (1 - γ)`입니다. `γ = 0.9` → 10단계. `γ = 0.99` → 100단계. `γ = 0.999` → 1000단계.

너무 낮으면 에이전트가 단편적으로 행동합니다. 너무 높으면 조기 단계가 멀 미래 보상에 대한 책임을 공유하므로 크레딧 할당이 노이즈가 됩니다. LLM RLHF는 일반적으로 에피소드가 짧고 제한되어 있으므로 `γ = 1`을 사용합니다. 제어 작업은 `0.95–0.99`를 사용합니다. 장기 전략 게임은 `0.999`를 사용합니다.

## 함정

- **비가 마르코프 상태.** 마지막 세 관찰이 필요하면, "상태"는 현재 관찰 그 자체가 아닙니다. 수정: 프레임 스택(DQN on Atari는 4 스택) 또는 순환 상태 사용(관찰에 대한 LSTM/GRU).
- **희소 보상.** 큰 상태 공간에서 승리만 보상은 학습을 거의 불가능하게 합니다. 보상을 형태화(중간 신호)하거나 모방으로 부트스트랩(단계 9 · 09).
- **보상 해킹.** 프록시 보상을 최적화하면 병리학적 행동이 종종 발생합니다. OpenAI의 보트 경주 에이전트는 결승선을 finish하는 대신 영원히 전원을 수집하며 원을 돌았습니다. 항상 대상 결과에서가 아니라 프록시에서 보상을 정의하세요.
- **할인 명세 오류.** 무한 수평선 작업에서 `γ = 1`은 모든 값을 무한하게 만듭니다. 항상 유한한 수평선 또는 `γ < 1`으로 제한하세요.
- **보상 척도.** {+100, -100}의 보상은 {+1, -1}과 동일한 최적 정책을 제공하지만 기울기 크기가 전혀 다릅니다. PPO/DQN에 넣기 전에 `[-1, 1]` 정도 정규화하세요.

## 활용

2026년 스택은 코드를 건드리기 전에 모든 RL 파이프라인을 MDP로 축소합니다:

| 상황 | 상태 | 행동 | 보상 | γ |
|------|------|------|------|---|
| 제어 (운동, 조작) | 관절 각도 + 속도 | 연속 토크 | 작업별 형태화 | 0.99 |
| 게임 (체스, 바둑, 포커) | 보드 + 이력 | 합법적 수 | 승리=+1 / 패배=-1 | 1.0 (유한) |
| 재고 / 가격 책정 | 재고 + 수요 | 주문 수량 | 수익 - 비용 | 0.95 |
| LLM용 RLHF | 컨텍스트 토큰 | 다음 토큰 | 끝에서의 보상 모델 점수 | 1.0 (에피소드 ~200 토큰) |
| 추론용 GRPO | 프롬프트 + 부분 응답 | 다음 토큰 | 끝에서의 검증기 0/1 | 1.0 |

어떤 학습 루프보다 먼저 다섯 튜플을 작성하세요. 대부분의 "RL이 작동하지 않는다" 버그 보고서는 종이에서 망가진 MDP 공식화로 추적됩니다.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|----------|
| MDP | "강화 학습 설정" | 마르코프 속성을 만족하는 튜플 `(S, A, P, R, γ)`. |
| 상태 | "에이전트가 보는 것" | 선택된 정책 클래스에서 미래 역학에 대한 충분 통계. |
| 정책 | "에이전트의 행동" | 조건부 분포 `π(a \| s)` 또는 결정론적 맵 `s → a`. |
| 수익 | "총 보상" | 현재 단계からの 할인된 보상 합계 `Σ γ^t r_t`. |
| 가치 | "상태가 얼마나 좋은가" | `π` 하에서 `s`에서 시작하는 예상 수익. |
| Q-값 | "행동이 얼마나 좋은가" | `s`에서 첫 번째 행동 `a`로 시작하는 예상 수익. |
| 벨만 방정식 | "동적 프로그래밍 재귀" | 가치 / Q를 한 단계 보상 plus 할인된 후계자 가치로 분해하는 고정점 분해. |
| 할인 `γ` | "미래 대 현재" | 멀리 있는 미래 보상에 대한 기하학적 가중치; 유효 시야 `~1/(1-γ)`. |
