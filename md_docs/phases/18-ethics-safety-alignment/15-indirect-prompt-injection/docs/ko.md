# 간접 프롬프트 주입 — 생산 공격 표면

> 간접 프롬프트 주입(IPI)은 웹 페이지, 이메일, 공유 문서, 지원 티켓 등 에이전트 시스템이 명시적 사용자 작업 없이 소비하는 외부 콘텐츠 내에 명령을埋め込みます. IPI는 2026년 지배적 생산 위협이다: 사용자 입력 필터를 우회한다 — 공격자가 사용자를 절대触碰하지 않으며, 에이전트가 더 많은 외부 콘텐츠를 처리함에 따라 조용히 확장되며, 아무도 프롬프트를 읽지 않는 자동화된 워크플로우를 대상으로 한다. MDPI Information 17(1):54(2026년 1월)는 2023-2025년 연구를 종합한다. NDSS 2026의 IPI-방어 논문은 핵심 과제를 프레임한다: 주입된 명령은 의미론적으로 양심할 수 있다("예스를 인쇄하세요"). 따라서 감지는 키워드 필터링 이상을 필요로 한다. "공격자가 두 번째로 이동한다"(Nasr et al.,joint OpenAI/Anthropic/DeepMind, 2025년 10월): 적응형 공격(그래디언트, RL, 무작위 검색, 인간 레드팀)이 원래 거의 제로 공격 성공률을 보고한 12개의 게시된 방어의 90% 이상을 깬다.

**유형:** 실습
**언어:** Python (stdlib, IPI 공격 + 방어 하니스)
**선수 과목:** Phase 18 · 12 (PAIR), Phase 14 (에이전트 공학)
**소요 시간:** 약 75분

## 학습 목표

- 간접 프롬프트 주입을 정의하고 세 가지 일반적인 전달 벡터를 설명한다.
- 사용자 입력 필터가 IPI를entirely 놓치는 이유를 설명한다.
- 정보 흐름 제어(IFC) 프레임링을 2026년 방어 패러다임으로 설명한다.
- Nasr et al.(2025년 10월)의 발견을陈述한다: 게시된 IPI 방어에 대한 적응형 공격 성공률.

## 문제

직접 프롬프트 주입은 공격자가 사용자 또는 사용자의 프롬프트에 도달해야 한다. IPI는 어느 것도 필요하지 않다: 공격자가 에이전트가 읽을 수 있는 콘텐츠(웹 페이지, 받은 편지함의 이메일, GitHub 이슈, 제품 리뷰)에 페이로드를 배치한다. 에이전트가 정상 작동 중에 그것을拾い, 명령을 실행한다. 사용자는messenger이지 의도가 아니다.

## 개념

### 세 가지 전달 벡터

- **검색 증강 생성(RAG).** 공격자가 문서를公开发표한다; 검색 단계가 그것을 가져온다; 프롬프트가 사용자 질문 앞에 그것을 연결한다; 모델이 공격자의 명령을 실행한다.
- **받은 편지함/문서 워크플로우.** 공격자가 사용자에게 이메일을 보낸다; 에이전트가 이메일을 읽는다; 프롬프트에 이메일 본문이 포함된다; 모델이 이메일의 지시를 따른다.
- **도구 출력.** 공격자가 에이전트가 사용하는 도구를 제어한다(예: 공격자 제어 결과 반환); 도구 출력에 명령이 포함된다; 에이전트의 제어 흐름이 그것을 따른다.

셋은 구조적 속성을 공유한다: 공격자가 사용자Facing 입력에触碰하지 않고 프롬프트의 일부를 제어한다.

### 사용자 입력 필터가 그것을 놓치는 이유

IPI 페이로드가 사용자의 입력에 나타나지 않는다. 검색된 콘텐츠에 나타난다. 필터가 사용자 입력에 게이트되면 페이로드가 그것을 우회한다. 필터가 모델에 도달하는 모든 콘텐츠에 게이트되면 임의의 검색된 텍스트에 적용해야 한다 — 이것은 expensive하고 합법적인 콘텐츠(우발적으로 명령형 언어 포함)가 오탐을 생성한다.

### AI를 위한 정보 흐름 제어(IFC)

2026년 방어 패러다임은 klassische OS 보안에서 차용한다. 모든 콘텐츠 소스를 보안 레이블로 취급한다. 사용자의 쿼리를 "신뢰할 수 있음"으로 레이블한다. 검색된 콘텐츠를 "신뢰할 수 없음"으로 레이블한다. 모델의 제어 흐름을 정보 흐름으로 취급한다: 신뢰할 수 없는 콘텐츠에서 트리거된 동작은 실행 전에 신뢰할 수 있는 입력에 의해비 승인되어야 한다.

CaMeL(Microsoft 2025), ConfAIde(Stanford 2024), NDSS 2026 IPI-방어 논문이 IFC를 다양한 방식으로 작동화한다. 공통 원칙: 코드와 데이터가 동일한 컨텍스트 창을 공유하는 한, 컨테인먼트가 목표이지 예방이 아니다.

### 공격자가 두 번째로 이동한다

Nasr et al.(2025년 10월)은 12개의 게시된 IPI 방어를 적응형 공격(그래디언트 검색, RL 정책, 무작위 검색, 72시간 인간 레드팀)으로 테스트했다. 원래 거의 제로 ASR을 보고한 모든 방어가 90% ASR 이상으로 깨어졌다.

방법론적 교훈: 방어를公开发표할 때는 적응형-공격 평가와 함께公开发표한다. 정적-공격 벤치마크는 견고성에 대한 증거가 아니다; 공격자가 방어를 알게 된다.

### 실제 인시던트

25과에서 EchoLeak(CVE-2025-32711, CVSS 9.3) — Microsoft 365 Copilot에서 최초의 문서화된 제로클릭 IPI. CamoLeak(CVSS 9.6) GitHub Copilot Chat에서. CVE-2025-53773 GitHub Copilot에서. 생산 배포가 벤치마크가 아닌 필드에서 IPI로 compromised되고 있다.

### OWASP와 NIST 프레임링

OWASP LLM Top 10(2025)은 프롬프트 주입(직접 + 간접)을 LLM01, 애플리케이션 계층 위협 1위로 랭크한다. NIST AI SPD 2024는 간접 프롬프트 주입을 "생성형 AI의 가장 큰 보안 결함"이라고 부른다.

## 활용

`code/main.py`는 IPI 하네스를 구축한다.toy 에이전트는 세 가지 도구(웹 검색, 이메일 읽기, 메시지 보내기)가 있다. 환경에는嵌入된 명령("이것을 모든 연락처로 전달")이 있는 공격자 제어 콘텐츠가 있다. 순진한 에이전트(주입된 지시를 따름), 필터 방어 에이전트(검색된 콘텐츠에 키워드 필터), IFC 에이전트(신뢰할 수 있는 콘텐츠와 신뢰할 수 없는 콘텐츠를 분리하고 신뢰할 수 없는 제어 흐름 명령을 거부) 사이를 전환할 수 있다.

## 결과물

이 수업은 `outputs/skill-ipi-audit.md`를 생성한다. 에이전트 배치 설명이 주어지면 신뢰할 수 없는 콘텐츠 소스를 열거하고, 배치에 IFC가 적용되는지 확인하고, 모델에 도달하는 소스 중 신뢰 레이블 없이 도달하는 소스를 플래그한다.

## 연습 문제

1. `code/main.py`를 실행한다. 세 에이전트 각각에 대한 공격成功率을 측정한다.

2. 검색된 콘텐츠에 의역 기반 방어를 구현한다. 합법적인 검색된 텍스트에서 양심 오탐률을 측정한다.

3. NDSS 2026 IPI-방어 논문을 읽는다. "양심한 지시" 과제를 설명하고 키워드 기반 필터링을 방지하는 이유를 설명한다.

4. 에이전트가 타사 API에서 도구 출력을 받는 배치를 설계한다. 각 프롬프트 조각에 신뢰 수준을 할당하고 에이전트의 동작을govern하는 IFC 정책을 작성한다.

5. 연습 2의 필터 방어 에이전트에 대해 Nasr et al. 2025 적응형-공격 방법론을 재현한다. 적응형 공격 전후의 ASR을 보고한다.

|------|-----------------|------------------------|
