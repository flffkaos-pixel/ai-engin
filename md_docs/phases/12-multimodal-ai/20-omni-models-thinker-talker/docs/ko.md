# 옴니 모델: Qwen2.5-Omni와 Thinker-Talker 분할

> 2024년 5월 GPT-4o의 제품 데모는 기본 모델 때문이 아니라 제품 형태 때문에 파괴적이었습니다 — 당신이 말하고, 모델이 카메라가 보는 것을 보며, 250ms 이내에 응답하는 음성 인터페이스. 오픈 생태계는 2024년과 2025년의 나머지 기간 동안 그 제품 표면에 도달하기 위해 경쟁했습니다. Qwen2.5-Omni(2025년 3월)는 참조 오픈 설계입니다: Thinker(대형 텍스트 생성 트랜스포머) + Talker(병렬 음성 생성 트랜스포머), 스트리밍 음성 토큰으로 연결. Mini-Omni는 단순화했고, Moshi는 지연 시간을 맞췄으며, GLM-4-Voice는 중국어로 확장했습니다. 이 레슨은 Thinker-Talker 아키텍처와 스트리밍 실시간 대화를 가능하게 하는 지연 시간 예산을 읽습니다.

**Type:** Build
**Languages:** Python (stdlib, streaming pipeline latency simulator + VAD loop)
**Prerequisites:** Phase 12 · 19 (audio-LLMs), Phase 12 · 16 (any-to-any)
**Time:** ~180 minutes

## 학습 목표

- 추론 파이프라인을 Thinker(텍스트 추론)와 Talker(음성 합성)로 분할하고 병렬 스트리밍이 작동하는 이유를 설명한다.
- 대화형 상호작용에 대한 첫-오디오-바이트-까지-시간(TTFAB) 예산을 구성 요소별로 계산한다.
- Thinker 내에서 비전, 오디오, 텍스트에 걸친 TMRoPE의 시간-정렬 위치 인코딩을 설명한다.
- 세 가지 실시간 대화 패턴을 나열한다: 반이중, 턴테이킹, 전이중.

## 문제

실시간 음성 어시스턴트는 빠르게 많은 일을 해야 합니다:

1. 사용자 듣기. 실시간 음성 토큰화, 음성 활동 감지(VAD)로 사용자가 말을 마쳤을 때 인식.
2. 선택적으로 보기. 2-4 FPS의 카메라 입력, 오디오와 함께 Thinker로 스트리밍.
3. 생각하기. 대화 기록을 조건으로 응답 구성.
4. 말하기. 오디오 토큰 합성, 파형으로 디코딩, 사용자 스피커로 스트리밍.

각 단계는 지연 시간을 추가합니다. 대화형 감각은 총 왕복 < 500ms를 요구합니다 — 그 이하에서 사용자는 지연을 인지하지 못합니다. GPT-4o는 ~250ms를 주장. Moshi ~160ms. Qwen2.5-Omni ~350-500ms.

모든 구성 요소는 스트리밍해야 합니다. "모든 것을 배치한 다음 디코딩"은 안 됩니다.

## 개념

### Thinker와 Talker

Qwen2.5-Omni의 분해:

- Thinker: 7B-80B 텍스트 생성 트랜스포머. 인터리브된 텍스트 + 이미지 + 오디오 토큰 소비. 무엇을 말할지 나타내는 텍스트 토큰 출력.
- Talker: 더 작은 음성 생성 트랜스포머(200M-1B). Thinker의 텍스트 출력 토큰 + 최근 음성-컨텍스트 토큰 소비. 이산 음성 토큰(residual-VQ 인덱스) 출력.
- 음성 디코더: 음성 토큰을 실시간 오디오 샘플로 변환하는 스트리밍 파형 디코더(SNAC, MoVQGAN 계열).

분리가 중요합니다. Thinker는 좋은 추론을 위해 커야 합니다. Talker는 작업이 지역적이기 때문에 작을 수 있습니다 — 텍스트를 음성 토큰으로 변환. 더 큰 Talker가 더 표현력이 있는 것은 아닙니다; 더 느릴 뿐입니다.

둘을 병렬로 실행:

1. Thinker가 텍스트 토큰 t_i 방출.
2. Talker가 t_i 소비(스트리밍을 통해)하고 음성 토큰 s_i, s_{i+1}, ..., s_{i+k} 방출.
3. 음성 디코더가 음성 토큰이 도착할 때 소비하고 오디오 샘플 방출.
4. Thinker가 텍스트 토큰 t_{i+3}에 있을 때, Talker는 이미 t_0..t_{i+2}에 대한 오디오를 스트리밍한 상태.

### TMRoPE — 시간-정렬 멀티모달 위치

Thinker는 이미지 프레임(예: 4 FPS로 도착), 오디오 프레임(50프레임/초로 도착), 대화 기록의 텍스트를 통합해야 합니다. 순진한 시퀀스 순서(모든 이미지, 그 다음 모든 오디오, 그 다음 텍스트)는 시간적 정렬을 잃습니다.

TMRoPE는 모든 토큰에 절대 타임스탬프를 할당합니다. t=2.3s의 비전 토큰. t=2.32s의 오디오 토큰. 사용자의 "멈춰" 텍스트 토큰이 t=2.35s. RoPE는 타임스탬프로 어텐션을 회전; 모델은 이를 시간적으로 동시적인 것으로 봅니다.

이것은 "인사하면서 손을 흔들다"가 작동하기 위한 인프라입니다 — 모델이 동일한 개념적 순간에 비디오 프레임과 오디오를 봅니다.

### 스트리밍 음성 합성

음성 토큰은 스트리밍되어야 합니다. Mini-Omni(Xie & Wu, 2024)는 "언어 모델이 듣고, 스트리밍 중에 생각하면서 말할 수 있음"을 도입했습니다: Thinker 출력 토큰과 Talker 출력 토큰이 동일한 시퀀스에서 인터리브. Talker는 Thinker가 다음 텍스트 토큰을 확정하는 즉시 실행됩니다. 배치 경계가 없습니다.

Moshi(Défossez et al., 2024년 10월)는 가장 빠른 오픈 구현입니다. 단일 A100에서 160ms TTFAB. 아키텍처: 교대 위치에서 텍스트와 음성 토큰을 방출하는 단일 7B 트랜스포머, 사고 스트림과 말하기 스트림을 분리하는 "내적 독백" 포함. 이것은 사실상 Thinker + Talker가 신중한 학습으로 하나의 모델에 융합된 것입니다.

### VAD 및 턴테이킹

음성 활동 감지는 입력 측에서 실행됩니다. 두 가지 패턴:

- 반이중: 사용자가 말하고, 모델이 듣습니다. 모델이 말하고, 사용자가 듣습니다. VAD 침묵 감지를 통한 명확한 핸드오프(~200ms).
- 전이중: 둘이 동시에 말할 수 있습니다. 모델이 뒷말("어-허")을 하거나 방해할 수 있습니다. 훨씬 어렵습니다. Moshi가 이를 지원합니다.

Qwen2.5-Omni는 기본적으로 반이중을 지원하며, 침묵 임계값을 통한 턴테이킹을 제공합니다. 전이중은 애플리케이션-계층 처리가 필요합니다.

### Qwen3-Omni (2025년 11월)

후속 모델. Qwen3-80B Thinker, 더 큰 Talker, 개선된 TMRoPE-v2. GPT-4o의 250ms에 가까운 지연 시간. 오픈 가중치. OmniBench 벤치마크에서 Gemini 2.0 Live와 경쟁력 있음.

### 프로덕션 지연 시간 예산

일반적인 스트리밍 상호작용의 경우:

- 마이크 -> 오디오 토큰: 40-80ms.
- 프리필(프롬프트 + 기록): 7B에서 100-200ms, 70B에서 훨씬 더.
- 첫 Thinker 텍스트 토큰: 40ms.
- Talker가 첫 텍스트 토큰 처리: 20ms.
- 첫 음성 토큰 확정: 40ms.
- Residual-VQ 디코드: 30ms.
- 음성 파형 디코드: 50-80ms.

총 TTFAB: 7B에서 320-510ms, 70B에서 600-900ms. 최첨단 품질은 보통 70B+를 의미; 따라서 최첨단 지연 시간 격차.

### 토큰-속도 수학

50Hz 기본 음성 토큰의 16kHz 음성에서, 출력 초당 50개의 음성 토큰이 필요합니다. Talker는 따라잡기 위해 ≥50 tok/s를 방출해야 합니다. H100에서 30-80 tok/s의 일반적인 LLM 처리량에서, 작은(200-300M) Talker는 충분히 빠릅니다; 7B Talker는 뒤쳐집니다.

이것이 "그냥 메인 모델을 사용"하는 대신 전용 소형 Talker 모델이 존재하는 이유입니다.

## 사용하기

`code/main.py`:

- 모의 토큰-방출 속도로 Thinker-Talker 파이프라인 시뮬레이션.
- 구성 가능한 모델 크기 및 마이크 샘플 속도에 대한 TTFAB 계산.
- VAD 침묵 임계값으로 반이중 턴테이킹 데모.

## 결과물

이 레슨은 `outputs/skill-omni-streaming-budget.md`를 생성합니다. 실시간 음성 제품의 목표 TTFAB 및 기능 세트(비전 입력, 이중 언어, 전이중)가 주어지면, Qwen2.5-Omni, Qwen3-Omni, Moshi 또는 Mini-Omni를 선택하고 Thinker/Talker를 크기 조정합니다.

## 연습 문제

1. 목표 TTFAB는 300ms입니다. 7B Thinker와 300M Talker에서 각 구성 요소의 지연 시간을 작성하세요.

2. Qwen2.5-Omni는 TMRoPE를 사용합니다. 사용자가 t=1s에 말하기 시작하고 카메라가 t=1.2s에 제스처를 포착하는 프롬프트에 대해 모델이 보는 것을 설명하세요.

3. 전이중 지원은 모델이 듣는 동안 오디오를 방출해야 합니다. 이를 가르치는 학습 데이터 형식을 제안하세요.

4. Moshi의 논문 섹션 4를 읽으세요. "내적 독백" 분리를 설명하고 Thinker-Talker 분할을 피하는 이유를 설명하세요.

5. 처리량 예산을 계산하세요: 50 기본-레이어 토큰/초에서 16kHz 음성을 따라잡기 위해 Talker가 토큰을 얼마나 빨리 방출해야 하나요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|----------|
| Thinker | "추론 두뇌" | 무엇을 말할지 생성하는 대형 텍스트 생성 트랜스포머 |
| Talker | "음성 생성 입" | Thinker의 텍스트에서 이산 음성 토큰을 생성하는 소형 트랜스포머 |
| TTFAB | "지연 시간 예산" | 첫-오디오-바이트-까지-시간: 사용자 음성 종료부터 첫 오디오 샘플 출력까지 |
| TMRoPE | "시간-정렬 RoPE" | 비전, 오디오, 텍스트 전반에 걸친 절대 타임스탬프를 사용한 위치 인코딩 |
| Half-duplex | "턴테이킹" | 사용자와 모델이 번갈아 가며; VAD 침묵이 사용자-완료 감지 |
| Full-duplex | "동시" | 모델이 동시에 말하고 들을 수 있음; 뒷말 가능 |
| Inner monologue | "Moshi 분리" | 사고-스트림과 말하기-스트림이 인터리브되는 단일-모델 설계 |
