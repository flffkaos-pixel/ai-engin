# 문서 및 다이어그램 이해

> 문서는 사진이 아닙니다. PDF, 과학 논문, 송장, 필기 양식에는 일반 이미지 이해가 포착할 수 없는 레이아웃, 표, 다이어그램, 각주, 헤더 및 의미 구조가 있습니다. VLM 이전 스택은 파이프라인이었습니다: Tesseract OCR + LayoutLMv3 + 표-추출 휴리스틱. VLM 물결은 이를 OCR-없는 모델 — Donut(2022), Nougat(2023), DocLLM(2023) — 로 대체했으며, 이들은 구조화된 마크업을 직접 출력합니다. 2026년까지 최첨단은 "2576px 네이티브로 Claude Opus 4.7에 페이지 이미지를 그냥 제공"하는 것이며, 구조화된-마크업 출력은 무료로 제공됩니다. 이 레슨은 문서 AI의 세 시대 아크를 읽습니다.

**Type:** Build
**Languages:** Python (stdlib, layout-aware document parser skeleton)
**Prerequisites:** Phase 12 · 05 (LLaVA), Phase 5 (NLP)
**Time:** ~180 minutes

## 학습 목표

- 문서 AI의 세 시대를 설명한다: OCR 파이프라인, OCR-없음, VLM-네이티브.
- LayoutLMv3의 세 가지 입력 스트림을 설명한다: 텍스트, 레이아웃(bbox), 이미지 패치, 통합 마스킹 포함.
- Donut(OCR-없음, 이미지 → 마크업), Nougat(과학 논문 → LaTeX), DocLLM(레이아웃-인지 생성형), PaliGemma 2(VLM-네이티브)를 비교한다.
- 새로운 작업(송장, 과학 논문, 필기 양식, 중국어 영수증)에 대한 문서 모델을 선택한다.

## 문제

"이 PDF를 이해하라"는 속임수처럼 어렵습니다. 정보는 다음에 위치합니다:

- 텍스트 내용(신호의 90%).
- 레이아웃(헤더, 각주, 사이드바, 2단 형식).
- 표(행, 열, 병합된 셀).
- 그림 및 다이어그램.
- 필기 주석.
- 글꼴 및 타이포그래피(제목 vs 본문).

원시 OCR은 텍스트만 추출하고 나머지는 잃습니다. 송장에 신경 쓰는 시스템은 "합계: $1,245"가 각주가 아닌 오른쪽 아래에서 왔다는 것을 알아야 합니다.

## 개념

### 시대 1 — OCR 파이프라인 (2021년 이전)

고전적 스택:

1. PDF → 페이지당 이미지.
2. Tesseract(또는 상용 OCR)가 단어당 경계 상자와 함께 텍스트 추출.
3. 레이아웃 분석기가 블록(헤더, 표, 문단) 식별.
4. 표 구조 인식기가 표 파싱.
5. 도메인 규칙 + 정규식이 필드 추출.

깨끗한 인쇄 텍스트에 작동. 필기, 기울어진 스캔, 복잡한 표, 비영어 스크립트에서 실패. 모든 실패 모드는 사용자 정의 예외 경로 필요.

### TrOCR (2021)

TrOCR(Li et al., arXiv:2109.10282)는 Tesseract의 고전적 CNN-CTC를 합성 + 실제 텍스트 이미지로 학습된 트랜스포머 인코더-디코더로 대체. 필기 및 다국어 텍스트에서 깔끔한 승리. 여전히 파이프라인(감지기 다음 TrOCR 다음 레이아웃)이지만, OCR 단계가 극적으로 개선.

### 시대 2 — OCR-없음 (2022-2023)

최초의 OCR-없는 모델은 말했습니다: 감지를 완전히 건너뛰고, 이미지 픽셀을 구조화된 출력에 직접 매핑.

Donut(Kim et al., arXiv:2111.15664):
- 인코더-디코더 트랜스포머, 인코더는 Swin-B.
- 출력은 양식 이해용 JSON, 요약용 마크다운 또는 작업별 스키마.
- OCR 없음, 레이아웃 없음, 감지 없음.

Nougat(Blecher et al., arXiv:2308.13418):
- 과학 논문에 특화 학습.
- 출력은 LaTeX / 마크다운.
- 방정식, 다중-단 레이아웃, 그림 처리.
- 모든 arXiv-파서가 호출하는 모델.

이들은 전문가이며 일반주의자가 아닙니다. 과학 논문에서 Donut은 실패; 송장에서 Nougat은 실패.

### LayoutLMv3 (2022)

다른 트랙. LayoutLMv3(Huang et al., arXiv:2204.08387)는 OCR을 유지하지만 레이아웃 이해를 추가:

- 세 가지 입력 스트림: OCR 텍스트 토큰, 토큰당 2D 경계 상자, 이미지 패치.
- 세 가지 모달리티 모두에 걸친 마스크된 학습 목적 함수(마스크된 텍스트, 마스크된 패치, 마스크된 레이아웃).
- 다운스트림: 분류, 엔터티 추출, 표 QA.

LayoutLMv3는 OCR-기반 문서 이해의 정점. 양식 및 송장에 강력. OCR 업스트림 필요. 표준화된 문서 벤치마크에서 VLM 이전 최고 정확도.

### DocLLM (2023)

DocLLM(Wang et al., arXiv:2401.00908)은 LayoutLM의 생성형 형제. 레이아웃 토큰을 조건으로 자유 형식 답변 생성. 문서에 대한 QA에 더 좋음; 여전히 OCR 입력에 의존.

### 시대 3 — VLM-네이티브 (2024+)

2024년 VLM은 파이프라인을 완전히 대체할 만큼 충분히 좋아졌습니다. 고해상도 전체 페이지 이미지를 VLM에 제공하고, 질문하고, 답변을 얻습니다.

- LLaVA-NeXT 336-tile AnyRes는 작은 문서에 작동.
- Qwen2.5-VL 동적-해상도는 2048+ 픽셀을 네이티브로 처리.
- Claude Opus 4.7은 2576px 문서 지원.
- PaliGemma 2(2025년 4월)는 특히 문서 + 필기용으로 학습.

VLM-네이티브와 OCR-파이프라인 간의 격차는 빠르게 좁혀졌습니다. 2026년까지 VLM-네이티브는 다음에서 승리:

- 현장 텍스트(필기 + 인쇄, 혼합 스크립트).
- 병합된 셀이 있는 복잡한 표.
- 텍스트에 포함된 수학 방정식.
- 텍스트 주석이 있는 그림.

OCR 파이프라인은 여전히 다음에서 승리:

- 페이지당 지연 시간이 중요한 대규모 순수-스캔 워크로드.
- 파이프라인 신뢰성(확정적 실패 vs VLM 환각).
- 감사 가능한 OCR 출력이 필요한 규제 환경.

### Claude 4.7 / GPT-5 최첨단

2576-픽셀 네이티브 입력에서, 최첨단 VLM은 문서 이해를 인간에 가까운 정확도로 수행. 2026년 초 벤치마크 수치:

- DocVQA: Claude 4.7 ~95.1, PaliGemma 2 ~88.4, Nougat ~77.3, 파이프라인 LayoutLMv3 ~83.
- ChartQA: Claude 4.7 ~92.2, GPT-4V ~78.
- VisualMRC: Claude 4.7 ~94.

폐쇄형 모델 격차는 주로 해상도와 기본-LLM 규모. 7B의 오픈 모델은 몇 포인트 뒤쳐지지만 따라잡고 있음.

### 수학 방정식 및 LaTeX 출력

과학 논문은 방정식에 대한 정확한 LaTeX 출력이 필요. Nougat은 이에 대해 학습. LaTeX 대상으로 학습된 VLM(Qwen2.5-VL-Math, Nougat 파생)은 사용 가능한 LaTeX를 생성. 명시적 LaTeX 학습 없이 VLM은 읽을 수 있지만 부정확한 전사를 생성.

2026년 과학-논문 파이프라인의 경우: PDF에 Nougat을 체인으로 연결한 다음, 까다로운 페이지에 VLM.

### 필기

여전히 가장 어려운 하위 작업. 혼합 인쇄 + 필기(의사 노트, 작성된 양식)는 OCR 파이프라인이 비용 측면에서 여전히 VLM을 능가하는 분야. 필기 전용 VLM은 개선 중(Claude 4.7, PaliGemma 2).

### 2026년 레시피

새로운 문서-AI 프로젝트의 경우:

- 대규모 순수-인쇄 송장: LayoutLMv3 + 규칙, 비용 효율적.
- 혼합 문서(과학 + 필기 + 양식): VLM-네이티브(PaliGemma 2 또는 Qwen2.5-VL).
- 전체 arXiv 수집: 수학용 Nougat, 그림용 VLM.
- 규제: 교차-확인용 OCR 파이프라인 + VLM 검증기.

## 사용하기

`code/main.py`:

- 장난감 레이아웃-인지 토크나이저: (텍스트, bbox) 쌍이 주어지면 LayoutLMv3-스타일 입력 생성.
- Donut-스타일 작업 스키마 생성기: 양식용 JSON 템플릿.
- OCR-파이프라인, Donut, Nougat, VLM-네이티브 간 페이지당 토큰 예산 비교.

## 결과물

이 레슨은 `outputs/skill-document-ai-stack-picker.md`를 생성합니다. 문서-AI 프로젝트(도메인, 규모, 품질, 규제)가 주어지면, OCR 파이프라인, OCR-없음 전문가, VLM-네이티브 중에서 선택.

## 연습 문제

1. 귀하의 프로젝트는 하루 1000만 장의 송장입니다. 정확도를 잃지 않고 페이지당 비용을 최소화하는 스택은 무엇인가요?

2. LayoutLMv3가 양식 QA에서 순수-CLIP-VLM을 능가하지만 현장-텍스트에서 성능이 낮은 이유는 무엇인가요? bbox 스트림이 무엇을 포기하나요?

3. Nougat은 LaTeX를 생성합니다. VLM-네이티브 출력이 LaTeX 충실도에서 Nougat을 능가하는 테스트 케이스와 Nougat이 승리하는 케이스를 제안하세요.

4. PaliGemma 2 논문(Google, 2024)을 읽으세요. PaliGemma 1 대비 문서 정확도를 높인 핵심 학습-데이터 추가는 무엇인가요?

5. 규제-안전 하이브리드를 설계하세요: 기본 OCR 파이프라인, 보조 VLM 교차-확인. 불일치를 어떻게 해결하나요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|----------|
| OCR pipeline | "Tesseract 스타일" | 단계별 스택: 감지 -> OCR -> 레이아웃 -> 규칙; 결정적, 깨지기 쉬움 |
| OCR-free | "Donut 스타일" | 명시적 OCR을 건너뛰는 이미지-출력 트랜스포머; 단일 모델 |
| Layout-aware | "LayoutLM" | 입력에 토큰당 bbox 좌표 포함; 모달리티 간 통합 마스킹 |
| VLM-native | "최첨단 VLM" | 페이지 이미지를 Claude/GPT/Qwen VLM에 고해상도로 직접 제공; 파이프라인 없음 |
| DocVQA | "문서 벤치" | 문서 VQA 표준; 가장 많이 인용되는 점수 |
| Markup output | "LaTeX / MD" | 자유 형식 텍스트 대신 구조화된 출력 형식; 다운스트림 자동화 가능 |
