# Chameleon과 초기 융합 토큰 전용 멀티모달 모델

> 지금까지 본 모든 VLM은 이미지와 텍스트를 별도로 유지한다. 시각 토큰은 비전 인코더에서 나오고, 투영기로 흐르고, 그 다음 LLM 내부에서 텍스트와 만난다. 비전과 텍스트 어휘가 겹치지 않는다. Chameleon(Meta, 2024년 5월)은 질문했다: 만약 그것이 그렇다면? 이미지를 공유 어휘의 이산 토큰 시퀀스로 변환하는 VQ-VAE를 훈련한다. 이제 모든 멀티모달 문서는 하나의 시퀀스다 — 인터리브된 텍스트 토큰과 이미지 토큰, 단일 자기 회귀 손실. 부작용: 모델은 혼합 모달 출력 생성이 가능하다 — 단일 추론 호출에서 대체되는 텍스트와 이미지 토큰. 이 레슨은 초기 융합 논의를 읽고 토이 버전을 종단간 구축한다.

**유형:** 실습
**언어:** Python (stdlib, VQ-VAE 토크나이저 + 인터리브드 디코더)
**선수 과목:** Phase 12 · 05, Phase 8 (생성형 AI)
**소요 시간:** ~180분

## 학습 목표

- 공유 어휘 + 단일 손실이 모델이 할 수 있는 것을 어떻게 변경하는지 설명한다.
- VQ-VAE가 이미지를 트랜스포머의 다음 토큰 목표와 호환되는 이산 시퀀스로 토큰화하는 방법을 설명한다.
- Chameleon의 훈련 안정성 트릭 назвать: QK-Norm, 드롭아웃 배치, LayerNorm 순서.
- Chameleon 대 BLIP-2의 Q-Former 접근법을 비교하고 각각이 올바른 선택인 경우를 설명한다.

## 문제

어댑터 기반 VLM(LLaVA, BLIP-2, Qwen-VL)은 텍스트와 이미지를 두 가지 다른 것으로 취급한다. 텍스트 토큰은 `embed(text_token)`을 통과; 이미지는 `visual_encoder(image) → projector → ... pseudo_tokens`를 통과. 모델은 중간에서 병합되는 두 입력 경로를 가진다.

세 가지 결과:

1. LLM은 이미지를 소비할 수만 있고 방출할 수는 없다. 출력은 텍스트만.
2. 혼합 모달 문서(문단의 이미지 교대, 기사와 같이)는 어색하다 — 모델 외부에서 멀티모달 입력을 파싱하거나 생성을 체인으로 연결해야 한다.
3. 배포 불일치. 시각 토큰과 텍스트 토큰이 히든 공간의 다른 영역에 있어 미세한 정렬 문제를 만든다.

Chameleon은 전제를 거부한다: 이미지는 공유 어휘의 이산 토큰 시퀀스일 뿐이다. 인터리브드 문서에서 하나의 손실, 하나의 자기 회귀 디코더로 모델을 훈련하면 혼합 모달 생성을 무료로 언럭한다.

## 개념

### VQ-VAE를 이미지 토크나이저로

토크나이저는 벡터 양자화 변이 자동 인코더다. 아키텍처:

- 인코더: 이미지를 공간 피처 맵으로 매핑하는 CNN + ViT, 말하여 32x32 피처의 차원 256.
- 코드북: K개의 학습된 벡터 어휘(Chameleon은 8192 사용), 역시 차원 256.
- 양자화: 각 공간 피처에 대해 L2 거리로 가장 가까운 코드북 항목을 조회한다. 연속 피처를 정수 인덱스로 교체.
- 디코더: 양자화된 피처를 픽셀로 되돌리는 CNN.

훈련: VAE 재구성 손실 + 커밋먼트 손실 + 코드북 손실. 코드북 인덱스는 이미지의 이산 알파벳을 형성한다.

Chameleon의 경우: 하나의 이미지가 8192 어휘에서drawn된 32*32 = 1024 토큰이 된다. 텍스트 토큰(LLM의 BPE 어휘, 말하여 32000)과 연결. 최종 어휘: 40192. 트랜스포머는 하나의 시퀀스, 하나의 손실을 본다.

### 공유 어휘

Chameleon의 어휘는 텍스트 토큰, 이미지 토큰, 모달리티 구분자를 결합한다. 각 토큰은 단일 ID를 가진다. 입력 임베딩 레이어는 모든 ID를 D차원 히든 벡터로 매핑한다. 출력 투영은 히든에서 어휘 로짓으로 매핑한다. Softmax가 다음 토큰을 선택한다, 모달리티에 관계없이.

구분자가 중요하다: `<image>`와 `</image>` 태그가 이미지-토큰 시퀀스를 감싼다. 생성 시 모델이 `<image>`를 방출하면, 하류 소프트웨어는 다음 1024 토큰이 픽셀 렌더링을 위해 디코더로 보내지는 VQ 인덱스임을 안다.

### 혼합 모달 생성

추론은 공유 어휘에서 다음 토큰 예측이다. 예시 프롬프트: "Draw a cat and describe it." Chameleon이 방출:

```
<image> 4821 1029 2891 ... (1024 image tokens) </image>
The cat is orange, sitting on a windowsill...
```

모델은 자율적으로 순서를 선택한다 — 이미지 먼저, 텍스트 먼저, 또는 인터리브. 동일한 디코더, 동일한 손실.

어댑터 VLM이 텍스트만 생성하는 것과 대비. Chameleon은 모델 출력 모달리티의 질문을 다시 열어둔다.

### 훈련 안정성 — QK-Norm, 드롭아웃, LayerNorm 순서

초기 융합 훈련은 규모에서 불안정하다. Chameleon의 논문은 세 가지 트릭을 문서화했다:

- QK-Norm. 도트 곱 전 어텐션 내의 쿼리 및 키 투영에 LayerNorm을 적용한다. 깊이에서 로짓 크기 폭발을 방지한다. 2024년 이후 여러 대형 모델에서 사용.
- 드롭아웃 배치. 어텐션과 MLP 후가 아니라 모든 잔차 추가 후에 드롭아웃. 이미지 토큰의 그래디언트가 지배할 수 있을 때 더 많은 정규화가 필요하다.
- LayerNorm 순서. 잔차 분기에서 Pre-LN(표준), 마지막 블록의 스킵 연결에 추가 LN. 최종 레이어 그래디언트 흐름을 안정화.

이러한 트릭 없이는 34B-파라미터 Chameleon 훈련이 여러 체크포인트에서 발산했다. 그것들로 수렴한다. 훈련 레시피는 아키텍처만큼 기여다.

### 토크나이저의 재구성 천장

VQ-VAE는 손실이 있다. 8192 코드북 항목과 512x512 이미지의 토큰당 1024에서 재구성 PSNR은 약 26-28 dB에서 캡된다. 이는 인식을 위한 이미지 생성이 가능하지만 연속 공간 확산(Stable Diffusion 3는 32+ dB 달성)보다 분명히 더 나쁘다.

토크나이저가 병목이다. 더 나은 토크나이저(MAGVIT-v2, IBQ, SBER-MoVQGAN)가 천장을 높인다. Emu3(레슨 12.12)는 더 나은 토크나이저만으로 SDXL 품질 생성을 달성한다.

### Chameleon 대 BLIP-2 / LLaVA

Chameleon(초기 융합, 공유 어휘):
- 하나의 손실, 하나의 디코더.
- 혼합 모달 출력을 생성.
- 토크나이저가 품질 천장.
- 비싸다: 추론 경로에서 생성된 이미지당 VQ-VAE 디코더.

BLIP-2 / LLaVA(후기 융합, 별도 타워):
- 비전 입력, 텍스트 출력만.
- 사전훈련된 LLM을 재사용.
- 이해를 위한 토크나이저 병목 없음.
- 싸다: 단일 정방향 통과.

태스크별로 선택. 이미지 생성이 필요하면 Chameleon 패밀리. 이해만 필요하면 어댑터-VLM이 더 단순하고 더 많은 사전훈련 컴퓨트를 재사용한다.

### Fuyu와 AnyGPT

Fuyu(Adept, 2023)는 관련된 접근법이다: 완전히 별도의 비전 인코더를 건너뛰고 원시 이미지 패치를 LLM의 입력 투영에 토큰처럼 공급, 토크나이저 없음. Chameleon보다 더 단순하지만 공유 어휘 출력 생성을 잃는다.

AnyGPT(Zhan 등, 2024)는 네 가지 모달리티로 Chameleon을 확장한다: 텍스트, 이미지, 음성, 음악. 각에 대해 동일한 VQ-VAE 트릭, 공유 트랜스포머. Any-to-any 생성. 레슨 12.16에서 더 많이 다룸.

## 활용

`code/main.py`는 토이 종단간 초기 융합 모델을 구축한다:

- 8x8 패치를 코드북 인덱스(K=16)로 매핑하는 작은 VQ-VAE 스타일 양자화기.
- (텍스트 ID 0..31) + (이미지 ID 32..47) + (구분자 48, 49)의 공유 어휘.
- 합성 캡션 + 이미지-토큰 시퀀스에서 훈련된 토이 자기 회귀 디코더(바이그램 테이블).
- 프롬프트가 주어지면 대체 텍스트 + 이미지 토큰을 방출하는 샘플링 루프.

코드는 신호 흐름을 종단간 추적할 수 있도록 트랜스포머를 의도적으로 작게 유지한다(바이그램).

## 결과물

이 레슨은 `outputs/skill-tokenizer-vs-adapter-picker.md`를 생성한다. 제품 사양(이해만 vs 이해 + 생성, 필요한 이미지 품질, 비용 예산)이 주어지면 Chameleon 패밀리(초기 융합)와 LLaVA 패밀리(후기 융합) 사이에서 선택하고 정량적 경험칙으로正当화한다.

## 연습 문제

1. Chameleon은 512x512 이미지당 K=8192 코드북 항목과 1024 토큰을 사용한다. 24비트 RGB 이미지와 비교한 압축 비율을 추정한다. 손실이 있는가? 얼마나 손실이 있는가?

2. 동일한 VQ-VAE 밀도에서 4K 이미지(3840x2160)는 몇 개의 이미지 토큰을 생성하는가? Chameleon 스타일 모델이 단일 추론 호출에서 4K 이미지를 생성할 수 있는가? 무엇이 먼저 부서지는가 — 컨텍스트, 토크나이저 품질, KV 캐시?

3. 순수 Python에서 QK-Norm을 구현한다. 64차원 쿼리와 키가 주어지면 LayerNorm 전후의 도트 곱을 보여준다. 왜 깊이에서 크기 제어가 중요한가?

4. QK-Norm 없이 34B에서 관찰한 정확한 실패 모드를 설명하기 위해 Chameleon 섹션 2.3(훈련 안정성)을 읽는다. "노름 폭발" 서명은 무엇이었는가?

5. 텍스트 전용 프롬프트가 주어지면 혼합 모달 응답을 방출하도록 토이 디코더를 확장한다. 훈련 데이터 분포 60% 텍스트 우선 / 40% 이미지 우선 given에서 모델이 이미지 우선 대 텍스트 우선을 선택하는 빈도를 측정한다.

| 용어 |人们在说什么 | 실제 의미 |
|------|-----------------|------------------------|
| 초기 융합 | "통합 토큰" | 이미지가 첫 번째 단계부터 트랜스포머의 어휘를 공유하는 이산 토큰으로 변환됨 |
| VQ-VAE | "이미지 토크나이저" | 이미지를 트랜스포머가 예측할 수 있는 정수 인덱스로 매핑하는 CNN + ViT + 코드북 |
| 공유 어휘 | "하나의 사전" | 텍스트 + 이미지 + 모달리티 구분자를 덮는 단일 토큰 ID 공간 |
| QK-Norm | "어텐션 안정자" | 도트 곱 전 쿼리와 키에 적용되는 LayerNorm, 노름 폭발을 방지 |
| 혼합 모달 생성 | "텍스트 + 이미지 출력" | 단일 패스에서 인터리브드 텍스트와 이미지 토큰을 자율적으로 생산하는 추론 |
| 코드북 크기 | "K 항목" | VQ-VAE가 양자화할 수 있는 이산 벡터의 수; 압축과 충실도의 트레이드오프 |
| 토크나이저 천장 | "재구성 한계" | VQ 토큰 디코딩으로 달성 가능한 최고 PSNR; 모델의 이미지 품질 경계 |
