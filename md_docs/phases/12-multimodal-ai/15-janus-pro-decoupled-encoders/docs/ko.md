# Janus-Pro: 통합 멀티모달 모델을 위한 분리된 인코더

> 통합 멀티모달 모델에는 피할 수 없는 긴장이 있습니다. 이해는 의미 특징을 원합니다 — SigLIP 또는 DINOv2 출력 벡터는 개념 수준 정보로 가득합니다. 생성은 재구성 친화적인 코드를 원합니다 — 선명한 픽셀로 다시 구성되는 VQ 토큰. 두 목표는 단일 인코더에서 호환되지 않습니다. Janus(DeepSeek, 2024년 10월)와 Janus-Pro(DeepSeek, 2025년 1월)는 해결책은 시도를 멈추는 것이라고 주장합니다: 두 인코더를 분리하세요. 작업 간에 트랜스포머 본체는 공유하되, 이해는 SigLIP을 통해, 생성은 VQ 토크나이저를 통해 라우팅하세요. 7B에서 Janus-Pro는 GenEval에서 DALL-E 3를 능가하고 MMMU에서 LLaVA와 일치합니다. 이 레슨은 두 인코더가 하나가 실패하는 곳에서 왜 작동하는지 읽습니다.

**Type:** Build
**Languages:** Python (stdlib, dual-encoder routing + shared-body signal)
**Prerequisites:** Phase 12 · 13 (Transfusion), Phase 12 · 14 (Show-o)
**Time:** ~120 minutes

## 학습 목표

- 단일 공유 인코더가 이해 또는 생성 품질을 왜 저하시키는지 설명한다.
- Janus-Pro의 라우팅을 설명한다: 이해를 위한 입력 측의 SigLIP 특징, 생성을 위한 입력 및 출력의 VQ 토큰.
- Janus-Pro가 Janus가 성공하지 못한 곳에서 성공하게 만든 데이터-믹스 스케일링을 추적한다.
- 분리형(Janus-Pro), 결합-연속형(Transfusion), 결합-이산형(Show-o) 아키텍처를 비교한다.

## 문제

통합 모델은 이해와 생성 전반에 걸쳐 트랜스포머 본체를 공유합니다. 이전 시도(Chameleon, Show-o, Transfusion)는 모두 두 방향에 대해 하나의 시각적 토크나이저를 사용합니다. 토크나이저는 절충안입니다:

- 재구성(생성)에 최적화됨: VQ-VAE는 미세한 픽셀 세부 정보를 포착하지만 의미적 응집력이 약한 토큰을 생성합니다.
- 의미(이해)에 최적화됨: SigLIP 임베딩은 "고양이" 이미지를 "고양이" 토큰 근처에 그룹화하지만 좋은 재구성을 허용하지 않습니다.

Show-o와 Transfusion은 한 방향에서 눈에 띄는 품질 비용을 지불합니다. Janus-Pro가 묻습니다: 작업이 다른 요구 사항을 가질 때 왜 하나의 토크나이저를 요구하는가?

## 개념

### 분리된 시각적 인코딩

Janus-Pro의 아키텍처는 두 인코더를 분리합니다:

- 이해 경로. 입력 이미지 → SigLIP-SO400m → 2층 MLP → 트랜스포머 본체.
- 생성 경로. 입력 이미지(기존 이미지를 조건으로 하는 경우) → VQ 토크나이저 → 토큰 ID → 트랜스포머 본체.
- 출력 생성. 트랜스포머가 예측한 이미지 토큰 → VQ 디코더 → 픽셀.

트랜스포머 본체는 공유됩니다. 본체의 업스트림과 다운스트림은 모두 작업별입니다.

입력은 프롬프트 형식으로 구분됩니다: `<understand>` 태그는 SigLIP을 통해 라우팅되고, `<generate>`는 VQ를 통해 라우팅됩니다. 또는 라우팅이 작업에서 암시적입니다.

### 이것이 작동하는 이유

이해 손실은 CLIP-스타일 사전 학습이 의미적 유사성에 맞게 조정한 SigLIP 특징을 얻습니다. 입력 특징이 작업에 더 좋기 때문에 모델의 인식 벤치마크가 Show-o / Transfusion보다 향상됩니다.

생성 손실은 토크나이저가 재구성에 맞게 조정한 VQ 토큰을 얻습니다. VQ 코드가 픽셀로 깔끔하게 다시 구성되기 때문에 이미지 품질이 Show-o보다 향상됩니다.

공유 트랜스포머 본체는 두 가지 입력 분포(SigLIP 및 VQ)를 보고 둘 다 작업하는 법을 학습합니다. 주장: 충분한 데이터 + 충분한 매개변수가 있으면 본체가 전환을 흡수합니다.

### 데이터 스케일링 — Janus vs Janus-Pro

Janus(원본, arXiv 2410.13848)는 분리를 도입했지만 작은 규모(1.3B 매개변수, 제한된 데이터)였습니다. Janus-Pro(arXiv 2501.17811)는 확장했습니다:

- 7B 매개변수 (vs 1.3B).
- 1단계(정렬)를 위해 7200만에서 9000만 이미지-텍스트 쌍.
- 2단계(통합)를 위해 2600만에서 7200만.
- 3단계를 위해 20만 이미지-생성 명령어 샘플 추가.

결과: Janus-Pro-7B는 MMMU에서 LLaVA와 일치하고(60.3 vs ~58), GenEval에서 DALL-E 3를 능가합니다(0.80 vs 0.67). 하나의 공개 모델, 통합 스펙트럼의 양측에서 경쟁력 있음.

### JanusFlow — 교정된 플로우 변형

JanusFlow(arXiv 2411.07975)는 VQ 생성 경로를 교정된-플로우 생성 경로(연속)로 교체합니다. 분할은 SigLIP-이해 + 교정된-플로우-생성이 됩니다. 품질 한계가 더 높아집니다. 아키텍처는 분리된-인코더-공유-본체로 유지됩니다.

### 공유 본체의 역할

트랜스포머 본체는 통합 시퀀스를 처리하지만 두 가지 입력 분포를 가집니다. 그 역할은:

- 이해를 위해: SigLIP 특징 + 텍스트 토큰 소비 → 텍스트를 자기회귀적으로 출력.
- 생성을 위해: 텍스트 토큰 + (선택적 이미지 VQ 토큰) 소비 → 이미지 VQ 토큰을 자기회귀적으로 출력.

본체는 블록별 모달리티별 가중치를 가지지 않습니다. Qwen이나 Llama 내부에서 찾을 수 있는 텍스트-스타일 트랜스포머에 두 개의 입력 어댑터가 추가된 것입니다.

흥미롭게도, 이는 Janus-Pro의 본체가 사전 학습된 LLM에서 초기화될 수 있음을 의미합니다. Janus-Pro는 실제로 DeepSeek-MoE-7B에서 초기화됩니다. 이 선택이 중요합니다: LLM은 처음부터 학습한 통합 모델이 도달하기 어려운 추론 능력을 제공합니다.

### InternVL-U와의 비교

InternVL-U(레슨 12.10)는 2026년 후속 작업입니다. 다음을 결합합니다:

- 네이티브 멀티모달 사전 학습(InternVL3 백본).
- 분리된-인코더 라우팅(SigLIP 입력, VQ + 확산 헤드 출력).
- 통합 이해 + 생성 + 편집.

InternVL-U는 Janus-Pro의 아키텍처 선택을 더 큰 프레임워크에 포함시킵니다. 분리된-인코더 아이디어는 이제 대규모 통합 모델의 기본값입니다.

### 한계

분리된 인코더는 아키텍처 복잡성을 추가합니다. 학습할 두 개의 토크나이저, 유지할 두 개의 입력 경로, 두 세트의 실패 모드. 생성을 필요로 하지 않는 제품의 경우 Janus-Pro는 과도하게 설계되었습니다 — LLaVA 계열 이해 모델을 선택하세요.

이해를 필요로 하지 않는 제품의 경우 Janus-Pro는 과잉 자격입니다 — Stable Diffusion 3 / Flux 모델을 선택하세요.

둘 다 필요한 제품의 경우 Janus-Pro는 현재 참조 개방형 아키텍처입니다.

## 사용하기

`code/main.py`는 Janus-Pro 라우팅을 시뮬레이션합니다:

- 두 개의 모의 인코더: SigLIP-유사(256차원 의미 벡터 생성) 및 VQ-유사(정수 코드 생성).
- 작업 태그를 기반으로 인코더를 선택하는 프롬프트 라우터.
- 어떤 인코더가 생성했든 관계없이 토큰 시퀀스를 처리하는 공유 본체(대용).
- 1단계(정렬)에서 3단계(명령어 튜닝)로의 가중치 샘플 스케줄 전환.

이미지 QA, T2I, 이미지 편집의 3가지 예제에 대한 라우팅 경로를 출력합니다.

## 결과물

이 레슨은 `outputs/skill-decoupled-encoder-picker.md`를 생성합니다. 최첨단 수준의 품질로 통합 생성 + 이해를 원하는 제품이 주어지면, 구체적인 데이터-규모 권장 사항과 함께 Janus-Pro, JanusFlow 또는 InternVL-U를 선택합니다.

## 연습 문제

1. Janus-Pro-7B는 GenEval에서 DALL-E 3를 능가합니다. 7B 오픈 모델이 생성에서는 최첨단 독점 모델과 일치하지만 이해에서는 그렇지 않은 이유를 설명하세요.

2. 라우터 함수를 구현하세요: 프롬프트 텍스트가 주어지면 `understand` 또는 `generate`로 분류하세요. "설명한 다음 스케치하세요"와 같은 모호한 프롬프트는 어떻게 처리하나요?

3. JanusFlow는 VQ 경로를 교정된 플로우로 대체합니다. 트랜스포머 본체가 이제 무엇을 출력하고, 손실에서 무엇이 변경되나요?

4. Janus-Pro 아키텍처가 하나 더 분리된 인코더로 처리할 수 있는 네 번째 작업을 제안하세요. 예: 이미지 분할(DINO-스타일), 깊이(MiDaS-스타일).

5. Janus-Pro 섹션 4.2(데이터 스케일링)를 읽으세요. Janus 대비 T2I 품질 향상에 가장 기여하는 데이터 단계는 무엇인가요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|----------|
| Decoupled encoding | "두 개의 시각적 인코더" | 방향별로 분리된 토크나이저 또는 인코더: 이해를 위한 의미적, 생성을 위한 재구성 |
| Shared body | "하나의 트랜스포머" | 단일 트랜스포머가 각 인코더의 출력을 처리; 모달리티별 가중치 없음 |
| SigLIP for understanding | "의미 특징" | 풍부한 개념적 특징을 제공하지만 재구성이 좋지 않은 CLIP 계열 비전 타워 |
| VQ for generation | "재구성 코드" | 픽셀로 깔끔하게 디코딩되는 벡터 양자화된 토큰 |
| JanusFlow | "교정된-플로우 변형" | VQ 대신 연속 플로우 매칭 생성 헤드를 가진 Janus-Pro |
| Routing tag | "작업 태그" | 입력 인코더를 선택하는 프롬프트 마커(`<understand>` / `<generate>`) |
