# 임의 해상도 비전: Patch-n'-Pack과 NaFlex

> 실제 이미지는 224x224 정사각형이 아니다. 영수증은 9:16, 차트는 16:9, 의료 스캔은 4096x4096, 모바일 스크린샷은 9:19.5일 수 있다. 2024년 이전 VLM 답변 — 모든 것을 고정 정사각형으로 리사이즈 —는 OCR, 문서 이해, 고해상도 장면 파싱을 작동하게 만드는 신호를 버렸다. NaViT(Google, 2023)는 블록 대각선 마스킹으로 가변 해상도 패치를 단일 트랜스포머 배치에 패킹할 수 있음을 보여주었다. Qwen2-VL의 M-RoPE(2024)는 절대 위치 테이블을 완전히 버렸다. LLaVA-NeXT의 AnyRes는 고해상도 이미지를 기본 + 하위 이미지로 타이링했다. SigLIP 2의 NaFlex 변형(2025)은 이제 모든 종횡비에 단일 체크포인트로服務하려는 오픈 VLM의 기본 인코더다. 이 레슨은 patch-n'-pack을 종단간 구현한다.

**유형:** 실습
**언어:** Python (stdlib, 패치 패커 + 블록 대각선 마스크)
**선수 과목:** Phase 12 · 01 (ViT 패치), Phase 12 · 05 (LLaVA)
**소요 시간:** ~120분

## 학습 목표

- 가변 해상도 이미지의 배치에서 패치를 하나의 시퀀스로 패킹하고 블록 대각선 어텐션 마스크를 구축한다.
- 주어진 태스크에 대해 AnyRes 타이링(LLaVA-NeXT), NaFlex(SigLIP 2), M-RoPE(Qwen2-VL) 중 선택한다.
- 리사이즈 없이 OCR, 차트, 사진의 토큰 예산을 계산한다.
- 정사각형 리사이즈의 세 가지 실패 모드 назвать: 눌린 텍스트, 잘린 콘텐츠, 패딩의 낭비된 토큰.

## 문제

트랜스포머는 시퀀스를 기대한다. 배치는 동일한 길이의 시퀀스 스택이다. 이미지가 224x224이면 매번 196개의 패치 토큰을 얻으며, 패딩이 필요하지 않고 완료. 224에서 훈련, 224에서 추론, 해상도에 대해 다시 생각할 필요 없음.

세상은 협력하지 않는다. 문서는 세로(8.5x11 인치, 2:3 정도). 차트 스크린샷은 가로(16:9). 영수증은 길고 얇다(1:3). 의료 이미지는 2048x2048 이상으로 제공된다. 모바일 장치 스크린샷은 1170x2532(0.46:1)다.

세 가지 2024년 이전 옵션과 각각이 실패하는 이유:

1. 고정 정사각형(224x224 또는 336x336)으로 리사이즈. 눌림이 텍스트와 얼굴을 왜곡한다. 다운스케일이 차트 레이블과 OCR 내용을 파괴한다. LLaVA-1.5까지 표준 관행.
2. 고정 종횡비로 크롭. 이미지의 대부분을 버리며, 크롭 위치 선택이 그 자체의 비전 문제다.
3. 가장 긴 변으로 패딩. 왜곡을修正하지만 세로 이미지에 패딩에 50%+ 토큰을 낭비한다. 모든 패드 토큰에 대한 2차 어텐션 비용.

2024-2025년 답변: 트랜스포머가 이미지의 네이티브 해상도에서 패치를 먹도록 하고, 낭비된 계산 없이 이종 배치를 하나의 시퀀스로 패킹하는 방법을 알아낸다.

## 개념

### NaViT와 patch-n'-pack

NaViT(Dehghani 등, 2023)는 이것이 규모에서 작동함을 보여준 논문이다. 아이디어는 기계적이다:

1. 배치의 각 이미지에 대해 선택한 패치 크기(말하여 14)에서 네이티브 패치 그리드를 계산한다.
2. 각 이미지의 패치를 자체 가변 길이 시퀀스로 펼친다.
3. 모든 이미지의 패치를 배치에 대해 하나의 긴 시퀀스로 연결한다.
4. 이미지 A의 패치가 이미지 A 내에서만 attend하도록 블록 대각선 어텐션 마스크를 구축한다.
5. 패치당 패치 위치 정보(2D RoPE 또는 분수 위치 임베딩)를携带한다.

336x336(576 토큰), 224x224(256 토큰), 448x336(768 토큰)의 세 이미지의 배치는 1600x1600 블록 대각선 마스크가 있는 1600토큰 시퀀스가 된다. 패딩 없음. 낭비된 계산 없음. 트랜스포머가 임의의 종횡비를 처리한다.

NaViT는 또한 훈련 중 분수 패치 드롭핑을 도입했다 — 배치에서 50%의 패치를 무작위로 드롭 — 이는 정규화하고 훈련을 가속화한다. SigLIP 2가 이것을 상속했다.

### AnyRes (LLaVA-NeXT)

LLaVA-NeXT의 AnyRes는 실용적인 대안이다. 고해상도 이미지와 고정 인코더(336의 CLIP 또는 SigLIP)가 주어지면:

1. 이미지의 종횡비에 가장 잘 맞는 미리 정의된 그리드 레이아웃 세트에서 선택 — (1x1), (1x2), (2x1), (1x3), (3x1), (2x2) 등.
2. 이미지를 그리드에 타이링; 각 타일이 336x336 크롭이 된다.
3. 또한 썸네일을 생성: 전체 이미지를 336x336으로 리사이즈한 것을 글로벌 컨텍스트 토큰으로.
4. 고정된 336-인코더를 통해 모든 타일을 인코딩. 타일 토큰 + 썸네일 토큰을 연결한다.

672x672 이미지의 경우 2x2 그리드 + 썸네일: 4 * 576 + 576 = 2880 시각 토큰. 비싸지만 효과적 — LLM은 로컬 디테일과 글로벌 컨텍스트를 모두 본다.

AnyRes는 인코더가 동결되고 하나의 해상도만 지원하는 경우 선택이다. 큰 이미지의 토큰 수를 폭발시킨다(4x4 그리드의 1344x1344 이미지는 9216 + 576 ≈ 9800 토큰으로, 8k LLM 컨텍스트의 대부분을 채운다).

### M-RoPE (Qwen2-VL)

Qwen2-VL은 멀티모달 Rotary Position Embedding을 도입했다. NaViT의 분수 위치나 AnyRes의 타일-썸네일이 아닌, 각 패치가 3D 위치(시간, 높이, 너비)를携带한다. 쿼리/키 회전이 임의의 H, W, 시간 길이를 처리한다.

M-RoPE는 재훈련 없이 네이티브 동적 해상도를 제공한다. 추론에서HxW 이미지를 공급하면, 패치 임베더가 H/14 x W/14 토큰을 생성하고, 각 토큰이 (t=0, r=row, c=col) 위치를 얻으며, RoPE가 올바른 주파수로 어텐션을 회전하고, 완료. Qwen2.5-VL과 Qwen3-VL이 이것을 계속한다. InternVL3의 V2PE는 모달리티당 가변 인코딩과 함께 동일한 아이디어다.

AnyRes와 달리, M-RoPE는 네이티브 해상도에서 O(H x W / P^2) 토큰이다 — 승법적 타일 오버헤드 없음. NaViT와 달리 단일 이미지를 예상한다. 해상도 간 배칭에는 여전히 patch-n'-pack이 필요하다.

### NaFlex (SigLIP 2)

NaFlex는 SigLIP 2 체크포인트의 네이티브-플렉스 모드다. 단일 모델이 추론에서 여러 시퀀스 길이(256, 729, 1024 토큰)를 제공한다. 내부적으로 훈련 중 NaViT 스타일 patch-n'-pack과 패치당 절대 분수 위치를 사용한다. 판매 포인트: 단일 체크포인트, 태스크 berdasarkan 추론에서 토큰 예산 선택.

시맨틱 태스크(분류, 검색)의 경우 256 토큰. OCR이나 차트 이해의 경우 1024 토큰. 재훈련 없음.

### 패킹 마스크

블록 대각선 마스크는 대부분의 구현이 헛딥는 곳이다. 길이 `n_i`와 이미지 `i=0..B-1`가 있는 이종 배치의 총 길이 `N_total`을 덮는 패킹된 시퀀스에 대해, shape `(N_total, N_total)`의 마스크 `M`은 두 인덱스가 모두 동일한 이미지의 블록에 속하면 1, 그렇지 않으면 0이다. 누적 길이 목록에서構築할 수 있다:

```
offsets = [0, n_0, n_0+n_1, ..., N_total]
M[i, j] = 1 iff there exists b where offsets[b] <= i < offsets[b+1] and offsets[b] <= j < offsets[b+1]
```

이것은 `torch.block_diag` 또는 명시적 gather으로 PyTorch에서 한 줄이다. FlashAttention의 가변 길이 경로(`cu_seqlens`)는 마스크를 완전히 건너뛰고 누적 길이 텐서를 직접 사용하여 시퀀스 내에서 attend한다 — 전형적인 배치에서 밀집 마스크보다 ~10x 빠르다.

### 토큰 예산

태스크별로 전략 선택:

- OCR / 문서: 1024-4096 토큰. SigLIP 2 NaFlex 1024, 또는 AnyRes 3x3 + 썸네일.
- 차트 및 UI: 384-448 네이티브에서 729-1024 토큰. Qwen2.5-VL 동적 해상도와 최대 픽셀 캡.
- 자연 사진: 256-576 토큰이면 충분. 다운스트림 LLM이 충분히 본다. 콘텐츠 밀도가 높은 곳에서 토큰 비용 지불.
- 비디오: 공간 풀링 후 프레임당 64-128 토큰, 2-8 FPS. 레슨 12.17이 이것을 다룬다.

2026년 프로덕션 규칙: 태스크당 per-task max-pixels 캡을 선택하고, 해당 캡까지 네이티브 종횡비로 인코딩하고, 배치를 패킹하고, 패딩을 건너뛴다. Qwen2.5-VL은 정확히 이 노브를 위해 `min_pixels`와 `max_pixels`를 제공한다.

## 활용

`code/main.py`는 정수 픽셀 좌표가 있는 이종 이미지 배치에 대한 patch-n'-pack을 구현한다:

- (H, W) 이미지 크기 목록을 취한다.
- 패치 크기 14에서 각 이미지의 패치 시퀀스 길이를 계산한다.
- 총 길이 `sum(n_i)`의 하나의 시퀀스로 패킹한다.
- 블록 대각선 어텐션 마스크를 구축한다(명확성을 위해 밀집).
- 패킹된 비용 대 정사각형 리사이즈와 AnyRes 타이링을 비교한다.
- 혼합 배치(영수증, 차트, 스크린샷, 사진)의 토큰 예산 테이블을 인쇄한다.

실행한다. 나오는 숫자가 모든 2026년 오픈 VLM이 patch-n'-pack을 사용하는 이유다.

## 결과물

이 레슨은 `outputs/skill-resolution-budget-planner.md`를 생성한다. 혼합 종횡비 워크로드(OCR, 차트, 사진, 비디오 프레임)와 총 토큰 예산이 주어지면 올바른 전략(NaFlex, AnyRes, M-RoPE, 또는 고정 정사각형)을 선택하고 per-request 구성을 emit한다. VLM 크기를 제품에 맞출 때 이 스킬을 사용한다 — 지연 시간 예산을 죽이는 묵묵한 10x 토큰 폭발을防止한다.

## 연습 문제

1. 영수증은 600x1500(1:2.5)이다. 패치 크기 14에서 네이티브 해상도 토큰은 몇 개인가? 336으로 정사각형 리사이즈 후에는 몇 개인가? 실제로 어떤 것이 OCR 정확도를 더 많이 잃는가?

2. 길이가 256, 576, 729, 1024인 네 이미지의 배치를 위해 블록 대각선 마스크를 구축한다. 어텐션 행렬이 2585x2585이고 정확히 `256^2 + 576^2 + 729^2 + 1024^2` 개의非ゼロ 항목이 있음을 확인한다.

3. 1792x896 이미지 at patch 14에서 비교: (a) 336으로 정사각형 리사이즈 후 인코딩, (b) AnyRes 2x1 + 썸네일, (c) 네이티브의 M-RoPE. 어떤 것이 토큰이 가장 적은가? 어떤 것이 대부분의 디테일을 보존하는가?

4. 분수 패치 드롭핑을 구현한다: 패킹된 시퀀스가 주어지면 均一하게 50% 토큰을 무작위로 드롭하고, 블록 대각선 마스크를 accordingly 업데이트한다. 마스크의 희소성 변경을 측정한다.

5. Qwen2-VL 논문(arXiv:2409.12191) 섹션 3.2를 읽는다. `min_pixels`와 `max_pixels`가 무엇을 제어하는지, 두 경계가 모두 중요한 이유를 두 문장으로 설명한다.
