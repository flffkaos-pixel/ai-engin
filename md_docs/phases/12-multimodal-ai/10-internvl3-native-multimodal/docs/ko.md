# InternVL3: 네이티브 멀티모달 사전훈련

> InternVL3 이전의 모든 오픈 VLM은 동일한 3단계 레시피를 따랐다: 수조 개의 텍스트 토큰에서 훈련된 텍스트 LLM을 가져와서 비전 인코더를 붙이고, 이어서 미세조정한다. 이것이 작동하지만 정렬 빚이 있다 — 텍스트 LLM은 순수 텍스트에 전체 사전훈련 예산을 사용했으며 시각 토큰을 기본적으로 이해하지 못한다. 사후에 비전을 추가하면 LLM은 텍스트를 잊지 않고 시각 입력을 텍스트 추론에 연결하는 방법을 다시 배워야 한다. InternVL3(Zhu 등, 2025년 4월)는 사후 접근법을 거부한다: 하나의 사전훈련 실행, 텍스트와 멀티모달이 첫 번째 단계부터 인터리브드. 결과는 78B 파라미터에서 MMMU-Pro에서 Gemini 2.5 Pro와 일치한다. 이 레슨은 네이티브 사전훈련의 사례와 그것을 만들 때 무엇이 변경되는지를 읽는다.

**유형:** 학습
**언어:** Python (stdlib, 훈련 코퍼스 믹서)
**선수 과목:** Phase 12 · 05, Phase 12 · 07 (레시피)
**소요 시간:** ~120분

## 학습 목표

- 사후 VLM 훈련이 정렬 빚을 누적하는 이유를 설명하고, 세 가지 측정 가능한 증상(격심한 망각, 답변 드리프트, 시각-텍스트 불일치)을 인용한다.
- InternVL3의 네이티브 사전훈련 코퍼스 혼합과 텍스트 : 인터리브드 : 캡션 비율이 중요한 이유를 설명한다.
- V2PE(가변 시각 위치 인코딩)를 Qwen2-VL의 M-RoPE와 비교한다.
- 시각 해상도 라우터(ViR)와 디커플드 비전-언어(DvD) 배포 최적화를 назвать.

## 문제

사후 VLM 훈련이 기본이다. LLaVA, BLIP-2, Qwen-VL, Idefics — 모두 이미 사전훈련된 LLM(Llama, Vicuna, Qwen, Mistral)을 가져와서 비전을 추가한다. 훈련 단계는 일반적으로 다음과 같다:

1. 동결 LLM + 동결 비전 인코더 + 훈련 가능 투영기, 임베딩 정렬을 위해 캡션 페어로 훈련.
2. LLM 동결 해제, 명령어 데이터에서 훈련(LLaVA-Instruct, ShareGPT4V).
3. 선택적 태스크별 미세조정.

정렬 빚의 세 가지 증상이 나타난다:

- 격심한 망각. 사후 VLM이 텍스트만 있는 스킬을 잊는다. GSM8K 점수가 5-10 포인트 감소. Hellaswag 점수가 감소. 순수 텍스트 에이전트가 퇴보.
- 답변 드리프트. 동일한 시각 질문의 작은 문구 변경이 다른 답변을 얻는다. 시각 인코더가 LLM의 자체 토큰보다 약한 바인딩으로 LLM에 연결된다.
- 시각-텍스트 불일치. VLM이 이미지를 올바르게 설명한 다음 자체 설명과 모순되는 질문에 답할 수 있다. 시각 토큰은 텍스트가 하는 것처럼 LLM의 내부 일관성 검사에 동일한 방식으로 참여하지 않는다.

이러한 증상은 잘 문서화되어 있다. MM1.5 섹션 4가 그것을 정량화한다. LLaVA-OneVision의 절제가 그것을暗示한다. 네이티브 사전훈련이 답변이다.

## 개념

### 네이티브 멀티모달 사전훈련

InternVL3는 첫 번째 단계부터 네이티브 멀티모달인 코퍼스에서 처음부터 훈련한다. 혼합:

- 40% 텍스트만 데이터(FineWeb, Proof-Pile-2 등)
- 35% 인터리브드 이미지-텍스트 데이터(OBELICS, MMC4 스타일)
- 20% 페어링된 이미지-캡션 데이터
- 5% 비디오-텍스트 데이터

시각 토큰, 텍스트 토큰, 교차 모드 상호작용이 첫 번째 그래디언트 단계에서 동일한 손실에 모두 참여한다. 정렬 사전훈련 없음, 투영기 동결 단계 없음, 복구할 격심한 망각 없음.

훈련은 기본 모델에 대해 단일 단계다. 명령어 튜닝이 뒤따르지만 기본 모델은 시각 토큰을 1단계 시민으로 이미 이해한다.

### V2PE (가변 시각 위치 인코딩)

Qwen2-VL은 고정 축 할당으로 M-RoPE를 사용한다. InternVL3는 V2PE를 도입한다: 위치 인코딩이 모달리티 유형(텍스트, 이미지, 비디오)마다 학습 가능한 스케일링으로 달라진다. 실제로:

- 텍스트 토큰은 1D 위치(텍스트 인덱스)를 얻는다.
- 이미지 패치는 2D 위치(행, 열)를 얻는다.
- 비디오 프레임은 3D 위치(시간, 행, 열)를 얻는다.

세 가지가 동일한 RoPE 주파수 기본을 공유하지만 밴드당 히든 딤 할당은 고정 분할이 아닌 학습된 파라미터다. 사전훈련 중 시간 대 공간 주파수 분해능을 교환할 자유.

V2PE의 절제 주장: 동일한 컴퓨트에서 M-RoPE보다 비디오 벤치마크에서 1-2 포인트. 혁명이 아니지만 더 깔끔하다.

### 시각 해상도 라우터 (ViR)

배포 최적화. 모든 이미지가 풀 해상도 인코딩이 필요한 것은 아니다. 낮은 디테일의 하나의 객체가 있는 사진은 1280px 네이티브에서 인코딩될 때 토큰을 낭비한다. ViR은 인코딩 전에 질문에 답하기 위해 필요한 최소 해상도를 예측하는 작은 분류기다.

라우팅에는 세 가지 계층이 있다: 저해상도(256 토큰), 중해상도(576), 고해상도(2048+). 프로덕션 트래픽의 쿼리 60%에서 低 또는 중이 충분하다. 순 효과: 동일한 품질에서 2-3x 처리량.

### 디커플드 비전-언어 배포 (DvD)

대형 VLM을 제공할 때 비전 인코더는 이미지당 한 번 실행되지만 LLM은 출력 토큰마다 자동 회귀적으로 실행된다. 두 구성 요소는 서로 다른 병목(비전 = 컨볼 + 어텐션의 GPU 메모리 대역폭; LLM = KV 캐시)을 가진다. DvD는它们을 별도의 GPU로 분할하고 그 사이를 스트리밍한다.

8B + 400M 인코더 모델의 경우 DvD는 배치 배포 대비 노드당 처리량을 roughly 두 배로 늘린다.

### 단일 단계 대 다중 단계 품질

InternVL3의 기본 벤치마크 주장: 78B 파라미터에서 MMMU-Pro의 Gemini 2.5 Pro와 일치. 38B에서 GPT-4o와 일치. 8B에서 오픈-8B 리더보드를 주도. 단일 단계 사전훈련 + 명령어 튜닝 레시피로 모두.

정렬 빚 가설은 측정 가능하다: InternVL3-8B는 단위 시각 벤치마크 이득당 Qwen2.5-VL-7B보다 적은 텍스트 벤치마크 포인트(MMLU, GSM8K)를 잃는다. 모델이 더 많은 범용이다 because 훈련이 두 조각이 아닌 한 조각이었기 때문이다.

### InternVL3.5와 InternVL-U

InternVL3.5(2025년 8월)는 레시피를 확장한다. 동일한 네이티브-사전훈련 접근법, 더 많은 데이터, 더 많은 파라미터. MMMU 개선은 점진적이다.

InternVL-U(2026)는 통일된 생성을 추가 — 동일한 백본 위에 MMDiT 헤드를 통한 이미지 출력. "U"는 "이해 + 생성"을 의미하며, Transfusion 스타일 통일 모델(레슨 12.13)을 추구한다. 동일한 네이티브-사전훈련 백본이 이해와 생성 헤드를 모두 지원한다.

### 네이티브 사전훈련의 트레이드오프

네이티브 사전훈련은 무료가 아니다:

- 컴퓨트. 처음부터 새 VLM을 훈련하는 것은 텍스트 LLM 훈련과 동일한 비용 — 수백만 GPU 시간. 사후 수정은 기존 LLM 가중치를 재사용하여 대부분의 비용을 절약한다.
- 데이터. 규모에서 인터리브드 이미지-텍스트 코퍼스는 드물다. OBELICS는 141M 문서; MMC4는 571M. 텍스트만 15T 토큰으로 제공된다. 멀티모달 사전훈련 데이터 부족은 어려운 제약이다.
- 기본 LLM 재사용. 네이티브 사전훈련은 나중에 새 LLM을 넣을 옵션을 포기한다. 사후는 투영기만 재훈련하여 Llama-3.1을 Llama-4로 교환할 수 있다.

InternVL3가 하는 베팅: 정렬 빚이 재사용 손실보다 나쁘다. 벤치마크가 주장을支持한다. 생산 비용 장벽이 미래 랩이 저렴하게 복제하는 것을 막는다. 사후 VLM은 대부분의 프로젝트에 더 저렴하기 때문에 계속 존재할 것이다.

## 활용

`code/main.py`는 훈련 코퍼스 믹서와 ViR 라우터 시뮬레이터다:

- 대상 코퍼스 혼합(%텍스트, %인터리브드, %캡션, %비디오)을 가져와서 모달리티당 예상 단계수를 계산한다.
- 쿼리 배치에서 ViR 라우팅을 시뮬레이션(분포: 50% 저디테일, 30% 중, 20% 고디테일)하고 평균 토큰 수를 보고한다.
- 인코더 대 LLM FLOP이 주어지면 DvD 처리량 추정을 보고한다.
- 파라미터, 컴퓨트, 데이터, 예상 정렬 빚 증상에서 사후 대 네이티브 사전훈련의 나란히을 인쇄한다.

## 결과물

이 레슨은 `outputs/skill-native-vs-posthoc-auditor.md`를 생성한다. 제안된 VLM 훈련 계획이 주어지면 네이티브 또는 사후 갈지审计하고, 정렬 빚 위험을 플래그하며, 코퍼스 혼합을 권장한다. 새 오픈 VLM 프로젝트의 크기를 조정하고 훈련 전략을 선택해야 할 때 사용한다.

## 연습 문제

1. InternVL3-8B(네이티브 사전훈련)와 LLaVA-OneVision-7B(사후)의 컴퓨트 델타를 추정한다. GPU 시간 비율? 격차를 설명하는 것은?

2. InternVL3는 40% 텍스트 / 35% 인터리브드 / 20% 캡션 / 5% 비디오를 보고한다. 대상 태스크가 비디오 무거우면 새로운 비율을 제안하고 기본 모델이 상당한 텍스트와 캡션 데이터가 여전히 필요한 이유를議論한다.

3. 망각에 대한 MM1.5 섹션 4를 읽는다. 사후 훈련이 가장 큰 회귀를 보인 정확한 벤치마크를 назвать. 회귀 비용은 얼마나 들었는가?

4. ViR은 트래픽의 60%를 저해상도 인코딩으로 라우팅한다. 어떤 종류의 쿼리가 잘못 라우팅되는가(고해상도가 필요할 때 저해상으로 보내는가)? 세 가지 라우터 실패 모드를 제안한다.

5. DvD는 비전과 LLM을 별도의 GPU로 분할한다. 어떤 트래픽 패턴에서 DvD가 도움이 되는 대신 처리량을 해치는가?

| 용어 |人们在说什么 | 실제 의미 |
|------|-----------------|------------------------|
| 네이티브 멀티모달 사전훈련 | "처음부터 함께" | 텍스트 + 이미지 + 비디오 토큰이 나중에 볼트온되지 않고 단계 1부터 손실에 참여 |
| 정렬 빚 | "사후 페널티" | 동결 LLM에 비전을 붙이는 것에서 오는 텍스트 스킬과 답변 일관성의 측정 가능한 회귀 |
| V2PE | "가변 시각 위치 인코딩" | 모달리티당 학습 가능한 위치 인코딩 할당; InternVL3의 M-RoPE 후속 |
| ViR | "해상도 라우터" | 인코딩 전에 쿼리당 필요한 최소 해상도를 선택하여 추론 토큰을 절약하는 작은 분류기 |
| DvD | "디커플드 배포" | 한 GPU에 비전 인코더, 다른 GPU에 LLM, 스트림 핸드오프; 대형 VLM의 처리량을 두 배로 증가 |
| InternVL-U | "통일된 이해 + 생성" | 네이티브-사전훈련 백본에 이미지 생성 헤드를 추가하는 2026년 후속 |
| 인터리브드 코퍼스 | "OBELICS / MMC4" | 자연스러운 읽기 순서로 텍스트와 이미지가 있는 문서; 네이티브 사전훈련의 원자재 |
