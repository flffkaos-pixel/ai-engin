# Emu3: 이미지 및 비디오 생성을 위한 다음 토큰 예측

> BAAI의 Emu3(Wang 등, 2024년 9월)는 확산 대 자기 회귀 논쟁을 끝냈어야 할 2024년 결과다. 텍스트 + VQ 이미지 토큰 + 3D VQ 비디오 토큰의 통합 어휘에서 다음 토큰 예측 목적만으로 훈련된 Llama 스타일 디코더 전용 트랜스포머가 이미지 생성에서 SDXL를 이기고 인식에서 LLaVA-1.6를 이긴다. CLIP 손실 없음. 확산 스케줄 없음. 분류기 자유 안내는 추론에서 품질에 사용되지만 핵심 훈련 목적은 선생력 기반 다음 토큰 예측이다. Nature에 발표. 이 레슨은 더 나은 토크나이저와 규모가 전부라는 Emu3 논지를 읽고 확산 접근법과 대비한다.

**유형:** 학습
**언어:** Python (stdlib, 3D 비디오 토크나이저 수학 + 자기 회귀 샘플러 스켈레톤)
**선수 과목:** Phase 12 · 11 (Chameleon)
**소요 시간:** ~120분

## 학습 목표

- 이미지 품질에 확산이 필요하다는 오랜 가정에도 불구하고 Emu3의 단일 손실 다음 토큰 목적지가 작동하는 이유를 설명한다.
- 3D 비디오 토크나이저를 설명한다: 시공간 VQ 코드북이 어떤 모습인지, 왜 패치가 시간을 가로지르는지.
- Emu3 대 Stable Diffusion XL를 (훈련 컴퓨트, 추론 비용, 품질 천장)에서 비교한다.
- 동일한 Emu3 모델이 수행하는 세 가지 역할을 назвать: Emu3-Gen(画像 생성), Emu3-Chat(인식), Emu3-Stage2(비디오 생성).

## 문제

2024년까지의 Conventional Wisdom: 이미지 생성에는 확산이 필요하다. 논리: 이산 이미지 토큰은 디테일을 재구성하기 위해 너무 많은 정보를 잃고, 자기 회귀 샘플링은 수천 개의 토큰에 걸쳐 오류를 누적한다. Stable Diffusion, DALL-E 3, Imagen, Midjourney 모두某种 형태의 확산을 사용한다. Chameleon(레슨 12.11)은 소규모에서 이것을 부분적으로 반증했지만 SDXL의 품질과 일치하지 않았다.

Emu3는 논쟁을 정면으로 공격했다. 주장: 더 나은 시각 토크나이저 + 충분한 규모 + 다음 토큰 손실 = 확산을 능가하는 이미지 생성을 동일한 인식도 하는 모델에서.

발표 당시 이 베팅은 논쟁의 여지가 있었다. 2년이 지난 지금, 오픈소스 통합 생성 패밀리(Emu3, Show-o, Janus-Pro, Transfusion)가 연구의 기본 경로다; 생산 프론티어 모델은 일부 변형을 사용하는 것으로 보인다.

## 개념

### Emu3 토크나이저

핵심 재료는 시각 토크나이저다. Emu3는 토큰당 8x8 해상도 감소로 IBQ 클래스 토크나이저(역병목 양자화기, SBER-MoVQGAN 패밀리)를 훈련한다. 512x512 이미지는 코드북 크기 32768에서 64x64 = 4096 토큰이 된다.

이것은 512x512당 K=8192에서 1024 토큰의 Chameleon보다 크지만 토큰당 더 저렴하다(더 작은 코드북 조회, 더 간단한 코덱). 핵심 지표: 재구성 PSNR 30.5 dB, 32 dB의 Stable Diffusion 연속 잠재 공간과 경쟁력 있다.

비디오의 경우: 3D VQ 토크나이저가 시공간 패치(4x4x4 픽셀)를 하나의 정수로 인코딩한다. 8 FPS의 4s 클립은 32 프레임; 4x 공간 및 4x 시간 감소로 256x256에서 토큰 수는 (256/4) * (256/4) * (32/4) = 64 * 64 * 8 = 32,768 토큰.

토크나이저 품질이 천장이다. Emu3의 기여는 부분적으로 "우리 очень хороший 토크나이저를 훈련했다"다.

### 단일 손실 훈련

Emu3는 텍스트 토큰, 2D 이미지 토큰, 3D 비디오 토큰에 걸쳐 공유 어휘에서 다음 토큰 예측이라는 하나의 목적지를 사용한다. 가중치는 훈련 중 모달리티별 요인으로 곱해지지만 손실 함수는 동일하다.

혼합에서 훈련:
- 이미지 생성: `<text caption> <image> image_tokens </image>`
- 이미지 인식: `<image> image_tokens </image> <question> text_tokens`
- 비디오 생성: `<text caption> <video> video_tokens </video>`
- 비디오 인식: 유사.
- 텍스트만: 표준 NTP.

모델은 데이터 분포에서 이미지 토큰 대 텍스트 토큰을 언제 방출할지 학습한다. 생성은 `<image>` 태그 후 이미지 토큰을 예측하는 것으로부터 emergence.

### 분류기 자유 안내와 온도

자기 회귀 이미지 생성은 추론에서 분류기 자유 안내(CFG)로 훨씬 더 좋아진다. Emu3는 그것을 사용한다: 두 번 생성, 한 번은 전체 캡션으로, 한 번은 빈 캡션으로, 안내 가중치(전형적인 3.0-7.0)로 로짓을 혼합한다. 이것은 확산이 사용하는 동일한 CFG 트릭으로, 자기 회귀 설정에 차용된다.

온도가 중요하다: 너무 높으면 아티팩트; 너무 낮으면 모드崩壊. Emu3의 권장 온도는 인식에는 1.0, 이미지 생성에는 0.8이다.

### 세 가지 역할, 하나의 모델

Emu3는 세 가지 기능적으로 다른 API로 제공되지만 하나의 기본 가중치 세트다:

- Emu3-Gen. 이미지 생성. 입력 텍스트, 출력 이미지 토큰.
- Emu3-Chat. VQA 및 캡셔닝. 입력 이미지(토큰), 출력 텍스트.
- Emu3-Stage2. 비디오 생성 및 비디오 VQA. 입력 텍스트 또는 비디오, 출력 텍스트 또는 비디오.

태스크별 헤드 없음. 다른 프롬프트 템플릿만. 동일한 체크포인트.

### 벤치마크

Emu3 논문(2024년 9월):

- 이미지 생성: MJHQ-30K FID에서 SDXL를 이김(5.4 vs 5.6), GenEval 전체에서 비슷(0.54 vs 0.55 — 통계적 동점), Deep-Eval의 복합에서 동등.
- 이미지 인식: VQAv2에서 LLaVA-1.6를 이김(75.1 vs 72.4) 및 MMMU에서 roughly 일치.
- 비디오 생성: Sora 시대 공개 벤치마크 모델과 경쟁력 있는 FVD에서 4초 클립 품질.

숫자가 항상 이기는 것은 아니다 — Emu3는 여기서 한 포인트를 주고 거기서 한 포인트를 얻는다 — 하지만 "다음 토큰 예측이 전부 필요한다"라는 주장은 모달리티 전반에 방어 가능하다.

### 컴퓨트 비용

Emu3는 7B-파라미터 모델로 약 3000억 개의 멀티모달 토큰에서 훈련되었다. GPU 시간은 A100 클래스 실리콘에서 Llama-2-7B 사전훈련과 roughly comparable(2k-4k GPU년). Stable Diffusion 3와 같은 확산 모델은 유사한 예산에서 훈련되지만 더 복잡한 파이프라인이 필요하다.

추론에서 Emu3는 이미지당 SDXL보다 느리다: 30 tok/s에서 4096 이미지 토큰은 512x512 이미지에 대해 ~2분, SDXL의 2-5초 대비. 투기지 디코딩과 KV-캐시 최적화가 격차를 좁히지만 닫지는 않는다. 자기 회귀 이미지 생성은 컴퓨트 무겁다; 이것이 지속적인 트레이드오프다.

### 왜 중요한가

Emu3의 심층적 기여는 개념적이다. 다음 토큰 예측이 이미지 생성에서 확산과 일치하도록 확장되면 통합 모델 경로(하나의 손실, 하나의 백본, 모든 모달리티)가 가능하다. 미래 모델은 별도의 텍스트 인코더, 별도의 확산 스케줄러, 별도의 VAE가 필요하지 않다. 하나의 트랜스포머, 모달리티당 하나의 토크나이저, 규모.

Show-o, Janus-Pro, InternVL-U가 모두 이것을 기반으로 구축하거나 도전한다. 2025년까지 중국 랩(BAAI, DeepSeek)이 미국 랩보다 이 방향으로 더 적극적이다.

## 활용

`code/main.py`는 두 가지 토이 조각을 구축한다:

- 2D 대 3D VQ 토크나이저 수 계산기: (해상도, 패치, 클립 길이, FPS)가 주어지면 이미지 대 비디오의 토큰 수를 계산.
- 온도에서 분류기 자유 안내가 있는 자기 회귀 이미지-토큰 샘플러.

CFG 구현은 Emu3의 레시피와 일치한다 — 안내 가중치로 조건부 및 무조건부 로짓을 혼합.

## 결과물

이 레슨은 `outputs/skill-token-gen-cost-analyzer.md`를 생성한다. 생성 제품 사양(이미지 또는 비디오, 대상 해상도, 품질 계층, 지연 시간 예산)이 주어지면 토큰 수, 추론 비용을 계산하고 Emu3 패밀리 대 확산을 선택한다.

## 연습 문제

1. Emu3는 8x8 감소에서 512x512 이미지당 4096 토큰을 생성한다. 1024x1024와 2048x2048의Equivalent를 계산한다. 추론 지연 시간에 무엇이 발생하는가?

2. Emu3 섹션 3.3(비디오 토크나이저)를 읽는다. 3D VQ 패치 형태를 설명하고 왜 8x8x1이 아닌 4x4x4인지 설명한다.

3. 분류기 자유 안내 가중치 5.0 대 3.0: 어떤 시각적 효과? `code/main.py`에서 수학을 추적한다.

4. 300B 토큰에서 Emu3-7B의 훈련 FLOP를 계산하고 Stable Diffusion 3와 비교한다. 어떤 것이 훈련 비용이 더 많이 들었는가?

5. Emu3는 FID에서 SDXL를 이지만 LLaVA-1.6와 같은 전문 VLM에 대한 VQAv2에서 아니다. 통합 손실 접근법이 다른 벤치마크에서 전문 모델과 다른 강도를 보이는 이유를 설명한다.

## 핵심 용어

| 용어 |人们在说什么 | 실제 의미 |
|------|-----------------|------------------------|
| 다음 토큰 예측 | "NTP" | 표준 자기 회귀 손실: 토큰[0..i]가 주어지면 토큰[i+1]을 예측; 토큰화될 때 모든 모달리티에 대해 작동 |
| IBQ 토크나이저 | "역병목 양자화기" | 더 큰 코드북(32768+)과 Chameleon보다 더 나은 재구성을 가진 VQ-VAE의 한 클래스 |
| 3D VQ | "시공간 양자화기" | (시간, 행, 열)로 인덱싱되는 코드북; 하나의 토큰이 4x4x4 픽셀 큐브를 덮음 |
| 분류기 자유 안내 | "CFG" | 가중치 감마로 조건부 및 무조건부 로짓을 혼합; 추론에서 이미지 품질을 높임 |
| 통합 어휘 | "공유 토큰" | 텍스트 + 이미지 + 비디오가 모두 동일한 정수 공간에서 drawn; 모델이 다음으로 올바른 모달리티를 예측 |
| MJHQ-30K | "이미지 생성 벤치마크" | 30k 프롬프트가 있는 Midjourney 품질 벤치마크; Emu3가 여기서 FID를 보고 |
