# 오디오-언어 모델: Whisper에서 Audio Flamingo 3까지의 아크

> Whisper(Radford et al., 2022년 12월)는 음성 인식을 정착시켰습니다 — 68만 시간의 약한 지도 다국어 음성, 간단한 인코더-디코더 트랜스포머, 이후 모든 ASR 릴리스가 인용하는 벤치마크. 그러나 인식은 추론이 아닙니다. "이 녹음에 어떤 악기가 있나요" 또는 "화자가 어떤 감정을 표현하고 있나요" 또는 "3분에 무슨 일이 일어났나요"라고 묻는 것은 전사가 아닌 오디오 이해가 필요합니다. Qwen-Audio, SALMONN, LTU, NVIDIA의 Audio Flamingo 3(AF3, 2025년 7월)는 그 스택을 점진적으로 구축했습니다: Whisper-급 인코더 유지, Q-former 추가, 오디오-텍스트 명령어 데이터 학습, 사고의 사슬 추론 추가. 이 레슨은 그 아크를 따라갑니다.

**Type:** Build
**Languages:** Python (stdlib, log-Mel spectrogram + audio Q-former skeleton)
**Prerequisites:** Phase 6 (Speech and Audio), Phase 12 · 03 (Q-Former)
**Time:** ~180 minutes

## 학습 목표

- 파형에서 log-Mel 스펙트로그램을 계산한다: 윈도잉, FFT, 필터 뱅크, 로그 변환.
- 인코더 옵션을 비교한다: Whisper 인코더, BEATs, AF-Whisper 하이브리드. 각각이 언제 승리하는가.
- 오디오 Q-former를 구축한다: N개의 학습 가능한 쿼리가 스펙트로그램 패치에 교차 어텐션.
- 캐스케이드(Whisper-후-LLM) vs 엔드-투-엔드 오디오-LLM 학습을 설명한다: 엔드-투-엔드가 추론에 대해 더 잘 확장되는 이유.

## 문제

음성 인식은 Whisper에 의해 해결되었습니다. 오디오의 OCR은 상용화되었습니다. 그러나 "상용화"는 전사에서 멈춥니다. 모델이 들은 내용 — 타이밍, 화자, 감정, 음악 구조, 환경 소리 — 에 대해 추론할 수 없다면, 전사만으로는 제품 기능을 구동할 수 없습니다.

세 가지 명백한 경로:

1. 캐스케이드: Whisper가 전사, LLM이 전사 내용에 대해 추론. 순수-음성 시나리오에서 작동. 음악, 환경 오디오, 다중-화자 중첩, 감정에 대해 실패.
2. 엔드-투-엔드 오디오-LLM: 오디오 인코더가 오디오 토큰을 LLM에 직접 공급, 전사 생략. 음향 정보(감정, 화자, 환경) 보존. 새로운 학습 데이터 필요.
3. 하이브리드: 오디오 인코더 + 전사와 추론을 모두 수행할 수 있는 텍스트 디코더. Qwen-Audio와 Audio Flamingo가 이 경로를 선택.

## 개념

### Log-Mel 스펙트로그램: 입력 특징

모든 오디오 인코더는 동일한 특징으로 시작합니다: log-Mel 스펙트로그램.

1. 16kHz로 리샘플링.
2. 25ms 윈도우, 10ms 홉으로 단시간 푸리에 변환.
3. FFT 결과의 크기 취함.
4. Mel 필터 뱅크(일반적으로 0-8000Hz에서 로그-간격의 80개 필터)를 적용하여 지각적 주파수로 워핑.
5. 동적 범위를 위해 로그 압축(log(1 + x)).

결과: (T, 80) 형태의 2D 배열, 여기서 T는 시간 프레임 수. 100Hz 프레임 속도의 30초 클립: (3000, 80).

### Whisper의 인코더

Whisper의 인코더는 log-Mel 스펙트로그램을 시간 프레임의 시퀀스로 처리하는 12-레이어 ViT-스타일 트랜스포머입니다. 출력: 시간 프레임당 하나의 히든 상태 벡터.

ASR의 경우 Whisper의 디코더는 인코더 출력을 조건으로 텍스트 토큰을 생성하는 교차 어텐션 트랜스포머입니다. 표준 인코더-디코더.

ALM(오디오-LLM)의 경우, 다른 LLM에 대한 입력으로 인코더 출력을 원합니다. 패턴: Whisper 인코더 동결, Q-former 학습 가능, LLM 동결 또는 튜닝.

### BEATs 및 오디오-특화 인코더

Whisper는 음성-지배적 데이터로 학습되었습니다. 음악 및 환경 오디오에 대해 더 약합니다.

BEATs(Chen et al., 2022)는 AudioSet에서 학습된 자기-지도 트랜스포머입니다. 동일한 매개변수 수에서 Whisper보다 음악 및 환경 소리를 더 잘 포착합니다.

AF-Whisper(Audio Flamingo 3의 하이브리드): Whisper + BEATs 특징을 오디오 입력으로 연결. Whisper는 언어 신호를, BEATs는 음향 신호를 전달.

### 오디오 Q-former

BLIP-2의 시각적 Q-former와 동일한 패턴. 고정된 수의 학습 가능한 쿼리(종종 32 또는 64)가 오디오 인코더의 출력 프레임에 교차 어텐션. 쿼리는 LLM이 소비하는 오디오 토큰이 됩니다.

학습 정렬 단계: Q-former만, 오디오-텍스트 쌍(AudioCaps, Clotho)에 대한 대조 + 캡셔닝 손실. 명령어 단계: 엔드-투-엔드, LLM 동결 해제, 명령어 데이터 학습.

### 아크 — SALMONN, Qwen-Audio, AF3

SALMONN(Tang et al., 2023): Whisper + BEATs + Q-former + LLaMA. 심각한 추론 능력을 가진 최초의 오픈 오디오-LLM. MMAU 벤치마크에서 ~0.55 복합 점수.

Qwen-Audio(Chu et al., 2023): 유사한 아키텍처, 더 풍부한 데이터셋으로 학습, 다중-턴 대화에 맞춤 튜닝. MMAU ~0.60.

LTU — Listen, Think, Understand(Gong et al., 2023): 명시적 추론 데이터, 오디오 클립에 대한 사고의 사슬에 초점. 더 작지만 더 집중적.

Audio Flamingo 3(Goel et al., 2025년 7월): 현재 오픈 SOTA. 8B LLM 백본(Qwen2 7B), Whisper-large 인코더 concat BEATs, 64-쿼리 Q-former, 100만+ 오디오-텍스트 명령어 쌍 학습. MMAU 0.72, 일부 하위 작업에서 독점 최첨단과 일치.

AF3는 또한 오디오를 위한 온디맨드 사고의 사슬을 도입합니다: 모델은 최종 답변 전에 선택적으로 사고 토큰("먼저 악기를 식별해보겠습니다: ...")을 방출할 수 있습니다. 사고가 활성화되면 복잡한 추론 작업에서 정확도가 3-5포인트 향상됩니다.

### 캐스케이드 vs 엔드-투-엔드

캐스케이드 파이프라인:

1. Whisper가 오디오 전사 → 텍스트.
2. LLM이 텍스트에 대해 추론.

"이 팟캐스트를 요약해줘"에 완벽하게 작동. 다음에 대해 실패:
- "이 노래의 분위기는?" — 분위기는 소리에 있고, 단어에 없음.
- "말하는 사람은 Alice인가 Bob인가?" — 화자 식별 필요.
- "폭발이 몇 초에 발생하나요?" — 시간적 그라운딩이 텍스트에서 손실.
- "이것은 실제 오디오인가 생성된 오디오인가?" — 딥페이크 탐지는 음향 특징 필요.

엔드-투-엔드는 음향 신호를 보존. Qwen-Audio와 AF3는 음악, 환경, 감정을 네이티브로 처리.

### 2026년 프로덕션 레시피

새로운 오디오-이해 제품의 경우:

- 캐스케이드: 전사가 목표이고, 음악이나 감정 추론이 없는 경우.
- AF3 / Qwen-Audio-계열: 음악, 감정, 다중-화자 또는 복잡한 오디오 추론이 필요한 경우.

캐스케이드가 더 저렴하고 간단. 엔드-투-엔드가 더 유능.

### MMAU — 오디오 추론 벤치마크

MMAU(Massive Multimodal Audio Understanding)는 2024-2025 오디오 추론 벤치마크:

- 음성, 음악, 환경 소리 전반의 10,000개 오디오-텍스트 QA 쌍.
- 분류, 시간적 추론, 인과 추론, 개방형 QA 포함.
- 캐스케이드 파이프라인이 체계적으로 놓치는 것을 테스트.

오픈 SOTA(AF3) 0.72; 독점 최첨단 ~0.78(Gemini 2.5 Pro, Claude Opus 4.7). 격차는 VideoMME의 오픈-vs-폐쇄 델타보다 작아, 오디오-LLM이 성숙해지고 있음을 나타냄.

## 사용하기

`code/main.py`:

- stdlib에서 log-Mel 스펙트로그램 계산 구현: 윈도잉, naive DFT, Mel 필터-뱅크.
- 오디오 Q-former 스켈레톤: 인코더 출력 프레임이 주어지면 Q, K, V, 어텐션 계산, N개 토큰 방출.
- 장난감 작업에서 캐스케이드-vs-엔드-투-엔드 비교.

## 결과물

이 레슨은 `outputs/skill-audio-llm-pipeline-picker.md`를 생성합니다. 오디오 작업(전사, 음악 태깅, 감정 추론, 다중-화자 화자분할, 환경 분류)이 주어지면, 캐스케이드, 엔드-투-엔드 AF3 또는 하이브리드를 선택합니다.

## 연습 문제

1. 16kHz, 25ms 윈도우, 10ms 홉, 80개 Mel 빈에서 30초 클립의 log-Mel 스펙트로그램 차원을 계산하세요. 48kHz에서 어떻게 변하나요?

2. Whisper가 음악에서 성능이 낮은 이유는 무엇인가요? BEATs가 Whisper가 포착하지 못하는 어떤 오디오 특징을 포착하나요?

3. 64개 쿼리 vs 32개 쿼리의 오디오 Q-former: 어떤 작업 복잡성에서 64가 효과가 있나요? 32는 무엇을 위해 계산을 절약하나요?

4. AF3 섹션 4(온디맨드 사고)를 읽으세요. 사고의 사슬이 가장 도움이 되는 세 가지 오디오 작업을 제안하세요.

5. AF3의 출력을 사용하여 최소 화자분할 파이프라인을 구현하세요. 화자 변경을 어떻게 알리나요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|----------|
| Log-Mel spectrogram | "Mel 특징" | Mel 필터 뱅크 후 로그-크기 값의 2D (시간, 주파수) 배열 |
| Audio Q-former | "오디오 Perceiver" | 오디오 인코더 출력에서 LLM에 공급되는 고정 길이 쿼리로의 교차 어텐션 병목 |
| Cascaded | "ASR-후-LLM" | Whisper가 전사하고 텍스트 LLM이 추론하는 파이프라인; 음향 정보 손실 |
| End-to-end | "오디오-LLM" | Q-former를 통해 오디오 특징이 LLM에 직접 입력; 음향 신호 보존 |
| BEATs | "오디오 AudioSet 인코더" | AudioSet에서 학습된 SSL 트랜스포머; 음악 + 환경 소리에 강함 |
| MMAU | "오디오 추론 벤치" | 음성, 음악, 환경 전반의 10k QA 쌍; 2024 평가 표준 |
| On-demand thinking | "오디오 CoT" | 모델이 최종 답변 전에 선택적으로 추론 토큰을 방출, 정확도 3-5포인트 향상 |
