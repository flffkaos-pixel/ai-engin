# LLaVA와 비주얼 명령어 튜닝

> LLaVA(2023년 4월)는 지구상에서 가장 많이 복제된 멀티모달 아키텍처다. BLIP-2의 Q-Former를 2-layer MLP로 교체하고, Flamingo의 게이트된 교차 어텐션을 순진한 토큰 연결로 교체했으며, 텍스트 전용 캡션에서 GPT-4로 생성된 158k 비주얼 명령어 턴에서 훈련했다. 2023년과 2026년 사이에 VLM을 구축한 모든 실무자는 LLaVA의 어떤 변형을 구축했다. LLaVA-1.5는 AnyRes를 추가했다. LLaVA-NeXT는 해상도를 높였다. LLaVA-OneVision은 하나의 레시피로 이미지, 멀티이미지, 비디오를 통합했다. 이 레슨은 레시피를 읽고, 투영기를 구현하며, "더 단순한 것이 이긴" 이유를 설명한다.

**유형:** 실습
**언어:** Python (stdlib, 투영기 + 명령어 템플릿 빌더)
**선수 과목:** Phase 12 · 02 (CLIP), Phase 11 (LLM 엔지니어링 — 명령어 튜닝)
**소요 시간:** ~180분

## 학습 목표

- ViT 패치 임베딩(차원 1024)을 LLM의 임베딩 차원(차원 4096)으로 매핑하는 2-layer MLP 투영기를 구축한다.
- LLaVA 2단계 레시피를 따라간다: (1) 558k 캡션 페어에서 투영기 정렬, (2) 158k GPT-4 생성 턴에서 비주얼 명령어 튜닝.
- 이미지 토큰 플레이스홀더, 시스템 프롬프트, 사용자/어시스턴트 턴으로 LLaVA 형식 프롬프트를 구성한다.
- 커뮤니티가 Q-Former의 토큰 예산 승리에도 불구하고 MLP로 이동한 이유를 설명한다.

## 문제

BLIP-2의 Q-Former(레슨 12.03)는 이미지를 32개의 토큰으로 압축한다. 깔끔하고 효율적이며 벤치마크에 좋다. 하지만 두 가지 문제가 있다.

첫째, Q-Former는 훈련 가능하지만 손실은 최종 태스크가 아니다. 1단계는 ITC+ITM+ITG를 훈련한다. 2단계는 LM 손실을 훈련한다. 쿼리는 LLM이 그 후에 디코딩해야 할 중간 표현을 학습한다. 정보가 병목에서 손실된다.

둘째, Q-Former는 188M 파라미터를 가지며, LLaVA의 2023년 규모에서 대상 LLM과 공동 설계해야 했다. LLM을 변경하면 Q-Former를 재훈련해야 한다. 비전 인코더를 변경하면 재훈련해야 한다. 모든 조합이 별도의 R&D 프로젝트였다.

LLaVA의 대답은 단순함에 부끄러울 정도로 했다: ViT의 576개 패치 토큰을 가져와서 각각 2-layer MLP(`1024 → 4096 → 4096`)를 통과시킨 다음 모든 576개를 LLM의 입력 시퀀스에 던진다. 병목 없음. 기이한 목표에 대한 1단계 사전훈련 없음. 직접 LM 손실로 MLP만 훈련한다.

데이터는 어디서 오는가? LLaVA의 두 번째 통찰력: GPT-4(텍스트 전용)를 사용하여 명령어 데이터를 생성한다. 이미지의 COCO 캡션과 바운딩 박스 데이터를 GPT-4에 제공하고, 대화, 설명, 복잡한 추론 질문을 생성하도록 요청한다. 158k 명령어-응답 턴 무료. 인간 주석 없음.

결과: 8개의 A100에서 하루 동안 실행되고 MMMU에서 Flamingo를 이기고 커뮤니티가 확장할 수 있는 오픈 체크포인트를 배송한 VLM. 2023년 후반까지 50+ 포크가 파생되었다.

## 개념

### 아키텍처

13B의 LLaVA-1.5:
- 비전 인코더: CLIP ViT-L/14 @ 336 (1단계에서 동결, 2단계에서 선택적으로 동결 해제).
- 투영기: GELU 활성화가 있는 2-layer MLP, `1024 → 4096 → 4096`.
- LLM: Vicuna-13B (나중에 Llama-3.1-8B).

이미지 + 텍스트 프롬프트에 대한 정방향 통과:

```
img -> ViT -> 차원 1024의 576 패치
패치 -> MLP -> 차원 4096의 576 토큰
프롬프트: 시스템 + "<image>" 플레이스홀더 + 사용자 질문
<image> 토큰을 576개의 투영된 토큰으로 교체
전체 시퀀스를 LLM에 공급
응답 디코딩
```

이미지는 LLM 컨텍스트의 576 토큰을 차지한다. 2048 컨텍스트에서 이는 1472 토큰의 텍스트 공간을 남긴다. 32k 컨텍스트에서는 반올림 오차다.

### 1단계: 투영기 정렬

ViT 동결. LLM 동결. 2-layer MLP만 훈련. 데이터셋: 558k 이미지-캡션 페어(LAION-CC-SBU). 손실: 투영된 이미지 토큰에 조건화된 캡션에 대한 언어 모델링.

배치 128에서 단일 에폭으로 몇 시간 내에 완료된다. 투영기는 ViT 공간에서 LLM 공간으로 매핑하는 방법을 학습한다. 태스크별 감독 없음.

### 2단계: 비주얼 명령어 튜닝

투영기 동결 해제(여전히 훈련 가능). LLM 동결 해제(일반적으로 전체, 때때로 LoRA). 158k 비주얼 명령어 턴에서 훈련.

명령어 데이터가 트릭이다. Liu 등은 다음과 같이 생성했다:
1. COCO 이미지를 가져온다.
2. 텍스트 설명(5개의 인간 캡션 + 바운딩 박스 목록)을 추출한다.
3. 세 가지 프롬프트 템플릿으로 GPT-4에 보낸다:
   - 대화: "이 이미지에 대한 사용자와 어시스턴트 사이의来回 대화를 생성한다."
   - 상세 설명: "이미지의 풍부하고 상세한 설명을 제공한다."
   - 복잡한 추론: "이미지에 대한 추론이 필요한 질문을 한 다음 답한다."
4. GPT-4 출력을 (명령어, 응답) 페어로 파싱한다.

이것은 이미지를 직접 만지지 않는다 — 텍스트 설명만. GPT-4는 그럴듯한 이미지 내용을 환각한다. 약간의 노이즈이지만 작동했다: 158k 턴이 대화를解锁するには十分였다.

### 커뮤니티가 이것을 복제한 이유

- 조정할 1단계 특정 손실 없음. LM 손실 전체.
- 투영기가 몇 시간이 아닌 일에 훈련된다.
- LLM을 교환할 수 있다(LLaVA-Llama2, LLaVA-Mistral, LLaVA-Llama3) 투영기만 재훈련하여.
- 비주얼 명령어 데이터 파이프라인은 GPT-4를 사용하며 새 도메인에 대해 저렴하게 재생성할 수 있다.

### LLaVA-1.5와 LLaVA-NeXT

LLaVA-1.5(2023년 10월) 추가:
- 명령어 튜닝에 혼합된 학술 태스크 데이터(VQA, OKVQA, RefCOCO).
- 더 나은 시스템 프롬프트.
- 2048 → 32k 컨텍스트.

LLaVA-NeXT(2024년 1월) 추가:
- AnyRes: 고해상도 이미지를 336x336 크롭의 2x2 또는 1x3 그리드로 분할, plus 하나의 글로벌 저해상도 썸네일. 각 크롭은 576 토큰이 된다; 이미지당 총 약 2880 시각 토큰. OCR 및 차트 태스크가 뛰었다.
- ShareGPT4V가 있는 더 나은 명령어 데이터 혼합(GPT-4V 캡션).
- 더 강력한 기본 LLM(Mistral-7B, Yi-34B).

### LLaVA-OneVision

레슨 12.08에서 OneVision을 자세히 다룬다. 짧은 버전: 동일한 투영기이지만 단일 이미지, 멀티이미지, 비디오를共享 시각 토큰 예산으로 하나의 모델에서 다루는 커리큘럼으로 훈련.

### Q-Former와의 비교

| | Q-Former (BLIP-2) | MLP (LLaVA) |
|---|---|---|
| 이미지당 시각 토큰 | 32 | 576 (기본) 또는 2880 (AnyRes) |
| 훈련 가능 파라미터 | 188M + LM | 40M + LM |
| 1단계 손실 | ITC+ITM+ITG | LM만 |
| LLM 드롭인 | 재훈련 필요 | 최소 재훈련으로 교환 |
| 멀티이미지 | 어색함 | 자연스러움 (연결) |
| 비디오 | 어색함 | 자연스러움 (프레임당 연결) |
| 토큰 예산 | 작음 | 큼 |

MLP는 단순성과 토큰 유연성에서 승리한다. Q-Former는 토큰 예산에서 승리한다. 2023년 후반까지 토큰 예산은 더 이상 제한 제약이 아니었다(LLM 컨텍스트가 32k-128k+로 성장) 그리고 단순성이 지배했다.

### 프롬프트 형식

```
A chat between a curious human and an artificial intelligence assistant. The assistant gives helpful, detailed, and polite answers to the human's questions. USER: <image> Describe this image in detail. ASSISTANT: The image shows ...
```

`<image>`는 플레이스홀더 토큰이다. 토큰화 전에 N개의 투영된 시각 토큰으로 교체된다. 토크나이저는 훈련된 것보다 약간 더 긴 시퀀스를 보지만 LLM은 1단계가 그것을 배우기 때문에 새로운 입력을 처리한다.

### 파라미터 경제학

LLaVA-1.5-7B 분해:
- CLIP ViT-L/14 @ 336: 303M (1단계 동결, 2단계에서 자주 동결 해제).
- 투영기 (2x linear): ~22M 훈련 가능.
- Llama-7B: 7B.
- 총계: 7.3B 파라미터. 2단계 동안 훈련 가능: 전체 7B + 22M 투영기.

2단계 훈련 비용: ~8xA100에서 ~20시간. 이것이 핵심 숫자다 — 하루, 하나의 노드, 재현 가능. 이것이 LLaVA가 확산된 이유다.

## 활용

`code/main.py` 구현:

1. 토이 스케일에서 2-layer MLP 투영기(dim 16 → 32 → 32) 순수 Python으로.
2. 프롬프트 구축 파이프라인: 시스템 프롬프트 + N개의 투영된 토큰으로 교체된 `<image>` + 사용자 턴 + 어시스턴트 생성 플레이스홀더.
3. 576토큰 시각 블록이 LLM 컨텍스트에서 어떻게 보이는지 시각화(2k/32k/128k 컨텍스트의 percentage).

## 결과물

이 레슨은 `outputs/skill-llava-vibes-eval.md`를 생성한다. LLaVA 패밀리 체크포인트가 주어지면 10프롬프트 vibes-eval 스위트(3 캡셔닝, 3 VQA, 2 추론, 2 거부)를 실행하고 인간이 읽을 수 있는 점수카드를 보고한다. 벤치마크가 아니다; 투영기와 LLM이 잘 연결되고 있는지 확인하는 smoke test.

## 연습 문제

1. `1024 → 4096 → 4096`에서 2-layer MLP 투영기의 훈련 가능 파라미터 수를 계산한다. GELU와 바이어스와 함께, LLaVA-13B의几分 Represent인가?

2. "거부" 케이스에 대한 LLaVA 프롬프트를 구성한다 — 이미지에 개인이 포함되어 있다. 예상되는 어시스턴트 응답을 작성한다. LLaVA가 이것을 제로샷에서 거부해야 하는 이유와 거부를 강화하기 위해 어떤 훈련 데이터가 필요한가?

3. LLaVA-NeXT 블로그의 AnyRes 섹션을 읽는다. AnyRes에서 1344x672 이미지의 시각 토큰 수를 계산한다. 336x336의 기본 576 토큰과 비교한다.

4. LLaVA 1단계 투영기는 캡션에 대한 LM 손실로 훈련된다. 1단계를 건너뛰고 2단계(비주얼 명령어 튜닝)로 바로 가는 경우 어떻게 되는가? Prismatic VLMs 절제(arXiv:2402.07865)를 인용하여 답변한다.

5. LLaVA-Instruct-150k는 COCO 캡션과 GPT-4를 사용하여 명령어를 생성한다. 새 도메인(의료 X선, 위성 이미지)에 대해 도메인 명령어를 생성하는 4단계 데이터 파이프라인을 설명한다. 각 단계에서 무슨 일이 잘못될 수 있는가?

## 핵심 용어

| 용어 |人们在说什么 | 실제 의미 |
|------|----------------|------------------------|
| 투영기 | "MLP 브릿지" | ViT 차원을 LLM 차원으로 매핑하는 GELU가 있는 2-layer MLP |
| 이미지 토큰 | "<image> 플레이스홀더" | 추론 전에 N개의 투영된 시각 토큰으로 교체되는 프롬프트 마커 |
| 비주얼 명령어 튜닝 | "LLaVA 2단계" | (이미지, 명령어, 응답) 삼중항에서 GPT-4 생성 훈련 |
| 1단계 정렬 | "투영기 사전훈련" | ViT와 LLM을 동결하고 캡션에 대한 LM 손실로 투영기를 훈련 |
| AnyRes | "멀티크롭 타이링" | 타일 그리드로 고해상도 이미지를 분할하고 각 타일의 시각 토큰을 연결 |
| LLaVA-Instruct | "GPT-4 생성" | COCO 캡션 + GPT-4에서 합성된 158k 명령어-응답 페어 |
| 비전 인코더 동결 | "백본 잠김" | CLIP 가중치가 1단계에서 업데이트되지 않음, 2단계에서도 그렇지 않은 경우도 있음 |
| ShareGPT4V | "더 나은 캡션" | 더 높은 품질 정렬에 사용되는 GPT-4V로 생성된 1M 밀집 캡션 |
| VQA | "비주얼 질문 응답" | 이미지에 대한 자유 형식 질문에 답하는 태스크 |
| Prismatic VLMs | "디자인 공간 논문" | 투영기와 데이터 선택을 체계적으로 테스트하는 2024 Karamcheti 절제 |
