# 비전 트랜스포머와 패치-토큰 프리미티브

> 무엇이든 멀티모달 이전에, 이미지는 트랜스포머가 처리할 수 있는 토큰 시퀀스가 되어야 한다. 2020년 ViT 논문은 16x16 픽셀 패치, 선형 투영, 위치 임베딩으로 이 문제를 해결했다. 5년이 지난 2026년 현재 모든 프론티어 모델(네이티브 2576px의 Claude Opus 4.7, Gemini 3.1 Pro, Qwen3.5-Omni)도 여전히 같은 방식으로 시작한다 — 인코더는 ViT에서 DINOv2, SigLIP 2로 바뀌었지만, 레지스터 토큰이 추가되고, 위치 부호 체계가 2D-RoPE가 되었지만, 프리미티브는 그대로 유지되었다. 이 레슨은 패치-토큰 파이프라인을 종단간 읽고 stdlib Python으로 구현하여 Phase 12의 나머지 부분에 "비전 토큰"에 대한 구체적인 정신 모델을 구축한다.

**유형:** 학습
**언어:** Python (stdlib, 패치 토크나이저 + 지오메트리 계산기)
**선수 과목:** Phase 7 (트랜스포머), Phase 4 (컴퓨터 비전)
**소요 시간:** ~120분

## 학습 목표

- 정확한 위치 인코딩을 사용하여 HxWx3 이미지를 패치 토큰 시퀀스로 변환한다.
- 주어진 (패치 크기, 해상도, 히든 딤, 깊이)의 ViT에 대한 시퀀스 길이, 파라미터 수, FLOP를 계산한다.
- ViT를 2020년 연구에서 2026년 프로덕션으로 끌어올린 세 가지 업그레이드 назвать: 자기지도 사전훈련 (DINO/MAE), 레지스터 토큰, 네이티브 해상도 패킹.
- 다운스트림 태스크를 위한 CLS 풀링,.mean 풀링, 레지스터 토큰 중에서 선택한다.

## 문제

트랜스포머는 벡터 시퀀스로 작동한다. 텍스트는 이미 시퀀스다(바이트 또는 토큰). 이미지는 3개 색 채널을 가진 2D 픽셀 그리드다 — 시퀀스가 아니다. 모든 픽셀을 펼치면 224x224 RGB 이미지는 150,528 토큰이 되고, 해당 길이에서 자기 어텐션은 비실행 가능하다(시퀀스 길이에 대해 2차).

2020년 이전 접근법은 앞에 CNN 피처 추출기를 붙였다: ResNet은 2048차원 벡터의 7x7 피처 맵을 생성하고, 그 49개 토큰을 트랜스포머에 전달한다. 작동하지만 CNN의 바이어스(병렬 동등성, 로컬 수용 필드)를 상속받고 트랜스포머의 확장에 대한 욕구를 잃는다.

Dosovitskiy 등(2020)은 직설적인 질문을 했다: CNN을 건너뛰면 어떨까? 이미지를 고정 크기 패치(예: 16x16 픽셀)로 분할하고, 각 패치를 벡터로 선형 투영하고, 위치 임베딩을 추가하고, 시퀀스를 Vanilla 트랜스포머에 전달한다. 당시에는 이것이 이단이었다 — 컨볼루션 없는 비전. 충분한 데이터(JFT-300M, 그 다음 LAION)와 함께 ResNet을 이기고 ImageNet에서 계속 개선되었다.

2026년까지 ViT 프리미티브는 의심의 여지없는 기반이 되었다. 모든 오픈 가중치 VLM의 비전 타워는 어떤 후손이다(DINOv2, SigLIP 2, CLIP, EVA, InternViT). 질문은 더 이상 "패치를 사용해야 하는가?"가 아니라 "패치 크기, 해상도 스케줄, 사전훈련 목표, 위치 인코딩이 무엇인가"이다.

## 개념

### 토큰으로서의 패치

 shape `(H, W, 3)`의 이미지 `x`와 패치 크기 `P`가 주어지면, `(H/P) x (W/P)` 개의 비오버랩 패치 그리드로 이미지를 분할한다. 각 패치는 `P x P x 3` 픽셀 큐브다. 각 큐브를 `3 P^2` 벡터로 펼친다. 공유 선형 투영 `W_E` of shape `(3 P^2, D)`를 적용하여 각 패치를 모델의 히든 차원 `D`로 매핑한다.

 canonical config의 경우:
- 해상도 224, 패치 크기 16 → 그리드 14x14 → 196개 패치 토큰.
- 각 패치는 `16 x 16 x 3 = 768` 픽셀 값, `D = 768`로 투영.
- 학습 가능한 `[CLS]` 토큰 추가 → 시퀀스 길이 197.

패치 투영은 kernel size `P`, stride `P`, `D` 출력 채널이 있는 2D 컨볼루션과 수학적으로 동일하다. 이것이 프로덕션 코드가 실제로 구현하는 방식이다 — `nn.Conv2d(3, D, kernel_size=P, stride=P)`. "선형 투영" 프레임은 개념적이며, 커널 프레임은 효율적이다.

### 위치 임베딩

패치에는 고유한 순서가 없다 — 트랜스포머는它们을 배낭으로 본다. 초기 ViT는 학습 가능한 1D 위치 임베딩을 추가했다(위치당 하나의 768차원 벡터, 197개). 작동하지만 모델을 훈련 해상도에 종속시킨다: 추론에서 그리드를 변경하면 위치 테이블을 보간해야 한다.

 сучасний 비전 백본은 2D-RoPE(Qwen2-VL의 M-RoPE, SigLIP 2의 기본값) 또는 인자분해 2D 위치를 사용한다. 2D-RoPE는 패치의 (행, 열) 인덱스를 기반으로 쿼리 및 키 벡터를 회전하므로 모델은 회전 각도에서 상대적 2D 위치를 유추한다. 위치 테이블 없음. 모델은 추론에서 임의의 그리드 크기를 처리한다.

### CLS 토큰, 풀링된 출력 및 레지스터 토큰

이미지 수준 표현은 무엇인가? 세 가지 선택지가 공존한다:

1. `[CLS]` 토큰. 패치 시퀀스 앞에 학습 가능한 벡터를 추가한다. 모든 트랜스포머 블록 후, CLS 토큰의 히든 상태가 이미지 표현이다. BERT에서 상속됨. 원본 ViT, CLIP에서 사용됨.
2. Mean 풀. 패치 토큰의 출력 히든 상태를 평균화한다. SigLIP, DINOv2, 대부분의 최신 VLM에서 사용됨.
3. 레지스터 토큰. Darcet 등(2023)은 명시적 싱크 토큰 없이 훈련된 ViT가 자기 어텐션을 하이재킹하는 높은 노름의 "아티팩트" 패치를 개발함을 관찰했다. 4-16개의 학습 가능한 레지스터 토큰을 추가하면 이 부하를 흡수하고 밀집 예측 품질(세그멘테이션, 깊이)을 향상시킨다. DINOv2와 SigLIP 2는 모두 레지스터와 함께 제공된다.

다운스트림 태스크에 따라 선택이 중요하다. 분류에는 CLS가 적합하다. 패치 토큰이 LLM에 입력되는 VLM의 경우 풀링을 완전히 건너뛴다 — 모든 패치가 LLM 입력 토큰이 된다. 레지스터는 핸드오프 전에 삭제된다(它们는 스캐폴딩이지 내용이 아니다).

### 사전훈련: 감독, 대조, 마스킹, 자기 증류

2020년 ViT는 JFT-300M에서 감독 분류로 사전훈련되었다. 빠르게 대체되었다:

- CLIP (2021): 400M 페어의 대조적 이미지-텍스트. 레슨 12.02.
- MAE (2021, He 등): 75% 패치 마스킹, 픽셀 재구성. 자기지도, 순수 이미지로 작동.
- DINO (2021) / DINOv2 (2023): 학생-교사 자기 증류, 레이블 없음, 캡션 없음. 2023 DINOv2 ViT-g/14는 가장 강력한 순수 비전 백본이며 "밀집 피처" 사용 사례의 기본값.
- SigLIP / SigLIP 2 (2023, 2025): 시그모이드 손실과 네이티브 종횡비를 위한 NaFlex가 있는 CLIP. 2026년 오픈 VLM(Qwen, Idefics2, LLaVA-OneVision)의 지배적인 비전 타워.

사전훈련 선택은 백본이 어떤 것에 좋은지를 결정한다: 텍스트와의 시맨틱 매칭을 위해 CLIP/SigLIP, 밀집 비전 피처를 위해 DINOv2, 다운스트림 미세조정 출발점으로 MAE.

### 확장 법칙

ViT 확장(Zhai 등 2022)은 ViT의 품질이 모델 크기, 데이터 크기, 컴퓨트에서 예측 가능한 법칙을 따름을 확립했다. 고정 컴퓨트에서:
- 더 큰 모델 + 더 많은 데이터 → 더 나은 품질.
- 패치 크기는 시퀀스 길이와 충실도 사이의 레버다. 패치 14(DINOv2/SigLIP SO400m의 전형적인)는 패치 16보다 이미지당 더 많은 토큰을 생성한다; OCR 및 밀집 태스크에 더 좋지만 속도는 느리다.
- 해상도는 다른 큰 레버다. 224에서 384, 512로 가면 거의 항상 도움이 되지만 FLOP에서 2차 비용이든다.

ViT-g/14 (1B 파라미터, 패치 14, 해상도 224 → 256 토큰)와 SigLIP SO400m/14 (400M 파라미터, 패치 14)는 2026년 오픈 VLM의 두 가지 주력 인코더다.

### ViT의 파라미터 수

전체 계산은 `code/main.py`에 있다. ViT-B/16 @ 224의 경우:

```
patch_embed = 3 * 16 * 16 * 768 + 768  =  591k
cls + pos    = 768 + 197 * 768          =  152k
block        = 4 * 768^2 (QKVO) + 2 * 4 * 768^2 (MLP) + 2 * 2*768 (LN)
              = 12 * 768^2 + 3k          =  7.1M
12 blocks    = 85M
final LN    = 1.5k
total       ≈ 86M
```

이렇게 모든 ViT를 대략 계산한 후 체크포인트를 로드한다. 백본 크기는 다운스트림 VLM에서 VRAM 바닥을 설정한다.

### 2026년 프로덕션 구성

2026년 대부분의 오픈 VLM이 배송하는 인코더는 네이티브 해상도(NaFlex)에서 SigLIP 2 SO400m/14다. 다음을 갖추고 있다:
- 400M 파라미터.
- 패치 크기 14, 기본 해상도 384 → 이미지당 729개 패치 토큰.
- 이미지 수준 태스크를 위한 Mean 풀; VQA를 위해 모든 729개 패치가 LLM으로 흐른다.
- 4개의 레지스터 토큰, LLM 핸드오프 전에 삭제됨.
- 네이티브 종횡비를 위한 이미지 수준 스케일링이 있는 2D-RoPE.

해당 구성의 모든 결정은 읽을 수 있는 논문으로 추적할 수 있다.

## 활용

`code/main.py`는 패치 토크나이저와 지오메트리 계산기다. (이미지 H, W, 패치 P, 히든 D, 깊이 L)를 받아 다음을 보고한다:

- 패칭 후 그리드 형태와 시퀀스 길이.
- 합성 8x8 픽셀 토이 이미지에 대한 토큰 시퀀스(펼침 + 투영 경로 워크스루).
- 패치 임베딩, 위치 임베딩, 트랜스포머 블록, 헤드별로细分된 파라미터 수.
- 대상 해상도에서 정방향 통과당 FLOP.
- ViT-B/16 @ 224, ViT-L/14 @ 336, DINOv2 ViT-g/14 @ 224, SigLIP SO400m/14 @ 384의 비교 표.

실행한다. 파라미터 수를 게시된 숫자와 일치시킨다. 패치 크기와 해상도를 가지고 토큰 수 비용을 느껴본다.

## 결과물

이 레슨은 `outputs/skill-patch-geometry-reader.md`를 생성한다. ViT 구성(패치 크기, 해상도, 히든 차원, 깊이)이 주어지면 토큰 수, 파라미터 수, VRAM 추정을 근거와 함께 생성한다. VLM용 비전 백본을 선택할 때마다 이 스킬을 사용한다 — "토큰이 폭발하고 LLM 컨텍스트가 가득 찼다" 놀라움을 방지한다.

## 연습 문제

1. 패치 크기 14에서 네이티브 1280x720 입력으로 Qwen2.5-VL에 대한 패치-토큰 시퀀스 길이를 계산한다. CLS 전용 표현과 어떻게 비교되는가?

2. 패치 14에서 1080p 프레임(1920x1080)은 몇 개의 토큰을 생성하는가? 5분 동영상에서 30FPS로 총 몇 개의 비전 토큰인가? 무엇이 가장 많이 절약하는가: 풀링, 프레임 샘플링, 토큰 병합?

3. 순수 Python에서 패치 토큰에 대한 평균 풀링을 구현한다. DINOv2 출력의 196개 토큰에 대한 평균 풀링이 모델의 `forward`가 pooled embedding을 요청할 때 반환하는 것과 일치함을 확인한다.

4. "Vision Transformers Need Registers"(arXiv:2309.16588)의 섹션 3을 읽는다. 레지스터가 흡수하는 아티팩트를 두 문장으로 설명하고 다운스트림 밀집 예측에 왜 중요한지 설명한다.

5. `code/main.py`를 수정하여 패치-n'-팩을 지원하도록 한다: 서로 다른 해상도의 이미지 목록이 주어지면 단일 패킹된 시퀀스와 블록 대각선 어텐션 마스크를 생성한다. 레슨 12.06에 도달할 때 그것에 대해 확인한다.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제로 의미하는 것 |
|------|----------------|------------------------|
| 패치 | "16x16 픽셀 정사각형" | 입력 이미지의 고정 크기 비오버랩 영역; 하나의 토큰이 된다 |
| 패치 임베딩 | "선형 투영" | 펼쳐진 패치 픽셀을 D차원 벡터로 매핑하는 공유 학습 행렬(또는 stride=P인 Conv2d) |
| CLS 토큰 | "클래스 토큰" | 전체 이미지를 나타내는 앞쪽에 추가된 학습 가능한 벡터; 2026에서는 선택적 |
| 레지스터 토큰 | "싱크 토큰" | 사전훈련 중 ViT가 개발하는 높은 노름의 어텐션 아티팩트를 흡수하는 추가 학습 가능한 토큰 |
| 위치 임베딩 | "위치 정보" | 시퀀스를 순서로 인식하게 만드는 위치당 벡터 또는 회전; 2D-RoPE가 현대의 기본값 |
| 그리드 | "패치 그리드" | 주어진 해상도와 패치 크기에 대한 (H/P) x (W/P) 2D 패치 배열 |
| NaFlex | "네이티브 플렉서블 해상도" | SigLIP 2 기능: 단일 모델이 재훈련 없이 여러 종횡비와 해상도를 지원 |
| 백본 | "비전 타워" | VLM에서 LLM에 공급되는 패치-토큰 출력을 가진 사전훈련된 이미지 인코더 |
| 풀링 | "이미지 수준 요약" | 패치 토큰을 하나의 벡터로 전환하는 전략: CLS, mean, 어텐션 풀, 또는 레지스터 기반 |
| 패치 14 vs 16 | "더 미세 vs 더 거친 그리드" | 패치 14는 이미지당 더 많은 토큰을 생성하며 OCR에 더 좋고 속도는 느리다; 패치 16이 클래식한 기본값 |
