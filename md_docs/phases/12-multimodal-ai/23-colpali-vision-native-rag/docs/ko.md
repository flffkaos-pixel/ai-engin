# ColPali와 비전-네이티브 문서 RAG

> 전통적 RAG는 PDF를 텍스트로 파싱하고, 청크로 분할하며, 청크를 임베딩하고, 벡터를 저장합니다. 모든 단계에서 신호가 손실됩니다: OCR은 차트 데이터를 잃고, 청킹은 표 행을 깨며, 텍스트 임베딩은 그림을 무시합니다. ColPali(Faysse et al., 2024년 7월)는 더 간단한 질문을 던졌습니다: 왜 텍스트를 추출해야 하는가? PaliGemma를 통해 페이지 이미지를 직접 임베딩하고, ColBERT-스타일 늦은 상호작용을 검색에 사용하며, 문서가 가진 모든 레이아웃, 그림, 글꼴 및 서식 신호를 유지합니다. 발표된 벤치마크: 시각적으로 풍부한 문서에서 텍스트-RAG보다 종단간 정확도 20-40% 향상. ColQwen2, ColSmol, VisRAG가 패턴을 확장했습니다. 이 레슨은 비전-네이티브 RAG 논문을 읽고 작은 ColPali-유사 인덱서를 구축합니다.

**Type:** Build
**Languages:** Python (stdlib, multi-vector indexer + MaxSim scorer)
**Prerequisites:** Phase 11 (LLM Engineering — RAG basics), Phase 12 · 05 (LLaVA)
**Time:** ~180 minutes

## 학습 목표

- 바이-인코더 검색(문서당 하나의 벡터)과 늦은-상호작용 검색(문서당 여러 벡터)의 차이를 설명한다.
- ColBERT의 MaxSim 연산과 ColPali가 이를 텍스트 토큰에서 이미지 패치로 일반화하는 방법을 설명한다.
- 작은 ColPali-유사 인덱서를 구축한다: 페이지 → 패치 임베딩 → 쿼리-용어 임베딩에 대한 MaxSim → 상위-k 페이지.
- 송장/재무 보고서 사용 사례에서 ColPali + Qwen2.5-VL 생성기와 텍스트-RAG + GPT-4를 비교한다.

## 문제

PDF에 대한 텍스트-RAG는 문서의 대부분을 버립니다. 재무 보고서의 Q3 수익 성장은 보통 차트에 있습니다; 의료 보고서의 소견은 주석이 달린 이미지에 있습니다; 법적 계약의 서명 블록은 텍스트 사실이 아닌 레이아웃 사실입니다.

텍스트-RAG 파이프라인:

1. PDF → OCR / pdftotext를 통한 텍스트.
2. 텍스트 → 300-500 토큰 청크.
3. 청크 → 바이-인코더 임베딩(하나의 벡터).
4. 사용자 쿼리 → 임베딩 → 코사인 유사도 → 상위-k 청크.
5. 청크 + 쿼리 → LLM.

다섯 가지 손실 단계. 차트가 포착되지 않음. 표가 청크 경계에서 깨짐. 다중-단 레이아웃이 평탄화됨. 그림 주석이 사라짐.

ColPali의 해결책: OCR을 건너뛰고, 페이지 이미지를 직접 임베딩. 검색을 위해 ColBERT-스타일 늦은 상호작용을 사용하여 모델이 쿼리 시간에 세분화된 패치에 어텐션할 수 있도록 함.

## 개념

### ColBERT (2020)

ColBERT(Khattab & Zaharia, arXiv:2004.12832)는 텍스트 검색 방법입니다. 문서당 하나의 벡터 대신, 토큰당 하나의 벡터를 생성합니다. 쿼리 시간:

- 쿼리 토큰은 자체 임베딩(N_q 벡터)을 얻습니다.
- 문서 토큰은 임베딩(일반적으로 캐시된 N_d 벡터)을 얻습니다.
- 점수 = 쿼리 토큰에 대한 합계(문서 토큰에 대한 코사인 유사도의 최대값): Σ_i max_j cos(q_i, d_j).

이것이 MaxSim 연산입니다. 각 쿼리 토큰은 가장 잘 일치하는 문서 토큰을 "선택"합니다. 최종 점수는 합계입니다.

장점: 강력한 재현율, 용어-수준 의미론 처리. 단점: 문서당 N_d 벡터, 저장 비용 높음.

### ColPali

ColPali(Faysse et al., arXiv:2407.01449)는 ColBERT 패턴을 이미지에 적용합니다.

- 각 페이지는 PaliGemma(ViT + 언어)에 의해 패치 임베딩으로 인코딩됨: 페이지당 N_p 벡터.
- 각 사용자 쿼리(텍스트)는 쿼리-토큰 임베딩으로 인코딩됨: N_q 벡터.
- 점수 = Σ_i max_j cos(q_i, p_j), 즉 쿼리-텍스트-토큰과 페이지-이미지-패치에 대한 MaxSim.
- 총 점수로 상위-k 페이지 검색.

문서 수집 시간: PaliGemma로 모든 페이지를 임베딩하고, 모든 패치 임베딩을 저장. 쿼리 시간: 쿼리 토큰을 임베딩하고, 저장된 모든 페이지 임베딩에 대해 MaxSim을 계산하며, 상위-k 페이지 반환.

장점: 시각적으로 풍부한 문서에서 텍스트-RAG를 20-40% 능가. 각 패치-벡터가 로컬 레이아웃과 내용을 포착.

단점: N_p 패치 × 4-바이트 실수 × D-차원 벡터 페이지당 = 저장 공간 빠르게 증가. PQ / OPQ 양자화로 완화.

### ColQwen2와 ColSmol

ColQwen2(illuin-tech, 2024-2025)는 PaliGemma를 Qwen2-VL로 교체. 더 나은 기본 인코더, 더 나은 검색.

ColSmol은 로컬 / 엣지 사용을 위한 소규모 변형. ~1B 매개변수의 ColSmol 검색기가 소비자 GPU에서 실행.

### VisRAG

VisRAG(Yu et al., arXiv:2410.10594)는 다른 변형: 패치에 대한 MaxSim 대신, VLM으로 각 페이지를 단일 벡터로 풀링한 다음 바이-인코더 검색. 더 빠른 인덱싱 + 더 작은 저장 공간, 더 약한 재현율.

품질-vs-비용 트레이드오프: 품질을 위해 ColPali, 규모를 위해 VisRAG.

### M3DocRAG

M3DocRAG(Cho et al., arXiv:2411.04952)는 멀티-모달 검색을 다중-페이지 다중-문서 추론으로 확장. 문서 간 페이지 검색, VLM을 위한 다중-페이지 컨텍스트 구성.

### ViDoRe — 벤치마크

ColPali의 동반 벤치마크. Visual Document Retrieval Evaluation. 작업에는 재무 보고서, 과학 논문, 행정 문서, 의료 기록, 매뉴얼 포함. 메트릭: nDCG@5.

ColPali-v1은 ViDoRe에서 ~80% nDCG@5 점수; 동일한 문서에 대한 텍스트-RAG는 ~50-60% 점수.

### 종단간 RAG 파이프라인

비전-네이티브 RAG의 경우:

1. 수집: PDF → 페이지 이미지 → PaliGemma 인코딩 → 모든 패치 임베딩 저장.
2. 쿼리: 사용자 텍스트 → 쿼리-토큰 임베딩 → 모든 인덱싱된 페이지에 대한 MaxSim → 상위-k 페이지.
3. 생성: 상위-k 페이지 이미지 + 쿼리 → VLM(Qwen2.5-VL 또는 Claude) → 답변.

어디에도 OCR 없음. 그림, 차트, 글꼴, 레이아웃 모두 답변으로 흐름.

### 저장 공간 계산

페이지당 729개 패치와 128-차원 임베딩의 50페이지 재무 보고서:

- ColPali: 50 * 729 * 128 * 4 바이트 = ~18 MB 원시, PQ 후 ~4 MB.
- 텍스트-RAG: 50개 청크 * 768-차원 * 4 바이트 = ~150 kB.

ColPali는 문서당 ~30배 더 많은 저장 공간. 대규모에서 OPQ / PQ는 이를 ~5-10배로 낮추며, 일반적으로 허용 가능.

### 텍스트-RAG가 여전히 승리하는 경우

- 레이아웃 신호가 없는 순수-텍스트 문서(위키 기사, 채팅 로그). 텍스트-RAG가 더 간단하고 저장-비용이 저렴.
- 저장 비용이 지배적인 수백만 페이지 아카이브.
- 검색과 함께 추출 가능한 OCR 텍스트를 요구하는 엄격한 규제 요구 사항.

2026년의 다른 모든 것 — 재무 보고서, 과학 논문, 법적 계약, 의료 기록, UX 문서 — 비전-네이티브 RAG가 승리.

## 사용하기

`code/main.py`:

- 장난감 패치 인코더: "페이지"(특징 벡터의 작은 그리드)를 패치 임베딩 배열에 매핑.
- MaxSim 스코어러: 쿼리 토큰 임베딩 세트와 페이지 패치 세트 간 ColBERT-스타일 점수 계산.
- 5개의 장난감 페이지 인덱싱, 3개의 쿼리 실행, 점수와 함께 상위-k 반환.

## 연습 문제

1. 페이지당 729개 패치, 128-차원 임베딩, 4-바이트 실수의 200페이지 연례 보고서. 원시 저장 공간과 PQ-압축(8x) 저장 공간을 계산하세요.

3. ColPali는 페이지를 패치 세트로 인덱싱합니다. 대신 단어 수준(ColBERT가 하는 대로)으로 인덱싱하면 무엇이 바뀌나요? 트레이드오프?

4. 쿼리당 500ms 지연 시간 예산으로 100만-페이지 코퍼스에 대한 종단간 파이프라인을 설계하세요. ColQwen2 / VisRAG를 선택하고 정당화하세요.

5. M3DocRAG(arXiv:2411.04952)를 읽으세요. 다중-페이지 어텐션 패턴을 설명하고 단일-페이지 ColPali 검색과 어떻게 다른지 설명하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|----------|
| Late interaction | "ColBERT 스타일" | 단일 문서 벡터가 아닌 토큰당 또는 패치당 임베딩 + MaxSim을 사용한 검색 |
| MaxSim | "패치에 대한 최대" | 각 쿼리 토큰에 대해 가장 유사도가 높은 문서 토큰 선택; 쿼리 전체에 합산 |
| Bi-encoder | "단일-벡터" | 문서당 하나의 벡터; 더 빠르지만 세분성 손실 |
| Multi-vector | "문서당 다중-벡터" | 문서/페이지당 N_p 벡터 저장; 저장 비용 증가但 재현율 향상 |
| Patch embedding | "페이지 특징" | VLM 인코더에서 이미지 패치당 하나의 벡터, 페이지당 캐시됨 |
| ViDoRe | "비전 문서 벤치" | 시각적 문서 검색을 위한 ColPali의 벤치마크 제품군 |
| PQ quantization | "제품 양자화" | 저장 공간을 ~8배 줄이면서 벡터 유사성을 유지하는 압축 |
