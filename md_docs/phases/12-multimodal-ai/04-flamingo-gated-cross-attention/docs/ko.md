# Flamingo와 Few-Shot VLM을 위한 게이트된 교차 어텐션

> DeepMind의 Flamingo(2022)는 누구보다 먼저 두 가지를 했다. 단일 모델이 이미지와 비디오와 텍스트의 임의로 인터리브된 시퀀스를 처리할 수 있음을 보여주었다. 그리고 VLMs가 인컨텍스트에서 학습할 수 있음을 보여주었다 — 몇 개의 샷 프롬프트에 3개의 예시 (이미지, 캡션) 페어를 주고 모델이 어떤 그래디언트 단계 없이 새로운 이미지에 캡션을 답는다. 메커니즘: 게이트된 교차 어텐션 레이어, 동결 LLM의 기존 레이어 사이에 삽입되고, 초기화 시 LLM의 텍스트 능력이 보존되도록 0에서 시작하는 학습된 tanh 게이트. 이 레슨은 Flamingo의 Perceiver 리샘플러와 게이트된 교차 어텐션 아키텍처를 따라간다 — Gemini의 인터리브된 입력과 Idefics2의 시각 토큰의 조상.

**유형:** 학습
**언어:** Python (stdlib, 게이트된 교차 어텐션 + Perceiver 리샘플러 데모)
**선수 과목:** Phase 12 · 03 (BLIP-2 Q-Former)
**소요 시간:** ~120분

## 학습 목표

- tanh(gate) = 0을 통해 초기화 시 동결 LLM의 텍스트 능력을 보존하는 게이트된 교차 어텐션의 작동 방식 설명.
- N 이미지 패치 → K 고정 "latent" 쿼리를 교차 어텐션을 통해 생성하는 Perceiver 리샘플러 따라가기.
- 이미지가 배치되는 것을 존중하는 인과적 마스킹으로 인터리브된 이미지-텍스트 시퀀스를 Flamingo가 처리하는 방식 설명.
- few-shot 멀티모달 프롬프트 구조再現 (3개 이미지-캡션 예제 then 쿼리 이미지).

## 문제

BLIP-2는 32개의 시각 토큰을 동결 LLM의 입력 레이어에 공급한다. 프롬프트당 하나의 이미지에 작동한다. 하지만 "여기 이미지 A, 그것에 캡션을 답; 여기 이미지 B, 그것에 캡션을 답; 이제 여기 이미지 C, 그것에 캡션을 답"처럼 인터리브된 많은 이미지와 텍스트를 공급하고 싶다면 어떻게 할까? LLM의 자기 어텐션은 단일 스트림에서 이미지 토큰과 텍스트 토큰을 처리해야 하며, 어떤 위치가 어떤 이미지에 attend할 수 있는지에 대한 질문이 복잡해진다.

Flamingo의 답변: LLM의 입력 스트림을 전혀 변경하지 마라. 기존 LLM 블록 사이에 추가 교차 어텐션 레이어를 삽입한다. 텍스트 토큰은 여전히平常 대로 LLM의 인과적 자기 어텐션을 통해 흐른다. 몇 개의 LLM 블록마다, 텍스트 토큰은 새로운 게이트된 레이어를 통해 이미지 피처에 교차 어텐션한다. 게이트(0으로 초기화)는 단계 0에서 새로운 레이어가 노프임이다 — 모델은 사전훈련된 LLM과 정확히 동일하게 동작한다. 훈련이 진행됨에 따라 게이트가 열리고 시각 정보가 흐르기 시작한다.

Flamingo가答えた 두 번째 질문: 프롬프트당 가변 수의 이미지(0, 1, 또는 많음)를 어떻게 처리하는가? Perceiver 리샘플러 — 패치 수에 관계없이Whatever数量的を入力하고 고정数量的 시각 잠재 토큰을 생성하는 작은 교차 어텐션 모듈. LLM 교차 어텐션 레이어는 프롬프트에 이미지가 몇 개든 동일한 형태를 본다.

## 개념

### 동결 LLM

Flamingo는 동결된 Chinchilla 70B LLM에서 시작한다. 모든 70B 가중치 미손상. 기존 텍스트 자기 어텐션과 FFN이正常に作動한다.

### Perceiver 리샘플러

프롬프트의 각 이미지에 대해 ViT는 N개의 패치 토큰을 생성한다. Perceiver 리샘플러는 K개의 고정 학습 가능한 잠재(flamingo는 K=64 사용)가 있다. 각 리샘플러 블록은 두 하위 단계다:

1. 교차 어텐션: K개의 잠재가 N개의 패치 토큰에 attend(Q from latents, K/V from patches).
2. 잠재 내의 자기 어텐션 + FFN.

6개의 리샘플러 블록 후, 출력은 ViT가 생성한 패치 수에 관계없이 차원 1024의 K=64 시각 토큰이다. 224x224 이미지(196 패치)와 480x480 이미지(900 패치) 모두 64개의 리샘플러 토큰으로 출력된다.

비디오의 경우, 리샘플러가 시간적으로 적용된다: 각 프레임의 패치가 64개의 잠재를 생성하고, 시간적 위치 인코딩이 모델이 t=0과 t=N을 구별할 수 있게 한다. 전체 비디오는 T * 64개의 시각 토큰이 된다.

### 게이트된 교차 어텐션

동결 LLM의every M 레이어마다(M=4 사용), 새로운 게이트된 교차 어텐션 블록을 삽입한다:

```
x_after_llm_block = llm_block(x_before)
cross = cross_attn(x_after, resampler_output)
gated = tanh(alpha) * cross + x_after
x_before_next_block = gated
```

- `alpha`는 0으로 초기화된 학습 가능한 스칼라.
- `tanh(0) = 0`, init에서 게이트 분기가 0 기여.
- `alpha`가 0에서 멀어지면 교차 어텐션 기여가 부드럽게 성장.
- 잔차 연결은 완전히 열린 게이트도 LLM의 텍스트 표현을 덮어쓰지 않음을 의미; 시각 정보를 위에 추가할 뿐.

Flamingo에서 가장 중요한 설계 선택: 시각 conditioning은 추가적이고 게이트되며 초기화 시 0이다. 단계 0의 Flamingo는 텍스트 전용 입력에서 완벽한 Chinchilla 70B다.

### 인터리브된 입력에 대한 마스킹된 교차 어텐션

`<image A> caption A <image B> caption B <image C> ?`와 같은 프롬프트에서 각 텍스트 토큰은 시퀀스에서 그것보다 먼저온 이미지만 봐야 한다. 교차 어텐션 마스크가 강제한다: 위치 `t`의 텍스트 토큰은 가장 최근 이미지 인덱스 `i_t`보다 작은 이미지 인덱스 `i`를 가진 이미지의 리샘플러 토큰에만 attend한다. "가장 최근 이전 이미지만 보기" 또는 "이전 모든 이미지 보기"는 모두 유효한 선택; Flamingo는 전자를 선택했다.

### 인컨텍스트 few-shot 학습

Flamingo 프롬프트는 다음과 같다:

```
<image1> A photo of a cat. <image2> A photo of a dog. <image3> A photo of a
```

모델은 완성 패턴을 보고 "bird"(또는 image3이 무엇이든)를 출력한다. 그래디언트 단계 없음. 동결 LLM의 인컨텍스트 학습 능력이 게이트된 교차 어텐션을 통해 전달된다 — 이것이 논문의 핵심이고 그것이 중요한 이유다.

### 훈련 데이터

Flamingo는 세 가지 데이터셋에서 훈련했다:

1. MultiModal MassiveWeb (M3W): 인터리브된 이미지와 텍스트가 있는 43M 웹 페이지, 읽기 순서 재구성.
2. 이미지-텍스트 페어 (ALIGN + LTIP): 4.4B 페어.
3. 비디오-텍스트 페어 (VTP): 27M 짧은 비디오 클립.

OBELICS(2023)는 인터리브된 웹 코퍼스의 오픈 재생이며, Idefics, Idefics2 및 대부분의 오픈 "Flamingo 유사" 모델이 훈련한다.

### OpenFlamingo와 Otter

OpenFlamingo(2023)는 오픈 재생이다. 아키텍처 동일(Perceiver 리샘플러 + 동결 LLaMA 또는 MPT의 게이트된 교차 어텐션). 3B, 4B, 9B에서 체크포인트. 더 작은 기본 LLM과 더 적은 데이터로 품질이 뒤처진다.

Otter(2023)는 MIMIC-IT(멀티모달 지시의 데이터셋)에 대한 명령 튜닝으로 OpenFlamingo를 기반으로 구축하여 게이트된 교차 어텐션이 명령 따르기에도 작동함을 보여준다.

### 후손

- Idefics / Idefics2 / Idefics3: Hugging Face의 게이트된 교차 어텐션 계보, 점진적으로 단순화(Idefics2는 적응형 풀링으로 직접 패치 토큰 대신 리샘플러를 삭제).
- Flamingo-to-Chameleon 전환: 2024년까지 많은 팀이 초기 융합(레슨 12.11)으로 이동했다; 백본 동결이 필요한 곳에서는 Flamingo 스타일 게이트된 교차 어텐션이 프로덕션에 남아 있다.
- Gemini의 인터리브된 입력: 개념적으로 Flamingo의 인터리브된 형식 유연성을 상속하지만 정확한 메커니즘은 독점적이다.

### BLIP-2와의 비교

| | BLIP-2 | Flamingo |
|---|---|---|
| 시각 브릿지 | 입력에서 한 번의 Q-Former | 모든 M 레이어에서 게이트된 교차 어텐션 |
| 시각 토큰 | 이미지당 32개 | 교차 어텐션 레이어당 이미지당 64개 |
| 동결 LLM | 예 | 예 |
| Few-shot 인컨텍스트 | 약함 | 강함 — 논문의 핵심 |
| 인터리브된 입력 | 네이티브 지원 없음 | 예, 설계 대상 |
| 훈련 데이터 | 130M 페어 | 1.3B 페어 + 43M 인터리브된 페이지 |
| 파라미터 수 | 188M 훈련 | ~10B 훈련(교차 어텐션 레이어) |
| 컴퓨트 | 8 A100에서 며칠 |数千 TPUv4에서 몇 주 |

 예산으로 단일 이미지 VQA에는 BLIP-2를 선택. 인터리브드, few-shot 또는 멀티이미지 추론에는 Flamingo/Idefics2를 선택.

## 활용

`code/main.py` 데모:

1. 8개의 학습 가능한 잠재가 있는 36개의 가짜 패치 토큰에 대한 Perceiver 리샘플러(순수 Python 교차 어텐션).
2. `alpha = 0` → 출력이 입력과 동일(LLM 변경 없음), then `alpha = 2.0` → 시각 기여 혼합된 게이트된 교차 어텐션 단계.
3. "(image 1) (text 1) (image 2) (text 2)" 시퀀스에 대한 2D 어텐션 마스크를 생성하는 인터리브드 마스크 빌더.

## 결과물

이 레슨은 `outputs/skill-gated-bridge-diagnostic.md`를 생성한다. 오픈 VLM의 구성(리샘플러 Y/N, 교차 어텐션 빈도, 게이트 방식)이 주어지면 Flamingo 계보 요소를 식별하고 동결 전략을 설명한다. 미세조정이 텍스트 성능을 저하시킨 이유를 디버깅하는 데有用(답: 게이트가 너무 빨리 너무 넓어졌다).

## 연습 문제

1. Flamingo-9B의 시각 파라미터 수 계산: 9B LLM + 1.4B 게이트된 교차 어텐션 레이어 + 64M 리샘플러. 훈련된 총 파라미터의几分?

2. PyTorch에서 게이트된 잔차 `y = tanh(alpha) * cross + x`를 구현한다. `alpha=0`으로 init에서 `y==x`임을 실험적으로 보여준다.

3. 배치에서 각 프롬프트가 다른 이미지 수를 가질 때 OpenFlamingo가 여러 이미지를 처리하는 방식(arXiv:2308.01390) 섹션 3.2를 읽는다. 패딩 전략을 설명한다.

4. Flamingo의 교차 어텐션 마스킹이 텍스트 토큰이 모든 이전 이미지가 아닌 *가장 최근 이전* 이미지에만 attend하도록 하는 이유는 무엇인가? Flamingo 논문 섹션 2.4를 읽고 트레이드오프를 설명한다.

5. 인컨텍스트 few-shot: 새로운 Flamingo 변형에 대해 "이미지 → 메인 객체의 색상"에 대한 4개의 예제로 프롬프트를 구성한다. 예제 수를 0에서 8으로 변경할 때 예상 정확도 패턴을 설명한다.

## 핵심 용어

| 용어 |人们在说什么 | 실제 의미 |
|------|----------------|------------------------|
| Perceiver 리샘플러 | "고정-latent 교차 어텐션" | 가변数量的 입력 패치에서 K개의 고정 토큰을 생성하는 모듈 |
| 게이트된 교차 어텐션 | "Tanh 게이트 브릿지" | 잔차 레이어 `y = tanh(alpha)*cross + x`, 학습 가능한 alpha, init 0 |
| 인터리브된 입력 | "혼합 시퀀스" | 읽기 순서로 이미지와 텍스트가 자유롭게 혼합된 프롬프트 형식 |
| 동결 LLM | "LLM 그래디언트 없음" | 텍스트 LLM의 가중치가 업데이트되지 않음; 리샘플러 + 교차 어텐션 레이어만 훈련 |
| Few-shot | "인컨텍스트 예제" | 프롬프트에 몇 개의 (이미지, 답변) 페어를 제공; 미세조정 없이 모델이 일반화 |
| OBELICS | "인터리브드 웹 코퍼스" | 읽기 순서로 이미지와 텍스트가 있는 141M 웹 페이지의 오픈 데이터셋 |
| Chinchilla | "70B 동결 기본" | Flamingo의 동결 텍스트 LLM, DeepMind의 Chinchilla 논문에서 |
| 게이트 스케줄 | "alpha가 어떻게 움직이는지" | 훈련 중 교차 어텐션 게이트가 열리는 속도 |
| 교차 어텐션 빈도 | "every M 레이어" | 게이트된 교차 어텐션 블록이 삽입되는 빈도; Flamingo는 M=4 사용 |
| OpenFlamingo | "오픈 재생" | MosaicML/LAION 3-9B의 오픈 체크포인트; Flamingo와 아키텍처 동일 |
