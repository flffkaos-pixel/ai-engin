# MIO와 Any-to-Any 스트리밍 멀티모달 모델

> GPT-4o는 대부분의 오픈 모델이 복제할 수 없는 제품을 제공합니다: 음성을 듣고, 비디오를 보고, 실시간으로 응답하는 에이전트. 2024년 후반까지의 오픈 생태계 응답은 MIO(Wang et al., 2024년 9월)였습니다. MIO는 텍스트, 이미지, 음성, 음악을 토큰화하고, 하나의 인과적 트랜스포머를 인터리브된 시퀀스 위에서 학습하며, 모든 모달리티에서 모든 모달리티로 생성합니다. AnyGPT(Zhan et al., 2024년 2월)는 개념 증명이었고, MIO는 확장 버전입니다; Unified-IO 2(Allen AI, 2023년 12월)는 비전 + 행동 grounding을 가진 사촌입니다. 이 레슨은 any-to-any 패턴 — 네 개의 토크나이저, 하나의 트랜스포머, 스트리밍 친화적 디코딩 — 을 읽습니다.

**Type:** Learn
**Languages:** Python (stdlib, four-modality token allocator + streaming decode loop)
**Prerequisites:** Phase 12 · 11 (Chameleon), Phase 6 (Speech and Audio)
**Time:** ~120 minutes

## 학습 목표

- 충돌 없이 텍스트, 이미지, 음성, 음악 토큰을 호스팅하는 공유 어휘를 설계한다.
- SEED-Tokenizer(이미지)와 SpeechTokenizer residual-VQ(음성)를 압축 + 재구성 트레이드오프 측면에서 비교한다.
- any-to-any 생성을 구축하는 4단계 커리큘럼을 설명한다.
- 세 가지 오픈 any-to-any 레시피와 주요 트레이드오프를 나열한다: MIO, AnyGPT, Unified-IO 2.

## 문제

통합 멀티모달 모델은 주장하기는 쉽지만 대규모로 구축하기는 어렵습니다. 2024년까지의 대부분 "any-to-any" 시스템은 파이프라인 방식이었습니다: 비전 모델 → 텍스트 표현 → 음성 모델 → 오디오. 각 단계에서 정보가 손실되고, 지연 시간이 추가되며, 학습이 복잡해집니다. GPT-4o의 데모 비디오는 1초 미만 응답의 단일 모델 대안을 보여주었습니다; 오픈 시스템은 몇 달 뒤쳐졌습니다.

엔지니어링 과제:

- 모든 모달리티에 대한 토크나이저가 존재해야 하며, 재구성에 충분히 무손실에 가깝게 압축해야 하고, 트랜스포머가 소비할 수 있는 속도로 토큰을 생성해야 합니다.
- 단일 어휘는 텍스트(32k+), 이미지(16k+), 음성(4k+), 음악(8k+)을 위한 공간을 할당해야 합니다. 최소 4만 개 이상의 항목.
- 학습 데이터는 모든 입력-출력 쌍(텍스트→이미지, 이미지→음성, 음성→이미지 등)을 포함해야 하거나 모델이 구성할 수 있어야 합니다.
- 추론은 대화형 지연 시간(<500ms 첫-오디오-바이트-까지-시간)에 충분히 빠르게 출력 토큰을 스트리밍해야 합니다.

## 개념

### 4개 모달리티를 위한 4개 토크나이저

MIO의 토크나이저 스택:

- 텍스트: 표준 BPE, 어휘 ~32000.
- 이미지: SEED-Tokenizer (2023) — 이산 코드북을 가진 양자화된 VAE, 4096개 항목, 이미지당 32x32 토큰.
- 음성: SpeechTokenizer residual-VQ (2023) — 16kHz 파형을 8개 계층적 코드북으로 인코딩; 첫 번째 레벨은 대략적인 내용, 이후 레벨은 운율과 화자 identity 추가.
- 음악: 유사한 residual-VQ(Meta의 MusicGen / Encodec 계열), 4-8개 코드북.

각 모달리티는 정수 토큰을 생성합니다. 토큰은 공유 어휘에서 분리된 ID 범위를 얻습니다:

```
text:   0..31999
image:  32000..36095  (4096개 이미지 토큰)
speech: 36096..40191  (4096개 음성 기본 토큰, 잔차 레이어 추가)
music:  40192..48383  (8192개 음악 토큰)
sep:    48384..48390  (<image>, <speech>, <music>, </...> 등)
```

총계: ~48k 어휘. 입력 임베딩과 출력 투영이 모두 이를 포함합니다.

### 스트리밍 디코드

음성 생성은 residual-VQ를 사용합니다. 트랜스포머는 기본(레이어 0) 음성 토큰을 예측합니다; 병렬 디코딩된 잔차 양자화기가 이후 레이어를 예측합니다. 각 레이어 0 토큰은 16kHz에서 약 50ms의 오디오입니다.

스트리밍 패턴:

1. 사용자가 마이크로 말함; 실시간 오디오 토크나이저가 50ms마다 음성 토큰을 방출.
2. MIO가 토큰이 도착할 때 소비(프롬프트 프리필 + 증분 순전파).
3. 출력 토큰이 생성될 때 스트리밍; 병렬 음성 디코더가 약 50-150ms 지연 시간으로 오디오 샘플로 변환.
4. 첫-오디오-바이트-까지-시간: MIO 논문에서 ~300-500ms, GPT-4o의 ~250ms에 접근.

Mini-Omni(arXiv:2408.16725), GLM-4-Voice(arXiv:2412.02612), Moshi(arXiv:2410.00037)는 보완적인 스트리밍 음성-LLM 설계입니다. 특히 Moshi는 단일 GPU에서 160ms 왕복을 달성합니다.

### 4단계 커리큘럼

MIO의 학습 커리큘럼:

1. 1단계 — 정렬. 대규모 모달리티-쌍 코퍼스: 텍스트-이미지, 텍스트-음성, 텍스트-음악. 각 쌍은 자체 토큰 어휘 세그먼트를 사용합니다. 공유 어휘를 학습.
2. 2단계 — 인터리브. 다중-모달리티 인터리브 문서(이미지 + 비디오가 있는 블로그, 대본이 있는 팟캐스트 등). 교차-모달리티 컨텍스트 학습.
3. 3단계 — 음성 강화. 텍스트 능력을 잃지 않고 음성 품질을 높이기 위한 추가 오디오 데이터.
4. 4단계 — SFT. 모달리티 전반의 명령어 튜닝: VQA, 캡셔닝, 내레이션, 음성-음성 대화.

단계를 누락하면 특정 능력이 저하됨: 2단계를 건너뛰면 모델이 교차-모달리티 컨텍스트를 잃음; 3단계를 건너뛰면 음성이 나빠짐.

### 시각적 사고의 사슬

MIO는 시각적 사고의 사슬(chain-of-visual-thought)을 도입합니다: 모델이 추론 단계로 중간 이미지 토큰을 방출합니다. "고양이가 나무에 오르고 있나요?"에 대해 모델은:

1. 장면을 렌더링하는 `<image>` 토큰 방출(입력 이미지 또는 스케치에서).
2. 스케치를 분석하는 텍스트 방출.
3. 최종 답변 방출.

렌더링된 중간 이미지는 스크래치패드 역할을 합니다. 공간 추론 작업에서 벤치마크가 향상됩니다. 아이디어는 텍스트 추론을 위한 사고의 사슬을 반영합니다.

### Any-to-Any 경쟁자

- AnyGPT (arXiv:2402.12226): 4개 모달리티(텍스트, 이미지, 음성, 음악), 유사한 설계.
- Unified-IO 2 (arXiv:2312.17172): 비전 행동 출력, 깊이, 법선 맵 추가. 더 다양한 작업, 더 작은 규모.
- NExT-GPT (arXiv:2309.05519): LLM + 모달리티별 확산 디코더. 단일 모델 접근 방식이 아님.
- CoDi (arXiv:2305.11846): 구성 가능한 확산; 공유 잠재 변수를 통한 any-to-any.

MIO는 순수-토큰 any-to-any에 가장 가깝습니다. AnyGPT는 개념적 조상입니다.

### 지연 시간 예산

대화형 제품의 경우, 모든 구성 요소의 지연 시간이 중요합니다:

- 마이크에서 오디오 토큰까지: ~50ms.
- 프리필(오디오 토큰 + 기록): 8B 모델에서 ~100ms.
- 첫 출력 토큰: ~50ms.
- 병렬 residual-VQ + 음성 디코더: ~100-150ms.

총 첫-오디오-바이트-까지-시간: 최소 ~300ms. GPT-4o는 ~250ms 주장. Moshi는 160ms 주장. MIO/AnyGPT는 공개 벤치마크당 400-600ms 범위.

### Any-to-Any가 여전히 어려운 이유

2026년에도 오픈 any-to-any 모델은 두 가지 축에서 폐쇄형에 뒤쳐집니다:

- 음성 품질. residual-VQ 토크나이저는 손실이 있습니다; 대화형 음성이 ElevenLabs-급 음성에 비해 로봇처럼 들립니다.
- 교차-모달리티 추론. "보이는 것에 대해 노래해봐"라고 요청하는 것은 순수-비전 작업보다 여전히 더 자주 실패합니다.

이것은 공개 연구 문제입니다. Qwen3-Omni(레슨 12.20)는 2025년 가장 진보된 오픈 시도입니다.

## 사용하기

`code/main.py`:

- 4-모달리티 어휘 할당을 정의하고 출력합니다.
- 멀티모달 입력 목록(텍스트, 이미지, 오디오-클립, 음악)을 토크나이저 라우터를 통해 라우팅합니다.
- 지연 시간 계산과 함께 텍스트-음성 응답에 대한 스트리밍 디코드를 시뮬레이션합니다.
- 인코더, 프리필, 디코더 지연 시간이 주어졌을 때 예상 첫-오디오-바이트-까지-시간을 계산합니다.

## 연습 문제

1. 귀하의 제품은 음성 입력을 받아 음성 출력을 반환합니다. 종단간 지연 시간 예산 목표는 얼마인가요? 시간을 소비하는 구성 요소를 나열하세요.

2. SpeechTokenizer residual-VQ는 8개의 코드북을 사용합니다. 잔차 레벨의 병렬 디코딩이 왜 필요한지(순차적 대신)와 어떤 지연 시간 절감을 가져오는지 제안하세요.

3. 귀하의 어휘는 32k 텍스트 + 4k 이미지 + 4k 음성을 가집니다. 8k 음악과 ~10개의 구분자를 추가하세요. 히든 차원 4096에서 임베딩-행렬 매개변수 비용은 얼마인가요?

4. 시각적 사고의 사슬은 중간 이미지를 방출합니다. 어떤 종류의 질문이 혜택을 받나요? 어떤 종류가 추가 토큰으로 인해 손해를 보나요?

5. Moshi(arXiv:2410.00037)를 읽으세요. "내적 독백(inner monologue)" 기법을 설명하고 MIO의 시각적 사고의 사슬과 비교하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|----------|
| Any-to-any | "멀티모달 입/출력" | 텍스트, 이미지, 음성, 음악을 모든 방향으로 수용하고 방출하는 단일 모델 |
| Residual-VQ | "음성 토크나이저 스택" | 각 레이어가 정보를 추가하는 다중-코드북 토큰화; 기본 레이어는 내용, 이후 레이어는 운율 |
| SEED-Tokenizer | "이미지 코드" | MIO가 사용하는 4096개 항목 코드북을 가진 이산 이미지 토크나이저 |
| Chain-of-visual-thought | "시각적 스크래치패드" | 모델이 최종 답변 전에 추론 단계로 중간 이미지를 생성함 |
| Time-to-first-audio-byte | "TTFAB" | 사용자 음성에서 첫 오디오 출력까지의 지연 시간; 대화형 감각을 위해 <500ms |
| Four-stage curriculum | "학습 레시피" | 정렬 -> 인터리브 -> 음성 강화 -> SFT, 순서대로 |
