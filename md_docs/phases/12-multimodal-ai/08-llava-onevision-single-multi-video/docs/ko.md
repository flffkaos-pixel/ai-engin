# LLaVA-OneVision: 하나의 모델에서 단일 이미지, 멀티이미지, 비디오

> LLaVA-OneVision(Li 등, 2024년 8월) 이전에 오픈 VLM 세계에는 별도의 계보가 있었다: 단일 이미지를 위한 LLaVA-1.5, Mantis와 VILA 같은 멀티이미지 모델, Video-LLaVA와 Video-LLaMA 같은 비디오 모델. 각각이 자신의 벤치마크에서 이기고 다른 곳에서는 실패했다. LLaVA-OneVision은 단일 커리큘럼이 세 가지 시나리오를 모두 지배하는 하나의 모델을 훈련할 수 있다고 주장했고, 그리고 비상적 태스크 전송 효과(단일 이미지 스킬이 비디오로 내보내기, 멀티이미지 추론이 단일 이미지로 내보내기)가 전문가들의 합보다 뛰다는 것이었다. 레시피는 단순하다: 시나리오 전반에 일정하게 유지되는 시각 토큰 예산, plus 단일 이미지에서 OneVision(멀티이미지)으로 비디오로 이동하는 명시적 커리큘럼. 이 레슨은 예산, 커리큘럼, 비상적 동작을 읽는다.

**유형:** 실습
**언어:** Python (stdlib, 토큰 예산 솔버 + 커리큘럼 플래너)
**선수 과목:** Phase 12 · 05 (LLaVA), Phase 12 · 06 (임의 해상도)
**소요 시간:** ~180분

## 학습 목표

- 단일 이미지, 멀티이미지, 비디오 입력 전반에 일정하게 유지되는 시각 토큰 예산을 설계한다.
- catastropic forgetting 없이 단일 이미지에서 비디오로 스킬을 전송하는 훈련 커리큘럼을 주문한다.
- 커리큘럼이 올바르게 수행되면 동일한 파라미터 수에서 단일 모델이 전문가를 이기는 이유를 설명한다.
- LLaVA-OneVision이 보고한 세 가지 비상적 능력 назвать: 멀티카메라 추론, 세트오브마크 프롬프팅, iPhone 스크린샷 에이전트.

## 문제

이미지, 멀티이미지, 비디오는 각각 다르게 모델에 부담을 준다.

단일 이미지는 고해상도 토큰(AnyRes, ~2880 시각 토큰)을 원한다. 샘플당 예산: 하나의 이미지, 2880 토큰.

멀티이미지는 moderate 해상도(~576 토큰 각)에서 여러 이미지를 원한다 그래서 이미지 간 추론이 컨텍스트에 적합하다. 샘플당 예산: 4-8 이미지, 각각 576, 2300-4600 토큰.

비디오는 낮은 해상도(~196 토큰 per frame after pooling)에서 많은 프레임을 원한다 temporal dynamics를 캡처하기 위해. 샘플당 예산: 8-32 프레임, 각각 196, 1600-6200 토큰.

별도의 모델을 훈련시키면 하나의 예산을 선택한다. 하나의 모델을 훈련시키면 예산이 컨텍스트를 폭발시키지 않고 시나리오 전반에 합리적으로 확장되어야 한다.

Pre-OneVision, 기본 답변은 "하나의 시나리오를 훈련시키고, 다른 것은 무시"였다. Video-LLaVA는 추가 훈련 단계로 비디오를 이미지 모델에 맞게改造했다. LLaVA-NeXT는 타이링으로 멀티이미지 지원을 추가했다. 세 가지 모두 깔끔하게 처리하지 못했다.

## 개념

### OneVision 토큰 예산

LLaVA-OneVision은 샘플당 approximately 3000-4000 토큰의 통합 시각 토큰 예산을 선택하며, 시나리오별로 다르게 할당된다:

- 단일 이미지: AnyRes-9(3x3 타일 + 썸네일), 각각 384에서 729 패치의 각 타일, 공격적인 2x2 볼리니어 풀링 → 타일당 182. 총계: 9 * 182 + 182 = 1820 토큰. 또는 729-퍼-타일에서 AnyRes-4 = 2916 + 729.
- 멀티이미지: 각각 moderate 해상도(384, 타이링 없음), 729 토큰 풀링 없음. 예산 6 이미지 → 4374 토큰.
- 비디오: 공격적인 3x3 볼리니어 풀리로 384 해상도에서 32 프레임 → 프레임당 81 토큰. 총계: 32 * 81 = 2592 토큰.

할당은 roughly 일정한 총 토큰을 유지한다. LLM은 컨텍스트를 폭발시키는 배치를 절대 보지 않는다. 인코더는 시나리오당 다른 지오메트리를 생성하지만 LLM은 동일한 예산을 소비한다.

### 3단계 커리큘럼

LLaVA-OneVision은 세 단계로 훈련한다:

1. 단일 이미지 SFT(SI 단계). 모든 데이터가 단일 이미지+텍스트. 고해상도 AnyRes 입력에서 훈련. 이것은 지각, OCR, 세밀한 이해를 가르친다. LLaVA-NeXT 데이터 plus OneVision 특정 단일 이미지 데이터를 사용.
2. OneVision SFT(OV 단계). 통합된 토큰 예산에서 단일 이미지 + 멀티이미지 + 비디오 혼합(균일하게 샘플링된 프레임). 이종 배치 형태를 처리하는 모델을 훈련. 가중치 재설정 없음 — 1단계에서 계속.
3. 태스크 전송(TT 단계). 일반적으로 제품에 따라 멀티이미지 또는 비디오가 더 무거운 대상 태스크 혼합으로 계속. 선택적 배포 미세조정.

중요: 커리큘럼 순서가 중요하다. 비디오 먼저 또는 멀티이미지 먼저 훈련은 동일한 데이터로도 단일 이미지 성능을 더 나쁘게 만든다. 논문이 이것을 명시적으로 절제한다.

### 커리큘럼 작동 이유

단일 이미지 훈련이 지각 기반을 구축한다. 패치 토큰이 세밀한 시각 피처를 carries; LLM은它们을 텍스트와 통합하는 방법을 학습한다. 멀티이미지와 비디오는 구조적挑战(어떤 이미지가 which, 무엇이 먼저 happened)을 도입하는데, 이는 강력한 지각 기반 없이는 학습하기 어렵다.

처음부터 함께 모든 시나리오를 훈련시키면 모델이 지각을 underfit하고(배치당 단일 이미지 데이터 제한) 구조를 overfit한다(많은 멀티이미지/비디오 데이터). 결과: 교차 이미지 추론 패턴을 따르지만 시각적으로 얕은 모델.

커리큘럼 순서가 1단계에서 지각 강도를 주고 2단계에서 구성적/시간적 추론을 주며,either를 잃지 않는다.

### 비상적 크로스 시나리오 스킬

LLaVA-OneVision 논문은 세 가지 비상적 능력을 보고한다:

1. 멀티카메라 추론. 멀티이미지 + 비디오에서 별도로 훈련; 추론에서 멀티카메라 운전 장면에 대해 추론하도록 요청. 모델은 훈련에서 정확한 형식을 본 적이 없음에도视图을 올바르게 통합한다.
2. 세트오브마크 프롬프팅. 사용자가 번호가 매겨진 표시로 이미지의 개체에 주석을 답는다; 모델이 "표시 3이 표시 7과 관련하여 무엇을 하는가"를 추론한다. 표시도 주석도 훈련되지 않음; 공간 그라운딩 + 멀티이미지 참조의 조합에서 학습.
3. iPhone 스크린샷 에이전트. 사용자가 iPhone 스크린샷을 제공하고 다음 클릭을 계획하도록 요청한다. UI 스크린샷, 사용자 워크플로우 비디오, 멀티이미지 전/후 페어에서 훈련. 에이전트 사용 사례로 일반화.

이들은 훈련된 태스크가 아니다; 그들은 커리큘럼의 구성적 구조에서 나타난다.

### 시각 토큰 풀링

토큰 예산은 풀링을 필요로 한다. OneVision은 2D 패치 그리드에서 볼리니어 보간을 사용: 24x24 = 576 패치가 12x12 = 144(2x 인자) 또는 8x8 = 64(3x 인자)가 된다. 풀링은 지역성을 보존하기 위해 토큰 공간이 아닌 패치 그리드 공간에서 수행된다.

시나리오별 풀링 인자 선택은 그 자체가 하이퍼파라미터다. less 풀링 = 더 많은 토큰 = 더 풍부한 표현. 더 많은 풀링 = 더 적은 토큰 = 더 많은 프레임/이미지 맞음.

### LLaVA-OneVision-1.5

2025년 후속(LLaVA-OneVision-1.5, arXiv 2509.23661)은 훈련 데이터, 모델 가중치, 코드에서 "완전히 오픈"이다. 일부 벤치마크에서 독점 격차를 일치시키고 레시피를 민주화한다. 동일한 커리큘럼, 더 많은 데이터, 더 나은 기본 LLM. 아키텍처 변경 없음.

### Qwen2.5-VL와 대비

Qwen2.5-VL(레슨 12.09)는 다른 선택을 한다. M-RoPE와 동적 FPS를 고정 풀링 대신 사용한다. 예산이 입력과 함께 확장된다 — 1분 비디오는 5초 비디오보다 더 많은 토큰을 사용한다. LLaVA-OneVision은 예산을修正하고 풀링을 확장한다. 둘 다 작동한다; 구성가능성을 예측 가능성을 교환한다.

## 활용

`code/main.py`는 OneVision 스타일 VLM을 위한 커리큘럼 및 예산 플래너다. 샘플당 토큰 예산과 대상 시나리오 혼합(말하여 40% 단일 이미지, 30% 멀티이미지, 30% 비디오)이 주어지면:

- 시나리오별로 해상도, 풀링 인자, 프레임을 할당한다.
- 모든 시나리오가共享 예산 내에 맞는지 확인한다.
- 예상 토큰 수, LLM FLOP,哪些 시나리오가 토큰 부족인지 보고한다.
- 단계별 훈련 일정을 인쇄한다.

통합 시나리오 VLM을 미세조정하거나 VLM 배포의 per-request 비용을 sanity-check하기 위해 사용한다.

## 결과물

이 레슨은 `outputs/skill-onevision-budget-planner.md`를 생성한다. 대상 태스크 분포와 샘플당 예산이 주어지면 AnyRes 인자, 프레임당 풀링, 비디오 프레임 수, 커리큘럼 단계 가중치를 emit한다. 통합 시나리오 VLM을 훈련하거나 미세조정할 때마다 이것을 사용한다.

## 연습 문제

1. 당신의 제품이 80% 단일 이미지, 10% 멀티이미지(2-4 이미지), 10% 비디오(8-16 프레임)을 지원한다. 토큰 예산을 설계한다. 무거운 멀티이미지를 하지 않아서 절약한 추가 예산을 어디에置く가?

2. LLaVA-OneVision 섹션 4.3(비상적 능력)를 읽는다. 커리큘럼이 잠금 해제할 것 같지만 논문이 보고하지 않은 네 번째 비상적 스킬을 제안한다.

3. 커리큘럼 순서를 교환 — 멀티이미지 먼저, 그 다음 단일 이미지, 그 다음 비디오 훈련.哪些 벤치마크가 저하되고 왜인지 예측한다.

4. 논문은 샘플당 8프레임만으로 훈련된 비디오 벤치마크를 보고한다. 추론에서 30초 비디오로 일반화되는가? 무엇이 먼저 부서지는가 — 토큰 예산 또는 시간적 추론?

5. 24x24 패치를 12x12로의 볼리니어 풀링은 차원당 4x 감소다. stdlib Python에서 풀링을 구현하고 각 2x2 블록의 평균이 볼리니어 출력과 일치함을 확인한다.
