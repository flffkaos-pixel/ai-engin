# 멀티모달 에이전트와 컴퓨터 사용 (캡스톤)

> 2026년 최첨단 제품은 스크린샷을 읽고, 버튼을 클릭하고, 웹 UI를 탐색하고, 양식을 작성하고, 워크플로우를 종단간 완료하는 멀티모달 에이전트입니다. SeeClick과 CogAgent(2024)는 GUI 그라운딩 프리미티브를 증명했습니다. Ferret-UI는 모바일을 추가했습니다. ChartAgent는 차트를 위한 시각적 도구 사용을 도입했습니다. VisualWebArena와 AgentVista(2026)는 최첨단이 추구하는 벤치마크입니다 — 심지어 Gemini 3 Pro와 Claude Opus 4.7도 AgentVista의 어려운 작업에서 ~30%를 기록합니다. 이 캡스톤은 Phase 12의 모든 스레드 — 지각(고해상도 VLM), 추론(도구 사용이 있는 LLM), 그라운딩(좌표 출력), 장기 기억, 평가 — 를 하나로 모읍니다.

**Type:** Capstone
**Languages:** Python (stdlib, action schema + agent loop skeleton)
**Prerequisites:** Phase 12 · 05 (LLaVA), Phase 12 · 09 (Qwen-VL JSON), Phase 14 (Agent Engineering)
**Time:** ~240 minutes

## 학습 목표

- 멀티모달 에이전트 루프를 설계한다: 지각 → 추론 → 행동 → 관찰 → 반복.
- VLM이 JSON으로 방출할 수 있는 GUI 그라운딩 출력 스키마(클릭 좌표, 텍스트 입력, 스크롤, 드래그)를 구축한다.
- 스크린샷 전용 에이전트 vs 접근성-트리 에이전트 vs 하이브리드 에이전트를 비교한다.
- 작은 VisualWebArena 슬라이스에서 멀티모달 에이전트 벤치마크 평가를 설정한다.

## 문제

예약 사이트 워크플로우: "4월 15일 도쿄行 항공편, 통로 좌석, 800달러 미만, 예약해줘."

멀티모달 에이전트는 다음을 필요로 합니다:

1. 브라우저의 스크린샷 촬영.
2. 스크린샷 + URL + 목표를 계획으로 파싱.
3. 구조화된 행동 방출: 클릭(x,y), "Tokyo" 입력(요소 E), 아래로 스크롤, 선택(라디오 버튼).
4. 브라우저에 행동 적용.
5. 새 상태 관찰(다음 스크린샷).
6. 작업이 완료될 때까지 반복.

각 단계는 멀티모달 VLM 호출입니다. VLM 출력은 파싱 가능한 JSON이어야 합니다. 오류는 단계에 걸쳐 누적되므로 복구가 중요합니다.

## 개념

### GUI 그라운딩 — 프리미티브

GUI 그라운딩은: 스크린샷과 자연어 명령이 주어졌을 때, 클릭할 (x, y) 좌표(또는 다른 행동)를 출력하는 것입니다.

SeeClick(arXiv:2401.10935)은 대규모 최초의 오픈 결과였습니다: 합성 + 실제 GUI 데이터에 VLM을 미세 조정하고, 좌표를 일반 텍스트 토큰으로 출력. 작동.

CogAgent(arXiv:2312.08914)는 밀집된 UI를 위한 1120x1120 고해상도 인코딩을 추가. 점수: 웹 내비게이션에서 ~84%.

Ferret-UI(arXiv:2404.05719)는 모바일 UI에 초점을 맞추고 iOS 접근성 데이터와 통합.

출력 형식은 일반적으로 JSON:

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "검색 버튼"}
```

`element_desc`는 복구에 도움: 스크린샷 간 좌표가 어긋나면, 의미적 힌트가 시스템이 재-그라운딩할 수 있게 함.

### 행동 스키마

일반적인 행동 스키마는 6-10개의 행동 유형을 가짐:

- `click`: (x, y)
- `type`: (text, x?, y?)
- `scroll`: (direction, amount)
- `drag`: (x0, y0, x1, y1)
- `select`: (option_index)
- `hover`: (x, y)
- `navigate`: (url)
- `wait`: (ms)
- `done`: (success, explanation)

에이전트는 단계당 하나의 행동을 방출. 브라우저 래퍼가 실행하고 새 상태를 반환.

### 스크린샷 전용 vs 접근성-트리

두 가지 입력 모드:

- 스크린샷 전용: 전체 이미지, 구조적 정보 없음. 가장 일반적; 모든 앱에서 작동.
- 접근성 트리: 구조화된 DOM / iOS 접근성 정보. 그라운딩에 훨씬 더 신뢰성 있음; 트리를 사용할 수 있는 곳에서 작동.
- 하이브리드: 둘 다, 원자적 행동을 위한 신뢰성 있는 그라운더로 트리, 의미적 컨텍스트를 위한 스크린샷.

프로덕션 에이전트는 가능할 때 하이브리드를 사용. 브라우저 자동화(Selenium + 접근성)는 항상 트리를 가짐; 데스크톱 앱은 때때로 그럼.

### 장기 기억

20-단계 워크플로우는 20개의 스크린샷을 생성. VLM의 컨텍스트가 빠르게 채워짐. 세 가지 압축 전략:

- 요약-체인: 5단계마다 무슨 일이 일어났는지 요약, 오래된 스크린샷 삭제.
- 프레임-건너뛰기: 첫 번째, 마지막 및 매 3번째 스크린샷 유지.
- 도구-기록 로그: 행동 실행, 수행된 작업의 텍스트 로그 유지; 오래된 스크린샷을 다시 보지 않음.

Claude의 컴퓨터-사용 API는 로그 패턴을 사용. 더 간단하고, 더 신뢰성 있음.

### 시각적 도구 사용

ChartAgent(arXiv:2510.04514)는 차트 이해를 위한 시각적 도구 사용을 도입: 자르기, 확대, OCR, 외부 감지 호출. 에이전트는 도구 호출로 "영역 (100, 200, 300, 400)으로 자르고 OCR 호출"을 출력할 수 있음. 도구는 텍스트를 반환; VLM은 추론을 계속.

이 패턴은 일반화됨: set-of-mark 프롬프팅, 영역 주석, 외부 감지 도구 모두 동일한 "도구 호출 출력, 구조화된 응답 수신" 스키마에 맞음.

### 2026년 벤치마크

- ScreenSpot-Pro. ~1k 웹 스크린샷에 대한 GUI 그라운딩. 오픈 SOTA Qwen2.5-VL-72B ~85%. 최첨단 ~90%.
- VisualWebArena. 종단간 웹 작업(쇼핑, 포럼, 중고 거래). 오픈 SOTA ~20%. Gemini 3 Pro ~27%.
- AgentVista (arXiv:2602.23166). 2026년 가장 어려운 벤치마크. 12개 도메인에 걸친 현실적인 워크플로우. 최첨단 모델 27-40%; 오픈 모델 10-20%.
- WebArena / WebShop. 오래된 벤치마크; 최첨단에 의해 포화됨.

### 여전히 어려운 이유

에이전트 성능 병목:

1. 미세 규모의 시각적 그라운딩. "작은 X를 클릭"이 모바일 해상도에서 자주 실패.
2. 장기 계획. 10개 행동 후 에이전트가 목표에서 이탈.
3. 오류 복구. 클릭 실패(잘못된 버튼) 시, 감지 및 복구는 거의 학습 데이터에 없음.
4. 교차-페이지 컨텍스트. 탭 또는 긴 양식 간 이동 시 상태 손실.

연구 방향: 메모리 아키텍처, 명시적 재계획, 멀티모달 검증(행동 성공을 위한 스크린샷 일치).

### 캡스톤 빌드-잇

캡스톤 작업: 컴퓨터-사용 에이전트 구축:

1. 예약 사이트 모의 페이지의 HTML + 스크린샷 읽기.
2. 다중-단계 시퀀스 계획: 검색 → 선택 → 양식 작성 → 제출.
3. 행동 스키마와 일치하는 JSON 행동 방출.
4. 고정된 10-작업 슬라이스에서 평가.

레슨은 실제 브라우저로 쉽게 확장 가능한 스캐폴드 코드를 제공.

## 사용하기

`code/main.py`는 캡스톤 스캐폴드:

- 행동 스키마 JSON 정의(10개 행동).
- 사전으로 모의 브라우저 상태.
- 에이전트 루프 스켈레톤: 상태 수신, 행동 방출, 적용, 반복.
- 종단간 성공률 측정을 위한 10-작업 미니-벤치마크(합성 페이지).
- 행동 실패 시 오류-복구 후크.

## 결과물

이 레슨은 `outputs/skill-multimodal-agent-designer.md`를 생성합니다. 컴퓨터-사용 제품(도메인, 행동 세트, 평가 목표)이 주어지면, 전체 에이전트 루프, 메모리 전략, 그라운딩 모드 및 예상 벤치마크 점수를 설계.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|----------|
| GUI grounding | "클릭 좌표" | 모델이 스크린샷의 명령 대상에 대한 (x,y) 출력 |
| Action schema | "도구 정의" | 유효한 행동(클릭, 입력, 스크롤, 드래그)의 JSON 설명 |
| Accessibility tree | "구조화된 DOM" | 브라우저/iOS API에서 가져온 기계-판독 가능 UI 계층 구조 |
| Hybrid agent | "스크린샷 + 트리" | 이미지와 구조화된 정보를 모두 사용; 어느 하나보다 더 신뢰성 있음 |
| Visual tool use | "확대/자르기/감지" | 에이전트가 계획 중에 외부 비전 도구(OCR, 감지) 호출 |
| Summary-chain | "메모리 압축" | 주기적인 텍스트 요약이 긴 스크린샷 기록을 대체 |
| VisualWebArena | "E2E 웹 벤치" | 2024년 종단간 웹 작업 벤치마크 |
| AgentVista | "2026 하드 벤치" | 12개 도메인 현실적인 워크플로우; Gemini 3 Pro조차 ~30% 기록 |
