# Qwen-VL 패밀리와 동적-FPS 비디오

> Qwen-VL 패밀리 — Qwen-VL (2023), Qwen2-VL (2024), Qwen2.5-VL (2025), Qwen3-VL (2025) —는 2026년 가장 영향력 있는 오픈 비전-언어 모델 계보다. 각 세대는 나머지 오픈 생태계가 12개월 내에 복제한 단일 결정적 아키텍처 베팅을 했다: M-RoPE를 통한 네이티브 동적 해상도, 절대 시간 정렬이 있는 동적-FPS 샘플링, ViT의 윈도우 어텐션, 구조화된 에이전트 출력 형식. Qwen3-VL까지 레시피가 안정되었다: 네이티브-종횡비 입력이 있는 2D-RoPE-ViT 인코더,大型 Qwen3 언어 기본으로의 MLP 투영기, 그리고 OCR, 그라운딩, 에이전트 동작을 1단계 목표로 강조하는 훈련 단계. 이 레슨은 모든 노브가 왜那里에 있는지 이해할 수 있도록 계보를年代순으로 읽는다.

**유형:** 학습
**언어:** Python (stdlib, M-RoPE 인코더 + 동적-FPS 샘플러)
**선수 과목:** Phase 12 · 06 (patch-n'-pack)
**소요 시간:** ~120분

## 학습 목표

- M-RoPE의 3축 회전(시간, 높이, 너비)을 계산하고 세 개가 모두 필요한 이유를 설명한다.
- 비디오에 대한 동적-FPS 샘플링 전략을 선택하고 초당 토큰 대 이벤트 감지 정확도를 reasoning한다.
- 네 가지 Qwen-VL 세대 업그레이드를 순서대로 назвать 각각이 무엇을 가능하게 했는지.
- Qwen2.5-VL 스타일 JSON 에이전트 출력 형식을 배선하고 VLM 응답에서 구조화된 도구 호출을 파싱한다.

## 문제

Qwen-VL은 2023년 8월 LLaVA-1.5와 BLIP-2에 대한 직접적인 대응으로 출시되었다. Qwen 팀이 목표로한 격차는 세 가지: 해상도, 비디오, 구조화된 출력.

해상도: LLaVA-1.5는 336x336에서 실행되었다. 사진에는 좋지만 중국어 청구서나 밀집 스프레드시트 스크린샷에는 쓸모없다. Qwen-VL의 첫 번째 혁신은 448x448와 그라운딩 바운딩 박스 출력으로, 모델이 사물을 가리킬 수 있게 했다.

비디오: Video-LLaMA는 프레임당 인코더를 쌓아 LLM에 공급했다. 짧은 클립에는 작동했지만 시간 축이 신호인 수백 분 비디오에는 그렇지 않다. Qwen 팀은 시간을 이해하는 단일 인코더를 원했다.

구조화된 출력: LLaVA는 자유 형식 텍스트를 방출한다. 에이전트에는 JSON이 필요하다. Qwen-VL은 바운딩 박스 좌표를 텍스트로 포함하여 명시적인 JSON 출력 형식으로 훈련했다.

모든 Qwen-VL 세대가 이 세 축 중 하나를 확장한다.

## 개념

### Qwen-VL (2023년 8월)

첫 번째 세대: OpenCLIP ViT-bigG/14를 인코더로(2.5B 파라미터), LLama 호환 Q-Former(256 쿼리의 1단계), Qwen-7B 기본. 기여:

- 448x448 해상도(그 당시 오픈 VLM의 SOTA).
- 그라운딩: 명시적 좌표-토큰 출력과 함께 이미지-텍스트 페어로 훈련. "The cat is at `<box>(112, 204), (280, 344)</box>`".
- 처음부터 중국어 + 영어 다국어 훈련.

그 당시 벤치마크: 영어에서 GPT-4V와 경쟁, 중국어에서 지배적. 그라운딩 감독이 실제 헤드라인이었다.

### Qwen2-VL (2024년 9월) — M-RoPE와 네이티브 해상도

Qwen2-VL는 고정 해상도 + Q-Former 스택을 네이티브 동적 해상도 ViT 인코더로 교체했다. 주요 변경:

- 네이티브 동적 해상도. ViT는 28로 나눌 수 있는 모든 HxW(패치 14에 2x 공간 병합)를受け入れ한다. 1120x672(40x24 병합 패치)의 이미지는 960 시각 토큰을 생성한다. 리사이즈 없음, 타이링 없음, 썸네일 없음.
- M-RoPE (멀티모달 RoPE). 각 토큰은 1D 대신 3D 위치(t, h, w)를 carries한다. 이미지의 경우 t=0, 비디오의 경우 t = frame_index. RoPE는 축당 주파수로 쿼리/키 벡터를 회전한다. 위치 임베딩 테이블 없음.
- MLP 투영기. Q-Former를 삭제; 병합된 패치 토큰에서 2-layer MLP 사용.
- 동적 FPS가 있는 비디오. 기본적으로 1-2 FPS로 샘플링되지만 모델은 임의의 프레임 수를受け入れ.

결과: Qwen2-VL-7B가 여러 멀티모달 벤치마크에서 GPT-4o와 일치하고 DocVQA에서 그것을 이겼다(94.5 vs 88.4). 아키텍처 변경이 결정적이었다.

### Qwen2.5-VL (2025년 2월) — 동적 FPS + 절대 시간

Qwen2.5-VL의 큰 전환은 비디오였다. 동적 FPS는 "필요할 때 더 많은 프레임을 샘플링"이 아니다. 논문은 다음과 같이 공식화했다:

- 절대 시간 토큰. 위치 인덱스(프레임 0, 1, 2...) 대신 실제 타임스탬프를 사용한다. "At 0:04, the cat jumps." 모델은 프레임 토큰과 интер리브된 `<time>0.04</time>` 토큰을 본다.
- 동적 FPS. 느린 영상은 1 FPS, 액션은 4+ FPS로 샘플링. 사용자 또는 트레이너가 선택; M-RoPE가 적응한다.
- ViT의 윈도우 어텐션. 공간 어텐션은 처리량을 위해 윈도우됨(블록 내 로컬); 몇 레이어마다 글로벌 어텐션.
- 명시적인 JSON 출력 형식. 도구 호출 데이터에서 훈련: "{\"tool\": \"click\", \"coords\": [380, 220]}". 에이전트 즉시 사용 가능.
- MRoPE-v2 스케일링. 위치가 최대 입력 크기로 스케일되어 10분 비디오가 주파수 범위를 벗어나지 않음.

벤치마크: Qwen2.5-VL-72B가 대부분의 비디오 벤치마크에서 GPT-4o를 이기고, 문서에서 Gemini 2.0과 일치하며, GUI 그라운딩을 위한 오픈 모델 SOTA 설정(ScreenSpot: 84% 정확도 vs GPT-4o의 38%).

### Qwen3-VL (2025년 11월)

Qwen3-VL은 재창조보다 통합하는 점진적 업그레이드다: 더 큰 LLM 백본(Qwen3-72B), 확장된 훈련 데이터, 개선된 OCR, Qwen3 "thinking mode"를 통한更强的 추론. ViT와 M-RoPE는 유지. 논문은 아키텍처보다 데이터와 훈련 개선에 집중한다.

계보 숙어: 2025년까지 Qwen-VL 아키텍처가 안정되었다. 추가 세대는 기본 것이 아닌 컴퓨트와 데이터를 확장한다.

### M-RoPE 수학적으로

고전 RoPE는 쌍으로 된 좌표를 사용하여 위치 `m`에 대해 차원 `d`의 쿼리 `q`를 회전한다:

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE는 히든 딤을 세 개의 밴드로 분할한다. 말하여 `d = 96`. 시간에 32 차원, 높이에 32, 너비에 32를 할당한다. 각 밴드는 자체 축 위치에 따라 회전한다. (t=5, h=10, w=20)의 패치는 세 밴드에 `R_t(5)`, `R_h(10)`, `R_w(20)` 회전을 적용받는다.

텍스트 토큰은 `t = text_index, h = 0, w = 0`(또는 정규화된 선택)을 사용하며 호환성을 유지한다. 비디오 프레임은 `t = frame_time, h = row, w = col`을 사용한다. 단일 이미지는 `t = 0`을 사용한다.

이점: 하나의 위치 인코딩이 분기 코드나 다른 위치 테이블 없이 텍스트, 이미지, 비디오를 처리한다.

### 동적-FPS 샘플링 로직

 duration `T`초와 대상-토큰 예산 `B`의 비디오가 주어지면:

1. 감당할 수 있는 최대 FPS 계산: `fps_max = B / (T * tokens_per_frame)`.
2. `{1, 2, 4, 8}`에서 `fps <= fps_max`를 만족하는 대상 FPS 선택.
3. 모션이 높으면(옵티컬 플로우 휴리스틱 또는 명시적 사용자 요청) 더 높은 FPS 선택. 모션이 낮으면 더 낮은 FPS 선택.
4. 선택한 FPS로 균일하게 샘플링; 프레임 사이에 `<time>t</time>` 토큰 삽입.

Qwen2.5-VL는 이것을 암묵적으로 훈련한다; 추론에서 사용자는 `fps` 매개변수로 제어한다. 81 토큰/프레임에서 4 FPS의 60초 액션 시퀀스 = 19440 토큰, 32k 컨텍스트에서 관리 가능.

### 구조화된 에이전트 출력

Qwen2.5-VL의 에이전트 훈련은 명시적으로 구조화된 도구 호출을 목표로 한다:

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

파싱은 결정적이다: 모델 출력에서 JSON.parse. 정규식과 모호성 처리가 필요했던 자유 형식 "click at (1024, 512)"와 비교. 이것이 Qwen2.5-VL의 ScreenSpot 점수가 Qwen2-VL의 55%에서 84%로 뛰어오른 이유다.

## 활용

`code/main.py` 구현:

- 텍스트, 이미지 패치, 비디오 프레임을 혼합한 패킹된 시퀀스에 대한 M-RoPE 위치 계산.
- 동적-FPS 샘플러: (duration, budget, motion_level)가 주어지면 FPS를 선택하고 프레임 타임스탬프를 방출.
- 좌표 필드가 있는 도구 호출 응답을 처리하는 토이 Qwen2.5-VL JSON-output 파서.

실행한 다음 5분 비디오에서 고정-FPS를 동적-FPS로 교환할 때의 차이를 느껴본다.

## 결과물

이 레슨은 `outputs/skill-qwen-vl-pipeline-designer.md`를 생성한다. 비디오 태스크(모니터링, 에이전트, 동작 인식, 접근성)가 주어지면 Qwen2.5-VL 구성(프레임 예산, FPS 전략, 윈도우-어텐션 플래그, 에이전트-출력 모드)과 지연 시간 추정을 emit한다. 비디오 제품에 Qwen-VL 패밀리 모델을 배포할 때마다 이것을 사용한다.

## 연습 문제

1. 숨겨진 48(밴드당 16, 기본 theta 10000)에서 (t=3, h=5, w=7)의 패치에 대한 M-RoPE 회전을 계산한다. 각 밴드의 처음 세 쌍에 대한 회전 각도를 보여준다.

2. 1 FPS에서 10분 보안 카메라 녹화의 프레임 수? 3x 풀에서 384 해상도로 총 토큰 수? Qwen2.5-VL의 기본 32k 컨텍스트가 그것을 처리하는가?

3. 30초 테니스 랠리 vs 30초 레시피 데모 vs 30초 UI-에이전트 녹성에 FPS를 선택한다. 동적-FPS 로직으로 각각을 justify한다.

4. Qwen2.5-VL은 Q-Former를 완전히 삭제한다. 간단한 MLP가 2025에는 작동하지만 2023에는 작동하지 않는 이유는? (힌트: 데이터 규모와 인코더 품질.)

5. 세 가지 Qwen2.5-VL JSON 도구 호출 출력을 Python dict로 파싱한다. 잘못된 형식의 JSON에서 무엇이 실패하고 Qwen cookbook이 권장하는 복구 전략은 무엇인가?

## 핵심 용어

| 용어 |人们在说什么 | 실제 의미 |
|------|-----------------|------------------------|
| M-RoPE | "멀티모달 RoPE" | 히든 딤의 시간, 높이, 너비 밴드가 있는 3D 회전 위치 임베딩 |
| 동적 FPS | "스마트 샘플링" | 모션, duration, 토큰 예산 기반으로 비디오별로 선택된 프레임 샘플링 속도 |
| 절대 시간 토큰 | "타임스탬프 토큰" | 모델이 프레임 인덱스가 아닌 실제 초을 보기 위해 시퀀스에서 интерлеaved된 `<time>t</time>` |
| 윈도우 어텐션 | "로컬 어텐션" | 속도를 위해 작은 윈도우로 제한된 공간 자기 어텐션; 주기적으로 글로벌 어텐션 추가 |
| 구조화된 에이전트 출력 | "JSON 모드" | 좌표와 도구 이름이 있는 파싱 가능한 JSON을 방출하도록 VLM에 가르치는 훈련 데이터 감독 |
| min_pixels / max_pixels | "해상도 경계" | 총 픽셀 수와 therefore 토큰 수를 제한하는 per-request Qwen2.5-VL 컨트롤 |
| 그라운딩 | "가리키기" | 텍스트 토큰으로 바운딩 박스 좌표 출력; Qwen-VL v1부터 사용 |
