# 백만-토큰 컨텍스트에서의 긴 비디오 이해

> 24 FPS의 1시간 4K 비디오를 패치화하고 임베딩하면 약 6000만 개의 토큰이 생성됩니다. 2시간 팟캐스트 에피소드를 전사하면 30,000개 토큰입니다. 전체 Blu-ray 장편 영화는 적극적인 풀링으로 압축하더라도 수십만 개의 토큰입니다. Google의 Gemini 1.5(2024년 3월)는 1000만-토큰 컨텍스트로 이 시대를 열었고, 시간에 걸친 비디오에서 신뢰할 수 있는 바늘-찾기-건초더미 회상을 수행했습니다. LWM(Liu et al., 2024년 2월)은 ring attention의 확장 경로를 보여주었습니다. LongVILA와 Video-XL은 수집을 더 확장했습니다. VideoAgent는 원시 컨텍스트를 에이전트 검색으로 대체했습니다. 각 접근 방식은 계산, 회상, 엔지니어링 복잡성에 대한 서로 다른 트레이드오프입니다. 이 레슨은 이들을 나란히 읽습니다.

**Type:** Build
**Languages:** Python (stdlib, needle-in-haystack simulator + agentic-retrieval router)
**Prerequisites:** Phase 12 · 17 (video temporal tokens)
**Time:** ~180 minutes

## 학습 목표

- 다양한 FPS 및 풀링에서 긴 형식 비디오에 대한 총 시각적-토큰 수를 계산한다.
- 세 가지 확장 경로를 설명한다: 브루트 컨텍스트(Gemini 1.5), ring attention(LWM), 토큰 압축(LongVILA / Video-XL).
- 원시-컨텍스트 비디오 VLM과 에이전트-검색 비디오 VLM(VideoAgent)을 정확도와 지연 시간 측면에서 비교한다.
- 30분 비디오에 대한 바늘-찾기-건초더미 테스트를 설계하고 특정 분에서의 회상을 측정한다.

## 문제

384 네이티브 해상도에서 Qwen2.5-VL 크기 패치의 단일 프레임은 ~729개 토큰입니다. 3x3 풀링에서 프레임당 81개 토큰입니다. 1 FPS의 30분 클립 = 1800프레임 = 145,800개 토큰. 2025년 오픈 VLM으로 가능하지만 빡빡합니다. 2 FPS에서 291,600개 토큰 — 가장 큰 컨텍스트만 맞습니다.

1 FPS의 2시간 영화는 583k 토큰입니다. 2026년 대부분의 오픈 모델을 넘어서며, Gemini 2.5 Pro가 필요하거나 더 적극적인 풀링이 필요합니다.

세 가지 확장 경로가 등장했습니다.

## 개념

### 경로 1: 브루트 컨텍스트 (Gemini 1.5, Claude Opus)

하드웨어로 문제를 해결합니다. 컨텍스트를 수백만 토큰으로 확장하고, 모든 것을 한 번의 순전파로 처리합니다.

Gemini 1.5 Pro는 1M 토큰으로 출시되었고, Gemini 1.5 Ultra는 10M으로, 2026년 Gemini 2.5 Pro는 비디오 시간을 안정적으로 처리합니다. 논문(arXiv:2403.05530)은 ~9.5M 토큰까지 99.7%의 바늘-찾기-건초더미 회상을 문서화합니다.

엔지니어링: 메모리 계층 구조(로컬 + 글로벌 + 스파스)와 긴-컨텍스트 효율성을 위한 MoE 전문가 라우팅이 있는 맞춤형 어텐션 구현. 완전한 세부 정보는 공개되지 않음. 오픈소스 아님.

### 경로 2: Ring Attention (LWM, LongVILA)

Ring attention은 긴 시퀀스를 "링"의 장치에 분산하며, 각 장치가 청크를 보유합니다. 전체 시퀀스에 걸친 어텐션은 각 장치가 청크를 링 패턴으로 다음 장치에 보내고, 부분 어텐션을 계산하며, 집계함으로써 발생합니다.

LWM(Liu et al., 2024)은 이 방식으로 1M-토큰 컨텍스트 모델을 학습했습니다. 학습 계산은 컨텍스트에 따라 선형적으로 확장되며, 이차적으로 확장되지 않습니다 — 어텐션의 이차적 비용은 링의 장치 간에 분할됩니다.

LongVILA(arXiv:2408.10188)는 패턴을 VLM에 적용했습니다. 프레임당 192개 토큰의 1400프레임 비디오 = 268k 컨텍스트, 8-방향 병렬 처리를 통한 ring attention으로 학습.

### 경로 3: 토큰 압축 (Video-XL, LongVA)

브루트 컨텍스트보다 저렴: LLM이 시퀀스를 보기 전에 적극적으로 압축.

Video-XL(arXiv:2409.14485)은 시각적 요약 토큰을 사용합니다: N개 프레임의 각 클립은 N개에 대해 어텐션하는 단일 "요약" 토큰을 생성합니다. 추론 시 LLM은 클립당 하나의 요약 토큰을 보아 컨텍스트를 극적으로 줄입니다.

LongVA는 "긴 컨텍스트 전이" 기법으로 LLM 컨텍스트를 200k에서 2M으로 확장합니다. 긴-컨텍스트 텍스트로 학습하고, 공유 표현을 통해 긴-컨텍스트 비디오로 전이합니다.

토큰 압축은 확장성을 위해 특정 타임스탬프에서의 회상을 희생합니다. 모델은 일반적으로 무슨 일이 일어났는지 알지만 정확한 프레임을 때때로 놓칩니다.

### 경로 4: 에이전트 검색 (VideoAgent)

전체 비디오를 LLM에 제공하지 마십시오. 대신 비디오를 데이터베이스로 취급하고 LLM을 사용하여 쿼리합니다.

VideoAgent(arXiv:2403.10517):

1. LLM이 질문을 읽습니다.
2. LLM이 관련 클립에 대한 검색 도구를 요청합니다("고양이가 있는 세그먼트 보여줘").
3. 도구가 일치하는 클립 타임스탬프를 반환합니다.
4. LLM이 VLM을 통해 해당 클립을 읽습니다.
5. LLM이 답변을 구성하거나 후속 쿼리를 요청합니다.

이것은 긴 비디오에 적용된 LLM-에이전트 패턴입니다. 더 저렴한 추론(관련 클립만 인코딩), 더 어려운 엔지니어링(검색 품질이 병목이 됨).

### 바늘-찾기-건초더미 벤치마크

표준 긴-컨텍스트 테스트: 비디오의 무작위 지점에 고유한 시각적 또는 텍스트 마커를 삽입한 다음, 이를 회상해야 하는 쿼리를 요청합니다.

메트릭: 비디오 길이 및 마커 위치에 따른 Recall@k.

Gemini 2.5 Pro는 최대 90분 비디오에서 >99% 회상을 기록합니다. 오픈 72B 모델(Qwen2.5-VL-72B, InternVL3-78B)은 30분에서 ~85-90%를 기록하고 60분을 넘어서면 저하됩니다.

VideoAgent는 2시간 이상에서 원시-컨텍스트 모델과 일치하거나 능가할 수 있습니다. 도구가 좋으면 검색이 바늘을 찾기 때문입니다.

### 경로 선택

최첨단 정확도의 15분 클립: 오픈 72B + 네이티브 컨텍스트가 일반적으로 작동합니다. Qwen2.5-VL-72B를 선택하세요.

30분에서 1시간 콘텐츠: 오픈용 LongVILA 또는 Video-XL; 폐쇄형용 Gemini 2.5 Pro. 품질 기준이 중요 — 최첨단은 폐쇄형으로 감.

2시간 이상 콘텐츠: VideoAgent 또는 유사한 검색 패턴. 또는 더 작은 청크로 요약하고 계층적 요약 제공.

### 2026년 프로덕션 패턴

실제로 프로덕션 긴-비디오 파이프라인은 하이브리드입니다:

1. 전체 비디오에 대해 동적-FPS 샘플링 + 적극적 풀링 실행(100k-토큰 글로벌 표현 획득).
2. 글로벌 요약을 위해 72B VLM에 전달.
3. 사용자가 자세한 질문을 하면, 요약을 인덱스로 사용하여 에이전트 검색 실행.

이는 글로벌 이해를 위한 브루트-컨텍스트와 로컬 세부 정보를 위한 검색을 결합합니다.

## 사용하기

`code/main.py`:

- 다양한 FPS + 풀링에서 1분에서 3시간까지 비디오에 대한 토큰 예산을 계산.
- 바늘-찾기-건초더미 실행 시뮬레이션: 무작위 타임스탬프에 마커 주입, 질문, 회상 점수.
- 다운스트림 VLM에 공급할 특정 클립을 선택하는 에이전트-검색 라우터 시뮬레이터 포함.

예산 테이블을 실행하고 규모 격차를 느껴보세요.

## 결과물

이 레슨은 `outputs/skill-long-video-strategy-planner.md`를 생성합니다. 비디오 지속 시간과 쿼리 복잡성이 주어지면, 브루트-컨텍스트, 압축 및 에이전트 검색 중에서 선택하고 지연 시간 + 품질 기대치를 계산합니다.

## 연습 문제

1. 1 FPS, 프레임당 81개 토큰의 45분 강의. 총 토큰 수? 어떤 모델의 컨텍스트에 맞나요?

2. 바늘-찾기-건초더미 테스트를 설계하세요: 마커를 몇 분에 주입하고, 정확한 쿼리 형식은 무엇인가요?

3. 브루트-컨텍스트 Qwen2.5-VL-72B(80k 컨텍스트)와 VideoAgent(Claude 3.5 + 검색)를 1시간 비디오에서 비교하세요. 회상에서 누가 이기나요? 지연 시간에서 누가 이기나요?

4. Ring attention의 메모리 비용은 시퀀스 길이에 선형적이고 장치 수에 선형적입니다. 이유를 설명하고 링-회전 단계를 생략하면 무엇이 실패하는지 설명하세요.

5. Gemini 1.5 섹션 5(바늘-찾기-건초더미)를 읽으세요. 논문은 1M 대 10M 토큰 경계에서의 회상에 대해 무엇을 발견했나요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|----------|
| Brute context | "그냥 더 많은 토큰" | LLM 컨텍스트를 수백만 토큰으로 확장; 모든 것을 한 번에 처리 |
| Ring attention | "LWM-스타일 병렬" | 각 장치가 청크를 보유하고 회전하는 분산 어텐션 패턴 |
| Token compression | "요약 토큰" | LLM 이전에 학습된 압축기를 통해 클립당 토큰 감소 |
| Needle-in-haystack | "NIH 테스트" | 무작위 지점에 고유 마커 삽입, 테스트 시 모델이 회상하도록 요청 |
| Agentic retrieval | "LLM 쿼리 플래너" | LLM이 관련 클립에 대한 검색 도구를 요청, VLM을 통해 읽고 답변 구성 |
| VideoAgent | "비디오 검색 패턴" | 표준 에이전트-검색 설계: 질문 -> 도구 -> 클립 -> 답변 |
