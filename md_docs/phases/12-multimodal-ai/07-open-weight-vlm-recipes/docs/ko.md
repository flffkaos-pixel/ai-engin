# 오픈 가중치 VLM 레시피: 실제로 중요한 것

> 2024-2026 오픈 가중치 VLM 문헌은 절제 테이블의 숲이다. Apple의 MM1은 이미지 인코더, 커넥터, 데이터 혼합의 13가지 조합을 테스트했다. Allen AI의 Molmo는 상세한 인간 캡션이 GPT-4V 증류보다 낫다고 증명했다. Cambrian-1은 20+ 인코더 비교를 실행했다. Idefics2는 5축 디자인 공간을 공식화했다. Prismatic VLMs는 통제된 벤치마크에서 27가지 훈련 레시피를 비교했다. 모든 노이즈에서, 소수의 결과가 논문을 가로질러 유지된다: 이미지 인코더가 커넥터 아키텍처보다 더 중요하고, 데이터 혼합이 둘 모두보다 더 중요하며, 상세한 인간 캡션이 증류된 합성 데이터보다 낫다. 이 레슨은 당신이 그것을 할 필요가 없도록 이러한 테이블을 읽는다.

**유형:** 학습 + 실험실
**언어:** Python (stdlib, 절제 테이블 파서 + 레시피 선택기)
**선수 과목:** Phase 12 · 05 (LLaVA 기준)
**소요 시간:** ~180분

## 학습 목표

- 5축 VLM 디자인 공간을 назвать: 이미지 인코더, 커넥터, LLM, 데이터 혼합, 해상도 스케줄.
- MM1 / Idefics2 / Cambrian-1 절제 테이블을 읽고 어떤 노브가 주어진 벤치마크를 이동하는지 예측한다.
- 컴퓨트 예산과 태스크 혼합이 주어지면 새 VLM에 대한 레시피(인코더, 커넥터, 데이터, 해상도)를 선택한다.
- 동일한 토큰 수에서 상세한 인간 캡션이 GPT-4V 증류보다 낫는 이유를 설명한다.

## 문제

수백 개의 오픈 가중치 VLM이 존재한다. "좋은"과 "최첨단" 사이의 격차 대부분은 아키텍처가 아니다. 데이터, 해상도 스케줄, 인코더 선택이다. 모델이 성능이 낮을 때 어떤 노브를 돌릴지 알면 5백만 GPU 시간 실수를 막을 수 있다.

2023년 파도(LLaVA-1.5, InstructBLIP, MiniGPT-4)는 캡션 페어 사전훈련 + LLaVA-Instruct-150k에서 실행되었다. 좋은 기준선. MMMU 35% 부근에서 정점.

2024년 파도(MM1, Idefics2, Molmo, Cambrian-1, Prismatic VLMs)는 완전한 절제를 실행했다. 결과는 놀랍고 실용적이었다.

## 개념

### 5축 디자인 공간

Idefics2(Laurençon 등, 2024)가 축을命名했다:

1. 이미지 인코더. CLIP ViT-L/14, SigLIP SO400m/14, DINOv2 ViT-g/14, InternViT-6B. 인코더는 패치 크기, 해상도, 사전훈련 목표가 다르다.
2. 커넥터. MLP (2-4 레이어), Q-Former (32 쿼리 + 교차 어텐션), Perceiver 리샘플러 (64 쿼리), C-Abstractor (컨볼루션 + 볼리니어 풀링).
3. 언어 모델. Llama-3 8B / 70B, Mistral 7B, Phi-3, Gemma-2, Qwen2.5. LLM 크기가 지배적 파라미터 비용이다.
4. 훈련 데이터. 캡션 페어(CC3M, LAION), 인터리브드(OBELICS, MMC4), 명령어(LLaVA-Instruct, ShareGPT4V, PixMo, Cauldron).
5. 해상도 스케줄. 고정 224/336/448, AnyRes, 네이티브 동적. 훈련 중 램핑 또는 일정.

모든 프로덕션 VLM은 각 축에서 선택을 한다. MMMU 점수의 대부분의 분산은 축 1, 4, 5에 의해 설명된다 — 커넥터를 선택한 것에 의해이 아니다.

### 축 1: 인코더 > 커넥터

MM1 섹션 3.2가 보여준 것: CLIP ViT-L/14에서 SigLIP SO400m/14로 교환하면 MMMU가 3+ 포인트 추가된다. 커넥터를 MLP에서 Perceiver 리샘플러로 교환하면 1 포인트 미만 추가된다. Idefics2가 복제: SigLIP > CLIP, Q-Former ≈ MLP ≈ Perceiver 동일한 토큰 수에서.

Cambrian-1의 "Cambrian Vision Encoders Match-Up"(Tong 등, 2024)은 비전 중심 벤치마크(CV-Bench)에서 20+ 인코더를 실행했다. 리더보드 상단은 DINOv2와 SigLIP의 혼합; CLIP는 중위권; ImageBind와 ViT-MAE는 하위권. CLIP ViT-L에서 DINOv2 ViT-g/14로의 격차는 CV-Bench에서 ~5-7 포인트다.

2026년 오픈 VLM의 기본 인코더는 시맨틱 + 밀집 피처를 위한 SigLIP 2 SO400m/14이며, 때때로 세그멘테이션/그라운딩이 필요하면 DINOv2 ViT-g/14 피처와 연결된다(Cambrian의 "Spatial Vision Aggregator"가 이것을 함).

### 축 2: 커넥터 설계는 같다

MM1, Idefics2, Prismatic, MM-Interleaved 모두 같은 결론에 도달했다: 고정 시각 토큰 수에서 커넥터 아키텍처는 거의 중요하지 않다. 평균 풀링된 패치에서 2-layer MLP는 동일한 토큰 예산에서 32-쿼리 Q-Former보다 1 포인트 이내에서 수행된다.

중요한 것은 토큰 수다. 더 많은 시각 토큰 = 더 많은 LLM 컴퓨트 = 더 나은 성능까지 어느 정도, 그 후 diminishing returns. 이미지당 64 토큰은 OCR에는 너무 적다. 대부분의 오픈 VLM에서 576-1024 토큰이 딜sweet spot다. 2048+는 문서와 차트에만 도움된다.

Q-Former 대 MLP는 비용 질문이지 품질 질문이 아니다: Q-Former는 이미지의 해상도에 관계없이 토큰을 32-64로 캡; MLP는 모든 패치 토큰을 방출한다. 고해상도 입력의 경우 Q-Former가 LLM 컨텍스트를 절약; 저해상도의 경우 차이는 노이즈다.

### 축 3: LLM 크기가 천장을 설정한다

7B에서 13B로 LLM을 두 배로 하면 모든 VLM 논문에서 MMMU에 2-4 포인트가 신뢰할 수 있게 추가된다. 70B에서 대부분의 벤치마크가 포화된다. VLM의 멀티모달 추론 천장은 LLM의 텍스트 추론 천장이다 — 비전 인코더는 그것을 공급할 수만 있고 그것을 위해 추론할 수는 없다.

이것이 Qwen2.5-VL-72B와 Claude Opus 4.7이 MMMU-Pro와 ScreenSpot-Pro를 으스러뜨리는 이유다: 언어 뇌가 방대하다. 영리한 커넥터 설계로 7B VLM이 70B VLM을 대체할 수 없다.

### 축 4: 데이터 — 상세한 인간 캡션이 증류보다 낫다

Molmo + PixMo(Deitke 등, 2024)는 2024년 결과로 모든 사람이 읽어야 한다. Allen AI는 인간 주석자가 1-3분 밀집 음성-텍스트 패스에서 이미지를 설명하도록 하여 712K 밀집 캡션 이미지를 생성했다. 훈련 데이터 어딘가에도 GPT-4V 증류가 없다.

Molmo-72B가 11개 벤치마크 중 11개에서 Llama-3.2-90B-Vision을 이겼다. �ель타는 아키텍처가 아니다 — 캡션 품질이다. 상세한 인간 캡션은 짧은 웹 캡션보다 이미지당 5-10배 더 많은 정보를 담고 있으며 GPT-4V 증류가 환각하는 곳에서 사실적으로 유지된다.

ShareGPT4V(Chen 등, 2023)와 Cauldron(Idefics2)은 혼합 인간 + GPT-4V 캡션으로 같은 플레이북을 따랐다. 추세가 명확하다: 2026년 프론티어를 위해 캡션 밀도 > 캡션 수량 > 증류 편의성.

### 축 5: 해상도와 그 스케줄

Idefics2의 절제: 384 -> 448이 1-2 포인트 추가. 448 -> 980 이미지 분할(AnyRes)과 함께 OCR 벤치마크에서 추가 3-5. 플랫 해상도 훈련은 중등 정확도에서 정체; 해상도 램핑(시작 224, 종료 448 또는 네이티브)이 더 빨리 정렬되고 더 높게 종료된다.

Cambrian-1이 해상도 대 토큰 트레이드오프를 실행했다: 고정 컴퓨트에서 더 낮은 해상도의 더 많은 토큰 또는 더 높은 해상도의 더 적은 토큰을 가질 수 있다. 더 높은 해상도가 OCR에서 이김;更低-분위-더-많은-토큰이 일반 장면 이해에서 이김.

2026년 프로덕션 레시피: 1단계 384 고정에서 훈련, OCR 무거운 태스크를 위해 1280까지 동적 해상도로 2단계.

### Prismatic 통제 비교

Prismatic VLMs(Karamcheti 등, 2024)는 모든 축을 제어한 논문이다. 동일한 13B LLM, 동일한 명령어 데이터, 동일한 평가 — 한 번에 하나의 축만 다름. 결과:

- 이미지당 시각 토큰 수가 분산의 ~60%를 설명한다.
- 인코더 선택이 ~20%를 설명한다.
- 커넥터 아키텍처가 ~5%를 설명한다.
- 나머지 ~15%(데이터 혼합, 스케줄러, LR)는 다른 모든 것.

이것은 대략적인 분해이지만 문헌에서 "무엇을 먼저 절제해야 하는가"에 대한 가장 깨끗한 답변이다.

### 2026년 선택기

증거에 따르면 2026년 새 프로젝트에 대한 기본 오픈 VLM 레시피:

- 인코더: NaFlex에서 네이티브 해상도의 SigLIP 2 SO400m/14, 세그멘테이션/그라운딩이 필요하면 밀집 피처를 위해 DINOv2 ViT-g/14와 연결.
- 커넥터: 패치 토큰에서 2-layer MLP. 토큰 제약이 없다면 Q-Former 건너뛰기.
- LLM: Qwen2.5 / Llama-3.1 / Gemma 2, 비용을 위해 7B, 품질을 위해 70B, 대상 지연 시간에 의해 선택.
- 데이터: PixMo + ShareGPT4V + Cauldron, 태스크 특정 명령어 데이터로 보충.
- 해상도: 동적(긴 변당 min 256, max 1280 픽셀).
- 스케줄: 1단계 정렬(투영기만), 2단계 전체 미세조정, 3단계 태스크 특정 미세조정.

これらの 기본값의 각각은 이 레슨 끝에 인용된 논문의 측정된 절제로 추적된다.

## 활용

`code/main.py`는 절제 테이블 파서와 레시피 선택기다. MM1과 Idefics2 절제 테이블을 인코딩(압축)하고 쿼리할 수 있다:

- "예산 X와 태스크 Y가 주어지면 어떤 레시피가 이기는가?"
- "7B Llama에서 SigLIP를 CLIP로 교환하면 예상되는 MMMU �ель타는 무엇인가?"
- "80% 신뢰도의 답을 위해 처음에 어느 축을 절제해야 하는가?"

출력은 예상 벤치마크 �ель타와 "처음에 절제" 권장 사항이 있는 순위 레시피 목록이다.

## 결과물

이 레슨은 `outputs/skill-vlm-recipe-picker.md`를 생성한다. 대상 태스크 혼합, 컴퓨트 예산, 지연 시간 대상이 주어지면 각 선택을正当化する 인용과 함께 전체 레시피(인코더, 커넥터, LLM, 데이터 혼합, 해상도 스케줄)를 emit한다. 새 VLM 프로젝트가 시작될 때마다 engineers가 Idefics2 절제 테이블을 재발명하는 것을 막는다.

## 연습 문제

1. MM1 섹션 3.2를 읽는다. 고정 2B LLM에서 예산 50M 이미지의 경우 어느 인코더가 이기는가? 13B LLM에서 답이 뒤집히는가? 왜?

2. Cambrian-1은 DINOv2 + SigLIP 연결이 비전 중심 벤치마크에서 둘 모두를 능가하지만 MMMU에서는 신호를 추가하지 않는다고 생각한다. 어떤 벤치마크가 gaining하고哪些がStaying 플랫인지 예측한다.

3. 당신의 대상은 2B LLM에서 모바일 UI 에이전트다. 인코더, 커넥터, 해상도, 데이터 혼합을 선택한다. 특정 절제 테이블로 각 선택을正当한다.

4. Molmo는 4B와 72B 모델을 배송한다. 4B는 폐쇄된 7B VLM과 경쟁력이 있다; 72B는 11/11 벤치마크에서 Llama-3.2-90B-Vision을 이긴다. 그것이 LLM 크기 정체 가설에 대해 무엇을 말하는가?

5. 7B VLM에서 데이터 혼합 품질과 인코더 품질을 분리하기 위한 절제 테이블을 설계한다. 최소 몇 번의 훈련 실행인가? 네 축 설정을 제안한다.
