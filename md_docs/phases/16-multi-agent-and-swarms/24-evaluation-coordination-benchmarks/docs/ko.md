# 평가 및 조정 벤치마크

> 다중 에이전트 평가 공간을 다루는 5개의 2025-2026 벤치마크. **MultiAgentBench / MARBLE** (ACL 2025, arXiv:2503.01935)는 마일스톤 KPI로 star/chain/tree/graph 토폴로지를 평가합니다; **graph는 연구에 가장 적합**, 인지 계획이 마일스톤 성취에 ~3% 추가. **COMMA**는 멀티모달 비대칭 정보 조정을 평가합니다; GPT-4o를 포함한 최첨단 모델이 무작위 baseline을 넘지 못합니다. **MedAgentBoard** (arXiv:2505.12371)는 4가지 의료 작업 카테고리를 다루며 멀티 에이전트가 단일 LLM을 지배하지 않는 경우가 많음을 발견합니다. **AgentArch** (arXiv:2509.10769)는 도구 사용 + 메모리 + 오케스트레이션을 결합한 엔터프라이즈 에이전트 아키텍처를 벤치마크합니다. **SWE-bench Pro** (arXiv:2509.16941)는 비즈니스 앱, B2B 서비스, 개발자 도구를 포괄하는 41개 레포에서 1865개 문제를 가집니다; 프론티어 모델이 Pro에서 ~23%, Verified에서 70%+ — 오염에 대한 현실 체크. Claude Opus 4.7 (2026년 4월)은 Pro에서 **64.3%**로 보고됩니다 (명시적 에이전트 팀 조정 포함; 기본 소스 아직 게시되지 않음 — 예상으로 취급); Verdent (에이전트 스캐폴드)가 Verified에서 **76.1% pass@1** 달성 (Verdent 기술 보고서). **AAAI 2026 Bridge Program WMAC** (https://multiagents.org/2026/)는 2026년 커뮤니티 초점입니다. 이 레슨은 MARBLE의 메트릭을 기반으로 빌드하고, 토폴로지 대 메트릭 스윕을 실행하며, "SWE-bench Verified를 그냥 넘었다고 해서 일반화의 증거가 되지 않는다"는 규칙을 고정합니다.

**유형:** 학습
**언어:** Python (stdlib)
**선수 과목:** Phase 16 · 15 (Voting and Debate Topology), Phase 16 · 23 (Failure Modes)
**소요 시간:** ~75분

## 문제

논문이 "우리의 멀티 에이전트 시스템이 더 좋다"고 주장할 때, 질문은: 무엇에, 무엇보다, 어떻게 측정합니까? 2023-2024년 멀티 에이전트 평가 시대는 혼란었습니다 — 모두가 자신의 메트릭, 자신의 baseline, 자신의 작업 세트를 선택했습니다. 2025-2026년 벤치마크가 구조를 적용했습니다.

공유 벤치마크 없이는 두 멀티 에이전트 시스템을 의미 있게 비교할 수 없습니다. 더 나쁘게는, 홀드아웃 벤치마크 없이는 프론티어 모델이 오염될 수 있습니다. SWE-bench Verified는 2025년 중반까지 학습 코포라에 부분적으로 오염되었습니다; 프론티어 점수가 부풀려졌습니다; Pro는 오염되지 않은 현실 체크로 설계되었습니다.

이 레슨은 5개의 정식 2026년 벤치마크를 열거하고 각각이 무엇을 측정하는지 이름 짓으며 벤치마크 주장을 의심하도록 가르칩니다.

## 개념

### MultiAgentBench (MARBLE) — ACL 2025

arXiv:2503.01935. 연구, 코딩, 계획 작업에서 4가지 조정 토폴로지 (star, chain, tree, graph)를 평가합니다. 마일스톤 기반 KPI가 최종 성공만이 아닌 부분 진행을 추적합니다.

측정 결과:

- **Graph** 토폴로지가 연구 시나리오에 가장 적합; 임의의 임의 비판을 지원합니다.
- **Chain**이 단계적 개선 코딩에 가장 적합.
- **Star**가 빠른 사실 통합에 가장 적합.
- ~4 에이전트 이후 graph에서 조정 세금이 나타납니다.
- **인지 계획**이 토폴로지 전반에 걸쳐 마일스톤 성취에 ~3% 추가.

사용时机: 조정 토폴로지를 사과 대 사과로 비교したいとき. MARBLE 레포 (https://github.com/ulab-uiuc/MARBLE)가 평가자를 제공합니다.

### COMMA — 멀티모달 비대칭 정보

에이전트가 다양한 관찰 양식를 가지며 완전한 정보 공유 없이 조정해야 하는 작업을 다룹니다. 보고된 결과가 불편합니다: GPT-4o를 포함한 프론티어 모델이 COMMA에서 에이전트-에이전트 협력에서 **무작위 baseline**을 넘지 못합니다. 신호는 멀티 에이전트 양식화가 과소 훈련되고 과소 평가되었다는 것입니다 — LLML은 단일 양식 협력을 합리적으로 처리합니다; 멀티 양식 조정崩溃.

사용时机: 시스템에 멀티모달 또는 비대칭 정보 조정이 있는 경우. COMMA의 null 결과는 주장 전에 측정하라는 경고입니다.

### MedAgentBoard — 도메인 스트레스 테스트

arXiv:2505.12371. 4가지 의료 작업 카테고리: 진단, 치료 계획, 보고서 생성, 환자 커뮤니케이션. 멀티 에이전트 대 단일 LLM 대 기존 규칙 기반 시스템 비교.

발견: 멀티 에이전트가 대부분의 카테고리에서 단일 LLM을 지배하지 않습니다. 멀티 에이전트 이점이 좁습니다 — 하위 작업이 명확히 분리 가능한 경우 (진단 + 치료) 작업 분해가 도움이 됩니다; 조율 오버헤드가 전문화 이득을 초과하면 해릅니다 (보고서 생성).

사용时机: 도메인이 명확한 단일 LLM baseline을 가질 때. MedAgentBoard의 교훈이 일반화되면, 많은 제안된 멀티 에이전트 시스템이 과엔지니어링되었습니다.

### AgentArch — 엔터프라이즈 아키텍처

arXiv:2509.10769. 도구 사용, 메모리, 오케스트레이션이 함께 레이어화된 엔터프라이즈 설정. 벤치마크가 각 레이어의 기여를 분리합니다: 도구 추가가 얼마나 도움이 됩니까? 메모리 추가가? 멀티 에이전트 오케스트레이션 추가가?

사용时机: 엔터프라이즈 에이전트 스택을 설계하고 각 레이어의 가치를 정당화해야 할 때. AgentArch는 측정할 수 없는 가치를 사는 것을 방지하는 데 도움이 됩니다.

### SWE-bench Pro — 현실 체크

arXiv:2509.16941. 비즈니스 앱, B2B 서비스, 개발자 도구를 포괄하는 41개 레포에서 1865개 문제. 이후 학습 컷오프로 **오염되지 않도록** 설계되었습니다. 프론티어 모델이 Pro에서 ~23%, Verified에서 70%+를 받습니다. 격차가 오염 신호입니다.

2026년 4월 점수:
- Pro의 Claude Opus 4.7: **64.3%** (명시적 에이전트 팀 조정 포함하여 보고됨; 기본 소스 게시되지 않음 — 예상으로 취급).
- Verified의 Verdent (에이전트 스캐폴드): **76.1% pass@1** (기술 보고서).
- 에이전트 스캐폴드 없이 Pro의 프론티어 원시 점수: ~23-35% (SWE-bench Pro 논문).

주목할 점: "우리는 SWE-bench Verified를 이겼다"는 더 이상 능력의 증거가 아닙니다. Pro가 현재 게이팅 테스트입니다. 에이전트 팀 스캐폴딩이 Pro에서 가늠할 수 있는 이득을 산출합니다 (~30-40포인트 델타), 이것이 2026년 멀티 에이전트 조정에 대한 가장 강한 경험적議論 중 하나입니다.

### AAAI 2026 WMAC

AAAI 2026 Bridge Program — Workshop on Multi-Agent Coordination (https://multiagents.org/2026/). 2026년 멀티 에이전트 AI 연구의 커뮤니티 초점. 수락된 논문과 워크숍 절차가 새로운 방법을 평가하는 정식 장소입니다; 프로덕션 결정에 대해 arXiv 프리프린트보다 WMAC 수락 주장을 deference하세요.

### 벤치마크 주장을 의심하세요 — 2026년 체크리스트

누군가 멀티 에이전트 결과를 주장할 때:

1. **어떤 벤치마크, 어떤 분할?** SWE-bench Verified 대 Pro가 많이 중요합니다. 잘못된 분할에서 보고된 숫자는 가치가 없습니다.
2. **오염 확인.** 벤치마크가 모델의 학습 컷오프 후 출시되었습니까? 그렇지 않으면 주의하여 취급하세요.
3. **Baseline 비교.** 단일 LLM baseline, 무작위, 이전 멀티 에이전트 작업 대비. "동일한 시스템의 튜닝되지 않은 버전 대비"가 아닙니다.
4. **통계적 유의성.** N trial, p-value, 신뢰 구간. 프론티어 모델은 고분산입니다; 단일 실행이 오도합니다.
5. **작업 다양성.** 하나 또는 많은 작업? 일반화가 프로덕션에 중요합니다.
6. **비용 공개.** 작업당 토큰, wall-clock. 90% 솔루션이 20x 비용이면 능력 주장이 아니라 사업 결정입니다.

### 벤치마크가 잘 측정하지 못하는 것

- **장기 조정.** 며칠의 wall-clock 상호작용. 모든 현재 벤치마크가 짧게 실행됩니다.
- **적대적 복원력.** 에이전트 중 하나가 악의적이거나 손상되면 어떻게 됩니까?
- **배포 시 드리프트.** 벤치마크는 정적입니다; 프로덕션 분포가 이동합니다.
- **비용 정규화 성능.** 대부분의 벤치마크가 원시 정확도를 보고하고 정확도별 달러가 아닙니다.

실제로 신경 쓰는 축에 대한 자체 내부 벤치마크를 구축하는 것이 종종 올바른 이동입니다.

## 빌드

`code/main.py`는 비対話적 walk-through입니다:

- 토이 작업에서 3개의 멀티 에이전트 시스템을 시뮬레이션합니다.
- 각에 대해 MARBLE 스타일 마일스톤 메트릭을 계산합니다.
- "학습" 세트에서 작업을 보류하여 오염 검사를 실행합니다.
- 무작위 baseline과 명시적으로 비교합니다.
- 벤치마크 주장 점수카드를 인쇄합니다.

실행:

```bash
python3 code/main.py
```

예상 출력: 원시 정확도, 마일스톤 성취, 작업당 비용, 무작위 baseline 델타, 오염 검사 노트가 있는 시스템 점수카드.

## 활용

`outputs/skill-benchmark-reader.md`는 모든 멀티 에이전트 벤치마크 주장을 읽고 엄격함 체크리스트를 적용합니다. 출력: 등급 및주의 사항.

## 결과물

프로덕션 평가 규율:

- **내부 벤치마크를 구축하세요** 실제 프로덕션 분포를 반영하는 것입니다. 공개 벤치마크가 정보를 제공하지만 대체하지 않습니다.
- **모든 비교에 무작위 baseline을 포함하세요.** 조정 작업에서 무작위보다 큰 마진으로 이기지 못하면 작업이 잘못 배치되었을 수 있습니다.
- **정확도와 함께 비용을 보고하세요.** 토큰 비용과 wall-clock. Ops 팀은 둘 다 필요합니다.
- **분기별로 벤치마크를 재구축하세요.** 프로덕션 분포가 이동합니다; 오래된 벤치마크가 오도합니다.
- **게시된 벤치마크 과적용을 피하세요.** 팀이 specifically SWE-bench Pro 숫자를 최적화하고 있다면 프로덕션에서 회귀할 것입니다.

## 연습문제

1. `code/main.py`를 실행하세요. 세 가지 시뮬레이션된 시스템 중哪一个가 마일스톤당 최고의 비용을 가짐니까? 가장 높은 원시 정확도 시스템과 일치합니까?
2. MultiAgentBench (arXiv:2503.01935)를 읽으세요. 자신의 작업 도메인에 대해 MARBLE이 어떤 토폴로지를 추천할지 결정하세요. 논문의 결과에서 정당화하세요.
3. SWE-bench Pro 논문을 읽으세요. specifically 무엇이 그것을 오염 저항적으로 만듭니까? 동일한 기술을 신경 쓰는 다른 벤치마크에 적용할 수 있습니까?
4. COMMA의 멀티모달 조정 발견을 읽으세요. 내부 벤치마크에 추가할 수 있는 간단한 멀티모달 조정 작업을 디자인하세요. 유용한 신호로 무엇이 카운트합니까?
5. 벤치마크 주장 체크리스트를 최근 멀티 에이전트 논문의 헤드라인 결과에 적용하세요. 주장에 어떤 등급을 부여하겠습니까?
