# 역할 전문화 — 플래너, 비평家, 실행자, 검증자

> 2026년의 가장 일반적인 멀티에이전트 분해: 하나의 에이전트가 계획하고, 하나가 실행하고, 하나가 비판하거나 검증합니다. MetaGPT (arXiv:2308.00352)는 이것을 SOP로 공식화하여 역할 프롬프트에 인코딩합니다 — 제품 관리자, 아키텍트, 프로젝트 관리자, 엔지니어, QA 엔지니어 — `Code = SOP(Team)`을 따릅니다. ChatDev (arXiv:2307.07924)는 디자이너, 프로그래머, 리뷰어, 테스터를 "채팅 체인"을 통해 연결하며 "의사소통 탈환각" (에이전트가 명시적으로 누락된 세부 정보를 요청합니다). 검증자가 없습니다: Cemri et al. (MAST, arXiv:2503.13657)는 모든 멀티에이전트 실패가 누락되거나 손상된 검증으로 추적될 수 있음을 보여줍니다. PwC는 CrewAI에서 구조화된 검증 루프로 7× 정확도 향상 (10% → 70%)을 보고했습니다.

**유형:** 학습 + 실습
**언어:** Python (stdlib)
**선수 과목:** Phase 16 · 04 (Primitive Model), Phase 16 · 05 (Supervisor)
**소요 시간:** ~60분

## 문제

범용 멀티에이전트 시스템은 범용 출력을 산출합니다. 그룹 채팅의 세 코더가 같은 형편없는 코드의 세 가지 맛을 작성합니다. 더 많은 에이전트를 추가하고, 더 많은 라운드를 추가해도 여전히 품질 임계값을 넘지 못합니다.

수정이 더 많은 에이전트가 아니라 *다른* 에이전트입니다. 고유한 역할을 할당합니다. 비평家に 플래너가 가지지 않은 도구를 부여합니다. 검증자에게 목적지 테스트 스위트를 부여합니다. 이제 시스템에는 grounded 수정이 있는 내부 불일치가 있습니다, 평행 추측만 있는 것이 아닙니다.

## 개념

### 네 가지 표준 역할

**플래너.** 목표를 읽고, 단계 목록 또는 스펙을 산출합니다. 도구: 지식 검색, 문서. 출력: 구조화된 계획.

**실행자.** 한 번에 하나의 계획 단계를 읽고, 아티팩트를 산출합니다. 도구: 실제 작업 도구 (코드 컴파일러, 쉘, API 클라이언트). 출력: 아티팩트.

**비평家.** 실행자의 출력을 플래너의 의도에 대해 읽습니다. 도구: 아티팩트에 대한 읽기 전용 액세스, 정적 분석. 출력: 이유와 함께 수락/거절.

**검증자.** 아티팩트를 읽고 결정적 검사를 실행합니다. 도구: 테스트 실행기, 타입 검사기, 스키마 검증기. 출력: 증거와 함께 통과/실패.

비평가는 주관적이며, 의견이 있으며, 종종 LLM 기반입니다. 검증자는 객관적이며, 결정적이며, 종종 코드 기반입니다. 그들은 같은 역할이 아닙니다.

### MetaGPT의 SOP 패턴

MetaGPT (arXiv:2308.00352)는 소프트웨어 엔지니어링 SOP를 역할 프롬프트로 인코딩합니다:

- **제품 관리자**가 PRD를 작성합니다.
- **아키텍트**가 시스템 설계를 산출합니다.
- **프로젝트 관리자**가 작업을 분할합니다.
- **엔지니어**가 구현합니다.
- **QA 엔지니어**가 테스트를 실행합니다.

각 역할에는 엄격한 입력/출력 스키마가 있습니다. 역할 프롬프트는 역할이 *무엇인가*와 *무엇을 생산해야 하는가*를 말합니다. `Code = SOP(Team)` 공식 — 결정적 SOP가 LLM 팀을 예측 가능한 파이프라인으로 전환합니다.

### ChatDev의 의사소통 탈환각

ChatDev는 키 무드를 추가합니다: 실행자가 계획에 없던 특정 세부 정보가 필요할 때, 계속하기 전에 디자이너에게 명시적으로 묻습니다. 이것은の詳細を作り出すという古典的な LLM 실패를 방지합니다.

구현: 역할 프롬프트에 "주어진 세부 정보가がなかった 특정 정보가 필요할 때, 출력을 생산하기 전에 이름으로 관련 역할에 질문하세요"가 포함됩니다.

### 검증자가 가장 중요한 이유

Cemri et al. (MAST)은 1642개의 멀티에이전트 실행 실패를 추적했습니다. 21.3%는 검증 격차였습니다 — 아무도 확인하지 않은 답을 시스템이 출하했습니다. 나머지 79%는 종종 "확인했지만 조용히 실패했거나 전혀 실행되지 않은 확인이 있었다"로 추적됩니다. 검증이 없습니다.

PwC는 (CrewAI 배포, 2025) 구조화된 검증 루프를 추가하면 정확도가 10%에서 70%로 이동했다고 보고했습니다. 하나의 역할에서 7× 게인.

### 비평가 대 검증자

- 비평가는 아티팩트를 품질에 대해 검토하는 LLM입니다. 주관적. 그럴듯한 산문으로 속일 수 있습니다.
- 검증자는 아티팩트에서 실행되는 결정적 프로그램입니다. 객관적. 증거와 함께 통과/실패를 제공합니다. 속일 수 없습니다.

둘 다 사용하세요. 비평가는 검증자가 표현할 수 없는 미묘한 문제를 포착합니다. 검증자는 비평가가 보지 못하는 버그를 포착합니다, 런타임에서만 표시되기 때문입니다.

### 안티 패턴

시스템의 모든 역할이 LLM이고 모든 역할의 출력이 "좋아 보입니다"입니다. 고전적인 MAST 실패 모드. 적어도 하나의 검증자를 추가하세요, 그 통과/실패가 코드가 아닌 LLM에 의해 결정되지 않습니다.

### 프레임워크 매핑

- **CrewAI** — `Agent(role, goal, backstory)`가 교과서 전문화 표면입니다.
- **LangGraph** — 노드는 전문화된 프롬프트를 가질 수 있습니다; 에지가 파이프라인을 적용합니다.
- **AutoGen** — GroupChat에서 한 단어 이름의 역할별 ConversableAgents.
- **OpenAI Agents SDK** — 역할 전문화 에이전트 간 핸드오프 도구.

## 실습

`code/main.py`는 간단한 Python 함수를 구축하는 4-역할 파이프라인을 구현합니다:

- **플래너**가 스펙을 산출합니다.
- **실행자**가 코드 문자열을 생성합니다.
- **비평가** (LLM-시뮬레이션)가 명백한 문제를 표시합니다.
- **검증자**가 테스트 케이스에 대해 샌드박스 (`exec`)에서 생성된 코드를 실행합니다.

데모가 두 번 실행됩니다: 실행자가 정확한 코드를 산출할 때 (비평가 + 검증자 모두 통과), 실행자가 스펙에서 벗어난 코드를 산출할 때 (비평가가 그럴듯해 보여서 버그를 놓치고, 검증자가 테스트가 실패하기 때문에 포착합니다).

실행:

```
python3 code/main.py
```

## 활용

`outputs/skill-role-designer.md`는 작업을 가져와 역할 명단 (3-5 역할), 역할당 입력/출력 스키마, 검증자 검사를 산출합니다. 에이전트를 프레임워크에 연결하기 전에 이것을 사용하세요.

## 결과물

체크리스트:

- **최소 하나의 결정적 검증자.** 전체-LLM否决.
- **역할당 명시적 I/O 스키마.** 플래너는 스펙을 반환하고 산문이 아닙니다; 실행자는 그 스키마를 읽습니다.
- **의사소통 탈환각.** 실행자는 정보가 누락될 때 플래너에게 물어야 합니다; 결코 그것을 만들지 않습니다.
- **비평/검증자 ordering.** 먼저 비평가를 실행합니다 (저렴, 설계 문제를 포착), 두 번째로 검증자를 실행합니다 (느림, 버그를 포착).
- **루프 예산.** 인간에게 에스컬레이션하기 전에 최대 2개의 비평가-실행자 수정 라운드.

## 연습 문제

1. `code/main.py`를 실행하고 검증자가 비평가가 놓친 버그를 어떻게 포착하는지 관찰합니다. 정적 분석 검사를 추가합니다 (`return` 발생 횟수 계산). 런타임 테스트가 놓치는 것을 무엇을 포착합니까?
2. 5번째 역할을 추가합니다: "요구사항 분석가"가 사용자 소원을 플래너-준비 스펙으로 번역합니다. 어떤 의사소통 탈환각 요청이 그것으로 흐를아야 합니까?
3. MetaGPT 섹션 3 ("에이전트")을 읽습니다. MetaGPT의 5개 역할 각각의 입력/출력 스키마를 나열합니다.
4. ChatDev의 채팅 체인 다이어그램 (arXiv:2307.07924 Figure 3)을 읽습니다. 의사소통 탈환각이 그렇지 않으면 무한했을 루프를 어떻게 끊는지 식별합니다.
5. PwC의 7× 정확도 게인이 검증 루프에서 왔습니다. 검증자를 추가해도 도움이 되지 않을 세 가지 작업을 가정합니다 — 정확한성의 결정적 검사가 불가능하거나 엄청나게 비싼 경우.
