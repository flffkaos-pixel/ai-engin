# 협상 및 담판

> 에이전트가 자원, 가격, 작업 할당, 조건을 협상합니다. 2026 벤치마크 세트가 명확합니다: NegotiationArena (arXiv:2402.05863)는 페르소나 조작("절박함")을 통해 LLMs가 페이오프를 ~20% 개선할 수 있음을 보여줍니다; "언어 모델의 협상 능력 측정" (arXiv:2402.15813)은 구매자가 판매자보다更难하고 규모가 도움이 되지 않음을 보여줍니다 — 그들의 **OG-Narrator** (결정적 제안 생성기 + LLM narrativer)가 거래율을 26.67%에서 88.88%로 밀어올렸습니다; 대규모 자율 협상 대회 (arXiv:2503.06416)가 ~180k 협상을 실행하고 **사고 사상 숨기기** 에이전트가 상대로부터 추론을 숨겨서 이긴다는 것을 발견했습니다; Bhattacharya et al. 2025 on Harvard 협상 프로젝트 메트릭에서 Llama-3이 가장 효과적, Claude-3이 가장 공격적, GPT-4가 가장 공정함을 순위로 매겼습니다. 이 레슨은 계약 네트워크 프로토콜(FIPA 조상, Lesson 02)을 구현하고, LLM 스타일 구매자/판매자를 연결하고, OG-Narrator-스타일 분해를 실행하고, 각 구조적 선택에 따라 거래율이 어떻게 변화하는지 측정합니다.

**유형:** 학습 + 실습
**언어:** Python (stdlib)
**선수 과목:** Phase 16 · 02 (FIPA-ACL Heritage), Phase 16 · 09 (Parallel Swarm Networks)
**소요 시간:** ~75분

## 문제

두 에이전트가 가격에 합의해야 합니다. 순수 언어 프롬프트로만 방치하면, 2024-2026년 LLM은 놀라울 정도로 낮은 비율(~27%)으로 거래를 성립시킵니다 (arXiv:2402.15813의严密 매개변수화된 담판에서). 규모가 그것을 고치지 않습니다: GPT-4는 GPT-3.5보다 구조적으로 협상에擅長하지 않습니다; 그것은 협상의 *언어*에 더 좋습니다.

근본적인 문제는 LLMs가 두 가지 작업을 혼동한다는 것입니다 — 제안 결정과 제안 narrating. OG-Narrator는これらを 분리했습니다: 결정적 제안 생성기가 수치적 움직임을 계산합니다; LLM만 narrative합니다. 거래율이 ~89%로 뛰어오릅니다.

이것은 클래식 멀티에이전트 발견을 반영합니다: 메커니즘과 통신 레이어를 분리하면 이깁니다. 계약 네트워크 프로토콜 (FIPA, 1996; Smith, 1980)이 참조 작업 시장 메커니즘입니다. Narration 슬롯에 LLM을 꽂으면 현대 LLM 지원 작업 시장을 얻습니다.

## 개념

### 계약 네트워크, 한 단락으로

Smith의 1980 계약 네트워크 프로토콜: **관리자**가 **제안 요청 (cfp)**를 broadcast합니다; **입찰자**가 제안 메시지와 함께 **제안**을 반환합니다; 관리자가 우승자를 선택하여 수상자에게 **제안 수락**을 보내고 패자에게 **제안 거절**을 보냅니다. 우승자가 작업을 수행합니다. 선택적 메시지: **거절** (입찰자가 제안을 거부). FIPA는 이것을 `fipa-contract-net` 상호작용 프로토콜로 编纂했습니다.

### OG-Narrator가 이기는 이유

"언어 모델의 협상 능력 측정" (arXiv:2402.15813)이 관찰한 바:

- LLM은 종종 협상 규칙을 어깁니다 (비の意味のない 가격으로 제안, 다른 쪽의 ZOPA를 무시).
- 그들은 잘 정박하지 않습니다 (나쁜 첫 제안を受け들임; 기호而非 전략적 금액으로 반提案.
- 규모만으로는 이것들을 고치지 않습니다. 더 큰 모델이 Similar한 전략적 오류로 더 그럴듯한 언어를 만듭니다.

OG-Narrator 분해:

```
            ┌──────────────────┐        ┌──────────────────┐
   state  → │ 제안 생성기     │ price → │  LLM 내러티브    │ → message
            │  (결정적)        │        │  (인간 스타일     │
            │                  │        │   안내를 작성)   │
            └──────────────────┘        └──────────────────┘
```

제안 생성기는 클래식 협상 전략입니다: Rubinstein 담판 모델, Zeuthen 전략, 또는 단순한tit-for-tat 가격. LLM이 narrative합니다. 메시지에 결정적 가격과 자연어 프레임이 포함됩니다.

거래율이 뛰는 이유:
- 가격이 담판 지대에 유지됩니다.
- 정박이 전략적입니다, 정서적이 아닙니다.
- LLM이 좋은 것을 합니다: 글쓰기.

### NegotiationArena 발견

arXiv:2402.05863가 표준 벤치마크를 제공합니다. 주요 발견:

- LLM은 페르소나를 채택하여 ("금요일까지 이것을 팔고 싶습니다") 페이오프를 ~20% 개선할 수 있습니다 — 페르소나 조작은 실제 전술입니다.
- 공평/협조적 에이전트가 적대적 에이전트에게 착취됩니다; 방어는 명시적 반대 포즈가 필요합니다.
- 대칭 쌍은 약 40%의 벤치마크 시나리오에서 불공정한 결과로 수렴합니다.

이것은 "LLM이 나쁜 협상가"가 아닙니다. "LLM이 착취 가능한 부분을 포함하여 너무 인간처럼 협상합니다."

### 사고 사상 숨기기

대규모 자율 협상 대회 (arXiv:2503.06416)가 many LLM 전략에 걸쳐 ~180k 협상을 실행했습니다. 우승자가 상대로부터 추론을 숨겼습니다:

- 에이전트가 공개可见 scratchpad에 "75달러까지만 갈 것입니다; 내 예약 가격은 70달러입니다"를 인쇄하면, 상대방이 그것을 읽습니다.
- 우승자는 전략을 비공개로 계산합니다; 출력 채널에는 제안과 최소 필수 narration만 포함됩니다.

이것은 클래식 게임 이론 (Aumann 1976, 합리성과 정보)에 대한 2026년 반향입니다: 개인 평가을 공개하면 페이오프가 듭니다. LLM은 이것을 직관하지 못하고 기꺼이 reasoning traces에 예약량을 입력하며, 그것이 상대로부터 보입니다.

엔지니어링要点: 개인 scratchpad 컨텍스트를 공개 메시지 컨텍스트와 분리합니다. 선택 사항이 아닙니다.

### Bhattacharya et al. 2025 — 모델 순위

Harvard 협상 프로젝트 메트릭 (원칙적 협상, BATNA 존중, 이해 상호성)에서:

- **Llama-3**이 거래를 성립시키는 데 가장 효과적이었습니다 (거래율 + 페이오프).
- **Claude-3**이 가장 공격적인 협상가였습니다 (높은 정박, 늦은 양보).
- **GPT-4**가 가장 공평했습니다 (페어링에서 페이오프 분산이 가장 작음).

이것은 2025년 스냅샷입니다. 요점은 2026년 4월에 어느 모델이 이기는지가 아니라 — 다른 기본 모델이 지속적인 협상 스타일을 가진다는 것입니다. 이기종 앙상블 (Lesson 15)이 이것을 다양성 소스로 포함합니다.

### 계약 네트워크 + LLM을 통한 작업 할당

LLM 멀티에이전트를 위한 계약 네트워크의 현대적 재사용:

1. 관리자 에이전트가 작업을 단위로 분해합니다.
2. 작업 설명과 함께 worker 에이전트에게 `cfp`를 broadcast합니다.
3. 각 worker가 제안을 반환합니다: `(price, eta, confidence)` — 가격은 토큰, 계산 단위, 또는 달러일 수 있습니다.
4. 관리자가 수상자를 선택합니다 (작업에 따라 단일 또는 복수) 및 수여합니다.
5. 거부된 worker는 다른 작업에 입찰할 자유가 있습니다.

조정이 동기 채팅이 아니라 broadcast-and-respond이므로 100 worker 이상 잘 확장됩니다. 프로덕션에서 사용: Microsoft Agent Framework의 오케스트레이션 패턴, 일부 LangGraph 구현.

### LLM 이해관계자 상호 협상

NeurIPS 2024 (https://proceedings.neurips.cc/paper_files/paper/2024/file/984dd3db213db2d1454a163b65b84d08-Paper-Datasets_and_Benchmarks_Track.pdf)가 **비밀 점수**와 **최소 수락 임계값**이 있는 다자간 채점 가능 게임을 소개합니다. 각 이해관계자는 비공개 유틸리티를 가집니다; LLM은 메시지에서 그것들을 추론해야 합니다. 이것은 2자 담판에서 N자 연대 형성으로의 일반화입니다. 이기종 worker 기능이 있는 프로덕션 작업 시장에 관련됩니다.

### narration 대 메커니즘 규칙

모든 2024-2026 협상 벤치마크에서 일관된 엔지니어링 규칙은:

> LLM이 narrative하게 하세요. LLM이 제안을 계산하게 하지 마세요.

제안이 숫자여야 하는 경우 (가격, ETA, 수량), 협상 상태에서 결정적으로 생성하고 LLM이 프레이밍을 생성하게 하세요. 제안이 제안 구조여야 하는 경우 (작업 분해, 역할 할당), LLM이 초안을 작성하게 하지만 전송하기 전에 스키마에 대해 검증하고 제약 조건을 확인하세요.

## 실습

`code/main.py`가 구현합니다:

- `ContractNetManager`, `ContractNetTask`, `Bid` — 관리자 + 입찰자, broadcast cfp, 제안 수집, 수여.
- `og_narrator_bargain(state, rng)` — OG-Narrator 구매자: 결정적 Zeuthen-스타일 양보, 중앙값 쪽으로.
- `seller_response(state, rng)` — 결정적 판매자 반提案 정책 (양쪽 스타일의 구조적 진실).
- `naive_llm_bargain(state, rng)` — 전체 LLM bargainer를 시뮬레이션합니다: 높은 분산으로 가격 선택, often ZOPA 외부.
- 측정: trial당 새로 샘플링된 예약 가격으로 1000번의 시도에서 거래율.

실행:

```
python3 code/main.py
```

예상 출력: 순진한 LLM 거래율 ~65-75%; OG-Narrator 거래율 ~85-95%; 15-25포인트 격차가 제안 생성에서 narration으로의 분해의 구조적 이점입니다. 세 입찰자와 하나의 작업이 있는 계약 네트워크 작업 시장 할당 예제도 포함합니다.

## 활용

`outputs/skill-bargainer-designer.md`가 협상 프로토콜을 설계합니다: 누가 제안을 생성하는지 (결정적 또는 LLM), 누가 narrative하는지, 개인 scratchpad가 공개 메시지에서 어떻게 분리되는지, 거래율이 어떻게 모니터링되는지.

## 결과물

프로덕션 협상 체크리스트:

- **Scratchpad를 분리합니다.** 개인 상태가 상대의 컨텍스트에 도달하지 않습니다. 이것은협상 불가능합니다.
- **결정적 제안 생성.** 가격, 수량, ETA: 계산하고, 프롬프트하지 마세요.
- **들어오는 모든 제안을 스키마에 대해 검증합니다.** ZOPA 외 제안은 프로토콜 경계에서 거부합니다.
- **라운드를 제한합니다.** 최대 3-5 라운드; 교착 상태에서 중재자로 에스컬레이션합니다.
- **거래율과 페이오프 분산을 지속적으로 측정합니다.** 하락하는 거래율은 증상입니다 — often 프롬프트 드리프트 또는 상대방 측 공격입니다.
- **거부된 모든 제안을 결정적 근거와 함께 로그합니다.** 계약 네트워크 관리자의 경우, 패자는 왜인지 이해해야 합니다.
