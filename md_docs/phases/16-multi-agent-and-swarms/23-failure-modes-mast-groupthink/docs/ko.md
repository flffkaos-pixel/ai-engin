# 실패 모드 — MAST, 그룹싱크, 단문화, 연쇄 오류

> 2026년 참조 택소노미는 **MAST** (Cemri et al., NeurIPS 2025, arXiv:2503.13657)로, 7개의 최첨단 오픈소스 MAS에서 1642개의 실행 추적에서 파생되었으며 **41–86.7% 실패율**을 보입니다. 세 가지 근본 카테고리: **명세 문제** (41.77%) — 역할 모호성, 불분명한 작업 정의; **조정 실패** (36.94%) — 통신 중단, 상태 desync; **검증 격차** (21.30%) — 누락된 검증, 부재한 품질 검사. **그룹싱크** 제품군 (arXiv:2508.05687)이 추가: 단문화 붕괴 (동일한 기본 모델 → 상관된 실패), 순응 편향 (에이전트가 서로의 오류를 강화), 결핍된 이론적 마음, 혼합 동기 역학, 연쇄적 신뢰성 실패. 연쇄 예: 재시도 폭풍 where 지불 실패가 주문 재시도를 촉발하여 재고 재시도를触发하고 재고 서비스를 압도합니다 (수 초 만에 10배 부하 — 서킷 브레이커 필요). 메모리 독성: 하나의 에이전트가 환각한 것이 공유 메모리에 들어가면, downstream 에이전트가 이를 사실로 취급합니다; 정확도가 점진적으로 저하되어 근본 원인 진단이 고통스러워집니다. **STRATUS** (NeurIPS 2025)는 전문화된 탐지 / 진단 / 검증 에이전트를 통해 1.5배 완화 성공 개선을 보고합니다. 이 레슨은 실패 모드를 일등 엔지니어링 대상으로 취급합니다.

**유형:** 학습
**언어:** Python (stdlib)
**선수 과목:** Phase 16 · 13 (Shared Memory), Phase 16 · 14 (Consensus and BFT), Phase 16 · 15 (Voting and Debate Topology)
**소요 시간:** ~75분

## 문제

멀티 에이전트 시스템이 실제 작업에서 41-86.7% 실패합니다 (Cemri et al. 2025가 7개의 오픈소스 MAS에서 측정). 이는 "그냥 더 많은 에이전트를 추가"로 디버그할 수 없습니다. 실패에는 구조적 원인이 있습니다. MAST 택소노미가 카테고리를 제공합니다. 이 레슨은 각 카테고리를 구체적인 탐지, 진단, 완화 패턴에 매핑하여 숫자가 자의적으로 보이지 않도록 합니다.

2026년 프로덕션 관행은 실패 모드를 디자인 입력으로 취급하는 것입니다. 아키텍처가 "충분히 좋"하지 않은 것은 각 MAST 카테고리를 지적하고 배포한 완화를 이름 짓 수 있을 때까지입니다.

## 개념

### MAST 카테고리

**명세 문제 (실패의 41.77%).** 에이전트의 작업이 충분히 Tight하게 정의되지 않았습니다. 예:

- 역할 모호성: 두 에이전트가 모두 검토자라고 생각합니다.
- 작업 미지정: "이것을 요약하세요"하지만 사용자가 특정 각도를 원했습니다.
- 성공 기준이 암묵적: 에이전트가 성공했는지 알 수 없습니다.

완화:
- 명시적 역할 계약을 작성하세요. 각 에이전트의 프롬프트는 무엇을 하는지 *그리고 무엇을 하지 않는지* 명시합니다.
- 작업당 수락 테스트. 에이전트가 시작하기 전에 "완료되면 X처럼 보입니다"를 정의합니다.
- 사전 점검 명세 확인: 배포 전에 작업 정의를 검토하는 별도의 에이전트.

**조정 실패 (36.94%).** 통신 또는 상태 중단.

예:
- 두 에이전트가 동기화 없이 공유 상태를 업데이트합니다.
- 에이전트 간 메시지 손실 (큐 실패, timeout).
- 상태 드리프트: 에이전트 A는 작업이 완료되었다고 생각합니다; 에이전트 B는 여전히 실행 중입니다.

완화:
- 낙관적 동시성이 있는 버전 관리된 공유 상태.
- 중요한 메시지에 대한 명시적 확인 (확인될 때까지 재시도).
- 주기적 상태 동기 체크포인트; 드리프트를 일찍 감지합니다.

**검증 격차 (21.30%).** 출력에 대한 독립적 확인이 없습니다.

예:
- 하나의 에이전트가 성공이라고 주장합니다; 아무도 확인하지 않습니다.
- 에이전트 체인이 각각 이전의 출력을 신뢰합니다.
- 구성된 동작에서 emergent 테스트 커버리지 누락.

완화:
- 독립적 검증 에이전트 (레슨 13). 읽기 전용, 독립적 소스 액세스.
- 명시적 핸드오프 계약: "A의 출력은 B가 시작되기 전에 검사기 C를 통과해야 합니다."
- 사후 분석을 위한 결과 로깅.

### 그룹싱크 제품군 (arXiv:2508.05687)

에이전트가 동질화하거나 서로를 모방할 때 5가지 관련 실패:

**단문화 붕괴.** 동일한 기본 모델 또는 학습 데이터 → 상관된 오류. 세 에이전트가 LLM을 공유하면 환각도 공유합니다.

**순응 편향.** 에이전트가 가장 시끄럽거나 가장 자신에 있는 동료 쪽으로 조정됩니다, 잘못되더라도.

**결핍된 ToM.** 에이전트가 서로의 신념을 모델화하지 못합니다; 조정이 무너집니다 (레슨 18).

**혼합 동기 역학.** 부분적으로 정렬된 인센티브가 있는 에이전트가 절충안으로 드리프트하여 아무도 만족하지 못합니다.

**연쇄적 신뢰성 실패.** 하나의 구성 요소 오류 패턴이 종속 구성 요소에서 오류 패턴을 트리거합니다.

### 연쇄 예 — 재시도 폭풍

고전적 2026년 사고 패턴:

```
지불 서비스가 요청의 10% 실패
   ↓
주문 에이전트가 지불 재시도 (지수 백오프지만 순진함)
   ↓
각 재시도가 새로운 주문-재고 확인
   ↓
재고 서비스가 정상 부하의 2배를 봄
   ↓
재고 서비스가 시간 초과 시작
   ↓
모든 주문이 재고 확인을 재시도
   ↓
재고 서비스가 정상 부하의 10배를 봄
   ↓
클러스터 중단
```

수정은 고전적입니다: **서킷 브레이커**. 하류 오류율이しきい値を超えると 기본값 또는 캐시된 결과로 단락합니다. 또한 요청당 재시도 예산을 상한합니다.

서킷 브레이커는 수정 없이 분산 시스템에서 직접 차용하는 몇 안 되는 멀티 에이전트 실패 완화 중 하나입니다.

### 메모리 독성 (재방문)

레슨 13에서: 하나의 에이전트의 환각이 공유 메모리 사실이 됩니다; downstream 에이전트가毒된 사실에 대해 추론합니다. MAST 관점에서 이것은 공유 메모리 레이어의 검증 격차입니다.

점진적 정확도 저하가 증상입니다. 시스템이 크래시하지 않습니다; 근본 원인 진단이 어려운 느린 드리프트가 있습니다.

완화: 추가 전용 로그, 출처,書き込み 불가능 검증기. 이미 레슨 13에서 다루었습니다.

### STRATUS — 실패 탐지용 전문 에이전트

STRATUS (NeurIPS 2025)는 다음을 배포할 때 1.5배 완화 성공 개선을 보고합니다:

- **탐지 에이전트.** 증상 패턴을監視합니다 (높은 불일치, 재시도 급증, 정확도 드리프트).
- **진단 에이전트.** 증상 given, MAST 택소노미에서 가능한 근본 원인을 추정합니다.
- **검증 에이전트.** 완화가 적용된 후 증상이 사라지는지 확인합니다.

이것은 에이전트 시스템에 적용된 SRE 스타일 인시던트 대응입니다. 세 역할은 모두 특수화된 프롬프트가 있는 LLM 에이전트일 수 있습니다.

### 실패 모드 감사

2026년 최선의 관행은 연간 (또는 주요 릴리스당) 실패 모드 감사입니다:

1. **추적 샘플.** ~1000개의 실제 실행 추적을 수집합니다.
2. **분류.** 각 추적의 실패에 대해 MAST + 그룹싱크 카테고리로 매핑합니다.
3. **카테고리별 실패율 계산.** 어떤 카테고리가 시스템에서 지배적입니까?
4. **완화 순위 지정.** 어떤 수정이 대부분의 실패를 제거합니까?
5. **2-3가지 완화를 선택합니다.** 구현합니다; 다음 분기 다시 감사합니다.

규율이 특정 선택보다 중요합니다. 감사가 없으면 실패가 소음으로 혼합되고 체계적으로 해결되지 않습니다.

### 시스템이 조용히 실패할 때

가장 위험한 실패 카테고리는 조용한 정밀도 실패입니다. 크게 실패하는 시스템 (크래시, 예외, 경고)은 모니터링할 수 있습니다. 그럴듯하지만 잘못된 출력을 생산하는 시스템은 예외 로그로 감지할 수 없습니다. 이것이 검증 격차가 실패 횟수의 21.30%에만 불구하고 가장 expensive한 카테고리인 이유입니다.

투자:
- 샘플 기반 인간 검토.
- 황금 데이터셋 회귀 테스트.
- 중요한 출력에 대한 교차 에이전트 교차 확인.

### 실패 대 느린 실패

일부 실패는 즉각적입니다; 일부는 느립니다. 즉각적 실패 (timeout, 스키마 불일치, auth 오류)는 감지가 저렴합니다. 느린 실패 (메모리 독성, 단문화 드리프트, 역할 모호성)는 감지와 예방이 비용이 많이 듭니다.

2026년 엔지니어링 이동: 드리프트가 눈에 띄는 오류가 되기 전에 잡을 수 있도록 느린 실패 프록시를 계측합니다. 동의율, 재시도율, 출력 길이 분포, 연속 에이전트 버전 간 편집 거리는 모두 유용한 프록시입니다.

## 빌드

`code/main.py`가 구현합니다:

- `FailureTaxonomy` — 시뮬레이션된 인시던트를 MAST + 그룹싱크 카테고리로 분류합니다.
- `CircuitBreaker` — 클래식 패턴; 오류율이しきい値を超えると 열립니다.
- `RetryStormSimulator` — 연쇄적 실패를 보여줍니다; 서킷 브레이커 on/off를 전환합니다.
- `DetectionAgent` — 스크립트된 STRATUS 스타일 증상 매처.

실행:

```
python3 code/main.py
```

예상 출력:
- 서킷 브레이커 없이 재시도 폭풍: 재고 오류가 급증합니다 (시뮬레이션).
- 서킷 브레이커 포함:しきい値에서 상한; degraded 모드 응답이 제공됩니다.
- 탐지 에이전트가 패턴에 플래그를 지정하고 MAST 카테고리를 이름 짓습니다.

## 활용

`outputs/skill-mast-auditor.md`는 멀티 에이전트 시스템에서 MAST 스타일 실패 모드 감사를 실행합니다. 추적 → 분류 → 완화 순위 지정.

## 결과물

프로덕션의 실패 모드 규율:

- **분기별 MAST 감사.** 연度が 아닙니다. 카테고리가 시스템이 성장함에 따라 이동합니다.
- **어디든 서킷 브레이커.**任何 종속 서비스에 대한 모든 발신 호출. 기본 오류율しきい値 5-10%에서 열립니다.
- **황금 데이터셋.** 작고 고품질, 인간 감사. 대해毎週 회귀 테스트.
- **STRATUS trio.** 탐지 + 진단 + 검증 에이전트가 프로덕션을 모니터링합니다. 탐지 에이전트만으로 시작합니다; 증상이 시끄러울 때 진단을 추가합니다.
- **실패 예산.** 카테고리별 실패율에 대한 명시적 SLO. 예산 초과 시 배송 중지 대화가 트리거됩니다.

## 연습문제

1. `code/main.py`를 실행하세요. 서킷 브레이커가 재시도 폭풍을 상한하는 것을 확인합니다. 실패しきい値를 변경하고 트레이드오프를 관찰합니다.
2. **느린 실패 프록시**를 구현하세요: 3개의 병렬 에이전트에 대한 동의율. 급격히 떨어지면 경고를 트리거합니다. 점진적으로 에이전트 출력을 상관시켜 단문화 드리프트를 시뮬레이션합니다.
3. Cemri et al. (arXiv:2503.13657)를 읽으세요. 7개 MAS 시스템 중 하나를 선택하고 상위 3개 실패 카테고리를 매핑합니다. 이것들이 MAST가 예측하는 것과 어떻게 비교합니까?
4. 그룹싱크 논문 (arXiv:2508.05687)을 읽으세요. 5개 패턴 중哪一个가 프로덕션에서 감지하기 가장 어려운지 식별합니다. 프록시 메트릭을 제안합니다.
5. 특정한 멀티 에이전트 시스템용 STRATUS 스타일 탐지-진단-검증 trio를 디자인합니다. 탐지가 무엇을监视합니까? 진단이 무엇을 추천합니까? 검증이 어떻게它们가 작동하는지 확인합니까?

## 핵심 용어

| 용어 | 人们怎么说 | 실제 의미 |
|------|----------------|------------------------|
| MAST | "2026년 택소노미" | Cemri 2025; 실패의 3개 근본 카테고리 + 14개 하위 유형. |
| Specification Problem | "역할 모호성" | 작업 또는 역할이 정의되지 않음; 에이전트가 무엇을 해야 할지 모름. |
| Coordination Failure | "상태 드리프트" | 에이전트 간 통신 또는 동기화 중단. |
| Verification Gap | "아무도 확인하지 않음" | 출력이 독립적 검증 없이 수락됨. |
| Groupthink family | "동질성 실패" | 단문화, 순응, 결핍된 ToM, 혼합 동기, 연쇄. |
| Monoculture collapse | "동일 모델, 동일 환각" | 공유 기본 모델 또는 학습 데이터에서 상관된 오류. |
| Retry storm | "연쇄적 오류 증폭" | 하나의 실패가 하류의 부하를 증폭시키는 재시도를 촉발합니다. |
| Circuit breaker | "오류율에서 빠른 실패" | 오류율이しきい値を超えると 열립니다; 기본값으로 단락합니다. |
| STRATUS | "인시던트 대응 trio" | 탐지 + 진단 + 검증 에이전트. 1.5배 완화 성공. |
| Memory poisoning | "환각 전파" | 공유 메모리 사실이 오염됨; downstream 에이전트가毒에서 추론합니다. |
