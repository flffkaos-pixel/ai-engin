# Consensu와 에이전트를 위한 Byzantine Fault Tolerance

> 클래식 분산 시스템 BFT가 확률적 LLM을 만납니다. 2025-2026년에 세 가지 연구 방향이 emerged: **CP-WBFT** (arXiv:2511.10400)는 각 투표에 신뢰도 프로브를 달加权합니다; **DecentLLMs** (arXiv:2507.14928)는 병렬 워커 제안과 기하 중앙값聚合으로 리더없음으로 갑니다; **WBFT** (arXiv:2505.05103)는 가중 투표와 계층적 구조 클러스터링을 결합하여 Core와 Edge 노드를 분할합니다. "AI 에이전트가 동의할 수 있는가?" (arXiv:2603.01213)의 정직한 경험적 결과는 스칼라 동의조차 오늘날에는脆弱하다는 것입니다 — 단일 기만적 에이전트가 Mixture-of-Agents를 손상시킬 수 있습니다. BFT는 필요하지만 충분하지 않습니다. 이 레슨은 최소 BFT 프로토콜을 구축하고, 세 가지 에이전트 특정 공격(비잔틴 거짓말, 시코판시적 conformity, 상관된 오류 monoculture)을 주입하고, 각 consensus 변형이 어떻게 대응하는지 측정합니다.

**유형:** 학습 + 실습
**언어:** Python (stdlib)
**선수 과목:** Phase 16 · 07 (Society of Mind and Debate), Phase 16 · 13 (Shared Memory)
**소요 시간:** ~75분

## 문제

N개의 LLM 에이전트가 각각 답변을 산출합니다. 그들이不同意합니다. 다수결 투표가 잘못된 것을 선택합니다, 왜냐하면 두 에이전트가 상관되어 있기 때문입니다 (동일한 기본 모델, 동일한 교육 데이터, 동일한 실패 모드). 세 번째 에이전트가 우연히 새로운 방식으로 잘못됩니다 — 그래서 다수는 가짜 다수입니다.

이제 기만적 에이전트를 추가합니다: 의도적으로 거짓말합니다. 또는 시코판시적 에이전트: 마지막에 말한 사람과 동의합니다. 클래식 BFT에서 가정은 Byzantine 노드가 분수 `f < n/3`라는 것과 행동이 임의라는 것입니다. 2026년 현실은 LLM 노드가 정직할 때도 확률적이고, 모델 간에 상관되어 있으며, 서로의 출력의 영향을 받는다는 것입니다. 독립적인 Bernoulli 유권자로 취급할 수 없습니다.

클래식 BFT (PBFT, 1999)는 틀리지 않았습니다 — 불완전합니다. 이는 임의의 비트 플립핑을 처리합니다. "세 명의 정직한 에이전트가 교육 데이터를 공유하기 때문에 동일한 환각을 공유한다"는 것을 처리하지 않습니다. 이 레슨은 PBFT의 기반에서 구축하고 세 가지 2025-2026 적응을上に階層化합니다.

## 개념

### 클래식 BFT가 제공하는 것

실용적 Byzantine Fault Tolerance (Castro & Liskov, OSDI 1999)는 `f < n/3` Byzantine 노드를 허용합니다. 프로토콜에는 세 단계(pre-prepare, prepare, commit)와 두 가지 기본 요소(서명된 메시지, 쿼럼 인증서)가 있습니다. `n >= 3f + 1` 정직-또는-악의적 노드 간의 단일 값에 대한 동의.

보장이 강하지만 가정합니다:

1. **독립적 장애.** Byzantines가 조정하지 않습니다.
2. **정직한 노드가 정말로 정직합니다.** 정직한 출력의 정확성은 문제가 아닙니다; 프로토콜은 فقط 불일치를 정렬합니다.
3. **질문에ground-truth 답이 있습니다.** 잘못된 사실에 대한 consensus도 여전히 consensus입니다.

LLM 에이전트는 세 가지 모두 위반합니다. 동일한 기본 모델을 실행하는 두 에이전트가 결함을 공유합니다. "정직한" LLM도 여전히 환각합니다. 그리고 모호한 질문에서, "진실"은 에이전트가 결정하는 것입니다 — 외부 오라클이 없습니다.

### 세 가지 LLM 특정 공격

**비잔틴 거짓말.** 하나의 에이전트가 의도적으로 잘못된 답변을 출력합니다. 클래식 BFT는 `f < n/3`이면 이를 처리합니다.

**시코판시적 conformity.** 하나의 에이전트가 투표 전에 다른 사람들의 답변을 읽고 마지막으로 말한 사람에게 맞춥니다. 악의적이지는 않지만, 가장 큰 목소리와 상관됩니다. 클래식 BFT는 에이전트가 모든 서명 검사를 통과하기 때문에 이것을防止하지 않습니다.

**상관된 오류 monoculture.** 세 에이전트가 기본 모델을 공유합니다. 그들이 동일한 잘못된 답변을 환각합니다. 다수가 잘못되었습니다. 클래식 BFT는 세 개 모두 "정직하게" 동의하기 때문에 도움이 되지 않습니다.

### 2025-2026 응답

**CP-WBFT** (arXiv:2511.10400) — Confidence-Probed Weighted BFT. 각 유권자가 답변에 신뢰도 프로브를 첨부합니다 (자기 보고 확률 또는 별도의 보정 모델의 예측). 투표 가중치가 신뢰도에 따라 확장됩니다. 완전한 그래프에서 +85.71% BFT 개선을 보고했습니다. 완화: 시코판시적 conformity (conformity 에이전트는 자발적 위치에 대해 낮은 신뢰도를 갖는 경향이 있습니다).

**DecentLLMs** (arXiv:2507.14928) — 리더없음. 워커 에이전트가 병렬로 제안하고, 평가자 에이전트가 제안에 점수를 매기고, 최종 답변은 scored 위치의 기하 중앙값입니다. `f < n/2`일 때 강력합니다. 완화: 비잔틴 거짓말과 상관된 오류 (기하 중앙값은 이상값에 강하고 밀도가 높은 클러스터 쪽으로 끌어당기며, 모델에 편향된 평균이 아닙니다).

**WBFT** (arXiv:2505.05103) — 계층적 구조 클러스터링이 있는 Weighted BFT. 투표 가중치는 응답 품질과 이력에서 학습된 신뢰 점수로 할당됩니다. 에이전트를 Core와 Edge로 클러스터화합니다; Core 에이전트가 먼저 consensus를 달성해야 하고, Edge 에이전트가 따릅니다. 완화: 확장성 (Core consensus가 작고 빠름) 및 부분적으로 monoculture (Core는 다양성을 위해 선택될 수 있음).

### 경험적: "AI 에이전트가 동의할 수 있는가?" (arXiv:2603.01213)

논문은 여러 프론티어 모델에서 스칼라 동의(LLM 에이전트가 단일 숫자 값에 동의)를 측정합니다. 발견은 uncomfortable합니다:

- 적이 없는 경우에도 LLM 에이전트가 많은 벤치마크에서 30% 이상의 속도로 스칼라 질문에不同意합니다.
- 기만적 페르소나를 채택하는 단일 에이전트가 Mixture-of-Agents consensus를 정직한 베이스라인에서 40 이상 백분율 포인트 끌어낼 수 있습니다.
-不同意율이 모델 다양성과 상관됩니다 — 이기종 앙상블이 동종 앙상블보다 더많이不同意합니다 (좋음: 상관되지 않은 오류) 그러나 더 천천히 드리프트합니다 (나쁨: 합의에 도달하는 데 더 오래 걸림).

要点: BFT는 출력을 정렬하는 기계를 제공하지만, 정렬된 출력이 올바른지 여부를 말해 주지 않습니다. 검증 (Phase 16 · 08 역할 전문화), 다양성 (Phase 16 · 15 debate 변형), 평가자 에이전트 (Phase 16 · 24 벤치마크)와 결합하세요.

### 핵심 프로토콜, 분리된

LLM 에이전트를 위한 최소 BFT 라운드:

```
1. task 도착; 각 에이전트 i가 답변 a_i를 산출
2. 각 에이전트가 [0, 1]에서 신뢰도 프로브 c_i를 첨부
3. aggregator가 모든 n 에이전트에서 (a_i, c_i)를 수집
4. aggregator가 의미론적 클러스터로 그룹화 (동등한 답변)
5. aggregator가 각 클러스터 C에 대한 가중치 계산:
     w(C) = sum_{i in C} c_i
6. winner = max 가중치의 클러스터, max > threshold * sum(c_i)인 경우
   그렇지 않으면: 재시도 또는 에스컬레이션
7. minority 클러스터가，事後 감사를 위해 출처와 함께 기록됨
```

의미론적 클러스터링 단계가 LLM 특정 트위스트입니다. "연구가 4.2%를 보고합니다"와 "4.2% 개선"이라는 두 답변은 동일한 클러스터입니다. 순진한 문자열 같음 검사는 이것을 놓칠 것입니다. 프로덕션에서는 저렴한 임베딩 모델 또는 명시적 정규화를 사용하세요.

### 임계값 튜닝

`threshold` 매개변수는 언제 수락하고 언제 재시도할지 결정합니다. 너무 낮으면: 약한 다수를 수락합니다. 너무 높으면: 아무것도 수락하지 않습니다. 경험적 범위: n=5-7 에이전트에 대해 0.5-0.67, 더 작은 n에 대해 더 높습니다. 임계값 아래에서는 인간 또는 다른 에이전트 앙상블로 에스컬레이션합니다.

### consensus가 도움이되지 않는 곳

- **모호한 질문.** 질문에ground truth가 없으면, consensus는 의견입니다. 그렇게 부르세요.
- **복합 질문.** "코드를 작성하고 설명하세요" — 두 가지 답변. 각기 독립적으로 투표하세요.
- **적대적 다중 라운드.** 에이전트가 이전 라운드를 관찰하고 모방할 수 있으면 (Du 2023 debate), 그들은 진실에 관계없이 서로 동의하기 시작합니다. 라운드를 제한하세요 (typically 2-3).

## 실습

`code/main.py`가 구현합니다:

- `AgentVoter` — (답변, 신뢰도)가 있는 스크립트된 정책.
- `MajorityVote` — 클래식 다수결.
- `CPWBFT` — 의미론적 클러스터링이 있는 신뢰도 가중 투표.
- `DecentLLMs` — scored 제안에 대한 기하 중앙값聚合.
- `Scenario` — 세 가지 공격 패턴에서 각 aggregator를 실행합니다.

구현된 공격 패턴:

1. `byzantine`: 하나의 에이전트가 높은 신뢰도로 거짓말합니다.
2. `sycophancy`: 하나의 에이전트가 보는 첫 번째 답변을 copying하고, 일치하는 신뢰도로.
3. `monoculture`: 세 에이전트가 동일한 잘못된 답변을 공유합니다 (상관된 오류), moderate 신뢰도로.

실행:

```
python3 code/main.py
```

예상 출력: (공격, aggregator) -> 최종 답변의 표, 올바른 답변이 강조 표시됩니다. 다수결이 monoculture 사례에서 실패합니다. CPWBFT의 신뢰도 가중치가 시코판시를 완화합니다. DecentLLMs의 기하 중앙값이 monoculture이 인구의 절반 미만일 때 정직한 클러스터 쪽으로 끌어당깁니다.

## 활용

`outputs/skill-consensus-designer.md`가 멀티에이전트 앙상블에 대한 consensus 프로토콜을 설계합니다: 클러스터링 방법, 가중치, 임계값, 하위 임계값 라운드에 대한 에스컬레이션 정책.

## 결과물

어떤 consensus 메커니즘을 shipping하기 전에:

- **최소한 세 가지 이상의 공격 패턴으로 공격 테스트.** 프로토콜이 조용히ではなく 예측 가능하게 실패해야 합니다.
- **모든 minority 클러스터를 출처와 함께 로그.** Minority 클러스터는 상관된 오류에 대한 조기 경고 시스템입니다.
- **제한된 라운드를 적용.** "동의할 때까지 debate 유지" 금지 — 시코판시를reward합니다.
- **정확성과 정답을 분리.** Consensus 출력은 검증자로 갑니다; 검증자는 앙상블과 독립적입니다.
- **동의율을 모니터링.** 급격한 상승은 conformity 편향을 의미합니다; 급격한 하락은 모델 드리프트를 의미합니다.

## 연습 문제

1. `code/main.py`를 실행합니다. 다수결이 monoculture 공격에서 실패하고 CPWBFT가 monoculture 신뢰도가 0.7 미만일 때 부분적으로 완화하는 것을 확인합니다.
2. 네 번째 공격 패턴을 추가합니다: **자동 abstention** — 하나의 에이전트가 응답을 거부합니다 ("모르겠습니다"). 각 aggregator가 abstention을 처리해야 할 방식은 무엇입니까? 선택을 구현합니다.
3. 의미론적 클러스터링을 문자열 정규화에서 임베딩 유사성으로 바꿉니다 (모든 오픈소스 임베딩 모델 사용). 시코판시 공격에 무엇이 발생합니까?
4. CP-WBFT (arXiv:2511.10400)를 읽습니다. 신뢰도 프로브 보정 단계를 구현합니다 (별도의 보정 모델이 각 에이전트의 자기 보고 신뢰도를 확인합니다). monoculture 시나리오에서 정확도 게인을 측정합니다.
5. "AI 에이전트가 동의할 수 있는가?" (arXiv:2603.01213)를 읽습니다. 단순화된 스칼라 동의 실험을 재현합니다: 세 에이전트, 하나의 스칼라 질문, 기만적 페르소나 프롬프트. CPWBFT 또는 DecentLLMs가 그것을 잡습니까?

## 핵심 용어

| 용어 |人们在说什么 | 实际含义 |
|------|----------------|------------------------|
| BFT | "Byzantine 내결함성" | `f < n/3` 임의의 장애로 consensus를 위한 Castro-Liskov 1999 프로토콜. |
| Byzantine | "모든 나쁜 행동" | 거짓말, 메시지 삭제, 조용한 실패 — 안전한 크래시를 제외한 모든 것. |
| 신뢰도 프로브 | "얼마나 확실합니까?" | 투표에 첨부된 자기 보고 또는 보정기 예측 확률. |
| 의미론적 클러스터링 | "같은 답변, 다른 단어" | 투표 전에 동등한 답변을 그룹화합니다. |
| 기하 중앙값 | "견고한 중심" | 샘플 포인트까지 거리의 합을 최소화하는 점. 평균과 달리 이상값에 강건합니다. |
| Monoculture | "같은 모델, 같은 실패" | 에이전트가 교육 데이터 또는 기본 모델을 공유할 때 상관된 오류. |
| 시코판시적 conformity | "가장 큰 목소리와 동의" | 유권자의 표가 먼저/가장 크게 말한 사람 쪽으로 편향됩니다. |
| Core/Edge | "계층적 BFT" | WBFT 분할: 먼저 작은 Core consensus, Edge 노드가 따릅니다. 지연 시간을 제한합니다. |
