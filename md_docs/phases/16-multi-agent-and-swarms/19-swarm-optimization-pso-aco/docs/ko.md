# LLM용 스웜 최적화 (PSO, ACO)

> bio-inspired 최적화가 LLM comeback을 보이고 있습니다. **LMPSO** (arXiv:2504.09247)는 각 입자의 속도가 프롬프트이고 LLM이 다음 후보를 생성하는 PSO를 사용합니다; 구조화된 시퀀스 출력(수학 표현, 프로그램)에서 잘 작동합니다. **Model Swarms** (arXiv:2410.11163)는 각 LLM 전문가를 모델 가중치 매니폴드에 PSO 입자로 취급하고 9개 데이터셋에서 12개 기준보다 **13.3% 평균 향상**을 200개의 인스턴스만으로 보고합니다. **SwarmPrompt** (ICAART 2025)가 PSO + Grey Wolf를 프롬프트 최적화에 hybridizes합니다. **AMRO-S** (arXiv:2603.12933)는 멀티에이전트 LLM 라우팅을 위한 ACO 영감 페로몬 전문가입니다 — **4.7x 속도 향상**, 해석 가능한 라우팅 증거, 학습에서 추론을 분리하는 품질 게이트 비동기 업데이트. 이 레슨은 프롬프트 매개변수 공간에서 PSO와 에이전트 라우팅에서 ACO를 구현하고, 이러한 클래식 알고리즘이 LLM 시대에 적합한 이유와 그렇지 않은 경우를 측정합니다.

**유형:** 학습 + 실습
**언어:** Python (stdlib)
**선수 과목:** Phase 16 · 09 (Parallel Swarm Networks), Phase 16 · 14 (Consensus and BFT)
**소요 시간:** ~75분

## 문제

작업 eval에서 62%를 받는 프롬프트가 있습니다. 개선하고 싶습니다. 순진한 이동은 gradient가 없는 수동 조정이며, 규모가 잘못됩니다. 강화 학습에는 reward 신호와 훈련에 충분한 롤아웃이 필요합니다. 프롬프트를 통한 역전파는 실제 가능하지 않습니다 — 프롬프트는 이산 문자열이지, 미분 가능한 매개변수가 아닙니다.

 클래식 bio-inspired 최적화 — 연속 검색 공간용 PSO, 경로 선택용 ACO —는 정확히 이 체제를 위해 설계되었습니다: gradient가 없음, 인구 기반, 평가당 저렴. LLM과 페어로 gradient가 없는 검색 단계에 페어링하면 놀랍도록 실용적인 optimizer를 얻습니다.

동일한 패턴이 멀티에이전트 시스템에서 에이전트 *라우팅*에 적용됩니다. ACO 스타일 페로몬 trail은 어떤 작업 유형에서 어떤 에이전트가 가장 잘 작동하는지 기록하고, 라우터가 trail을 exploit하고, 페로몬이衰減하여 경로를 다시 발견할 수 있습니다.

## 개념

### PSO 리프래셔 (Kennedy & Eberhart 1995)

입자 군 최적화: 연속 검색 공간에서 입자 군입니다. 각 입자는 위치 `x_i`와 속도 `v_i`를 가집니다. 각 반복:

```
v_i <- w * v_i + c1 * r1 * (p_best_i - x_i) + c2 * r2 * (g_best - x_i)
x_i <- x_i + v_i
fitness(x_i) 평가
개선 시 p_best_i 업데이트
개선 시 g_best 업데이트
```

여기서 `p_best`는 입자 자신의 최선, `g_best`는 스웜의 최선, `w, c1, c2`는 관성 + 인지 + 사회적 가중치, `r1, r2`는 무작위 요인입니다.

### LLM 출력에 대한 PSO — LMPSO

arXiv:2504.09247는 LLM 생성 구조화된 출력(수학 표현, 프로그램)에 PSO를 적응합니다. 각 입자는 후보 출력입니다. 속도는 현재 출력을 개인/전역 최선 쪽으로 수정하는 방법을 설명하는 *프롬프트*입니다. LLM이 속도 프롬프트에서 새 출력을 생성합니다. 속도의 "관성"은 "작은 점진적 변경을 만드세요"와 같은 프롬프트입니다.

이것이 잘 작동하는 경우:
- 출력이 구조화되어 있습니다 (파싱 가능, 평가 가능).
- 적합성이 자동입니다 (테스트 실행, 산술 평가).
- 인구가 작습니다 (~10-30 입자) 그래서 총 LLM 호출이 관리 가능합니다.

적합성에 인간 리뷰가 필요하면 잘 작동하지 않습니다 — 반복당 비용이 prohibitive합니다.

### Model Swarms

arXiv:2410.11163는 PSO를 출력 레이어에서 *모델* 레이어로 가져옵니다. 각 "입자"는 전문가 LLM(매개변수)입니다. 스웜이 gradient가 없는 업데이트를 통해 집단 최선 쪽으로 매개변수를 이동합니다. 보고됨: 9개 데이터셋에서 12개 기준보다 13.3% 평균 향상, 반복당 200개의 인스턴스만.

핵심 통찰력은 LLM 전문가 모델이 공유 매개변수 매니폴드(어댑터 가중치, LoRA 델타)에서 이미 근처에 있다는 것입니다. 이 낮은 차원 부분 공간에서 PSO는 저렴하고 효과적입니다.

### ACO 리프래셔 (Dorigo 1992)

개미 군 최적화: 개미가 그래프를 가로지릅니다; 각 경로에 페로몬 trail이 있습니다. 개미 이동 확률이 페로몬 강도로 가중됩니다. 작업을 완료한 개미는 솔루션 품질에 비례하여 페로몬을 depositing합니다. 페로몬은 시간이 지남에 따라衰減합니다.

### AMRO-S — 에이전트 라우팅용 ACO

arXiv:2603.12933는 멀티에이전트 라우팅에 ACO를 사용합니다. 각 작업 유형은 "목적지"입니다; 각 에이전트는 가능한 경로입니다. 좋은 출력을 producing하는 경로에 페로몬이 강해집니다. 주요 기여:

- **해석 가능한 라우팅 증거.** 페로몬 강도는 인간이 읽을 수 있는 신호입니다.
- **품질 게이트 비동기 업데이트.** 품질 검사를 통과한 후에만 페로몬이 업데이트되어 추론과 학습이 분리됩니다.
- **멀티에이전트 라우팅 벤치마크에서 4.7x 속도 향상.**

품질 게이트가 중요합니다: 없으면 빠르지만 잘못된 에이전트가 페로몬을 누적하고 시스템이 나쁜 경로에 lock in됩니다.

### LLM에 PSO / ACO를 사용할 때

**PSO 사용:**
- 검색 공간이 연속적이거나 연속 매개변수로 매핑됩니다 (프롬프트 임베딩, LoRA 가중치, 수치 생성 매개변수).
- 적합성이 저렴하고 자동입니다.
- 인구가 작을 수 있습니다 (10-30).

**ACO 사용:**
- 라우팅 또는 경로 선택 문제가 있습니다.
- 결정이 시간이 지남에 따라 강화됩니다 (같은 작업 유형이 돌아옵니다).
- 라우팅 결정에 대한 해석 가능한 증거가 필요합니다.

**어느 것도 사용하지 마세요:**
- 적합성에 인간 리뷰가 필요합니다 (반복당 비용이 너무 비쌉니다).
- 검색 공간이 PSO가 다루지 않는 방식으로 이산적이고 조합론적입니다 (대신 유전 알고리즘 사용).
- 실시간 결정이 단일 패스 heuristic에 비해 느리게 수렴합니다 (엄격한 지연 시간이 필요합니다).

### bio-inspired가 여전히 이기는 이유

Gradient 기반 방법은 미분 가능한 신호가 필요합니다. LLM 출력과 라우팅 결정은 쉽게 미분 가능하지 않습니다. 의사 gradient 방법 (강화 학습된 라우터, DPO-스타일 프롬프트 튜너)은 작동하지만 expensive한 훈련이 필요합니다.

PSO와 ACO는 *평가기* 함수만 필요합니다. 후보 출력이나 라우팅 결정을 점수화할 수 있으면 공간을 최적화할 수 있습니다. 그것이 적용 가능성에 대한 바를 훨씬 낮춥니다.

### 실용적 한계

- **인구 예산.** N 입자 × T 반복 × 평가당 비용. ~$0.02/호출에서 LLM eval의 경우, 20-입자 PSO가 50 반복 실행하면 ~$20입니다. 그에 따라 계획하세요.
- **탐색 대 활용.** 페로몬衰減율과 PSO 관성이 트레이드오프합니다; 너무 빠르면衰減 → 솔루션을 잊습니다; 너무 느리면 → 초기 지역 최적값에 갇힘.
- **재앙적 드리프트.** 적합성 지형이 변경되면 (새 데이터 분포) 두 알고리즘 모두 수렴한 다음 발산할 수 있습니다. 최선 적합성 안정성을 모니터하세요.

## 실습

`code/main.py`가 구현합니다:

- `LMPSO` — 수치 프롬프트 매개변수에 대한 PSO (temperature, top_k 가중치). 각 입자의 "LLM 생성"은 스크립트된 적합성 함수로 시뮬레이션됩니다. 30 반복 알고리즘을 실행하고 g_best 수렴을 보여줍니다.
- `AMRO_S` — ACO 스타일 라우팅. 3개 에이전트, 4개 작업 유형, 페로몬 행렬, 100개 라우팅된 작업. 시간에 따른 (task_type → agent 선택) 분포를 인쇄하여 trail 형성을 보여줍니다.
- 비교: 동일한 작업 스트림에서 무작위 라우팅 대 ACO 라우팅. 품질과 지연 시간을 측정합니다.

실행:

```
python3 code/main.py
```

예상 출력:
- LMPSO: g_best 적합성이 30 반복에 걸쳐 무작위에서 거의 최적에 가까워집니다.
- AMRO-S: 페로몬 테이블이 작업 유형당 올바른 에이전트에 안정됩니다; ACO 라우팅이 품질에서 무작위보다 ~30-40% 높고 지연도 감소합니다 (재시도 감소).

## 활용

`outputs/skill-swarm-optimizer.md`가 LLM / 에이전트 최적화 문제에 대해 PSO, ACO, 유전 알고리즘, gradient 기반 optimizer 중 선택을 도와줍니다.

## 결과물

- **작게 시작하세요.** 10-20 입자, 20-50 반복. 수렴 곡선이 명확한 이점을 보여주면만 확장하세요.
- **반복마다 페로몬 또는 g_best를 로그하세요.** trail 없이 스웜 optimizer를 디버깅하는 것은 고통스러릅니다.
- **품질 게이트 업데이트.** 특히 ACO 라우팅의 경우: 빠르고 잘못된 에이전트가 페로몬을 누적해서는 안 됩니다.
- **분포 이동 시 재설정.** eval 분포가 변경되면 오래된 페로몬은 오래되었습니다; 일시적으로衰減율을 재설정하거나 두 배로 합니다.
- **반복당 비용을 제한하세요.** 반복당 비용 메트릭을，发出합니다. $500/반복이고 0.5%만 향상하는 PSO는 출하 불가능합니다.
