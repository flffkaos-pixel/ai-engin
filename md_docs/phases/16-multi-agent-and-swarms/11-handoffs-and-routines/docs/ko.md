# 핸드오프와 루틴

> OpenAI Swarm의 핵심 primitive입니다: 하나의 에이전트가 작업을 완료하고 "이것을 위해另一位 에이전트에게 전달"합니다. Swarm에서 이것은 툴 호출입니다 — `handoff` 툴이 에이전트를 반환합니다. 이것은 수퍼바이저 패턴보다 가볍고, 루프가 필요할 때 더 유연합니다. 그러나 그 가벼움은 또한 모니터링하기更难한 상호 의존성을 만들 수 있습니다. 이 레슨은 핸드오프 mechanics, 루틴의 역할, 그리고 2026년 생산성의 교훈을 다룹니다.

**유형:** 학습
**언어:** TypeScript
**선수 과목:** Phase 16 · 04 (Primitive Model), Phase 16 · 05 (Supervisor)
**소요 시간:** ~45분

## 문제

파일이 순차적 파이프라인을 통해 이동할 때 무슨 일이 발생합니까? 각 단계에서 누가 결정합니까?

수퍼바이저 패턴에서 수퍼바이저가 결정합니다. 플래너가 계획을 세우고, 워커를 선택하고, 출력을 종합합니다.

핸드오프 패턴에서 에이전트 자체가 결정합니다. 각 에이전트는 "다음에 이것을 처리해야 할" 것을 결정하고 그에게 전달합니다.

## 개념

### Swarm 핸드오프 mechanics

OpenAI Swarm에서 핸드오프는 툴 호출입니다:

```typescript
const handoffTool = {
  name: "transfer_to_researcher",
  description: "이 작업을 연구자에게 전달합니다",
  parameters: {
    type: "object",
    properties: {
      task: { type: "string" },
      context: { type: "string" },
    },
  },
  handler: async ({ task, context }) => {
    return {
      agent: "researcher",
      task,
      context,
    };
  },
};
```

에이전트가 이 툴을 호출하면 컨트롤이 해당 에이전트에게 전달됩니다. 이것은 수퍼바이저의 "위임"보다 가볍습니다 — 에이전트가 직접 다른 에이전트를 호출합니다.

### 루틴

루틴은 사전 정의된 핸드오프 시퀀스입니다:

```typescript
const reviewRoutine = {
  name: "코드 리뷰 루틴",
  steps: [
    { agent: "author", action: "코드 작성" },
    { agent: "reviewer", action: "피드백 제공" },
    { agent: "author", action: "수정" },
    { agent: "reviewer", action: "승인 또는 거절" },
  ],
  maxIterations: 3,
};
```

루틴은 "항상 이 순서로"를 시행합니다. 핸드오프는 "상황에 따라 다릅니다"를 허용합니다.

### 수퍼바이저 대 핸드오프

| 측면 | 수퍼바이저 | 핸드오프 |
|------|----------|--------|
| 결정 위치 | 중앙 수퍼바이저 | 분산 에이전트 |
| 유연성 | 제한됨 (수퍼바이저가 허용하는 경우에만) | 높음 (에이전트가 직접 선택) |
| 추적 가능성 | 높음 (수퍼바이저가 흐름을 알고 있음) | 낮음 (핸드오프 체인을 따라야 함) |
| 복잡성 | 낮음 (하나의 결정자) | 높음 (상호 의존성) |
| 디버깅 | 수월함 | 각 핸드오프를 추적해야 함 |

### 루틴의 가치

루틴은 두 가지 문제를 해결합니다:

1. **일관성** — 에이전트가 "항상 리뷰어가 코드를 승인해야 합니다"를 알고 있습니다.
2. **품질 보호** — 에이전트가 루프에서 나가는 방법을 알기 때문에, 검토없이 코드가 shipping되는 것이防止됩니다.

### 실패 모드

- **핸드오프 암시、死** — 에이전트가 다른 에이전트에게 전달하지만 무엇을해야 할지 명시하지 않습니다.
- **순환 핸드오프** — A가 B에게 전달하고, B가 A에게 전달합니다. 영원히.
- **핸드오프 손실** — 에이전트가 전달하지만 수신자가それを知らずに 다음 단계를 진행합니다.

## 실습

`code/main.ts`는 세 가지 핸드오프 패턴을 구현합니다:

- **명시적 핸드오프**: 각 에이전트가 다음 에이전트를 명시적으로 선택합니다
- **루틴 기반 핸드오프**: 사전 정의된 시퀀스가 시행됩니다
- **혼합**: 일반적인 단계는 루틴, 예외는 명시적 핸드오프

실행:

```
npx tsx code/main.ts
```

## 핵심 용어

| 용어 |人们在说什么 | 实际含义 |
|------|----------------|------------------------|
| 핸드오프 | "다른 에이전트에게 전달" | 하나의 에이전트가 컨트롤을另一位에게 전달하는 메커니즘. |
| 루틴 | "사전 정의된 시퀀스" | 핸드오프의 사전 정의된 시퀀스. 일관성을 보장합니다. |
| 순환 핸드오프 | "영원한 루프" | 두 에이전트가 서로에게 전달하여 결코 끝나지 않습니다. |
| 핸드오프 암시、死 | "전달하지만 설명되지 않음" | 수신자가 무엇을해야 할지 모릅니다. |
