# 계층적 아키텍처와 그 실패 모드

> 계층적은 수퍼바이저가 중첩된 것입니다. 관리자 에이전트가 서브-관리자 위로, 워커 위로. CrewAI `Process.hierarchical`가 교과서 버전입니다: `manager_llm`이 동적으로 작업을 위임하고 출력을 검증합니다. LangGraph 등가물은 `create_supervisor(create_supervisor(...))`입니다. 작업이 실제 조직도인 경우 자연스러운 패턴입니다. 또한 관리자 루핑으로 무너질 가능성이 가장 높은 패턴이기도 합니다 — 관리자 에이전트가 작업을 잘못 할당하거나, 하위 출력을 오해하거나, 합의에 도달하지 못합니다. 순차적이 often 그것을 이깁니다.

**유형:** 학습 + 실습
**언어:** Python (stdlib)
**선수 과목:** Phase 16 · 05 (Supervisor Pattern)
**소요 시간:** ~60분

## 문제

수퍼바이저 패턴이 클릭되면 자연스러운 다음 단계는 "워커가 themselves 수퍼바이저라면 어떨까요?" 팀에 하위 팀이 있습니다; 회사에는 부서의 부서가 있습니다. 계층적 아키텍처가 그것을 미러합니다.

문제: LLM 관리자는 인간 관리자와 다릅니다. 인간 관리자는 보고서를 받는 것에 대해 안정적인priors를 가집니다. LLM 관리자는 턴마다 컨텍스트에 있는 것으로 org를 다시 추론합니다. 그 컨텍스트의 작은 드리프트, 그리고 전체 트리가 작업을 잘못 할당합니다.

## 개념

### 형태

```
                 Manager
                 ┌─────┐
                 └──┬──┘
           ┌────────┴────────┐
           ▼                 ▼
       Sub-Mgr A         Sub-Mgr B
       ┌─────┐           ┌─────┐
       └──┬──┘           └──┬──┘
         ┌┴──┬──┐          ┌┴──┐
         ▼   ▼  ▼          ▼   ▼
       W1  W2  W3         W4  W5
```

모든 내부 노드가 계획, 위임, 종합합니다. 리프만 작업합니다.

### 빛나는 곳

- **명확한 org 매핑.** 실제 작업이 부서별인 경우 ("법률팀이 문서를 리뷰하고, 재무팀이 문서를 리뷰하고, 엔지니어가 문서를 리뷰한 다음 임원용으로 종합"), 계층이 명확합니다.
- **지역 종합.** 각 서브-관리자가 팀 출력을 종합한 후 최상위 관리자가 봅니다. 최상위 관리자는 15개의 워커 출력이 아닌 3개의 서브-관리자 요약만 봅니다.

### 깨지는 곳

세 가지 실패 모드를 2026 포스트모템이 계속 찾습니다:

1. **작업 할당 오류.** 관리자가 목표를 읽고, 분해를 환각하고, 잘못된 서브-관리자에게 위임합니다. 서브-관리자가 주어진 것에obedient하게 작업하기 때문에, 오류는 인간이 포착할 수 있었을 위치에서 한 수준 제거된 최상위 종합에서만 표면화됩니다.
2. **출력 오해.** 서브-관리자가 "주장 X를 확인할 수 없음"을 반환합니다. 최상위 관리자가 "주장 X 미확인"으로 종합합니다. 의미가 각 수준에서 드리프트합니다.
3. **합의 루프.** 두 서브-관리자가 불확실합니다; 최상위 관리자가 그들에게 조정하도록 요청합니다; 그들이 다시 아래로 위임합니다; 워커가 다시 실행합니다; 서브-관리자가 약간 다른 답을 반환합니다; 루프. CrewAI의 `Process.hierarchical`는 단계 제한으로 이것을 방지하지만, 제한 자체가 이제 하이퍼파라미터입니다.

### 결정 질문

순차적 (선형 파이프라인) 대 계층적: 작업이 실제로 독립적인 하위 팀을 가집니까, 아니면 하나의 선형 흐름이 나무인 척합니까? 后者이면 순차적을 사용하세요. 전자이면 계층적을 사용하되 명시적 조정 규칙에 예산을 책정하세요.

### CrewAI의 구현

`Process.hierarchical`는 전문 크루 위로 관리자 LLM을 연결합니다. 관리자:

- 최상위 작업을接收하고,
- 크루에 하위 작업을 할당하고,
- 크루 출력을 평가하고,
- 수락, 다시 위임, 또는 반복할지 결정합니다.

문서: https://docs.crewai.com/en/introduction ("핵심 개념" 아래 "계층적 프로세스" 참조).

### LangGraph의 구현

LangGraph는 중첩된 `create_supervisor` 호출을 사용합니다. 내부 수퍼바이저는 자체 그래프를 가집니다; 외부 수퍼바이저는 내부 그래프를 불투명 노드로 취급합니다. 이것은 CrewAI보다 디버깅에 더 깨끗합니다 (각 그래프를 별도로 단계별로 진행할 수 있습니다) 하지만 트리를 동적으로 재형성하는 것은 더 표현하기 어렵습니다.

참조: https://reference.langchain.com/python/langgraph-supervisor.

## 실습

`code/main.py`는 3단계 계층을 실행합니다:

- 최상위 관리자: 작업을 "엔지니어링" 및 "법률" 분기로 분할,
- 엔지니어링 서브-관리자: "프론트엔드" 및 "백엔드" 워커로 분할,
- 법률 서브-관리자: 하나의 워커.

데모는 행복 경로 (모두 동의) 대 **摄동 경로**를 대비시킵니다 — 최상위 관리자의 분해가 "법률"을 "재무"로 잘못 표시하고 오류가 어떻게 캐스케이드되는지 관찰 — 서브-관리자가 재무 작업을 obedient하게 수행하고, 최상위 종합자가 재무 findings을 보고하고, 원래 법률 질문이 답변되지 않습니다.

실행:

```
python3 code/main.py
```

출력은 "요청된 것" 대 "전달된 것"의 명백한 나란한 비교와 함께 두 경로를 모두 보여줍니다.

## 활용

`outputs/skill-hierarchy-fitness.md`는 주어진 작업이 계층적, 순차적, 또는 플랫 수퍼바이저를 사용해야 하는지 평가합니다. 입력: 작업 설명, org 구조, 조정 예산. 출력: 방어해야 할 특정 실패 모드와 함께한 패턴 권장 사항.

## 결과물

계층적을 출하하는 경우:

- **트리 깊이를 2로 캡합니다.** 이미 3단계는 관찰 가능성에서 대부분의 오류를 숨깁니다.
- **명시적 조정 예산.** 최상위 관리자가 커밋해야 하는 최대 라운드를 설정합니다. 通常 2.
- **모든 종합에 출처.** 각 노드의 요약은 어떤 리프 출력이 그것을 산출했는지cite해야 합니다.
- **분해 드리프트에 대한 경고.** 각 단계에서 관리자의 분해를 로그합니다; 사용자 쿼리와diff합니다. 분해가 더 이상 쿼리를 덮지 않으면 경고를 발생시킵니다.

## 연습 문제

1. `code/main.py`를 실행하고 행복 대 摄동을 비교합니다. 최상위 출력이 사용자의 질문에서 완전히 벗어날 때까지 몇 수준의 관리자 핸드오프가 걸립니까?
2. 3단계 (상위 → 서브 → 서브-서브 → 워커)를 추가합니다. 깊이가 증가함에 따라 摄동 경로가 자체를 교정하는 빈도 대 완전히 드리프트하는 빈도를 측정합니다.
3. 각 서브-관리자에 항상 변경되지 않은 원본 사용자 질문으로 asking되는 "카나리" 워커를 추가합니다. 카나리 답변이 종합된 답변과 불일치할 때 관리자가 어떻게 반응해야 합니까?
4. CrewAI의 `Process.hierarchical` 문서를 읽으세요. CrewAI가 적용하는 하나의 구체적 가드레일 (단계 제한, manager_llm 제약)을 식별하고 어떤 실패 모드를目标是描述하세요.
5. 중첩된 LangGraph 수퍼바이저와 CrewAI 계층적을 비교합니다. 어느 것이 합의 루프를 더 저렴하게 감지합니까?

## 핵심 용어

| 용어 |人们在说什么 | 实际含义 |
|------|----------------|------------------------|
| 계층적 | "조직도 패턴" | 수퍼바이저之上的 수퍼바이저; 리프만 작업합니다. |
| Manager LLM | "보스" | 내부 노드에서 분해, 할당, 검증하는 LLM. |
| 분해 드리프트 | "보스가 줄을 잃음" | 최상위 관리자의 분할이 더 이상 원래 질문을 덮지 않습니다. |
| 합의 루프 | "끝없는 회의" | 서브-관리자가 불확실합니다; 상위가 다시 위임합니다; 워커가 다시 실행합니다; 예산이 소진될 때까지 루프. |
| 깊이-2 천장 | "2단계 이상 깊이 가지 마세요" | 경험적 가드레일: 3단계 이상은 관찰 가능성을 무너뜨립니다. |
| 카나리 질문 | "각 수준의 근본 진실" | 항상 변경되지 않은 원본 쿼리로 asking되는 워커, 드리프트를 감지합니다. |
| 출처 체인 | "누가 무엇이라고 했는지" | 각 종합에서 그것을 산출한 리프 출력까지 추적합니다. |
