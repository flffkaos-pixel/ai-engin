# 도구 사용과 함수 호출

> Toolformer (Schick et al., 2023)는 자기 지도 도구 주석을 시작했다. Berkeley Function Calling Leaderboard V4 (Patil et al., 2025)는 2026년 기준을 설정한다: 40% 에이전틱, 30% 멀티턴, 10% 라이브, 10% 비라이브, 10% 환각. 단일 턴은 해결되었다. 메모리, 동적 의사 결정, 장기 도구 체인은 아니다.

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 01 (Agent Loop), Phase 13 · 01 (Function Calling Deep Dive)
**Time:** ~60분

## 학습 목표

- Toolformer의 자기 지도 훈련 신호를 설명한다: 실행이 다음 토큰 손실을 줄일 때만 도구 주석을 유지.
- BFCL V4의 다섯 가지 평가 범주와 각각이 측정하는 것을 명명한다.
- 스키마 검증, 인수 강제 변환, 실행 샌드박싱이 있는 stdlib 도구 레지스트리를 구현한다.
- 2026년의 세 가지 미해결 문제(장기 도구 체이닝, 동적 의사 결정, 메모리)를 진단한다.

## 문제

초기 도구 사용은 질문했다: 모델이 올바른 함수 호출을 예측할 수 있는가? 현대 도구 사용은 질문한다: 모델이 40단계에 걸쳐 도구를 체이닝하고, 메모리를 사용하며, 부분적 관찰 가능성으로 작업하고, 도구 실패에서 회복하며, 존재하지 않는 도구를 환각하지 않을 수 있는가?

Toolformer는 기준선을 확립했다: 모델이 자기 지도로 도구 호출 시점을 학습할 수 있다. BFCL V4는 2026년 평가 목표를 정의한다. 둘 사이의 간격이 프로덕션 에이전트가 활동하는 공간이다.

## 개념

### Toolformer (Schick et al., NeurIPS 2023)

아이디어: 모델이 자신의 사전 훈련 코퍼스에 후보 API 호출을 주석으로 달게 하라. 각 후보에 대해 실행하라. 도구 결과를 포함하는 것이 다음 토큰의 손실을 줄이는 경우에만 주석을 유지하라. 필터링된 코퍼스로 미세 조정하라.

포함된 도구: 계산기, QA 시스템, 검색 엔진, 번역기, 캘린더. 자기 지도 신호는 순전히 도구가 텍스트 예측에 도움이 되는지에 관한 것이다 — 사람 레이블 없음.

규모 결과: 도구 사용은 규모에서 나타난다. 작은 모델은 도구 주석으로 손해를 보고, 큰 모델은 이득을 본다. 이것이 2026년 프론티어 모델이 강력한 도구 사용을 내장한 반면, 대부분의 7B 모델이 신뢰할 수 있으려면 명시적 도구 사용 미세 조정이 필요한 이유다.

### Berkeley Function Calling Leaderboard V4 (Patil et al., ICML 2025)

BFCL은 2026년 사실상의 평가다. V4 구성:

- **Agentic (40%)** — 전체 에이전트 궤적: 메모리, 멀티턴, 동적 결정.
- **Multi-Turn (30%)** — 도구 체인이 있는 대화형 상호작용.
- **Live (10%)** — 사용자가 제출한 실제 프롬프트 (더 어려운 분포).
- **Non-Live (10%)** — 합성 테스트 케이스.
- **Hallucination (10%)** — 도구를 호출하지 말아야 할 때 탐지.

V3는 상태 기반 평가를 도입했다: 도구 시퀀스 후 API의 실제 상태를 확인(예: "파일이 생성되었는가?"). V4는 웹 검색, 메모리, 형식 민감도 범주를 추가했다.

2026년 주요 발견: 단일 턴 함수 호출은 거의 해결되었다. 실패는 메모리(턴 간 컨텍스트 전달), 동적 의사 결정(이전 결과에 기반한 도구 선택), 장기 체인(20+단계 후 드리프트), 환각 탐지(도구가 맞지 않을 때 호출 거부)에 집중된다.

### 도구 스키마

모든 프로바이더는 스키마가 있다. 세부사항은 다르지만 동일한 형태를 공유한다:

```
name: string
description: string (what it does, when to use it)
input_schema: JSON Schema (properties, required, types, enums)
```

Anthropic은 `input_schema`를 직접 사용한다. OpenAI는 `function.parameters`를 사용한다. 둘 다 JSON Schema를 허용한다. 설명은 중요하다 — 모델이 올바른 도구를 선택하기 위해 읽는다. 잘못된 도구 설명은 잘못된 도구 선택 실패의 #1 근본 원인이다.

### 인수 검증

도구 호출을 신뢰하지 마라. 다음을 검증하라:

1. **타입 강제 변환.** 모델이 스키마가 int를 요구하는 곳에 문자열 "5"를 반환할 수 있다. 모호하지 않으면 강제 변환하고, 그렇지 않으면 거부.
2. **열거형 검증.** 스키마가 `status in {"open", "closed"}`라고 하는데 모델이 `"in_progress"`를 출력하면 설명적 오류와 함께 거부.
3. **필수 필드.** 필수 필드 누락 -> 충돌이 아닌 즉시 오류 관찰을 모델로 반환.
4. **형식 검증.** 날짜, 이메일, URL — 정규식이 아닌 구체적인 파서로 검증.

모든 검증 실패는 모델이 올바른 형태로 재시도할 수 있도록 구조화된 관찰을 반환해야 한다.

### 병렬 도구 호출

최신 프로바이더는 하나의 어시스턴트 턴에서 병렬 도구 호출을 지원한다. 루프:

1. 모델이 고유한 `tool_use_id`로 3개의 도구 호출을 출력.
2. 런타임이 실행 (독립적이면 병렬).
3. 각 결과가 `tool_use_id`로 상관된 `tool_result` 블록으로 반환.

엔지니어링 규칙: 상관 ID를 중요하게 취급하라. 이를 바꾸면 잘못된 도구-결과 라우팅이 발생한다.

### 샌드박싱

도구 실행은 샌드박스 경계다. 레슨 09에서 자세히 다룬다. 요약: 모든 도구는 읽기/쓰기 표면, 네트워크 액세스, 타임아웃, 메모리 제한을 지정해야 한다. 일반적인 `run_shell(cmd)`는 위험 신호다. 구체적인 `git_status()`가 더 안전하다.

## 직접 구현하기

`code/main.py`는 프로덕션 형태의 도구 레지스트리를 구현한다:

- JSON Schema 서브셋 검증기 (stdlib만).
- 설명, 입력 스키마, 타임아웃, 실행기가 있는 도구 등록.
- 인수 강제 변환 및 열거형 검증.
- 상관 ID를 사용한 병렬 도구 디스패치.
- 구조화된 문자열로서의 오류 관찰.

실행:

```
python3 code/main.py
```

트레이스는 미니 에이전트가 한 턴에서 세 개의 도구를 호출하고, 하나는 의도적으로 잘못된 형식으로 호출되어 모델이 조치할 수 있는 설명적 오류와 함께 거부되는 것을 보여준다.

## 활용하기

모든 프로바이더는 자체 도구 스키마가 있다 — Anthropic, OpenAI, Gemini, Bedrock. 여러 프로바이더가 필요하면 변환 레이어(OpenAI Agents SDK, Vercel AI SDK, LangChain 도구 어댑터)를 사용하라. BFCL은 참조 벤치마크다 — 도구 사용이 제품의 핵심이라면 출시 전에 에이전트에 대해 실행하라.

## 배포하기

`outputs/skill-tool-registry.md`는 주어진 작업 도메인에 대한 도구 카탈로그, 스키마 및 레지스트리를 생성한다. 설명 품질 검사(각 도구의 설명이 모델에게 언제 사용해야 하는지 알려주는가?)를 포함한다.

## 연습 문제

1. 모델이 다른 도구 사용을 명시적으로 거부할 수 있는 "no-op" 도구를 추가하라. BFCL 스타일 환각 테스트에서 측정하라.
2. int-as-string 및 float-as-string에 대한 인수 강제 변환을 구현하라. 강제 변환이 실제 버그를 숨기기 시작하는 지점은 어디인가?
3. 도구별 타임아웃과 차단 회로(3회 연속 실패 후 60초 동안 도구 거부)를 추가하라. 이는 모델의 복구 방식을 어떻게 바꾸는가?
4. BFCL V4 설명을 읽어라. 하나의 범주(예: "multi-turn")를 선택하고 10개의 예제 프롬프트를 에이전트를 통해 실행하라. 통과율을 보고하라.
5. stdlib 검증기를 Pydantic 또는 Zod로 포팅하라. Pydantic/Zod가 장난감이 놓친 것을 무엇을 잡았는가?
