# 다중 에이전트 토론 및 협업

> Du et al. (ICML 2024, "Society of Minds")는 N개의 모델 인스턴스가 독립적으로 답변을 제안한 후 R라운드에 걸쳐 반복적으로 상호 비판하여 수렴합니다. 사실성, 규칙 준수, 추론 능력을 향상시킵니다. 희소 토폴로지(Sparse topology)가 토큰 비용 면에서 완전 메시(full mesh)보다 우수합니다.

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 12 (Workflow Patterns), Phase 14 · 05 (Self-Refine and CRITIC)
**Time:** ~60분

## 학습 목표

- 토론 프로토콜을 설명합니다: N명의 제안자, R라운드, 공유 답변으로 수렴.
- 토론이 사실성, 규칙 준수 및 추론을 향상시키는 이유를 설명합니다.
- 희소 토폴로지를 설명합니다: 모든 토론자가 서로를 볼 필요는 없음.
- 스크립트형 LLM을 사용하여 완전 메시 및 희소 변형으로 stdlib 토론을 구현하고 토큰 비용 대 정확도를 측정합니다.

## 문제

Self-Refine (Lesson 05)은 하나의 모델이 자신을 비판하는 방식입니다 — 집단사고 위험이 있습니다. CRITIC (Lesson 05)은 외부 도구에 비판을 근거합니다 — 항상 사용 가능한 것은 아닙니다. 토론은 세 번째 모드를 도입합니다: 여러 인스턴스, 상호 비판, 불일치를 통한 수렴.

## 개념

### Society of Minds (Du et al., ICML 2024)

- N개의 모델 인스턴스가 동일한 질문에 대해 독립적으로 답변을 제안합니다.
- R라운드에 걸쳐 각 모델은 다른 모델의 제안을 읽고 비판합니다.
- 모델은 비판에 기반하여 답변을 업데이트합니다.
- R라운드 후 수렴된 답변을 반환합니다.

원래 실험은 비용 때문에 N=3, R=2를 사용했습니다. 어려운 문제(MMLU, GSM8K, 체스 수 유효성, 전기 생성)에서 더 많은 에이전트와 더 많은 라운드로 정확도가 향상됩니다.

교차 모델 조합이 단일 모델 토론보다 우수합니다: ChatGPT + Bard 함께 > 각각 단독.

### 희소 토폴로지

"Sparse Communication Topology를 통한 다중 에이전트 토론 개선" (arXiv:2406.11776, 2024-2025)은 완전 메시 토론이 항상 최적은 아님을 보여주었습니다. 희소 토폴로지(star, ring, hub-and-spoke)가 더 낮은 토큰 비용으로 정확도를 맞출 수 있습니다. 각 토론자는 일부 동료만 봅니다.

의미:

- 완전 메시 N=5, R=3 = 5 × 3 = 15개 제안, 각각 4명의 동료 읽기 = 60개 비판 작업.
- Star N=5, R=3 (하나의 허브 + 4개 스포크) = 15개 제안, 스포크는 허브만 읽음 = 12개 비판 작업.

### 토론이 도움이 될 때

- **사실성.** N개의 독립적 제안, 상호 검증으로 환각 감소.
- **규칙 준수.** 체스 수 유효성 — 한 모델이 규칙을 놓치면 다른 모델이 잡아냅니다.
- **개방형 추론.** 다양한 프레이밍이 올바른 답변으로 좁혀집니다.

### 토론이 해가 될 때

- **지연 시간에 민감한 UX.** N × R 직렬 라운드는 감당할 수 없는 지연 시간입니다.
- **비용에 민감한 규모.** 질문당 N × R 토큰.
- **단순 사실 조회.** 하나의 조회가 다섯 번의 토론보다 저렴합니다.

### 2026년 실제 구현

- **Anthropic orchestrator-workers** (Lesson 12) — 합성 단계가 있는 토론의 한 변형.
- **LangGraph supervisor** (Lesson 13) — 중앙 라우터 + 전문 에이전트가 노드로 토론을 구현할 수 있음.
- **OpenAI Agents SDK** (Lesson 16) — 반복적 비판을 위해 에이전트가 서로 핸드오프.
- **다중 에이전트 평가** — 평가 신호를 위한 토론 + evaluator-optimizer 쌍.

### 이 패턴이 실패하는 경우

- **수렴 붕괴.** 모든 에이전트가 첫 번째 잘못된 답변에 수렴합니다. 필수 불일치 라운드로 완화.
- **허브 실패.** 스타 토폴로지에서 잘못된 허브가 모든 사람을 오염시킵니다. 순환 또는 다중 허브 사용.
- **프롬프트 동질화.** 모든 에이전트가 동일한 프롬프트를 사용하여 동일한 답변을 생성합니다. 다양한 프롬프트 및/또는 모델 사용.

## 빌드하기

`code/main.py`는 stdlib 토론을 구현합니다:

- `Debater` 클래스 (토론자별 의견 변화가 있는 스크립트형 LLM).
- `FullMeshDebate` 및 `SparseDebate` 실행기.
- 세 가지 질문: 하나는 사실 기반, 하나는 규칙 기반, 하나는 추론 기반.
- 메트릭: 수렴된 답변, 수렴까지 라운드 수, 총 비판 작업 수.

실행:

```
python3 code/main.py
```

출력: 프로토콜별 정확도 및 비용; 희소가 더 낮은 비용으로 2/3 질문에서 완전 메시와 일치.

## 사용하기

- **Anthropic orchestrator-workers** — 간단한 2-3 워커 토론용.
- **LangGraph** — 체크포인팅이 있는 상태 저장 다중 라운드 토론용.
- **커스텀** — 연구 또는 특수 정확성 보장용.

## 배포하기

`outputs/skill-debate.md`는 구성 가능한 토폴로지, N, R 및 수렴 규칙을 가진 다중 에이전트 토론을 생성합니다.

## 연습 문제

1. "강제 불일치" 규칙을 구현합니다: 1라운드에서 모든 토론자가 서로 다른 제안을 생성해야 합니다. 수렴 속도에 미치는 영향을 측정합니다.
2. 신뢰도 가중 집계를 추가합니다: 토론자가 (답변, 신뢰도)를 반환; 집계자가 신뢰도로 가중치 부여. 도움이 되나요?
3. 하나의 "에이전트"를 다른 의견을 가진 다른 스크립트형 LLM으로 교체합니다. 이질성이 정확도를 향상시키나요?
4. 세 가지 질문에 대한 완전 메시 대 희소의 토큰 비용을 측정합니다. 비용 대 정확도를 그래프로 표시합니다.
5. Society of Minds 논문을 읽습니다. 장난감을 N=5, R=3으로 포팅합니다. 무엇이 깨지나요? 무엇이 개선되나요?
