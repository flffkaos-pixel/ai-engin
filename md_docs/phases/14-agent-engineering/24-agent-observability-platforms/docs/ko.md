# 에이전트 관측성: Langfuse, Phoenix, Opik

> 2026년을 지배하는 세 가지 오픈소스 에이전트 관측성 플랫폼. Langfuse(MIT) — 월 600만+ SDK 설치, 트레이싱 + 프롬프트 관리 + 평가 + 세션 재생. Arize Phoenix(Elastic 2.0) — 심층 에이전트 특화 평가, RAG 관련성, OpenInference 자동 계측. Comet Opik(Apache 2.0) — 자동화된 프롬프트 최적화, 가드레일, LLM-판단 환각 탐지.

**Type:** Learn
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 23 (OTel GenAI)
**Time:** ~45분

## 학습 목표

- 세 가지 주요 오픈소스 에이전트 관측성 플랫폼과 그 라이선스를 설명한다.
- 각각의 강점을 구분한다: Langfuse(프롬프트 관리 + 세션), Phoenix(RAG + 자동 계측), Opik(최적화 + 가드레일).
- 2026년까지 89%의 조직이 에이전트 관측성을 도입한 이유를 설명한다.
- LLM-판단 평가를 포함한 stdlib 트레이스-투-대시보드 파이프라인을 구현한다.

## 문제

OTel GenAI(레슨 23)는 스키마를 제공한다. 여전히 필요한 것은 스팬을 수집하고, 평가를 실행하고, 프롬프트 버전을 저장하고, 회귀를 표면화하는 플랫폼이다. 세 경쟁자는 각각 수명 주기의 다른 부분을 강조한다.

## 개념

### Langfuse (MIT)

- 월 600만+ SDK 설치, 19,000+ GitHub 스타.
- 기능: 트레이싱, 버전 관리 + 플레이그라운드가 포함된 프롬프트 관리, 평가(LLM-as-judge, 사용자 피드백, 커스텀), 세션 재생.
- 2025년 6월: 기존 상용 모듈(LLM-as-a-judge, 주석 큐, 프롬프트 실험, 플레이그라운드)이 MIT로 오픈소스화됨.
- 최강 분야: 프롬프트 관리 루프와 결합된 종단간 관측성.

### Arize Phoenix (Elastic License 2.0)

- 더 깊은 에이전트 특화 평가: 트레이스 클러스터링, 이상 탐지, RAG 검색 관련성.
- 네이티브 OpenInference 자동 계측.
- 프로덕션용 관리형 Arize AX와 페어링.
- 프롬프트 버전 관리 없음 — 더 넓은 플랫폼과 함께 드리프트/행동 회귀 도구로 포지셔닝.
- 최강 분야: RAG 관련성, 행동 드리프트, 이상 탐지.

### Comet Opik (Apache 2.0)

- A/B 실험을 통한 자동화된 프롬프트 최적화.
- 가드레일(PII 편집, 주제 제약).
- LLM-판단 환각 탐지.
- Comet 자체 측정 기준: Opik 로깅 + 평가 23.44초 vs Langfuse 327.15초(~14배 차이) — 벤더 벤치마크는 참고용으로만 활용.
- 최강 분야: 최적화 루프, 자동화된 실험, 가드레일 시행.

### 업계 데이터

Maxim(2026년 현장 분석)에 따르면: 89%의 조직이 에이전트 관측성을 도입했으며, 품질 문제가 최대 프로덕션 장벽(응답자의 32%)이다.

### 선택 가이드

| 필요 | 선택 |
|------|------|
| 프롬프트 관리가 포함된 올인원 | Langfuse |
| 심층 RAG 평가 + 드리프트 | Phoenix |
| 자동화된 최적화 + 가드레일 | Opik |
| 오픈 라이선스, ELv2 없음 | Langfuse (MIT) 또는 Opik (Apache 2.0) |
| Datadog / New Relic 통합 | 모두 가능 — 모두 OTel 내보내기 지원 |

### 이 패턴이 실패하는 경우

- **평가 전략 없음.** 평가 없는 트레이싱은 비싼 로깅에 불과하다.
- **근거 없는 자체 제작 LLM-판단.** CRITIC 패턴(레슨 05) 적용 — 판단에는 사실 확인을 위한 외부 도구가 필요하다.
- **트레이스와 연결되지 않은 프롬프트 버전.** 프로덕션에서 회귀 발생 시, 원인 프롬프트를 찾을 수 없다.

## 직접 구축하기

`code/main.py`는 stdlib 트레이스 수집기 + LLM-판단 평가기를 구현한다:

- GenAI 형식의 스팬을 수집한다.
- 세션별로 그룹화하고, 실패한 실행(가드레일 위반, 낮은 신뢰도 평가)에 태그를 지정한다.
- 에이전트 응답을 루브릭으로 평가하는 스크립트형 LLM-판단.
- 대시보드 형태 요약: 실패율, 주요 실패 원인, 평가 점수 분포.

실행:

```
python3 code/main.py
```

출력: Langfuse/Phoenix/Opik이 보여줄 세션별 평가 점수 및 실패 분류.

## 활용하기

- **Langfuse** 자체 호스팅 또는 클라우드; OTel 또는 SDK를 통해 연결.
- **Arize Phoenix** 자체 호스팅; OpenInference 자동 계측.
- **Comet Opik** 자체 호스팅 또는 클라우드; 자동화된 최적화 루프.
- **Datadog LLM Observability** 이미 Datadog을 사용하는 혼합 운영+ML 팀용.

## 배포하기

`outputs/skill-obs-platform-wiring.md`는 플랫폼을 선택하고 기존 에이전트에 트레이스 + 평가 + 프롬프트 버전을 연결한다.

## 실습

1. 일주일 분량의 OTel 트레이스를 Langfuse 클라우드(무료 티어)로 내보내자. 어떤 세션이 실패했는가? 왜 그런가?
2. 사용자 도메인에 맞는 LLM-판단 루브릭(사실 정확성, 어조, 범위 준수)을 작성하고 50개 트레이스로 테스트하자.
3. Langfuse 프롬프트 버전 관리와 Phoenix 트레이스 클러스터링을 비교하자. 무엇이 더 빠르게 문제를 알려주는가?
4. Opik의 가드레일 문서를 읽고, PII 편집 가드레일을 에이전트 실행 중 하나에 연결하자.
5. 세 가지를 자신의 코퍼스로 벤치마킹하자. 벤더 발표 수치는 무시하고 직접 측정하자.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|----------|
| 트레이싱 | "스팬 수집기" | OTel/SDK 스팬 수집; 세션별 인덱싱 |
| 프롬프트 관리 | "프롬프트 CMS" | 트레이스와 연결된 버전 관리 프롬프트 |
