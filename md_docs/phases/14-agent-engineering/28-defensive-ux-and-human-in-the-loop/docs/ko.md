# 방어적 UX와 인간-인-더-루프

> 에이전트 작동을 담당하는 팀은 실패에 대한 책임도 진다. 계획은 인간에게 표시되어야 한다. 파괴적인 작업은 확인이 필요하다. 거절은 이유와 함께 이루어져야 한다. 안전 장치가 없으면 생산권은 거부되어야 한다.

**Type:** Learn
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 27 (Prompt Injection)
**Time:** ~45분

## 학습 목표

- 에이전트 UI에서 방어적 UX의 네 가지 필수 패턴을 명명한다 (계획 공개, 확인 게이트, 거절 설명, 실행 취소).
- 인간-인-더-루프 확인이 필요한 세 가지 조건을 식별한다.
- 거절 설명이 없는 시스템과 거절 설명이 없는 시스템을 비교한다.
- 안전에 실패할 때 에이전트가 거절하는 것을 설명한다.

## 문제

에이전트가 작업을 수락하면 사용자가 책임 진다. 에이전트가 실패하면 — 잘못된 도구, 부적절한 실행, 인젝션 — 사용자가 대가를 치른다. 방어적 UX는 작업 전에 인간에게 통제권을 부여하고 실패 후에 명확성을 제공한다. 보안(인젝션 중지)과 사용성(더 빠른 작업 완료) 사이의 절충이다.

## 개념

### 네 가지 방어 UX 패턴

1. **계획 공개 (Plan disclosure).** 실행 전에 에이전트가 예상되는 단계를 표시. 전자 메일을 보내기 전에 "보낼까요? To: X, Subject: Y, Body: Z"를 표시. 이는 인간이 선택 사항을 검토할 수 있게 하면서도 작업 부하를 제한하여 절충한다.

2. **확인 게이트 (Confirmation gates).** 파괴적인 작업에는 확인이 필요. 삭제, 쓰기, 보내기, 구매는 단순한 "실행 취소"가 아닌 명시적 "예"를 요구. 지연 시간을 추가하지만, 회복할 수 없는 오류를 방지.

3. **거절 설명 (Refusal explanations).** 거절할 때 에이전트는 이유를 표시. "불완전한 정보로 인해 거절" 또는 "작업이 콘텐츠 정책을 위반"이 "할 수 없음"보다 낫다. 이는 사용자가 다음에 무엇을 해야 하는지 알 수 있게 한다. LLM이 생성한 설명은 품질이 다양할 수 있음 — 서비스에 적합할 정도로 충분히 좋은 품질을 확인하라.

4. **실행 취소 (Undo).** 최근 작업을 실행 취소. 에이전트가 상태 저장 작업(파일 편집, 데이터베이스 쓰기)을 추적하고 롤백을 제공. 에이전트 권한의 핵심 안전장치.

### 인간-인-더-루프 (HITL)

확인 게이트 이상의 의미. 확인 게이트는 작업 수준에서 작동한다. HITL은 에이전트가 인간의 승인 없이는 특정 작업을 수행할 수 없음을 의미한다. 조건:

1. **작업이 민감한 데이터에 접근하거나 수정하는 경우.** 고객 데이터 읽기, 자격 증명 수정.
2. **작업이 법적 또는 규제 영향을 미치는 경우.** 계약 체결, 규정 준수 진술서 제출.
3. **비용 임계값을 초과하는 경우.** 에이전트당 시간당 $100, 또는 작업당 $5.

### 거절 전략

거절은 작업이 완료될 수 없거나 안전하지 않을 때 발생. 거절은 명확성과 자율성 사이에서 절충. 다음이 있으면 좋음:

- **이유.** 무엇이 잘못되었는가 (원하는 내용 포함/불완전/정책 위반/리소스 없음 등).
- **제안.** "이 작업은 고객 ID가 필요합니다." 어떤 갭을 채워야 하는가.

LLM 기반 거절 설명의 품질은 다양함. 사용자가 가치 있다고 느끼는지 확인하라.

### 안전 기능 저하

방어가 실패할 때 — 분류기가 작동을 멈추거나 의심스러운 입력이 포함된 경우 — 안전한 상태는 거절이다.

**회로 차단기 패턴** (에이전트 운영의 안전 장치. 레슨 32에서 자세히 다름):

1. 분류기 = 거절 (이유와 함께).
2. 인젝션이 감지됨 = 중지 및 거절, 또는 격리된 컨텍스트에서만 계속.
3. 인간의 명시적 지시 만이 분류기 결정을 무시할 수 있음.

### 이 패턴이 잘못되는 경우

- **확인 피로.** 모든 작업에 확인이 필요하면 사용자가 "예"를 남발. 위험 순위에 따라 게이트.
- **LLM 거절 설명에 과도한 신뢰.** 모델이 거절을 잘못 설명함 ("정책 위반"이지만 실제로는 하드웨어 오류). 설명의 정확성을 관찰 가능성 시스템으로 추적.
- **실행 취소 시스템 없음.** 실행 취소가 없으면 확인 게이트가 모든 오류를 포착해야 하며, 완전히 포착할 수 없음.

## 직접 구현하기

`code/main.py`는 방어 UX 레이어를 구현:

- 작업 계획 생성기 (예측된 단계 표시).
- 위험 순위가 지정된 확인 게이트 시스템.
- 구조화된 거절 설명 (이유, 제안, 정책 참조).
- 상태 저장 작업(파일 편집, 생성, 삭제)을 추적하고 최근 3개 실행 취소를 허용하는 실행 취소 시스템.

실행:

```
python3 code/main.py
```

출력: 5개의 확인 + 3개의 거절 + 2개의 실행 취소를 보여주는 UX 흐름.

## 활용하기

- 계획 공개와 확인 게이트로 시작. "어디에나 확인"보다 낫다.
- 사용자 피드백이 확인 피로를 보여주면 게이트 임계값 조정.
- 인간-인-더-루프 프로세스 없이 민감한 데이터를 처리하는 에이전트를 출시하지 마라.

## 배포하기

`outputs/skill-defensive-ux.md` scaffolds a defensive UX layer with confirmation gates, refusal explanations, and undo.

## 연습 문제

1. 더 많은 상태 저장 작업 유형으로 실행 취소 확장: 파일 생성, 편집, 삭제, 이름 변경. 롤백이 각각에 대해 어떻게 보이는가?
2. 게이트된 작업을 위한 HITL 조건 구현: "작업 비용 > $5"에 대한 확인. 비용 임계값 시뮬레이션.
3. 거절 설명 채우기: "불완전한 정보", "정책 위반", "리소스 오류", "인젝션 감지". 각각에 대한 제안을 어떻게 만드는가?
4. 거절 설명의 정확성 추적. 잘못된 설명을 출력하고 측정하라.
5. 안전 기능 저하 트리거: 회로 차단기 패턴을 모델링하기 위해 분류기의 오류 시뮬레이션.

## 주요 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|-----------|
| Plan disclosure | "행동 표시" | 인간이 검토할 수 있도록 실행 전 단계 표시 |
| Confirmation gate | "안전 확인" | 실행 전 위험 작업에 대한 명시적 "예" 필요 |
| Refusal explanation | "거절 이유" | 거절 이유와 갭을 채우기 위한 제안 |
| Undo | "롤백" | 마지막 N개 상태 저장 작업을 취소 |
| HITL | "인간 승인 필요" | 특정 작업은 인간 확인이 필요 |
| Graceful degradation | "안전 실패" | 방어 실패 시 에이전트 거절 |
| Circuit breaker | "안전 장치" | 분류기 오류 시 자동 거절 |
