# 에이전트 운영

> 에이전트 운영은 에이전트 인프라를 안정적으로 유지한다. 이는 Phase 14 전체에 걸쳐 있는 운영 주제(관찰 가능성, 평가, 안전, 배포)를 함께 가져온다.

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 23 (Observability), Phase 14 · 28 (Defensive UX), Phase 14 · 30 (Custom Evaluation)
**Time:** ~60분

## 문제

에이전트가 하루 종일 실행된다. 오류가 발생한다. 인젝션이 포함된다. 비용이 초과된다. 운영은 일일 주도 면담으로 이어지는 주제이다. 이 레슨은 Phase 14의 분산된 운영 개념을 단일 전략으로 통합한다.

## 개념

### 운영 스택

1. **관찰 가능성 (레슨 23-24).** 추적, 로깅, 모니터링. "에이전트가 지금 무엇을 하고 있는가?"
2. **평가 (레슨 30).** 스코어 카드, 골든 세트, LLM-as-judge. "에이전트가 잘하고 있는가?"
3. **안전 (레슨 27-28).** 분류기, HITL, 실행 취소, 거절 설명.
4. **배포 (레슨 33-35).** Dify, Weave, 배포. "변경 사항을 어떻게 출시하는가?"

### 구성 요소가 조화롭게 작동하는 방식

에이전트 운영은 세 가지 메트릭을 안정적으로 유지한다:

- **가용성.** LLM 공급자가 작동 중인가? MCP 서버가 연결되어 있는가?
- **정확성.** 에이전트 출력이 예상과 일치하는가? 골든 세트 스코어 카드가 안정적인가?
- **비용.** 에이전트가 예산을 초과하고 있는가? 토큰 사용량이 증가하고 있는가?

이러한 메트릭은 관찰 가능성(가용성, 비용)과 평가(정확성)의 입력이다. 운영 역할은 메트릭이 임계값을 위반할 때 경보를 울리는 모니터링, 위반의 원인을 찾는 디버깅, 근본 원인을 해결하기 위한 완화를 포함한다.

### 일일 주도 면담 (Daily Standup)

에이전트 운영의 리듬:

1. **어제.** 어떤 에이전트가 실패했는가? 분류기가 인젝션을 놓쳤는가? 평가 점수가 떨어졌는가?
2. **오늘.** 어떤 에이전트를 수정할 것인가? 어떤 프롬프트를 변경할 것인가? 어떤 평가를 추가할 것인가?
3. **방해 요소.** 공급자가 다운되었는가? 저장소가 가득 찼는가? 비용이 예산을 초과했는가?

### 운영 시 에이전트 운영이 깨지는 경우

- **경보 피로.** 모든 지표가 중요한 것은 아니다. 가장 중요한 몇 가지에 집중하라.
- **운영 없이 평가.** 평가 대시보드를 구축했지만 아무도 보지 않는다. 평가를 일일 운영에 연결하라.
- **사일로화된 안전.** 안전이 별도의 팀에 의해 운영된다 — 분류기가 업데이트되면 에이전트 운영도 알지 못함. 안전을 에이전트 운영 스택의 일부로 포함하라.
- **비용 추적이 필요 이상으로 늦어짐.** 운영 비용을 알리는 데 지연 시간이 있는 추적 — 영수증이 도착했을 때는 이미 꽤 많은 비용이 발생한 후임.

## 직접 구현하기

`code/main.py`는 미니 운영 콘솔을 구현:

- 메트릭 수집기: LLM 호출(지연 시간, 오류, 비용)에서 집계.
- 임계값 기반 경보: 지연 시간, 오류율, 비용에 대한 임계값 위반.
- 안전 로그 수집기: 인젝션 이벤트, 거절(HITL) 이벤트 로깅.

실행:

```
python3 code/main.py
```

출력: 메트릭 집계 및 안전 로그, 에이전트 운영을 위한 콘솔을 시뮬레이션.

## 활용하기

- 운영을 처음부터 구축하지 마라. Datadog, Grafana, 또는 Langfuse와 같은 기존 도구를 사용하라.
- 메트릭을 일일 운영에 연결하라. 경보가 standup에 표시되어야 한다.
- 안전을 별도로 유지하지 마라 — 에이전트 운영 대시보드의 일부여야 한다.
- LLM 운영 비용을 추적하기 위한 비용 메트릭과 함께 OTel GenAI를 사용하라. 제한 시간 내에 비용을 알기 위해 실시간 비용 모니터링이 유용하다.

## 배포하기

`outputs/skill-agent-ops.md` scaffolds an agent operations console with metrics, alerts, safety logs, and cost tracking.

## 연습 문제

1. 더 많은 메트릭으로 경보 시스템 확장: p95 지연 시간, 오류율, 토큰 사용량. 각각에 대한 임계값 설정.
2. 실시간 LLM 비용을 추적하기 위한 비용 메트릭 수집기를 연결한다. OTel GenAI는 비용에 어떤 스팬 속성을 정의하는가?
3. 안전 로그 수집기를 관찰 가능성(레슨 23)에 연결: 거절 이벤트가 OTel 추적에 어떻게 나타나는가?
4. "지연 시간" 또는 "오류"의 하위 메트릭을 제공하기 위해 평가 점수를 운영에 연결한다.
5. 경보 피로 시뮬레이션: 20개의 경보를 생성하고 가장 중요한 3개로 줄인다. 기준은 무엇인가?
