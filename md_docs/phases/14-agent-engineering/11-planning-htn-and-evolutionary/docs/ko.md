# HTN 및 진화적 검색을 통한 계획

> 기호 계획은 계획이 증명 가능하게 올바른 경우를 처리한다. 진화적 코드 검색은 적합도 함수가 기계 확인 가능한 경우를 처리한다. ChatHTN (2025)과 AlphaEvolve (2025)는 LLM과 쌍을 이룰 때 각각이 무엇을 열어주는지 보여준다.

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 02 (ReWOO and Plan-and-Execute)
**Time:** ~75분

## 학습 목표

- 계층적 작업 네트워크(HTN)를 설명한다: 작업, 메서드, 연산자, 전제조건, 효과.
- ChatHTN의 하이브리드 루프를 설명한다 — LLM 폴백 분해가 있는 기호 검색.
- AlphaEvolve의 진화적 루프와 프로그래밍 방식 평가기에서만 작동하는 이유를 설명한다.
- 장난감 HTN 플래너와 장난감 진화적 검색을 stdlib으로 구현한다.

## 문제

ReWOO (레슨 02), Plan-and-Execute, ReAct는 대부분의 에이전트 계획을 다룬다. 잘 다루지 못하는 두 가지 경우:

1. **증명 가능한 정확성을 가진 계획.** 스케줄링, 항로 경로, 규정 준수 워크플로우 — 계획이 구조적으로 타당해야 함. 유창한 LLM 계획이 가끔 단계를 환각하는 것은 용납될 수 없음.
2. **기계 확인 가능한 적합도 함수를 가진 최적화.** 행렬 곱셈, 스케줄링 휴리스틱, 컴파일러 패스 — 목표는 "올바른 계획"이 아니라 "최상의 계획."

HTN 계획과 AlphaEvolve는 두 가지 다른 문제를 해결한다. 둘 다 LLM을 대체재가 아닌 증폭기로 사용한다.

## 개념

### 계층적 작업 네트워크

HTN은:

- **작업** — 복합(분해 대상) 및 기본(직접 실행 가능).
- **메서드** — 복합 작업을 하위 작업으로 분해하는 방법, 전제조건 포함.
- **연산자** — 전제조건과 효과가 있는 기본 행동.
- **상태** — 사실의 집합.

계획: 목표 작업과 초기 상태가 주어지면 전제조건이 순서대로 충족되는 기본 연산자로의 분해를 찾음.

HTN은 LLM보다 오래되었으며 여전히 증명 가능한 올바른 계획의 기준이다.

### ChatHTN (Gopalakrishnan et al., 2025)

ChatHTN (arXiv:2505.11814)은 기호 HTN과 LLM 쿼리를 인터리브:

1. 기존 메서드로 현재 복합 작업 분해 시도.
2. 적용 가능한 메서드가 없으면 LLM에 질문: "상태 `s`에서 `task`를 어떻게 분해하시겠습니까?"
3. LLM 응답을 후보 하위 작업으로 변환.
4. 연산자 스키마에 대해 검증; 잘못된 분해 거부.
5. 재귀.

논문의 핵심 주장: 생성된 모든 계획은 증명 가능하게 타당하다. LLM 제안은 직접 계획 편집이 아닌 후보 분해로만 들어가기 때문이다. 기호 레이어가 정확성을 소유하고, LLM이 메서드 라이브러리를 확장한다.

온라인 메서드 학습 (OpenReview `gwYEDY9j2x`, 2025 후속)은 회귀를 통해 LLM 생성 분해를 일반화하는 학습자를 추가 — LLM 쿼리 빈도를 최대 75%까지 줄임.

### AlphaEvolve (Novikov et al., 2025)

AlphaEvolve (arXiv:2506.13131, DeepMind, June 2025)는 다른 짐승이다: Gemini 2.0 Flash/Pro 앙상블이 조정하는 진화적 코드 검색.

루프:

1. 시드 프로그램 + 프로그래밍 방식 평가기(적합도 점수 반환)로 시작.
2. LLM 앙상블이 돌연변이 제안.
3. 평가기를 통해 돌연변이 실행.
4. 최고 유지; 다시 돌연변이.

발표된 성과:

- 56년 만의 4x4 복소 행렬 곱셈에 대한 Strassen 첫 개선 (48 스칼라 곱셈).
- Borg 스케줄링 휴리스틱을 통해 0.7% Google 컴퓨팅 회수.
- 프론티어 워크로드에서 32% FlashAttention 속도 향상.

하드 제약: 적합도 함수가 기계 확인 가능해야 함. 산문 답변에 대한 진화적 검색은 수렴하지 않음.

### 언제 어떤 것을 사용할지

| 문제 클래스 | 사용 | 이유 |
|-------------|------|------|
| 하드 제약이 있는 스케줄링 | HTN + ChatHTN | 증명 가능한 타당성 |
| 컴파일러 최적화 | AlphaEvolve | 기계 확인 가능한 적합도 |
| 다단계 작업 실행 | ReAct / ReWOO | 루프에 LLM, 형식적 보장 없음 |
| 테스트가 있는 코드 개선 | AlphaEvolve | 테스트가 평가기 |
| 정책 기반 자동화 | HTN | 전제조건이 정책 인코딩 |

### 이 패턴이 잘못되는 경우

- **연산자 없는 HTN.** 전제조건/효과 스키마 없이 타당성 주장은 붕괴. ChatHTN의 "LLM이 분해 제안"은 잘못된 이동을 거부하는 스키마가 필요.
- **실제 평가기 없는 AlphaEvolve.** "LLM에게 코드가 더 나은지 물어보기"는 적합도 함수가 아님. 평가기는 결정론적이고 빨라야 함.
- **과잉 엔지니어링.** 대부분의 에이전트 작업은 둘 중 하나도 필요로 하지 않음. 먼저 ReAct나 ReWOO를 사용하라.

## 직접 구현하기

`code/main.py`는 두 가지 장난감을 구현한다:

- 연산자, 메서드, 전제조건, 효과 및 복합 작업과 일치하는 메서드가 없을 때 발동하는 `LLMFallback`이 있는 stdlib HTN 플래너. "LLM"은 플래너가 오프라인에서 실행되도록 스크립트 기반 분해기.
- 산술 프로그램에 대한 stdlib 진화적 검색: 테스트 세트에서 `|f(x) - target|`을 최소화하는 표현식 성장. 평가기는 결정론적.

실행:

```
python3 code/main.py
```

트레이스는 HTN 플래너가 복합 작업을 분해(중간 계획에 LLM 폴백 포함)하고 진화적 루프가 목표 표현식에 수렴하는 것을 보여준다.

## 활용하기

- **HTN 플래너** — `pyhop`, `SHOP3`, 또는 도메인별 정책 시행을 위해 직접 구축.
- **ChatHTN** — 연구 코드; 패턴(기호 + LLM 폴백)은 모든 HTN 플래너에 깨끗하게 포팅됨.
- **AlphaEvolve** — DeepMind 논문; 패턴(앙상블 + 평가기)은 재현 가능. OpenEvolve 및 유사 오픈소스 포크 등장 중.
- **에이전트 프레임워크** — 아직 일급 HTN이나 AlphaEvolve를 제공하는 것은 없음. 하위 에이전트 또는 백그라운드 워커로 구축.

## 배포하기

`outputs/skill-hybrid-planner.md`는 LLM 역할이 명시적으로 범위 지정된 하이브리드 플래너 구조(HTN 또는 진화적)를 생성한다.

## 연습 문제

1. HTN 플래너를 역추적으로 확장: 연산자의 사후조건이 런타임에 실패하면 롤백하고 다음 메서드 시도.
2. ChatHTN에 LLM-메서드 캐시 추가: LLM이 상태 패턴 `P`에서 작업 `T`를 분해할 때 결과 저장. 다음 호출 시 먼저 메서드 라이브러리 재확인.
3. 진화적 검색 평가기를 실제 테스트 스위트로 교체. 20개 테스트 케이스를 통과하는 정렬 함수 진화; 수렴까지 세대 보고.
4. AlphaEvolve의 평가기 설계 노트 읽기. 관심 있는 도메인(SQL 쿼리 최적화, 테스트 스위트 최소화, 배포 YAML)에 대한 평가기 설계.
5. 결합: HTN을 사용하여 복합 작업을 하위 작업으로 분해한 다음 각 하위 작업의 기본 연산자에 진화적 검색 사용. 어디서 빛나고 어디서 과잉 엔지니어링하는가?

## 주요 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-------------------|-----------|
| HTN | "계층적 플래너" | 연산자, 전제조건, 효과가 있는 작업 분해 |
| Method | "분해 규칙" | 복합 작업을 하위 작업으로 나누는 방법 |
| Operator | "기본 행동" | 전제조건과 효과가 있는 구체적 단계 |
| ChatHTN | "LLM + HTN" | 메서드가 일치하지 않을 때 기호 플래너가 LLM에 질문 |
| AlphaEvolve | "진화적 코드 검색" | 앙상블 LLM이 코드 돌연변이; 결정론적 평가기가 선택 |
| Fitness function | "평가기" | 출력에 대한 결정론적, 기계 확인 가능한 점수 |
| Online method learning | "캐시된 LLM 분해" | 쿼리 비용 절감을 위해 LLM 계획 저장 + 일반화 |
