# BPE 토크나이저 처음부터

> 바이트 입력, ID 출력, ID가 동일한 바이트로 돌아옵니다. 모든 최신 텍스트 모델이 여전히 시작하는 토크나이저를 구축하세요.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 04 수업, Phase 07 트랜스포머 수업
**Time:** 약 90분

## 학습 목표
- 가장 빈번한 인접 심볼 쌍을 반복적으로 병합하여 원시 텍스트 코퍼스에서 바이트 쌍 인코딩 어휘를 학습합니다.
- 결정론적 병합 테이블을 구현하고 이를 새 텍스트에 적용하여 서브워드 ID 스트림을 생성합니다.
- 임의의 UTF-8 입력을 ID로 왕복시키고 정보 손실 없이 되돌립니다.
- 특수 토큰을 예약하고 보호하여 학습과 디코딩에서 살아남도록 합니다.
- 바이트 수준 알파벳이 범용 토크나이저에 적합한 바닥인 이유를 추론합니다.

## 프레임

언어 모델은 절대 텍스트를 보지 않습니다. 정수를 봅니다. 문자열에서 정수 목록으로의 매핑과 그 반대가 토크나이저입니다. 이 계층을 잘못 얻으면 학습 실행의 모든 손실 곡선이 잘못된 것을 측정하게 됩니다.

일반 텍스트 모델을 위한 서브워드 토크나이저의 지배적인 계열은 바이트 쌍 인코딩입니다. 아이디어는 작습니다. 알려진 알파벳에서 시작합니다. 학습 코퍼스에서 가장 자주 나타나는 인접 심볼 쌍을 찾습니다. 이를 새 심볼로 병합합니다. 어휘가 목표 크기에 도달할 때까지 반복합니다. 새 텍스트 인코딩은 동일한 병합 목록을 동일한 순서로 재사용합니다.

바이트 수준 변형을 구축할 것입니다. 알파벳은 유니코드 코드 포인트가 아닌 256개의 원시 바이트입니다. 이 선택이 토크나이저가 알 수 없는 토큰으로 폴백하지 않고 모든 UTF-8 입력을 처리할 수 있게 합니다.

## 파이프라인

\\\mermaid
flowchart LR
    A[raw corpus text] --> B[byte split per word]
    B --> C[count adjacent pair frequencies]
    C --> D{pair table empty?}
    D -- no --> E[merge most frequent pair]
    E --> F[append merge to merge table]
    F --> G[grow vocabulary by one id]
    G --> C
    D -- yes --> H[final vocab + merges]
    H --> I[encode new text]
    H --> J[decode ids back to bytes]
\\\

학습 측과 추론 측은 병합 테이블을 공유합니다. 그 공유가 계약입니다. 추론 시 병합 순서를 변경하면 다른 ID 스트림을 디코딩합니다.

## 바이트 알파벳

처음 256개의 ID는 원시 바이트 0x00부터 0xFF까지를 위해 예약됩니다. 이는 모든 입력 문자열이 병합이 발생하기 전에 어휘로 표현될 수 있음을 보장합니다. 바이트 블록 후에는 특수 토큰을 위해 작은 범위를 예약합니다. 학습 루프는 사전 토큰화된 스트림에서 완전히 제외되므로 해당 ID를 병합 대상으로 제안하지 않습니다.

사전 토크나이저는 학습이 보기 전에 코퍼스를 공백과 구두점 경계에서 분할합니다. 분할이 없으면 BPE 병합 단계가 단어 경계를 넘는 병합을 학습하게 되어 어휘가 일반적인 구문으로 채워집니다. 분할이 있으면 병합이 단어 내에 머무르고 결과가 일반화됩니다.

## 학습 루프

각 학습 단계에서 루프는 세 가지 작업을 수행합니다. 코퍼스의 모든 단어를 순회하며 현재 심볼의 각 인접 쌍이 나타나는 빈도를 단어 자체의 빈도로 가중치를 두어 계산합니다. 가장 높은 카운트를 가진 쌍을 선택합니다. 해당 쌍의 모든 발생을 어휘의 다음 빈 슬롯인 새 심볼로 다시 씁니다. 그런 다음 병합을 기록합니다.

\\\mermaid
sequenceDiagram
    participant Corpus
    participant PairCount
    participant MergeTable
    participant Vocab
    Corpus->>PairCount: count adjacent pairs
    PairCount->>MergeTable: pick top pair (a,b)
    MergeTable->>Vocab: assign new id = a+b
    MergeTable->>Corpus: rewrite every (a,b) to new id
    Corpus->>PairCount: recount for next step
\\\

각 단계의 비용은 심볼 시퀀스 목록으로 표현된 코퍼스 크기에 선형입니다. 백만 단어와 1만 ID의 목표 어휘의 경우, 병합이 적용됨에 따라 심볼 시퀀스가 줄어들기 때문에 루프가 몇 초 안에 완료됩니다.

## 새 텍스트 인코딩

추론은 병합 카운터를 호출하지 않습니다. 학습된 것과 동일한 순서로 병합 테이블을 적용합니다. 새 단어의 경우 인코더는 바이트 분할에서 시작합니다. 현재 시퀀스에서 가장 낮은 순위의 병합(가장 먼저 적용되는 것)을 찾습니다. 해당 병합을 수행합니다. 다시 스캔합니다. 테이블의 병합이 현재 시퀀스에 적용할 수 있는 것이 없을 때 루프가 종료됩니다.

순위에 따른 순서는 인코딩을 결정론적으로 만들고 동일한 입력에 대한 학습 동작과 일치시키는 속성입니다. 먼저 학습된 병합은 테이블의 맨 위에 있으며 먼저 적용됩니다. 동일한 위치에 두 병합이 적용될 수 있으면 낮은 순위의 병합이 승리합니다.

## 특수 토큰

특수 토큰은 바이트 스트림이 절대 생성할 수 없는 ID입니다. 수동으로 예약합니다. 이 수업에서는 두 가지로 충분합니다.

- endoftext는 사전 학습 중 문서를 구분합니다. 모델에 "여기서 새 문서가 시작됩니다, 이전 문서의 컨텍스트가 새지 않도록 하세요"라고 말합니다.
- pad는 짧은 시퀀스를 채워 배치가 직사각형 텐서가 되도록 합니다. 손실 마스크가 학습 중에 이를 숨깁니다.

인코더는 입력에서 특수 토큰을 허용하는 플래그를 받습니다. 플래그가 꺼져 있으면 문자열이 해당 토큰을 철자하는 바이트로 토큰화됩니다. 플래그가 켜져 있으면 리터럴 문자열이 예약된 ID에 매핑되고 병합 대상이 아닙니다.

## 왕복 보장

인코딩 후 디코딩은 입력 바이트를 정확히 반환해야 합니다. 디코더는 순서대로 모든 ID의 바이트 확장을 연결합니다. 모든 ID는 원시 바이트이거나 이전에 알려진 두 ID의 연결이므로 재귀적 확장은 항상 원시 바이트로 종료됩니다. 디코딩은 해당 바이트가 철자하는 UTF-8 문자열을 반환합니다.

이 수업의 테스트 스위트는 보이지 않는 문장, 유니코드 이모지가 있는 문장, 리터럴 특수 토큰을 포함하는 문장에서 해당 속성을 확인합니다.

## 이 수업이 하지 않는 것

가장 큰 프로덕션 토크나이저 스타일의 정규식 기반 사전 토크나이저를 구축하지 않습니다. 여기의 사전 토크나이저는 작은 공백 및 구두점 분할입니다. 작은 학습 코퍼스에서 합리적인 병합을 생성하기에 충분하며 나머지 수업 체인과의 계약은 동일하게 유지됩니다. 다음 수업은 토크나이저를 블랙박스로 취급하고 그 위에 슬라이딩 윈도우 데이터셋을 구축합니다.

쌍 카운터를 병렬화하지 않습니다. 수천 단어의 코퍼스에 대한 Python 루프는 1초 안에 완료됩니다. 더 큰 코퍼스의 경우 단어별로 쌍을 병렬로 카운트하고 리듀스하는 것이 명백한 방법입니다.

## 코드 읽는 방법

main.py는 네 개의 객체를 정의합니다. BPETokenizer는 어휘, 병합 테이블, 특수 토큰 테이블을 보유합니다. train은 학습 루프입니다. encode는 추론 경로입니다. decode는 바이트 연결입니다. 하단의 데모는 내장 코퍼스에서 작은 토크나이저를 학습하고, 보류된 문장을 인코딩하며, ID를 다시 디코딩하고, 둘 다 출력합니다. tests/test_bpe.py의 테스트는 왕복 속성, 특수 토큰 예약, 병합 순서를 고정합니다.

데모를 실행하세요. 그런 다음 데모의 목표 어휘 크기를 300에서 600으로 변경하고 보류된 문장의 인코딩된 길이가 어떻게 줄어드는지 확인하세요. 그 곡선이 BPE 압축 곡선입니다.
